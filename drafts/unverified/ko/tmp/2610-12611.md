# SoftwareGym: Scaling Computer-Use Agent Training with Diverse Synthesized Software Environments

**Source**: Jin et al., arXiv, 2026-10-08

**Lead**: Computer-use agents (CUAs) need interaction data from executable software, but integrating native apps is expensive (narrow coverage, overfitting risk) while browser-hosted worlds lack interaction depth. SoftwareGym is an automated multi-agent pipeline that designs, implements, and GUI-verifies synthetic desktop applications at scale. Its 182 apps across 12 categories reach a 91.5% mean GUI pass rate, and trajectories from them alone train a Qwen3.5-9B model that jumps from 41.39% to 56.97% Pass@3 on strictly out-of-domain OSWorld.

## Background

CUA training data comes from two sources, each with a flaw. Native desktop/mobile apps (OSWorld, Windows Agent Arena) preserve realistic state and complex workflows, but each app costs substantial integration effort—coverage stays narrow and agents overfit to a fixed pool. Browser-hosted synthetic worlds (InfiniteWeb, GUI-GENESIS) scale and control state easily, but share one browser/DOM substrate with limited workflow depth.

SoftwareGym targets three requirements jointly: interface/interaction diversity (for generalization), functional reliability (valid multi-step trajectories), and scalability (batch synthesis with minimal human input).

## SoftwareGym Pipeline

Three stages, each handled by specialized agents (built with Codex CLI + GPT-5.5, evaluated with Seed 2.1 Pro in Ubuntu VMs):

1. **Software Design**: FunctionDesigner expands minimal input into a functional specification (users, objects, operations, end-to-end workflows, acceptance checkpoints). StyleDesigner then creates variant-specific Avalonia UI blueprints forced to differ along at least two layout dimensions (tree-edit-distance checked), plus style-specific SVG icon assets.
2. **Implementation + source verification**: Coder builds the full app from the design package; DevCoder audits command bindings, logic, persistence, and startup against a functional manual.
3. **GUI evaluation + repair**: EvalTaskGenerateAgent writes checkpoint-based GUI tests (fixed after v1); GUIAgent executes them with mouse/keyboard (up to 50 steps/case). Failures loop back into localized repair, guarded by a visual-fidelity score so repair does not drift from the intended interface. Only apps passing both source and GUI verification enter the library.

**Task synthesis** then converts only GUI-verified capabilities (evidence-gated function trees) into leveled tasks (easy/normal/hard × file-based/blank-state) with programmatic outcome checks—forming SoftwareGym-Bench (120 tasks, 10 per category).

## Experiments

**Setup**: 182 synthesized apps across 12 categories. Multimodal SFT on Qwen3.5-9B using only SoftwareGym trajectories. Evaluation: OSWorld (244 tasks, 8 domains, zero OSWorld training data) and SoftwareGym-Bench; 3 rollouts per task, 100-step budget, Pass@3.

**Benchmarks**: OSWorld Pass@3, SoftwareGym-Bench Pass@3, GUI task pass rate, blueprint diversity (normalized tree-edit distance).

**Results**:

| Result | Number |
|--------|--------|
| OSWorld overall (base → trained) | 41.39% → 56.97% Pass@3 (+15.58pp), every domain improved, no OSWorld data used |
| SoftwareGym-Bench (base → trained) | 25.8% → 40.0% Pass@3, beating Qwen3.7-Plus and several larger specialized CUAs |
| GUI reliability across repair rounds | v1 54.9% → v2 81.1% → v3 91.5% mean pass rate |
| Style diversity (full vs simplified design) | Macro-average 4.9 → 83.6 |
| GUI-guided vs source-only repair | Same 50.4% start → 83.1% vs 48.8% |
| Synthesis cost per app (20-app sample) | ~237 min, 14.8M tokens, 1,718 calls, ~$70.76 |
| Combined SoftwareGym + OSWorld data | 47.5% on SoftwareGym-Bench (complementary, not redundant) |

## Relevance to Software Engineers

- **Synthetic envs as training data**: when real-app integration is the bottleneck, verified synthetic apps provide transferable supervision—gains carried over to real apps (OSWorld) untouched during training
- **Verify behavior, not just code**: source-level checks plateaued at ~49%; only GUI-executed checkpoint tests drove reliability to 91.5%—a pattern that transfers to any UI automation testing
- **Diversity must be enforced, not hoped for**: unconstrained generation converged to similar layouts; explicit pairwise-distance constraints (differ on ≥2 layout dimensions) raised diversity 17×
- **Evidence-gated task generation**: synthesize eval tasks only from capabilities with passing GUI evidence, or benchmarks test unimplemented behavior
- **Cost model**: ~$71 and ~4 hours per verified app—budgetable for building a private CUA training pool
