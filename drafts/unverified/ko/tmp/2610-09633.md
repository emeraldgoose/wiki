# Coding-Agent Benchmarks Should Match Their Users' Task Flows

**Source**: [huggingface](https://arxiv.org/abs/2610.09633)
**Date**: 2026-10-07

## Overview

The evaluation of coding agents typically relies on issue-derived benchmarks like SWE-Bench, where each task is a single user turn—almost always a new feature or bug fix. This paper argues that such benchmarks fail to capture how software engineers actually use interactive coding agents in production. The authors collected 4,782 real agent sessions from JetBrains IDEs ("Production Sessions"), filtering to the 33% with at least three user messages to study sustained interaction. These long sessions reveal two fundamental mismatches: (1) user requests cover a far wider mix of task types—questions about the codebase, planning, review, refactoring, and execution—not just feature implementation; (2) users frequently switch between task types within a single session, creating complex task flows that single-turn benchmarks cannot represent.

The paper introduces SWE-TaskFlow, a framework for transforming verified tasks into multi-turn task flows that mirror production patterns. A pilot study shows that the interaction layer itself changes measurement: agents that perform well on single-turn benchmarks can struggle when required to maintain context and adapt across a sequence of related requests.

## Background

Current agent benchmarks (SWE-Bench, SWE-Bench Pro) are constructed from GitHub issues, yielding isolated tasks. Real engineering work is conversational: developers ask clarifying questions, explore the codebase, plan changes, request reviews, and iterate. This gap means benchmark scores may not predict real-world utility.

## Methodology

The authors instrumented JetBrains IDEs to capture 4,782 agent sessions. They classified each user message into a taxonomy of task types (question, planning, review, refactoring, execution, other) and analyzed task-flow patterns—sequences of task types within a session. They then built SWE-TaskFlow, which takes verified SWE-Bench tasks and expands them into multi-turn flows by injecting realistic follow-up requests drawn from the observed distribution.

## Key Findings

- **Task diversity**: Production sessions span 6 task types; issue-derived benchmarks cover essentially one (feature/bug implementation).
- **Context switching**: 68% of multi-message sessions contain at least one task-type switch; the average session has 2.3 switches.
- **Benchmark transformation**: SWE-TaskFlow converts single-turn tasks into flows of 3–7 turns, preserving the original verification oracle.
- **Pilot results**: Agents strong on SWE-Bench show degraded pass rates on the transformed flows, especially when follow-ups require codebase understanding from prior turns.

## Relevance to Software Engineers

If you evaluate or adopt coding agents, single-turn benchmarks are insufficient. Look for evaluations that test multi-turn context retention, task switching, and codebase-aware follow-ups. SWE-TaskFlow provides a starting point for such evaluation.
