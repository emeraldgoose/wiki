# ThinkDrag: Semantic Drag-Based Image Editing with Visual Reasoning

**Source**: Fortes et al., arXiv, 2026-10-09

**Lead**: Drag-based editing (drag a handle point to a target) is intuitive but under-specified: the same displacement can mean rotating a part, translating a patch, or restructuring a scene, while existing methods treat drags as pure geometric displacements. ThinkDrag builds on the unified multimodal model BAGEL to interpret drags with scene semantics—optionally emitting an explicit reasoning trace before generating—and grounds each drag with Drag Endpoint Markers (DEM), a learned handle↔target correspondence signal. It achieves state-of-the-art generation quality on DragBench and the new DragBench++ benchmark, winning 80% of user-preference votes on the latter.

## Background

Drag editing progressed from DragGAN's GAN-latent optimization to diffusion test-time optimization (DragDiffusion, DragNoise, DragLoRA), one-step methods (FastDrag, GeoDrag), and feed-forward conditional generation from video-derived motion (InstantDrag, LightningDrag). All lean on the generative prior for plausibility while reading drags geometrically. Meanwhile unified multimodal models (BAGEL, Transfusion, Show-o) couple visual understanding with generation in one framework—exactly what ambiguous drags need, since executing them requires knowing what objects are and how they can move. A parallel line (unified models such as BAGEL) had not been adapted to spatially grounded manipulation.

## ThinkDrag: Data, Markers, and Joint Modeling

**Dataset.** Video-derived supervision is geometric and noisy (optical-flow failures, camera motion). Instead, an MLLM pipeline synthesizes source images (Qwen-Image, FLUX.2, Z-Image), proposes drag-compatible edit prompts, renders targets with FLUX.2, filters by MLLM judge, recovers semantic handle→target keypoints via Gemini 3 Pro (validated with DINOv3 + manual inspection), and writes reasoning chains via Gemini 3 Flash. Result: ~11K pairs from 7K sources → ~22K bidirectional samples (2.15 drags avg, 74% multi-drag, 123-word traces).

**Drag Endpoint Markers.** Each drag is expressed as structured text coordinates *plus* additive marker vectors $\mathbf{m}_k = \mathbf{m}_{\mathrm{shared}} + \mathbf{e}_k$ injected at handle and target VAE-token locations before every layer. Sharing one marker per drag biases the target location to attend to its handle—attention peaks at the handle for 51% of DragBench++ drags with DEM versus 6% without.

**Joint modeling.** Direct mode generates the edit from the multimodal prompt; reasoning mode first autoregressively generates the trace ($\mathcal{L}_{\mathrm{think}}$), then conditions rectified-flow image generation on prompt (+trace). Training on 10% text-conditioned samples additionally enables joint text-drag control (text disambiguates, drags anchor).

## Experiments

**Setup**: BAGEL-based, LoRA-adapted; evaluated on DragBench (205 samples) and the new DragBench++ (145 samples, 2.51 drags/sample, 108px avg displacement, pseudo-ground-truth reference edits, manual masks for mask-requiring baselines).

**Benchmarks**: DragBench and DragBench++; metrics MD (DIFT point tracking), MD$_{\mathrm{MLLM}}$ (GPT-5.5 tracking, more reliable under semantic change), IF / IF* (fidelity to input / to reference), FID, plus a 30-participant user study.

**Results**:

| Benchmark | ThinkDrag (direct) | Best baseline |
|-----------|-------------------|---------------|
| DragBench: IF / FID / MD | **0.918** / **30.05** / 28.84 | IF 0.900 (DragNoise); FID 38.90 (DragDiffusion); MD 22.77 (GeoDrag) |
| DragBench++: IF / IF* / MD / MD$_{\mathrm{MLLM}}$ | **0.875** / **0.905** / **47.66** / **34.24** | IF* 0.836 (LightningDrag); MD 48.36 (DragLoRA) |
| User study overall preference | **79.7%** (++) / **61.0%** (DragBench) | next best 7.7% / 17.0% |

Reasoning mode further lifts IF* to 0.911 (0.914 with reference prompt) and wins 56% of multi-drag samples; DEM alone cuts DragBench MD from 45.42 to 28.84. Notably, reference edits themselves score poorly on DIFT-MD, confirming MD$_{\mathrm{MLLM}}$ as the more semantic metric.

## Relevance to Software Engineers

Two portable ideas: (1) ambiguous spatial instructions should be resolved *semantically before* synthesis—an explicit reasoning trace doubles as an auditable, user-refinable artifact; (2) coordinate text alone under-grounds generation at scale, while a tiny learned correspondence signal (shared marker at both endpoints) sharply improves spatial precision—cheap to add to any token-based editor. If you ship editing features, adopt reference-based benchmarks like DragBench++ (multiple valid outputs need a plausibility anchor) and MLLM-judged spatial metrics where classic trackers break. Cost note: reasoning mode adds autoregressive latency (~14s total on H200); direct mode already beats baselines.
