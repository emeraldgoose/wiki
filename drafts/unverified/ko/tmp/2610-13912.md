# RSI-Anything: Unlocking Recursive Self-Improvement with World Models

**Source**: Cui et al., arXiv, 2026-10-09

**Lead**: Recursive self-improvement should turn interaction experience into lasting gains, but external feedback is expensive and world-model predictions go stale as policies evolve. RSI-Anything, built on the cross-domain JEPA-Anything predictor, uses world-model forecasts to guide action and learning-data selection, converts observed feedback into policy or workflow updates plus conditional world-model adaptation, and retains only policy–model pairs that pass component and compatibility checks. Across code repair, GUI agents, lab planning, reaction optimization, and an immune-science application, each loop links retained revisions to the next round of learning.

## Background

Within-task feedback refines solutions and across-round self-training updates policies, but recursiveness requires updates to persist and reshape subsequent interaction. World models can prospectively rank candidates to save feedback budget, yet policy updates shift the data distribution the predictor was trained on, and predictor updates change which candidates get selected—a coupled-update problem where improving either side alone need not improve the joint system. RSI-Anything makes prediction reliability under evolving policies an explicit design requirement.

## Framework: Predict, Update, Retain

Each cycle runs three stages. **Prediction-guided selection** scores policy-proposed candidates with the world-model readout $R_d(\hat{\tau}) = \sum_j w_{d,j} r_{\tau,j} - \Delta_d(\hat{\tau})$ (with optional uncertainty penalty), executes only affordable feasible ones, and admits high-utility imagined trajectories into training data via separate evidence-gated filters. **Feedback-driven improvement** converts observations into policy updates (demonstration, preference, or workflow search) and triggers predictor adaptation only when a reliability assessment on current-version predictions says "unreliable" with sufficient data and budget. **Recursive retention** applies component checks for each side plus a pair check on the assembled system's decision behavior under matched evaluation conditions; failures keep the current version, so only accepted pairs shape the next round.

## Experiments

**Setup**: Fixed ReasonFlux-Coder-7B policy on 200 CodeContests tasks (3 seeds, up to 3 feedback rounds, 4 candidates per round); MiniWoB++ checkboxes and OSWorld for GUI; LabHorizon F200 Level-2 (200 tasks) across five successive 4B policy versions; two Suzuki–Miyaura reaction screens vs. Bayesian optimization at matched experiment counts.

**Results**:

| Domain | Baseline | RSI-Anything | Note |
|--------|----------|--------------|------|
| Code repair (hidden pass rate) | 26.3% static verifier | 29.2% fixed WM → 31.2% adaptive WM | Same ~3.7 online calls/task; ranking 66.5→72.8%, Brier 0.488→0.358 |
| GUI checkboxes | 51% success, 5.30 acts/ep | 99% success, 3.21 acts/ep (−39.4%), 0 repeat clicks | OSWorld +5.5% relative over RLAnything |
| Lab planning (Final Score) | 21.80% v1 | 46.01% v5 (+24.21pp) | Beats Actor–Simulator–Selector 45.32% |
| Reaction GC screen (20 exps) | 87.5% BayesOpt | 93.0% (+5.5pp) | Flow screen at 40 exps: 96.15% vs 82.16% (+13.99pp) |
| APPS Intro / LiveCodeBench | random/static lower | 46.37% / 33.05% | Same coder and budgets |

An end-to-end immune-science application connects workflow evolution, immune world-model construction, self-correcting analysis, and prospective therapeutic hypothesis generation (awaiting experimental testing).

## Relevance to Software Engineers

RSI-Anything is a blueprint for self-improving agent systems under tight feedback budgets:

- **Gate expensive actions with a learned predictor**: rank candidates with a cheap world model before spending real executions, tests, or lab runs—gains held at identical online usage.
- **Version the policy–predictor pair, not each side**: compatibility checks on assembled behavior prevent a "better" predictor from degrading the deployed loop; keep current versions on check failure.
- **Adapt predictors conditionally**: re-fit only on verdict "unreliable" with enough fresh data, using current-version predictions for the assessment—avoids churn and stale pooling.
- **Track retained-version metrics**: the lab-planning 5-version progression shows compounding wins are measurable per retained revision, which suits staged rollouts with acceptance gates.
