# One Model to Loop Them All: Elastic Latent Recurrence for Language Models

**Source**: Ladhak et al., arXiv, 2026-10-08

**Lead**: Latent recurrent (looped) language models apply a shared layer block repeatedly, so one checkpoint can trade inference compute for accuracy via the loop count—but at one loop they typically trail a same-size non-recurrent model (the *one-loop tax*), making a separate dense model the better latency-tier choice. Elastic Latent Recurrence (ELR) is a training recipe that removes the tax: at one loop the model executes every unique layer exactly once at baseline parity, and each additional loop buys accuracy. Three choices make it work—a gated adaptive-delta state update, loop counts mixed *within* each optimizer step, and per-pass loop-index/budget conditioning—plus cost controls (delayed mixed-depth training, cross-loop route replay, last-loop KV caching) and a post-trained proof point, Koi-4B.

## Background

Elastic depth (one checkpoint served at several depths) is attractive for deployment: the loop count becomes a quality-vs-compute knob like reasoning effort, but without generating extra tokens. Prior looped models (Huginn, Parcae, Ouro) pay the one-loop tax—e.g., Huginn trails its baseline 34.9 vs. 46.4 on ARC-Easy—and small loop ranges or higher one-loop sampling probability alone do not remove it. Sampling one loop count per step (locked-step, as in Huginn) fails to preserve the one-loop endpoint even when one loop is drawn a third of the time.

## The ELR Recipe

The backbone is partitioned into input, shared recurrent (~middle half of layers), and output blocks, so one loop executes each unique layer exactly once with baseline-matching parameters and compute. (1) **Adaptive-delta update**: instead of replacing the state with the recurrent block output, take a gated step along the proposed revision with a learned per-token per-channel step size (zero-initialized, ~0.35 initial). (2) **Mixed-depth training with one-loop rank overrides**: sample loop counts uniformly but force a rotating fraction of data-parallel ranks to run one loop on every microbatch, so one-loop and deep gradients share the same optimizer update (~one-third one-loop probability). (3) **Loop-conditioned modulation**: condition each pass on progress $\tau_i = i/k$ and budget $\kappa = k/K$ via AdaLN/FiLM-style scale/shift, low-rank correction, and exit gating—zero-initialized so grafting preserves the checkpoint exactly.

Cost controls: **delayed mixed-depth training** (one loop for the first 75%, mixed depth only in the final quarter: ~1.16x baseline training FLOPs vs. 1.62x throughout); **cross-loop route replay** for MoE (reuse first-loop router assignments on later loops: −11.7% mixed-depth update time, no accuracy change); **last-loop KV caching** at inference (one shared cache overwritten per loop: attention KV memory stays at one-loop level, most multi-loop gains retained).

## Experiments

**Setup**: GDP-Hybrid-4B dense (1T tokens, AdamW) and GDP-Hybrid-30B-A3B MoE (300B tokens), same data/token budgets as matched non-recurrent baselines; delayed schedule $k \in \{1..4\}$, 10% override ($p_1 = 0.325$). Ten-task average (MMLU, MMLU-Pro, ARC-C, GSM8K, WinoGrande, CSQA, RACE-high, HumanEval, MBPP, MATH-500). Koi-4B: full recipe at 7T tokens + 256K context mid-training + SFT/RLVR post-training, evaluated on Artificial Analysis Intelligence Index v4.1 suite in the authors' harness.

**Results**:

| Model | 1-loop vs. baseline (10-task avg) | 1→4 loops gain |
|-------|-----------------------------------|----------------|
| GDP-Hybrid-4B ELR (65.13) | −0.52pp vs. 65.65 | +7.25pp |
| GDP-Hybrid-30B-A3B ELR (66.08) | +1.04pp vs. 65.04 | +4.75pp |

Most gain arrives early: 2 loops capture 79–87% of the 1→4 improvement. At 4 loops, latency is 2.33x TTFT / 2.06x decode vs. baseline; 3 loops capture 96% of the gain at 1.87x TTFT. Koi-4B's AA-Index estimate rises 18 → 26 → 28 → 29 over $k = 1..4$ (1 loop ≈ Qwen3.5-4B; 4 loops +3 over a ~6.5x-larger model), while generating *shorter* responses at higher loops (−21.8%/−29.5%/−32.7% output tokens): latent depth substitutes for chain-of-thought tokens, so per-rollout decode time rises only ~6% at 2 loops. Last-loop KV caching costs 0–3pp per benchmark at 4 loops (2.5x → 1x KV memory: 7.5 → 3.0 GiB per 128K-token request). Ablations on a 0.5B model confirm each choice: independent-rank mixing beats synchronized sampling but costs 36% step time (overrides recover part of it); conditioning lowers loss at every added loop and makes the delayed schedule beat from-scratch mixed-depth training.

## Relevance to Software Engineers

ELR gives serving teams a single-checkpoint multi-tier story: deploy one 4B artifact and serve latency-sensitive traffic at 1 loop and quality-sensitive traffic at 2–4 loops, with KV memory flat and per-rollout cost nearly flat at 2 loops thanks to shorter generations. The loop count behaves like a reasoning-effort dial that emits no extra tokens—useful where output-token budgets or streaming latency dominate. For training, the delayed schedule (≈16% extra FLOPs) and route replay make elasticity cheap to retrofit, and the zero-initialized grafting trick generalizes: add new conditioning to a trained checkpoint such that day-zero behavior is bit-identical, then learn departures. Open questions practitioners should note: returns diminish after loop 2, and per-request adaptive depth (vs. fixed loop count per request) remains future work.
