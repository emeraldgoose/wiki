# 에이전트 지속 학습을 위한 순환 하네스

**Source**: Xiao et al., arXiv, 2026-10-08

**핵심**: 긴 상호작용 스트림에서 동작하는 언어 모델 에이전트는 모델 가중치 없이 온라인으로 분포 변화에 적응해야 한다. 기존 하네스는 기억을 전방향으로만 진화—한 번 쓰고 영원히 검색—시켜 과일반화되거나 낡은 리플렉션이 이후 인스턴스를 계속 오도한다. ReHarness는 역방향 수정으로 고리를 닫는다: 각 인스턴스 후 수정 에이전트가 결과 궤적을 피드백으로 검색된 리플렉션을 다시 쓰고, 새 내용은 원천 궤적에 근거시킨다. 9개 벤치마크-백본 조합 중 8개에서 1위, 통계 유의한 이득.

## 배경

에이전트 하네스는 고정 LLM을 감싸는 영속 런타임 비계다: 기억 저장소(Mem0), 리플렉션 뱅크(RBank), 큐레이션 플레이북(ACE), 다양 리플렉션 생성기(DoT), 온라인 프롬프트 최적화기(GEPA-Online). 거의 모두 전방향 흐름으로만 상태를 진화시킨다: 마지막 궤적에서 추출→상태에 기록→나중에 검색. 한 번 기록된 리플렉션은 하류에서 얼마나 잘 작동했는지 기준으로 거의 수정되지 않는다. 분포가 바뀌면 낡은 지침이 남아 오류가 전파된다.

ReHarness는 엄격한 온라인 스트리밍 프로토콜을 노린다: 인스턴스는 한 번만 관찰, 리플레이 없음, 검증셋 없음, 그래디언트 없음(API 모델)—하네스 상태의 텍스트 피드백만 사용.

## ReHarness: 순환 고리 닫기

하네스 상태 $h_t$에서 인스턴스 $t$마다 세 단계:

1. **전방향 읽기**: 상위-$k$($k=5$) 관련 리플렉션 검색, 결정 에이전트 행동, 환경이 보상 반환 → 궤적 $\tau_t$
2. **역방향 수정**: 수정 에이전트가 검색된 각 리플렉션 $R_i$를 원천 궤적 $\tau_i$와 효과성 피드백 $\tau_t$로 독립 수정해 $R'_i$ 생성—빠진 근거 추가, 무근거 가설 교정, 적용 조건 축소. 새 내용은 반드시 $\tau_i$에 근거해야 함($\tau_t$에서 누설 금지)
3. **전방향 쓰기**: 기억 에이전트가 $\tau_t$를 새 리플렉션 $R_t$로 증류, 수정된 리플렉션을 시범으로 사용; $h_{t+1} = h'_t \oplus R_t$

정렬 예시: (내림차순에서 배운) "큰 수부터 배치"가 오름차순 질의를 오도; 수정이 "내림차순일 때만 큰 수부터"로 좁히고, 수정이 이후 인스턴스로 전파된다.

## 실험

**설정**: 엄격 온라인 스트리밍, 학습/검증 분리 없음, 스트림 사이 하네스 리셋, 태스크당 3개 샘플 롤아웃. 백본: Claude Opus 4.8, GPT-5.5, Gemini 3.7 Flash(방식 내 전 에이전트 동일 백본). 검색: Qwen3-Embedding-8B 상위-5. 베이스라인: Mem0, RBank, DoT, ACE, GEPA-Online, Top-K Raw, Full Raw.

**벤치마크**: CL-Bench(6개 태스크: 코호트 연구, 코드베이스 적응, DB 탐색, 매출 예측, 스펙트럼 모니터링, 포커), MemoryBench(영어 글쓰기 5개), MemoryArena(5개 도메인: 여행, 쇼핑, 웹 검색, 수학, 물리). 지표: 무상태 백본 대비 정규 이득, 스트림별 평균.

**결과**:

| 결과 | 수치 |
|--------|--------|
| 평균 정규 이득(ReHarness) | 0.240 — 9개 조합 중 8개 1위/공동 1위; Top-K Raw 0.168, Full Raw 0.164 대비 |
| 통계 유의성 | 짝 Wilcoxon + Bonferroni: 전 베이스라인 상회($p_{adj}$ < 0.05), Top-K Raw(0.039), Full Raw(0.043) 포함 |
| 수정의 원천 근거성 | 원천 궤적 근거 주장 95% 초과; 누설은 0.8–2.1%에 불과 |
| 반사실 리플레이(CL-Bench, Claude) | 0.335 vs 온라인 ReHarness 0.217 vs 수정 없음 0.144 — 수정은 유의미, 온라인 적용도 도움 |
| 안정성 / 가소성(평균) | 0.015 / 0.241 — 둘 다 평균 최고; 전방향 베이스라인은 안정성에서 음수 |
| 토큰 효율(CL-Bench, Claude) | 총 ~41.6M vs Top-K Raw ~52.7M vs Full Raw ~142.1M(압축 리플렉션이 원시 히스토리 상회) |
| 제거 연구 | $k=5$ 최적(더 크면 드리프트); 쓰기 시범에서 수정본 제거: 0.217 → 0.191 |

약점: 확률적 보상이 수정 신호를 흐리는 exploitable poker. 한계: 향후 수정을 위해 원시 궤적 저장 유지(스토리지 오버헤드).

## 소프트웨어 엔지니어를 위한 시사점

- **자기 교정 에이전트 기억**: 장수명 에이전트(지원 봇, 코딩 어시스턴트, 리서치 에이전트)에 기억/리플렉션 저장소가 있다면 수정 패스 추가—검색된 기억을 그것이 낳은 결과로 채점해 좁히거나 교정
- **근거 제약이 핵심**: 수정은 현재 궤적이 아니라 원천 궤적을 인용해야 함; 없으면 피드백이 누설이 되어 리플렉션 드리프트
- **적은 검색으로 충분**: $k=5$가 더 큰 수정 집합을 이김; 수정 범위를 제한해 비용과 드리프트 통제
- **압축이 원본을 이긴다**: 증류된 리플렉션 저장이 전체 히스토리의 ~1/3 토큰으로 더 높은 점수—운영 에이전트의 컨텍스트 윈도 예산에 직결
- **안정성과 가소성을 분리 측정**: 전방향 기억은 분포 변화 직후 종종 음수; 변화 후 전이와 분포 내 적응을 둘 다 테스트
