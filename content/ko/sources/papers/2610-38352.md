# WeVisCut: 내레이션에서 장편 비디오까지 한 에이전트로 편집실 전체 다루기

출처: Chenyu Mu 외 10인, arXiv:2610.38352, 2026-10-28.

**핵심 요약**: 내레이션에서 장편 비디오를 만들려면 샷 전반에 걸쳐 일관된 상호의존적 결정이 필요합니다. 기존 에이전틱 에디터는 범용 모델에 의존하는 다단계 워크플로를 자주 사용해, 작고 작업에 적응된 정책의 품질-비용 절충이 불분명했습니다. **WeVisCut**은 도구 실행과 정책 학습을 연결하는 장편 스크립트-투-비디오 시스템입니다. 에이전트 하네스는 제작 상태를 공유해 도구 피드백이 이후 결정과 복구에 반영되게 합니다. 완성 비디오가 자체 결정을 드러내지 않기 때문에, 4단계 데이터 파이프라인은 편집 인버전과 검증된 재생을 결합해 회복된 편집 의도를 실행 가능한 감독으로 바꿉니다. 3,750개 완성 비디오에 파이프라인을 적용해 **130,000개 이상 훈련 예제**를 얻었습니다. 이 감독으로 같은 하네스 안에서 제작을 조율하고 실패를 복구하는 단일 **9B 정책**을 학습합니다. WeVisCut은 편집 품질과 전달 안정성을 평가하는 **100태스크 벤치마크와 5개 지표**도 도입합니다. 공유 도구 환경에서 WeVisCut은 기반 모델을 크게 앞서고, 성공 출력 분당 생성 토큰을 거의 **33배 적게** 쓰면서 Claude Opus 5에 필적했습니다. 제안 지표에서 태스크 정합 네이티브 에디터도 능가했습니다.

## 핵심 내용

- 공유 제작 상태로 도구 실행과 정책 학습을 연결한다.
- 피드백이 이후 결정과 복구에 반영된다.
- 편집 인버전과 검증된 재생으로 완성 비디오에서 실행 가능 감독을 만든다.
- 3,750개 비디오에서 130,000개 이상 훈련 예제를 얻었다.
- 단일 9B 정책이 제작과 복구를 조율한다.
- 100태스크 벤치마크와 5개 지표를 도입했다.
- 성공 분당 토큰을 33배 줄여도 강한 모델에 필적했다.

## 상세

9B 정책은 다단계 범용 모델 워크플로를 같은 도구 하네스 내 단일 모델로 대체합니다. 토큰 효율은 추론 시 더 큰 범용 모델을 프롬프트하는 대신 편집 의도를 감독으로 복원하는 데서 옵니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 4단계 데이터 파이프라인과 평가 세부는 원문을 함께 확인해야 합니다.

## SW 엔지니어와의 관련성

- 공유 상태는 도구 피드백 기반 복구 루프를 가능하게 합니다.
- 역추출된 의도에서 감독을 만들면 토큰 비용을 줄일 수 있습니다.
- 작은 정책이 강한 범용 모델에 필적할 수 있음을 보여줍니다.
