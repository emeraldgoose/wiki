# ProgramGym: 장기 프로그램 재현 에이전트를 위한 학습 환경 확장

**Source**: Yang 외, arXiv, 2026-10-09

**핵심**: 코딩 에이전트는 대개 주어진 저장소를 고치거나(SWE-bench) 요구사항 문서대로 구현한다—*무엇을* 만들지 발견하고 *어떻게* 설계할지 정하는, 처음부터 만드는 엔지니어의 일은 하지 않는다. 프로그램 재현(소스·네트워크 없이 바이너리+문서만으로 관측 행태를 재구축)은 정확히 그것을 시험하지만, 검증 가능한 학습 환경이 드물고 단일 세션 에이전트는 긴 호라이즌에서 초기 증거를 잃는다. ProgramGym은 피드백 주도 파이프라인 Program-Env로 1,648개 검증 환경(C/C++/Go/Rust)을 만들고, 역할 분리된 분석→구현→리뷰 루프와 리비전 관리를 갖춘 Program-Agent로 푼다. 궤적 파인튜닝으로 Qwen3.8-27B의 ProgramBench Tests Passed가 34.87%에서 42.84%로 오르고, Program-Agent 적용 시 base·SFT 모델이 55.71%·56.25%까지 올라 플래그십 모델들을 넘는다.

## 배경

 이슈 해결·NL-to-repo 과제는 코드베이스나 명세서를 손에 쥐여줘서 국소 수정·구현 문제로 축소된다. ProgramBench식 재현은 발판을 치운다: 실행 전용 참조 바이너리, 문서, 네트워크 차단 샌드박스만 주고, 블랙박스 테스트가 공유 입력에서 후보와 참조의 행태를 비교한다. 기존 자원(SWE-Gym, SWE-smith)은 수정을 지도하고 처음부터 만들기를 지도하지 않으며, MindForge는 CLI 전용에 지도가 검증 불가하고, 원래 ProgramBench 200개 과제 중 플래그십 모델이 완전히 푼 것은 하나도 없었다. 두 가지 간극이 남는다: (1) 다양한 툴체인에서 참조 실행 파일 + 변별력 있는 블랙박스 테스트를 규모 있게 만들기, (2) 단일 세션 컨텍스트를 넘는 호라이즌에서 탐색-후-구축을 조율하기.

## Program-Env: 피드백 주도 환경 구축

30,459개 GitHub 후보(언어/스타 층화, 커밋 고정, 빌드 설정 심사)에서 Claude Code/Codex 하니스에 바깥 검증 루프를 얹어 세 단계를 돌린다:

1. **실행 파일 + 샌드박스**: 에이전트가 `download.sh`(온라인 의존성)와 `compile.sh`(오프라인 빌드)를 작성하고, 둘 다 성공하고 바이너리가 로드 검사를 통과해야 다음 단계로 가며, 아니면 진단이 반환되어 수정한다.
2. **디스패치**: 코드 규모로 모듈을 병렬 브랜치에 나누고, 커버리지를 계측하고, 문서를 추출한다.
3. **블랙박스 테스트**: 각 브랜치가 세 가지 피드백 문서(요약, 프로그램 분석 유도 미탐색 지점, 검증 스크린—통과·반복 일관성·더미 구현 기각·약한 assertion 검사)를 읽으며 반복하고, 모든 검사를 통과한 테스트만 병합 후 살아남는다.

결과: 1,648개 환경, 평균 커버리지 72.99%(중앙값 81.63%), 검증된 테스트 665,512개(저장소당 ~404개).

## Program-Agent: 역할 분리 장기 워크플로

세 단계가 독립 세션에서 돌아(공유 히스토리 없이 핸드오프 산출물만 전달) 컨텍스트 오염을 막는다: **분석**은 문서+참조 바이너리를 탐색해 `analysis.md`를 읽기 전용으로 고정하고, **구현**은 참조를 만지지 않고 핸드오프만으로 빌드한다(선행 기준선, 이후 점진 수정), **리뷰**는 후보와 참조의 행태 차이를 다음 라운드 요구사항으로 바꾼다. **리비전 관리**는 워크스페이스 밖에서 깨끗한 스냅샷을 컴파일해 통과본을 보관하고, 실패 단계는 새 세션에서 제한 예산 내 재시도하며, 그래도 안 되면 마지막 검증 리비전으로 롤백한다. $K = 5$ 라운드에서 Tests Passed는 43.49%($K{=}1$) → 54.13%($K{=}3$) → 56.25%($K{=}5$)로 오르고, 이득의 대부분은 $K{=}3$에서 나온다.

## 실험

**설정**: ProgramBench; 기준선 Claude Code(단일 세션, 컨텍스트 압축) vs Program-Agent($K = 5$); 모델 DeepSeek-V4-Flash-0731, Qwen3.8-27B base, Qwen3.8-27B-SFT(기각 샘플링 궤적의 ms-swift 파인튜닝); 격리 컨테이너(8 CPU, 16GB, 8시간 제한). 지표는 Tests Passed %(매크로 평균), Almost Resolved %(≥95%), Resolved %(100%, 부정행위 없음).

**벤치마크**: ProgramBench 프로그램 재현 과제; mini-SWE-agent 아래 프론티어 모델들을 참조점 삼는다.

**결과**:

| 모델 | 스캐폴드 | Tests Passed | base 대비 |
|-------|----------|-------------|----------|
| Qwen3.8-27B | Claude Code | 34.87% | — |
| Qwen3.8-27B-SFT | Claude Code | 42.84% | +7.97 (학습 효과) |
| Qwen3.8-27B | Program-Agent | 55.71% | +20.84 (스캐폴드 효과) |
| Qwen3.8-27B-SFT | Program-Agent | **56.25%** | +21.38 |
| Claude Opus 4.7 / Gemini 3.5 Flash (mini-SWE-agent) | — | 50.90% / 53.60% | Program-Agent 실행이 둘 다 상회 |
| DS-V4-Flash-0731 | Claude Code → Program-Agent | 57.68% → 58.97% | +1.29 |

행태 분석: Program-Agent는 행동 비중을 read/git(탐색+리비전) 쪽으로 옮기며, 특히 SFT 후 두드러진다. 그러나 Resolved %는 어디서나 ~0%에 머문다—완전 재현은 여전히 미해결이고, SFT 단독은 Claude Code 아래에서 Almost Resolved를 오히려 떨어뜨린다(3.50% → 1.50%).

## 소프트웨어 엔지니어를 위한 시사점

SWE 에이전트를 만드는 팀에 주는 교훈 세 가지: (1) *검증 가능한* 환경에 투자하라—4개 자동 테스트 품질 게이트(통과/일관성/더미/약한 assertion)는 에이전트 지도를 신뢰하기 위한 재사용 가능한 조리법이다; (2) 장기 작업은 하나의 거대 세션이 아니라 고정된 핸드오프와 검증된 체크포인트를 가진 분리된 역할들로 스캐폴딩하라—여기서는 +20pp로 파인튜닝의 +8pp을 압도한다; (3) 반복 예산을 명시적으로 잡아라($K{=}3$이 이득의 대부분). 주의: 과제 난이도는 쉬움 쪽으로 치우쳐 있고(1,648개 중 1,492개), 이득은 행태 일치 테스트 기준이라 테스트 입력에서의 일치를 뜻할 뿐 의미 동등이 아니다.
