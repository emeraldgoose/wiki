# Agent-R²: 실제 출처 데이터 합성으로 현실적 생산성 작업을 위한 에이전트 확장

**원문**: [arXiv:2611.08219](https://arxiv.org/abs/2611.08219) · **게시일**: 2026-11-05
**저자**: Teng Pan, Zixuan Wang, Yuchen Yan, Qifei Wu, Yao Chen, Yingqi Qu, Ruiqing Zhang, Yongliang Shen

## 개요

언어 모델 에이전트에 대해 이제는 현실적인 생산성 작업, 즉 장기적인 전문 워크플로 수행, 이질적인 파일 이해, 보고서·스프레드시트·프레젠테이션 같은 실제 산출물 작성이 기대된다. 논문은 이 영역의 병목을 학습 데이터에서 찾는다. 사람이 워크플로를 직접 작성하는 방식은 확장이 어렵고, LLM이 생성한 파일은 실제 문서가 지닌 레이아웃, 정보 공백, 파일 간 상호 참조를 갖추지 못한다. Agent-R²는 합성 파이프라인의 모든 단계를 실제 자료에 고정하는 방식으로 이 문제를 푼다. 직업 활동 씨앗을 이용해 웹 코퍼스에서 파일 중심 워크플로 청사진을 뽑아내고, 검색·검증 루프로 각 워크플로를 뒷받침하는 공개 파일을 수집한 뒤, 검증된 워크플로-파일 쌍에서 지시문과 세분화된 루브릭을 합성한다.

1만 개의 웹 코퍼스 후보에서 4천 개의 과제 인스턴스를 증류하며, 각 과제는 실제 다중 형식 첨부 파일과 산출물 수준의 루브릭을 짝짓고 평균 2.51개의 첨부 파일을 담는다. 50페이지를 넘거나 2MB를 넘는 파일은 버려 구축 비용을 통제하고, Claude-Opus-4.5를 전문가 정책으로 삼아 샌드박스에서 과제를 풀게 하여 참조 파일과 전문가 궤적을 만든다. 루브릭을 충족하지 못하는 항목은 수정하거나 산출물을 다시 만든 뒤에야 과제가 확정된다.

이 데이터로 Qwen3-4B-Thinking-2507 백본을 두 단계로 학습한다. 3천 개 인스턴스로 SFT를 하고, 1천 개 과제로 GRPO 기반의 루브릭 보상 강화학습을 진행하며, Qwen3.6-Plus를 판정 모델로 써서 산출물을 루브릭과 참조 파일 기준으로 채점한다. 4천 개 인스턴스만으로 학습한 Agent-R²-4B는 GDPval과 OfficeQA에서 훨씬 큰 기준 모델들을 제치고, 충분한 근거 확보나 구성, 검증에 앞서 그럴듯해 보이는 산출물을 내놓는 지름길 행동도 완화한다.

## 핵심 내용

- GDPval 전체에서 Agent-R²-4B는 51.0%로 Qwen3-235B-A22B-Thinking-2507의 48.0%를 앞서고, 도메인 외 OfficeQA에서도 14.8% 대 13.8%로 앞선다. GDPval Pass@1 기준 베이스 모델(32.4%) 대비 개선폭은 18.6포인트이다.
- 사무형 과제에서는 Pass@3 기준 Gemini-2.5-Pro와 4.7포인트 차이까지 좁히고, OfficeQA Pass@3는 26.8%로 235B 모델의 25.6%를 넘는다.
- 파이프라인은 실제 파일의 복잡성을 보존한다. 워크플로별로 공개 파일을 검색·검증하여 50페이지나 2MB를 넘는 파일은 버리고, PDF·스프레드시트·프레젠테이션을 원래 레이아웃과 파일 간 의존 관계 그대로 유지한다.
- SFT는 탐색 행동을 크게 바꾼다. 평균 도구 호출 단계가 베이스의 6.7에서 39.0으로 늘고 오류도 2.88에서 16.3으로 늘어나며, 완료율은 86.8%에서 78.2%로 소폭 내려간다.
- 강화학습은 탐색을 안정적인 완성으로 바꾼다. 완료율은 90.9%로 오르고, 평균 도구 호출은 33.1단계, 오류는 16.3에서 12.9로 줄어든다.
- 지름길 행동 지표가 단계마다 개선된다. 산출물 재검토 비율은 0.5%에서 SFT 후 91.7%, 강화학습 후 95.8%로 오르고, 미해결 오류 상태에서 작성을 강행하는 비율은 55.0%에서 11.0%로 떨어진다. 자리표시자 텍스트 비율은 5.7%까지 내려가 전문가가 작성한 GDPval 산출물과 같아지며, 추적 가능한 숫자 비율은 31.2%에서 38.8%로 오른다.
- 소거 실험은 두 설계 선택의 기여를 분리한다. 실제 파일로 학습한 SFT는 GDPval Pass@1 43.3%로 합성 파일의 41.4%보다 높고, 이때 전문가 궤적의 도구 호출은 20.4회로 합성 파일의 8.0회보다 2.54배 많다. 루브릭 보상을 빼면 강화학습 Pass@1이 51.0%에서 49.5%로 떨어진다.

## 세부 사항

### 합성 파이프라인

3단계 파이프라인은 직업 활동 씨앗에서 출발해 웹 코퍼스에서 워크플로 청사진을 추출한다. 첨부 파일 탐색 단계는 여러 차례의 검색-검증 루프를 돌며 제목과 요약으로 후보를 거르고 다운로드 후 표지나 목차 같은 핵심 부분을 직접 확인하며, 워크플로의 정보·조작 요구를 함께 충족하는 파일만 남긴다. 과제 합성 단계는 각 워크플로-파일 쌍을 샌드박스에서 구현하고, 페이지 단위 이미지 변환과 스프레드시트 표 변환을 거쳐 지시문과 루브릭을 함께 설계한다. 전문가 정책(Claude-Opus-4.5)이 과제를 풀어 참조 산출물을 만들고, 검증기가 루브릭과 대조한 뒤 문제가 있는 항목은 루브릭을 고치거나 산출물을 한 번 더 수정하도록 한다.

### 학습 및 평가 프로토콜

SFT는 전문가 궤적을 따라 파일을 살피고 도구로 산출물을 만들도록 가르치고, 루브릭 기반 강화학습은 지속 샌드박스에서 GRPO로 결과 품질을 최적화한다. 산출물과 근거는 모델이 읽을 수 있는 형태로 바뀐다. PDF, PPTX, DOCX는 이미지로 렌더링하고 XLSX는 재계산된 값과 수식, 렌더링된 페이지를 함께 보존한다. 보상은 판정 점수를 정규화한 값이며, 도구 호출 오류에는 중간 처벌을 두지 않아 특정 도구 호출 스타일에 치우치지 않도록 한다. GDPval은 Gemini-3.1-Pro를 심사 모델로 하는 에이전트 심사 프로토콜로 채점하고, OfficeQA는 규칙 기반 매칭과 모델 평가를 결합하며, 두 벤치마크 모두 100단계 상한을 둔다.

### 행동 분석

논문은 성능을 유효 단계, 즉 오류로 끝나지 않은 도구 호출 단계와 연결 짓고, 이것이 모델 규모 전반에서 GDPval Pass@1과 양의 상관을 보인다고 설명한다. 얕은 탐색 후 성급하게 산출물을 쓰는 실패 양상을 지름길 행동으로 규정하고, 재료 시험 보고서 사례에서는 베이스 모델이 가짜 스프레드시트 근거로 보고서를 쓰고 Gemini-2.5-Pro가 핵심 측정값을 NaN으로 바꾸어 빈 그래프를 만드는 반면, Agent-R²-4B는 구문 분석·계산·그리기 오류에서 복구하고 최종 그래프를 검증한다.

### 적용 범위

결과는 4B 백본으로 GDPval(도메인 내)과 OfficeQA(도메인 외)에서 확인되었다. 루브릭 검증 고리는 참조 산출물을 만들 강한 전문가 정책에 의존하며, 오디오·비디오 산출물을 포함하는 비사무형 GDPval 하위 집합은 상대적으로 어려운 영역으로 남아 있다. 이 하위 집합에서는 SFT보다 강화학습의 기여가 더 크게 나타난다.
