# 멀티모달 비전 인코딩 분해

**원문**: [arXiv:2611.17334](https://arxiv.org/abs/2611.17334) · **게시일**: 2026-11-12
**저자**: Ellis Brown, Chris Hoang, Shengyi Qian, Shang-Wen Li, Mike Lewis, Marjan Ghazvininejad, Luke Zettlemoyer, Lucas Beyer, Mengye Ren, Jakob Verbeek, Saining Xie, Hu Xu

## 개요

멀티모달 언어 모델이 시각 입력을 어떻게 인코딩해야 하는지는 아직 논쟁 중입니다. 대다수 모델은 사전학습된 비전 인코더를 붙이고, 최근 일부 레시피는 언어 모델과 함께 인코더를 처음부터 학습하며, 또 다른 레시피는 인코더를 아예 뺍니다. 저자들은 공개된 모델만으로는 이 논쟁을 판가름할 수 없다고 지적합니다. 비전 인코더는 세 가지 설계 선택을 한 덩어리로 묶고 있기 때문입니다. 상위 사전학습에서 오는 시각 사전, 시각 토큰만 쓰는 전용 시각 용량, 그리고 멀티모달 백본 앞에 그 용량을 두는 퓨전 이전 배치가 그것입니다. 여기에 공개 모델들은 데이터, 구조, 연산량까지 제각각입니다.

그래서 논문은 모든 구성 요소를 하나의 통제 프로토콜 아래에서 처음부터 학습합니다. 네 레시피가 하나의 백본 구조와 공통 데이터를 공유합니다. 사전학습 인코더, 스크래치 인코더, 인코더 없음, 그리고 시각 전용 용량을 백본 가장 초기 계층 안에 넣는 퓨전 내 방식입니다. 비교는 최종 모델을 만드는 모든 학습 단계의 연산을 합친 생애 연산량을 맞춘 상태에서 이루어지고, 시각 질의응답과 언어 벤치마크로 평가합니다. 주요 비교는 Qwen3 1.7B와 4B 구성에서 전용 시각 용량을 0.4B 파라미터로 고정해 수행하고, 스케일링 연구는 백본에 비례해 시각 용량을 키우는 0.6B에서 6.4B까지의 사다리를 씁니다.

결과는 세 줄로 요약됩니다. 시각 사전은 필요하지 않습니다. 함께 학습한 스크래치 인코더가 별도 단계 없이 사전학습 인코더와 대등했습니다. 진짜 중요한 것은 전용 시각 용량입니다. 인코더 없는 모델은 백본을 인코더 파라미터만큼 키워도 시각 이해에서 뒤처졌습니다. 그리고 그 용량이 퓨전 앞에 있을 필요는 없습니다. 초기 백본 계층에 넣은 퓨전 내 시각 전용 모듈이 퓨전 이전 인코더에 필적했고, 별도 인코더가 백본 앞에서 돌지 않으므로 첫 토큰까지의 시간도 줄일 수 있었습니다.

## 핵심 내용

- 사전학습 인코더, 스크래치 인코더, 인코더 없음, 퓨전 내 방식의 네 레시피를 비교하며, 외부 사전학습 모델 없이 모두 처음부터 학습하고 시각 입력 인코딩 방식만 다릅니다.
- 주요 비교는 Qwen3 1.7B와 4B 백본에서 전용 시각 용량을 0.4B 파라미터로 고정해 진행되고, 스케일링 연구는 백본 크기에 비례해 시각 용량을 키우는 0.6B에서 6.4B 사다리를 씁니다.
- 생애 연산량 예산은 6.5e20에서 2.9e22 FLOPS, 즉 56B에서 1.11T 토큰 환산분까지이며, 1.7B에서는 토큰 대 파라미터 비율 788, 4B에서는 306에 이릅니다.
- 지표의 동기로, 널리 쓰이는 인코더인 SigLIP 2는 400억 개 영상-텍스트 샘플, 약 10조 영상 토큰으로 학습되는데, 멀티모달 학습만 세면 이 비용이 숨겨집니다.
- 학습 데이터는 텍스트 전용과 영상-텍스트 시퀀스를 70 대 30으로 섞고, 텍스트는 Nemotron-CC v2와 v2.1에서, 영상-텍스트 쌍은 MetaCLIP 1.2 영어 하위집합에서 가져오며 캡션은 Qwen2.5-VL-32B로 재생성해 모든 레시피가 공유합니다.
- 첫째 발견: 시각 사전은 불필요합니다. 함께 학습한 스크래치 인코더가 사전학습 인코더와 대등하고, 공짜인 사전학습 인코더를 붙여도 스크래치 백본에는 도움이 되지 않습니다.
- 둘째 발견: 전용 시각 용량이 핵심입니다. 백본을 인코더의 0.4B 파라미터만큼 넓혀도 인코더 없는 모델은 시각 이해에서 뒤처집니다.
- 셋째 발견: 시각 용량은 퓨전 안으로 옮길 수 있습니다. 가장 초기 백본 계층에 시각 전용 용량을 더하면 퓨전 이전 인코더와 필적하고, 스케일링 법칙에서 퓨전 내 방식은 인코더를 좇는 반면 인코더 없는 모델은 모든 크기에서 뒤처집니다.
- 넷째 발견: 비교 결과는 조건을 넘어 유지됩니다. 사전학습된 1.7B 언어 모델에서 미드트레이닝으로 출발해도 결론이 같고, 퓨전 내 방식은 첫 토큰까지의 시간을 줄일 수 있습니다.
- H200 한 장에서 요청 16개를 동시에 처리하는 서빙 벤치마크, 요청당 448픽셀 이미지 한 장과 텍스트 256토큰 조건에서, 인코더 없는 모델은 1.7B에서 146밀리초, 4B에서 340밀리초로 대형 인코더보다 각각 31퍼센트, 16퍼센트 빠릅니다.
- 인코더 레시피는 4B에서 학습이 3퍼센트 느리고, 0.4B 예산에서 좁은 계층 27개로 이루어진 별도 스택을 쓰는 반면 퓨전 내 방식은 넓은 계층 8개를 씁니다.
- 평가는 12개 언어 벤치마크 평균으로 언어 점수를 냅니다. MMLU, ARC-Easy와 ARC-Challenge, HellaSwag, PIQA, WinoGrande, BoolQ, RACE 등이 포함됩니다.

## 세부 사항

### 통제 프로토콜

퓨전 경계는 시각 토큰과 텍스트 토큰이 처음 상호작용하는 첫 계층으로 정의되며, 그 이전의 계산은 퓨전 이전, 공유 백본 안의 계산은 퓨전 내입니다. 각 이미지의 시각 토큰은 서로 양방향으로 어텐션하고, 텍스트 토큰은 시각 토큰을 포함한 앞의 모든 토큰에 인과적으로 어텐션합니다. 워밍업-안정-감쇠 일정으로 한 번의 실행에서 여러 학습 길이를 뽑으며, 어떤 체크포인트든 학습 마지막 10퍼센트 동안 최고 학습률의 5퍼센트까지 감쇠시켜 마무리합니다. 최고 학습률은 1.7B에서 3e-4, 4B에서 2e-4로, 전체 파라미터 수의 제곱근 역수에 맞춰 정합니다.

### 중요한 것과 그렇지 않은 것

생애 연산량을 맞추면 별도의 인코더 사전학습은 선택 사항이 됩니다. 상위 연산을 공짜로 치고 더 많은 인코더 사전학습을 해도 인식 능력은 좋아지지만 시각 질의응답은 좋아지지 않습니다. 인코더 없는 백본을 0.4B 파라미터만큼 넓히거나 깊게 해도 시각 이해 격차는 닫히지 않으므로, 인코더의 우위는 전체 파라미터 수가 아니라 시각에 바치는 전용 용량에서 나옵니다. 퓨전 내 예산의 일부는 시각 전용 어텐션 사영에 들어가며, 추가 4B 실험에서 이 사영만으로도 도움이 됩니다.

### 서빙과 학습 속도

별도 인코더는 추론을 직렬화합니다. 각 이미지의 인코딩이 끝나야 백본이 출발하며, 해상도가 커질수록 시각 토큰이 많아져 인코더가 첫 토큰 시간에서 차지는 비중이 커지므로 절감 폭도 커집니다. 백본의 앞 k개 계층을 시각 토큰용으로 복제하는 MoT는 시각 전용 용량 0.4B까지는 퓨전 내 방식과 비슷하지만 예산이 커질수록 추가 지연이 더 빨리 늘어납니다. 텍스트와 이미지 요청이 섞인 연속 배칭 환경에서는 퓨전 내 시각 모듈이 텍스트 전용 요청과 같은 순전파에서 돌지만, 별도 인코더는 이미지 요청에만 지연을 더합니다. 논문의 블로그는 unbundling.github.io에 있습니다.
