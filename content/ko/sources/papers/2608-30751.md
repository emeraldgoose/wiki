# Autoregressive Mosaics: 텍스트 전용 언어 모델의 2D 공간 추론 탐침

출처: Ashwin Nedungadi, Stefan Oehmcke, Stefan Lüdtke (Institute for Visual & Analytic Computing, University of Rostock), arXiv:2608.30751v2, 2026-09-01.

[English version](../../../../en/sources/papers/2608-30751.md)

**핵심 요약**: 텍스트와 코드로만 훈련된 LLM은 때때로 인식 가능한 이미지를 그리는 프로그램을 생성할 수 있습니다. 그런데 그것이 **2D 공간 배치에 대한 내부 표현**인가, 아니면 단순히 **공간 설명을 코드로 번역하는 능력**인가 불분명합니다. AM-Bench는 이 둘을 분리합니다. 첫째, **번역 과제**는 그림의 완전한 기하를 말로 프롬프트에 주어 그 코드를 요구합니다. 둘째, **layout 과제**는 미지정 프롬프트에서 이미지를 구성하도록 요구합니다. **텍스트·코드 전용 8개 오픈 가중치 모델** 모두 지정된 기하를 신뢰성 있게 번역하지만 **개방형 layout 성능은 크게 다릅니다** — 즉 이 차이는 코드 생성 능력만으로 설명되지 않습니다. 출력 매체 ablation이 세 번째 발견을 더합니다. **절차적 코드를 raw SVG로 대체하면 전 모델의 layout 점수가 개선됩니다.** 활성화 탐침은 생성 전 완만한 배치가 존재함을 보이지만 그것은 프롬프트가 암시하는 배치만 반영하며, 생성 중 모델은 고정된 계획을 실행하는 것이 아니라 **변화하는 기하 상태를 추적**합니다.

## 분리할 가치가 있는 모호함

동기 관찰은 익숙합니다. GPT-4에게 TikZ로 유니콘을 그려달라고 하면 모델이 한 번도 본 적 없는 이미지로부터 알아볼 만한 결과를 얻습니다. 설명은 많지만 모두 같은 주장이 아닙니다.

LLM이 생성한 이미지 하나만으로는 이것을 알 수 없습니다. 나쁜 layout이 다음 중 무엇에서 오는지 알려주지 않습니다.

- 공간 배열을 **구성**하지 못한 것
- 적합한 layout을 필요한 프로그래밍 언어로 **표현**하지 못한 것
- **출력 매체 자체**가 그 layout의 표현을 제약한 것

기존 평가들은 이들을 엮어 놓습니다. 인식 벤치마크는 시각 입력을 요구하므로 텍스트 전용 모델을 통째로 놓칩니다. 생성 평가들은 최종 출력만 채점하며 공간 구성과 설명-코드 번역을 분리하지 않습니다. 이 논문의 기여는 그 인자들이 갈라지는 벤치마크입니다.

## 설계: 두 과제, 하나의 통제

AM-Bench는 이미지를 **autoregressive mosaic**으로 표현합니다 — 프로그램이 만들고 결정론적 실행기가 렌더링하는 작은 래스터입니다. 파이프라인은 네 단계입니다. 프롬프트 → 내부 계획 → 프로그램 코드 → 래스터화 기하.

| 과제 | 프롬프트 | 측정 |
|---|---|---|
| **번역** | 완전한 기하를 말로 명시 | 코드 생성 능력(통제) |
| **layout** | 미지정 | 배열 구성이라는 추가 과제 |

번역은 layout 수를 해석 가능하게 만드는 통제입니다. 같은 모델과 같은 출력 형식을 쓰므로, layout 격차는 코드 생성 능력이 될 수 없고 **공간 구성**이어야 합니다.

채점 방식은 과제에 따라 다릅니다. 번역은 **연속 좌표에서의 정확한 면적 기하 지표**로 채점하므로 점수가 캔버스 해상도에 의존하지 않습니다. layout는 참조 기하가 없어서 **비전 언어 모델**로 채점하고, 인간 채점자가 판정의 랭킹 신호를 뒷받침하는 근거를 제공합니다.

## 발견

**번역은 해결됐고 layout는 아닙니다.** 모든 모델이 지정된 기하를 신뢰성 있게 코드로 바꿉니다. 개방형 layout 성능은 모델 간에 크게 다릅니다. 이것이 논문의 핵심 실증 주장입니다: **layout 능력은 코드 능력의 대리 지표가 아닙니다.**

**출력 매체가 중요하고, 모두에게 중요합니다.** 절차적 코드를 **raw SVG로 대체하면 전 모델의 layout 점수가 개선됩니다.** 즉 공간 추론처럼 보이던 것의 일부는 표현 형식의 산물이었습니다 — 같은 기저 역량을, 그에 맞는 매체로 표현한 것뿐입니다.

**내부 계획은 기대와 다릅니다.** 모델 활성화 탐침은 생성 *전*에 완만한 layout 계획을 보입니다 — 그러나 그것은 **프롬프트가 암시하는 배치만** 반영합니다. 그리고 생성 중 모델은 처음 고정된 계획을 실행하는 것이 아니라 **변화하는 기하 상태를 추적**합니다.

마지막 결과가 흥미롭습니다. 내부에 깔끔한 "layout 후 렌더" 파이프라인이 없습니다. 모델은 더 점진적인 무언가를 하고 있습니다. 생성 전 계획은 모델이 따르는 설계도안이 아닙니다.

## 범위

저자들은 벤치마크가 무엇을 측정하는지 신중합니다: **모자이크 해상도에서의 allocentric 2D layout**입니다. 이는 embodied 공간 역량에 대한 **필요조건 탐침**이지 충분조건이 아니며, metric egocentric 연속성·깊이·가림은 다루지 않습니다. 활성화 수준 주장은 행동적(descriptive)이며, 저자들은 activation patching을 통한 직접적 인과 분석을 미래 작업으로 제시합니다.

## SW 엔지니어와의 관련성

- 모델의 그림이나 다이어그램 출력을 평가한다면 추론만큼 **출력 매체**를 측정하고 있습니다. 이 SVG 대 코드의 격차는 당신의 평가에 대한 경고입니다.
- 벤치마크에 통제를 포함하세요. 번역 과제가 layout 수를 "공간 구성"이 아니라 "코딩 가능 여부"가 되게 만들어 줍니다.
- 가능하면 **연속 좌표**로 채점하세요. 그래야 지표가 래스터 해상도에 의지하지 않습니다.
- VLM-as-judge에는 인간 검증이 필요합니다. 이 논문은 하고 그렇게 말하고, 많은 논문은 그렇지 않습니다.
- "생성 전 계획이 존재한다"는 "모델이 계획을 실행한다"와 같지 않습니다. t=0 상태가 아니라 궤적을 탐침하세요.
