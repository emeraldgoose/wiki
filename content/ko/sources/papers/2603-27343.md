# WMIP: 대규모 언어 모델의 누적 상태 추적을 위한 작업 기억 영감 프로그래밍 가능 프로브

**원문**: [arXiv:2603.27343](https://arxiv.org/abs/2603.27343) · **게시일**: 2026-03-28

## 개요

머릿속에서 점수를 계속 갱신하는 일은 작업 기억 과제다. 프롬프트에 초기 상태와 일련의 갱신을 나열해 놓고 중간 단계를 적지 말고 최종 결과를 요구하는 순간, 대규모 언어 모델도 이와 유사한 요구에 직면한다. 기존 상태 추적 시험들은 이 요구를 서로 다르게 둔다. Minerva의 수량 상태 과제는 출력 4,096토큰을 허용해 갱신을 글로 풀어 쓸 여지를 주고, GSM-Infinite는 애초에 단계별 추론을 요구한다. WMIP는 누적 상태 추적을 재는 작업 기억 영감 프로브로, 생성기가 갱신 수(3~100회)를 정하고 응답 프로토콜이 중간 단계를 적을 여유를 정해서 두 지렛대를 동일한 문항에서 따로 통제한다.

핵심 문항은 이름 붙은 세 개체에 정수 초기값을 주고, 개체 사이의 증가·감소·이동 K개를 순서대로 나열한 뒤 한 개체의 최종값을 자유 응답 정수 하나로 요구한다. 정답은 모델 합의가 아니라 프로그램이 계산한다. 60개 핵심 문항이 K=3, 5, 7을 다루고, 같은 생성기의 깊이 문항이 100회 갱신까지 확장한다. 문항 유형은 최종 상태, 중간 상태, 다중 대상을 포함한다. 네 가지 응답 프로토콜이 같은 문항에 적용된다. 16토큰 출력 한도와 단일 정수 규칙으로 중간 단계 적기를 막는 핵심 프로토콜, 프롬프트를 그대로 둔 512토큰 대형 예산, 16토큰에서 지시문만 바꾼 변형, 그리고 단계 적기를 요청하고 마지막 줄에 최종 답을 쓰게 하는 단계 적기 프로토콜이다.

18개 LLM을 합산하면 단일 단계 산술에서 84.9%, 핵심 문항에서 31.7%이며, 50회 갱신부터는 어떤 모델도 10%를 넘지 못한다. 프로토콜 지렛대가 결과를 지배한다. 512토큰 예산만으로는 절단이 사라질 뿐 단일 정수 채점 결과가 그대로이고, 단계 적기 프로토콜은 합산 정확도를 88.0%(1,080 중 950)로 끌어올린다. 이득에서 지시문 변화가 예산보다 약 두 배 크게 기여했다. 핵심 정확도는 Berkeley Function Calling Leaderboard 점수와도 양의 상관을 보인다(Overall·Multi-Turn·Agentic에서 Kendall tau-b 0.417~0.449).

이 논문의 결론은 모델만큼이나 측정에 관한 것이다. 단일 단계 산술이 강하다고 누적 추적이 믿을 만한 것은 아니며, 출력 프로토콜이 측정되는 정확도를 크게 바꾼다. Claude Sonnet 4.5는 핵심 프로토콜에서 0/60(전부 절단)이지만 대형 예산과 단계 적기 프로토콜에서 60/60이다. 핵심 점수가 낮다고 바탕 문제를 못 푸는 것은 아니라는 뜻이다. 생성기, 문항, 채점 코드, 전체 응답이 공개되어 있어 깊이·문항 유형·프로토콜을 넘나드는 재현 가능한 비교가 가능하다.

## 핵심 내용

- 통제된 두 지렛대: 생성기는 갱신 수와 문항 유형을, 프로토콜은 출력 예산과 채점 규칙을 정한다. 핵심 프로토콜은 갱신 전체를 보여 주면서 16토큰 한도와 단일 정수 규칙으로 중간 단계 적기를 제한한다.
- 18개 모델 합산: 단일 단계 산술 84.9% 대 핵심 문항(3~7회 갱신) 31.7%, 50회 갱신부터는 전 모델이 10% 미만이다.
- 지시문 변화가 예산보다 크다. 512토큰 예산은 마지막 정수 채점 기준으로 정답 195개를 추가하고, 단계 적기 지시문은 400개를 더 추가해 950/1,080(88.0%)에 이른다. 단계 적기는 18개 모델 모두를 향상시키고 절단은 217건에서 4건으로 줄어든다.
- 핵심 프로토콜에서 모델 편차가 크다. GPT-5.2는 56/60, GPT-4.1은 49/60인 반면 Llama-3.2-1B는 0~2/60으로, 합산 31.7%는 최상위 모델과 소형 모델의 격차를 가린다.
- 중간 상태 문항이 최종 상태 지름길을 배제한다. 조회 개체의 세 번째 갱신 이후 정확도가 첫 번째 갱신 이후보다 23.3%포인트 낮다(53.3% 대 30.0%). 뒤의 상태가 더 쉽지는 않다는 뜻이다.
- 조회 개체가 늘수록 추적 정확도는 떨어진다(M=1, 2, 4에서 각각 28.6%, 25.3%, 23.3%). 반면 조회 개체로 향할 갱신이 다른 개체로 우회돼 정답이 초기값과 같아지는 readout 문항은 오히려 높다(37.8~51.7%). 초기값에 기대는 경향과 일치하는 패턴이다.
- 확장 블록은 영역을 갈라 본다. 직접 대입은 90.0%인 반면 집합 갱신과 세기는 54.1%이고, 회의 횟수 세기가 34.1%로 가장 낮다.
- 결과는 생성 시드와 문구에도 민감하다. 4개 시드에서 순위 상관 평균은 0.821(GPT-4.1-mini는 40%포인트 폭), 같은 30문항을 숫자 전용 문구로 다시 쓴 5가지 버전은 평균 0.674다(Sonnet 4.5는 원래 문구 0/30, 캐주얼 문구 27/30).
- BFCL 상관은 양수지만 상태 추적 고유의 것은 아니다. 핵심 tau-b 0.417~0.449에 비해 산술은 0.687~0.740이고, 핵심 빼기 산술·핵심 빼기 상쇄 차이의 신뢰 구간은 모두 0을 포함한다.

## 세부 사항

- 버전 노트: 원 제목은 WMF-AM이었고 v1은 2026-03-28에 나왔으며, v3(2026-10-30)은 새 실험을 넣은 대폭 개정판이다. 이 요약은 v3를 따른다.
- 핵심 뱅크는 세 개체에 K=3, 5, 7 갱신을 얹은 60문항이고, 깊이 문항은 같은 생성기로 K=100까지 확장한다. 중간 상태 블록은 다섯 개체 궤적의 60문항, 다중 대상과 readout 블록은 M=1, 2, 4에 걸쳐 120문항이다.
- 단일 정수 규칙에서는 정수를 여러 개 쓴 응답이 0점 처리된다. 그래서 단계 적기 응답은 이 규칙에서는 2/1,080에 그치지만 마지막 정수 채점에서는 950/1,080이다. 합산 31.7%(342/1,080)는 단일 정수 채점 기준 수치다.
- 지시문 변형(사용자·시스템 지시를 바꾸고 16토큰은 유지)은 11개 모델을 향상시키고 2개는 비기게 하며 5개는 악화시켜, 이득을 어느 한 지시로 귀속할 수 없다. 숫자만 답한 응답은 핵심·지시·단계 적기 프로토콜에서 각각 813건, 986건, 0건이다.
- 채점 타당성 점검이 함께 보고된다. 정수 준수율, 절단 표식, 10,000회 모델 부트스트랩 구간이다. 두 독립 파서 사이에서 대입·집합·세기 응답 3,240건 중 7건만 정답 여부가 바뀌었고, Llama-3.3-70B 호스팅 엔드포인트는 핵심 문항에서 로컬 실행과 같은 31개 정답을 냈다.
- 코드, 문항, 채점 규격, 전체 모델 응답이 github.com/dengzhe-hou/WMIP에 공개되어 있다.
