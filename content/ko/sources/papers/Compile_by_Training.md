# Compile by Training: 자연어 명세를 로컬 신경 함수로

**arXiv**: [2609.04199](https://arxiv.org/abs/2609.04199) | **HuggingFace**: [papers/2609.04199](https://huggingface.co/papers/2609.04199) | **발행일**: 2026-09-03 | **제출자**: Yuntian Deng (University of Waterloo) | **발표**: EMNLP 2026 System Demonstrations

**저자**: Yuntian Deng, Pengyu Nie, Stuart Shieber

## 초록

반복적으로 호출되는 많은 텍스트 함수는 말로 설명하기는 쉽지만 규칙으로 구현하기는 어렵고, 매 입력마다 대형 원격 모델을 호출하면 반복 비용·지연·공급자 의존이 발생한다. 본 논문은 *compile by training(학습을 통한 컴파일)*을 제시한다. 자연어 명세를 재사용 가능한 신경 함수로 바꾸는 것이다. 컴파일 시점에 교사(teacher) 모델이 작업 전용 예제를 생성하고, 이를 이용해 소형 어댑터를 경량 인터프리터에 학습시킨다. 완성된 함수는 교사 없이 동작하며 일반 소프트웨어처럼 저장·버전관리·조합할 수 있다. Program-as-Weights(PAW) 고속 컴파일러가 정확히 일치하는 답을 하나도 내지 못한 부분집합인 FuzzyBench-Hard에서 compile by training은 의미 정확도(LLM Exact Match) **83.6%**에 도달했다. 대신 컴파일 비용은 고속 컴파일러의 수 초 대비 약 1분으로 더 크다. 저자들은 컴파일러를 공개 인터랙티브 서비스(programasweights.com)로 배포하고, 다중 사이트 웹사이트 도우미, 언어 제어 3D 아바타, 양방향 영어–Claudish 번역기에서 컴파일된 함수를 시연했다.

## 배경: 문제 설정 (WHY)

동기 예시는 이메일 분류 함수다. "Signature needed by EOD"는 `immediate`로, 뉴스레터는 `wait`로 매핑한다. 동작은 설명하기 쉽고 수천 통의 메일에 유용하지만 규칙으로 인코딩하기는 지루하다. 범용 원격 LLM은 처리할 수 있지만 매 호출마다 네트워크 지연, 공급자 비용, 외부 서비스 의존을 지불해야 한다.

논문은 반복 텍스트 함수의 큰 부류가 이 틈새에 있다고 본다. **기존 코드로 구현하기에는 너무 모호(fuzzy)하지만, 매번 대형 모델을 호출하기에는 너무 좁고 빈번한** 작업이다. 제안하는 재해석은 적응(adaptation)을 *소프트웨어 빌드 단계*로 바꾸는 것이다. 컴파일 시점에 대형 모델을 한 번 사용해 소형 재사용 함수를 만들고, LLM은 런타임 의존이 아니라 도구 빌더로 쓰는 것이다.

본 연구는 Program-as-Weights(PAW, Zhang et al., 2026) 위에 구축됐다. PAW에서는 신경 프로그램이 공유 로컬 인터프리터를 전문화한다. PAW는 단일 순전파로 프로그램을 예측하는 분할상환(amortized) 컴파일러를 도입했는데, 빠르지만(수 초) 모든 함수에 고정된 계산량만 쓴다. Compile by training은 동일한 프로그램 형식과 런타임 인터페이스를 유지하면서 분할상환 예측을 시작점으로 삼고, 교사 합성과 명세 전용 최적화에 추가 계산을 투자한다. 논문이 묻는 실용적 질문 세 가지는 (1) 추가 컴파일 투자가 1회 예측보다 더 좋은 함수를 만드는가, (2) 분 단위 빌드가 인터랙티브 서비스에서 usable한가, (3) 독립 컴파일된 신경 함수들이 더 큰 애플리케이션의 부품이 될 수 있는가이다.

## 방법론 (HOW)

### 시스템 인터페이스

형식적으로 시스템은 `p_s = Compile(s)`, `ŷ = Run(p_s, x)`를 제공한다. `s`는 자연어 명세, `p_s`는 컴파일된 프로그램, `x`는 새 입력, `ŷ`는 출력이다. 공유 동결 LM이 인터프리터 역할을 하고, 각 컴파일 프로그램이 이를 한 함수에 특화시키는 어댑터와 프롬프트를 공급한다. 사용자 흐름은 **명세(Specify)**(text-to-text 함수를 자연어로 기술) → **컴파일(Compile)**(빌드 작업 제출, 큐·학습 진행 모니터링) → **실행(Run)**(완성 프로그램을 열거나 다운로드해 SDK로 새 입력에 호출)이다. 다운로드된 `.paw` 아티팩트는 명세와 공유 인터프리터 전문화에 필요한 구성요소를 묶으며, 일반 소프트웨어 아티팩트처럼 저장·버전관리·캐시·재사용할 수 있다. 컴파일은 호스팅 과정(명세가 PAW 서비스와 교사 API로 전송)이지만, 로컬 SDK 실행은 이후 입력을 PAW나 교사에 보내지 않는다.

### 1단계 — 명세에서 감독 신호로

명세만으로는 학습할 라벨 예제가 부족하므로 하나 이상의 교사 모델이 작업 전용 데이터셋 `D_s = {(x_i, y_i)}, i=1..n ~ T(s)`를 합성한다. 교사 요청은 구조적 JSON 형식을 써서 생성 예제가 학습 파이프라인에 자동 진입하고, 컴파일러가 각 응답을 검증해 형식 오류·불완전 배치를 거부한다. 공개 서비스는 저비용 교사(대부분 예제 담당)와 대형 교사(보완 감독 담당)를 혼합한다. 예: `/pdf/` 링크에서 arXiv ID를 추출하고 `/abs/` 링크를 무시하는 명세에 대해 교사가 생성한 쌍은 `입력: "Check these papers: https://arxiv.org/pdf/2607.02512.pdf and https://arxiv.org/abs/2507.08800." → 출력: ["2607.02512"]`이다.

### 2단계 — 전문화와 패키징

명세마다 전체 모델을 학습시키면 비용이 감당 불가하므로, 모든 프로그램이 **동결된 양자화 Qwen3-0.6B 인터프리터**를 공유하고 각 함수는 경량 **LoRA 어댑터(rank 64, alpha 16)**와 런타임 스캐폴드로 표현된다. 스캐폴드는 자유 형식 명세를 구조적 작업 지시·예시로 인코딩하고 런타임 입력 자리표시자를 남긴 컴파일러 생성 프롬프트 템플릿이다. 분할상환 PAW 컴파일러가 초기 어댑터 파라미터 θ_s^(0)와 스캐폴드 r_s를 제공(수 초)하고, 합성 데이터셋에 대해 `L(θ_s) = Σ_{(x,y) ∈ D_s} −log p_{θ_s}(y | r_s(x))`를 **100-스텝 코사인 스케줄**로 최소화해 정교화한다. 최적화 후 어댑터 + 스캐폴드 + 원 명세 + 인터프리터 메타데이터를 프로그램 `p_s`로 패키징한다.

### 인터랙티브한 분 단위 컴파일

수십 초 빌드를 인터랙티브하게 만드는 세 가지 엔지니어링 선택: (1) **합성과 학습의 중첩** — 교사 요청·모델 로딩·학습을 동시에 시작하고, 첫 배치에 필요한 예제가 도착하면 학습을 개시해 합성에 따라잡힐 때만 블록하며, 들어오는 예제를 가장 이른 열린 배치 슬롯에 할당한다. 교사 합성이 학습 스텝보다 느리고 가변적이므로 크리티컬 패스가 단축된다. (2) **작업 조율과 재사용** — API가 영속 작업 기록을 유지하고 공유 큐가 GPU 워커에 분배하며, 워커는 새 예제를 요청하기 전 캐시된 교사 출력을 재사용하고, 완성 프로그램은 공유 아티팩트 스토어에 저장해 작업 기록에 연결한다. (3) **인터랙션 설계** — 컴파일을 블로킹 폼 제출이 아닌 백그라운드 소프트웨어 빌드로 취급한다. 사용자는 명세 제출 후 계속 탐색하면서 큐 위치와 학습 진행을 보고받고, 작업은 페이지 이동·새로고침에도 유지된다.

## 결과

**지표/벤치마크.** 완전 일치(exact match)는 지나치게 엄격하므로(예: 공백·키 순서만 다른 동일 JSON을 다르게 판정) 논문은 **LLM Exact Match(LEM)**를 보고한다. 명세·입력·참조·예측을 보고 LLM 심사자가 의미적으로 정답인지 판정하는 비율이다. 선정된 GPT-5.5 심사자는 저자 라벨 128개 대비 정확도 0.977, Cohen's κ = 0.946이다. 벤치마크 **FuzzyBench-Hard**는 PAW 고속 컴파일러가 정확 일치를 하나도 내지 못한 명세들의 부분집합이다(의미적으로 맞는 예측이 있어 LEM은 0이 아니다).

**학습 vs. 고속 컴파일러.** Compile by training은 평균 LEM을 **+0.612 절대 향상(0.224 → 0.836)**시키며, 컴파일 시간은 **50.9초 vs. 3.5초**이다.

**감독 선택 ablation(Table 1).** 3600개 고유 쌍을 반복해 6400개 학습셋을 만들 때, **GPT-5.4-mini와 GPT-5.5의 2:1 혼합이 mini 단독 대비 평균 LEM을 0.746 → 0.851**로 올렸다. 데이터 스케일링: 고유 쌍 1440개 → 0.821, 2400개 → 0.836, 3600개 → 0.836, 7200개 → 0.866 (2400~3600 구간 정체, 7200에서 추가 상승).

**지연.** 2026년 5월 출시 시점 대표 명세의 콜드 컴파일: **B300에서 50.9초, H200에서 68.2초, RTX에서 99.2초**. 교사 합성이 전체 지연을 지배하므로 합성/학습 중첩이 크리티컬 패스를 직접 단축한다. 4개 작업 동시 제출 부하 테스트에서는 전부 완료, 평균 큐 대기 **1.01초**, 워커 간 균등 활용이었다.

**배포 애플리케이션.** (1) *paw-helper* 웹사이트 어시스턴트: 범용 파이프라인 실행기와 사이트 전용 콘텐츠 팩을 분리하고, 팩에 **컴파일 프로그램 30개(실시간 라우팅 28개**, 평가·하위호환 2개)**를 탑재, 하나의 백엔드가 4개 사이트(저자 홈페이지, Waterloo CS486 강의 사이트, NeuralOS, PAW 사이트)를 서빙한다. 라우터가 웹사이트·페이지 맥락을 받아 질문을 작은 서브트리로 보내며, 컴파일된 분류기/답변기/선택기/검증기와 결정적 링크·BM25 검색을 혼합한다(예: CS486 "Assignment 1에서 뭐가 바뀌었나?" 질문에 강의 페이지 답변과 Piazza 답변을 병합). (2) *Avatar Director*: 자연어 명령 → 소규모 액션 DSL(순차·지속시간·반복·호환 병렬 동작), 브라우저에서 검증·렌더링해 3D 캐릭터를 애니메이션("jump twice, then dance"). 손수 작성한 검증 명령 **44개 중 43개**에서 기대 액션 구조를 생성했다. (3) *영어↔Claudish 번역기*: 방향당 하나의 명세 + 공유 0.6B 인터프리터용 어댑터 1개씩 파인튜닝. **2026년 8월 22일~9월 2일 웹 데모에서 100,747건의 성공 번역 요청**을 처리했다.

## 한계 / 열린 질문

- **합성 감독은 교사의 오류를 상속한다.** 확정적 정합이 필요한 애플리케이션은 출력을 검증하거나 결정적 제어 경로를 유지해야 한다는 것이 논문의 명시 입장이다. paw-helper의 분업(모호한 판단은 컴파일 함수에, 정확한 연산은 일반 코드에)이 권장 패턴이다.
- **평가는 정합성 + 지연 중심이며 UX가 아니다.** 애플리케이션 근거는 조합과 구조적 실행에 집중되어 있고, 체계적 사용자 연구는 향후 과제로 명시했다.
- **비용/정확도 프론티어가 아직 거칠다.** +0.612 LEM에 컴파일 지연 약 15배가 들고, 2400→3600 정체 구간 대비 7200에서의 상승 등 표본 효율 곡선이 열려 있으며, 고속 컴파일러만으로 충분한 경우가 언제인지도 열려 있다.
- **인터프리터 범위가 좁다.** 모든 결과가 단일 동결 0.6B 인터프리터와 text-to-text(또는 text-to-DSL) 함수에 국한되며, 다른 모달리티·대형 인터프리터·장기 에이전트 작업으로의 일반화는 검증되지 않았다.

## 소프트웨어 엔지니어와의 관련성

- **새 빌드 아티팩트: `.paw` 프로그램.** 모호한 텍스트 함수를 컴파일된 바이너리처럼 다루라. 버전관리·캐시·롤백하고 아티팩트 스토어에서 서빙한다. Compile/Run 분리는 비밀키와 벤더 호출을 빌드 시점에 가두고, 런타임은 로컬·오프라인 가능하게 만든다.
- **"모호한 명세 컴파일" 패턴을 그대로 재사용할 수 있다.** 명세 → 교사 합성 JSON 쌍(파이프라인에서 검증/거부) → 동결 소형 모델 위 LoRA(r=64, α=16, 분할상환 예측으로 웜스타트, 100-스텝 코사인) → 어댑터 + 프롬프트 스캐폴드 패키징. 구체적 출발 레시피: 고유 쌍 약 2400개(스케일링 곡선의 변곡점), 저비용/고성능 교사 2:1 혼합(해당 sweep에서 +0.105 LEM), 교사 지연을 숨기기 위한 합성의 학습 스트리밍이다.
- **모놀리식이 아니라 조합하라.** paw-helper의 검증된 토폴지: 결정적 검색·캐시·분기 제어 주변에 소형 컴파일 분류기/라우터/검증기를 배치한다. 모호한 모델이 판단하고 일반 코드가 실행한다. 지원 봇·트리아지 큐·사이트 어시스턴트에 그대로 적용 가능하다.
- **지연 예산 숫자.** B300급 GPU에서 콜드 컴파일 약 50초, 4중 동시성에서 큐 약 1초, 고속 컴파일러 폴백 3.5초. 블로킹 요청이 아니라 진행 UI가 있는 백그라운드 빌드에 적합하다. 고속 컴파일러를 기본값으로, 파인튜닝 컴파일을 "릴리스 빌드"로 제공하라.
- **쓰지 말아야 할 곳.** 정합 보장이 필요한 곳(과금, 접근 제어, 의료/법률)은 신경 함수 뒤에 결정적 검증기나 사람 승인을 반드시 둬라. 튜닝 후에도 어댑터는 14~17% 틀릴 수 있다.
