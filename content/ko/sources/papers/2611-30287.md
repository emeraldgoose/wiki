# MMMem: 작업 인식 멀티모달 경험 응집을 통한 자기 개선 에이전트

**원문**: [arXiv:2611.30287](https://arxiv.org/abs/2611.30287) · **게시일**: 2026-11-23 (v1)
**저자**: Yuxuan Chen, Changwei Lv, Yunfei Li, Zhongjing Du, Kehui Tan, Zijun Liao, Ruochong Zheng, Hao Chen, Can Deng, Zheni Zeng, Chang Liu, Jie Chen

## 개요

AI 에이전트는 장기간의 상호작용 동안 대화, 사진, 문서를 축적하고, 나중의 질문은 종종 그 기록들에 흩어진 증거들을 연결해야 합니다. 기존 멀티모달 메모리 방법은 대부분 원시 기록을 저장하고 검색할 뿐, 작업을 해결하면서 얻은 이해를 거의 보존하지 못해 에이전트가 연관된 질문에서 같은 실수를 반복합니다. MMMem은 대신 작업을 메모리의 편성 단위로 사용합니다. 완료된 각 작업은 작업 맥락, 결론, 그리고 뒷받침하는 출처로의 링크를 기록하는 "경험(experience)"으로 증류됩니다.

MMMem은 네 가지 전략을 결합합니다. 첫째, 출처 연결 다중 뷰 메모리는 원본 텍스트, 이미지, 렌더링된 페이지를 여러 기록에 흩어진 단서를 병합하는 합성 이미지인 생성 "장면 뷰(scene view)"와 함께 보관하여 검색에 문자 그대로의 표현과 구성된 표현을 모두 제공합니다. 둘째, 에이전트 자신의 출처에서 생성된 작업은 두 수준에서 지식을 정렬합니다. 첫 번째 채점 질문 전에 출처 지식을 검색 가능한 경험으로 외부 메모리에 통합하는 웜업 단계와, 모델의 파라미터적 지식을 작업 요구에 맞추는 자기 학습(AdamW를 사용한 1 에폭의 LoRA)이 각각 그 역할을 합니다. 셋째, 동일한 비전-언어 모델이 정답이나 채점 피드백 없이 완료된 작업에서 경험을 작성합니다. 넷째, 작업 인식 검색은 답변과 검증을 위해 출처 뷰와 관련 경험을 회상하며, 원본 증거로 뒷받침되는 재사용이 경험의 장기 보존을 안내합니다.

## 핵심 내용

- 벤치마크: LoCoMo(다중 세션 대화 메모리, 토큰 F1), Mem-Gallery(이미지-대화 연관, EM/토큰 F1/BLEU-1), LooGLE v2(장문 문서 증거 통합, 공식 집계 점)의 홀드아웃 부분집합을 사용했습니다. 리더는 Qwen3.5-9B와 MiniCPM-V 4.5(8.7B)이며 각각 별도로 학습했습니다.
- Qwen3.5-9B 기준 MMMem은 65.84 F1(LoCoMo), 77.21 F1(Mem-Gallery), 29.97(LooGLE v2)를 기록했고, MiniCPM-V 4.5 기준 56.40 / 70.27 / 24.67로, 8개 베이스라인(Direct/Full/Recent Context, Dense RAG, OCR-Memory, MemOCR, Mem0, A-Mem)에 대한 6가지 설정 모두에서 최고를 달성했습니다. 최고 베이스라인 대비 상대적 향상은 36.9%(LoCoMo), 17.6%(Mem-Gallery), 15.2%(LooGLE v2)입니다.
- Qwen3.5-9B에서 A-Mem 대비 MMMem은 LoCoMo에서 +17.75 F1, Mem-Gallery에서 +11.58 F1 향상을 보였습니다. Dense RAG는 6가지 설정 모두에서 Full Context를 앞섰고, MiniCPM-V 4.5에서는 Full Context가 Direct Answer보다 오히려 저하되었습니다. 즉 증거 선택이 메모리 표현만큼 중요합니다.
- Ablation: 6가지 설정 중 4가지에서 자기 학습을 제거했을 때 가장 큰 하락이 있었습니다(LoCoMo Qwen −5.65 F1). 작업 웜업을 제거하면 LooGLE v2에서 가장 큰 타격(−6.62 Qwen, −2.13 MiniCPM)이 있었는데, LooGLE 문서당 평균 약 1.5개의 채점 질문만 나오기 때문입니다. 경험 메모리를 제거하면 LooGLE v2(Qwen)에서 −5.76의 하락이 있었습니다. 생성 뷰는 LoCoMo/Mem-Gallery에서 도움(제거 시 −1.36/−3.12 Qwen)이 되지만 텍스트 중심의 LooGLE v2에서는 대부분 건너뛰었습니다.
- 사례 연구(Mem-Gallery, MiniCPM-V 4.5): 두 기록의 설명을 결합한 생성 장면 뷰가 대상 새의 검색 순위를 10위에서 2위로 끌어올리고 답을 "Blue Jay"에서 "Lazuli Bunting"으로 바꿨습니다. "Dunlin"을 Calidris alpina와 연결하는 회상된 경험은 사진 수를 5장에서 6장으로 바꿨습니다.
- 검색 설정: 출처 뷰 예산 3,000 토큰(LoCoMo) / 4,000 토큰(Mem-Gallery, LooGLE v2), Qwen3-Reranker-0.6B를 이용한 제로샷 재정렬, 최상위 경험은 별도 슬롯에 배치. 경험 메모리는 평가 단위마다 초기화되며 웜업은 채점되지 않습니다.

## 세부 사항

MMMem의 메모리는 원본 텍스트, 이미지, 렌더링된 페이지인 출처 노드와 여러 기록에 걸친 단서를 결합하는 생성 장면 뷰로 구축됩니다. 웜업은 각 단위의 첫 번째 채점 질문 전에 경험을 작성하는데, 단위에 질문이 적을 때 중요합니다. 자기 학습은 평가와 분리된 학습 단위에서 생성된 작업을 사용하며(LVBench와 OVO-Bench는 학습 전용 데이터로 포함), 공식 학습 단위 질문 텍스트가 스타일을 안내하지만 정답은 사용되지 않습니다. 경험 작성은 정답이나 채점 피드백을 전혀 보지 않으며, 벤치마크 정답, 주석 처리된 단서, QA 태그는 검색에서 제외됩니다. Ablation은 MMMem을 "Only Training"(동일하게 학습된 리더에 Dense RAG 적용)과 "w/o Training"과 비교하여 파라미터 적응과 메모리 워크플로가 상보적인 향상을 낸다는 것을 보입니다. 한계로는 LooGLE v2에서의 향상이 더 작다는 점이 지적되는데, 이 벤치마크는 출처 뷰 토큰 예산 안에서 장문 문서에 걸친 증거를 결합해야 하고 문서당 평균 약 1.5개의 채점 질문만 나와 이전 답변의 경험을 재사용할 기회가 적기 때문입니다.
