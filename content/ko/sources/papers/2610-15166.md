# ExeWorldBench: 코드 기반 실행형 3D 월드 모델링 벤치마크

출처: Xinge Peng 외 10인, arXiv:2610.15166, 2026-10-10.

**핵심 요약**: 코딩 에이전트는 세계가 어떻게 보이는지를 재현하는 단계를 넘어, 세계가 어떻게 작동하는지를 담은 **실행 가능한 월드**를 만드는 쪽으로 진화하고 있습니다. 이에는 세계의 구조·기계·인과 원리를 추론하는 **세계 이해**와, 그 이해를 물리 상호작용으로 동작이 창발하는 코드 시스템으로 옮기는 **실행형 구현**이 함께 필요합니다. **ExeWorldBench**는 이 두 능력의 통합을 코드 기반 3D 월드 구축으로 평가하는 첫 벤치마크를 표방합니다.

## 세 단계 과제

난도가 높아지는 세 과제로 구성됩니다. **Mechanism Executability**는 시각 관찰에서 개별 기구의 동작을 구현하는지, **Compositional Executability**는 공간·기계·인과 의존성이 있는 다단계 시스템으로 확장하는지 봅니다. **Intent-Driven Executable World Synthesis**는 고수준 목표와 물리 요구사항만 주어졌을 때 실행 가능한 월드를 합성하도록 요구합니다.

## 결과

프런티어 모델 실험에서 실행형 월드 모델링에 상당한 한계가 드러났습니다. 기존 벤치마크가 물리 추론·시각 충실도·행동 정확성을 따로 평가해 통합 능력을 보지 못했던 공백을 메우며, 더 물리적으로 근거 있고 인과적으로 일관된 월드 구축 시스템을 위한 진단 도구를 제공합니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 과제별 점수 분포, 모델별 실패 유형, 프롬프트·하네스 민감도는 원문과 공개 자료를 확인해야 합니다. 코드 실행 환경과 물리 엔진의 차이가 점수에 미치는 영향도 별도 검토가 필요합니다.

## SW 엔지니어와의 관련성

- 3D·시뮬레이션 에이전트를 만든다면 "장면이 그럴듯한가"와 "기구가 실제로 동작하는가"를 분리해 평가하세요. 이 벤치마크의 과제 분해가 좋은 출발점입니다.
- 코드 생성 에이전트의 평가는 정적 코드 일치가 아니라 실행 결과와 상호작용으로 봐야 합니다.
- 월드 합성 파이프라인에서는 목표·물리 제약·검증 가능한 행동을 명시적으로 분리해 두면 실패 원인 추적이 쉬워집니다.
