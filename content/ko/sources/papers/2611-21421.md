# AuXSpec: 실행 가능한 사후조건으로 프로그램 명세의 자동 형식화를 학습하기

**Source**: [arXiv](https://arxiv.org/abs/2611.21421)
**게시일**: 2026-11-16

## Overview

형식 명세는 프로그램의 의도된 동작을 정의하고 검증의 기반이 되지만, Lean 같은 정리 증명기(theorem prover)로 작성하는 일은 느리고 전문 지식을 많이 요구해, 형식적으로 올바른 코드 확장의 주요 병목이다. 자연어 문제로부터의 자동 형식화(autoformalization)는 가능성이 있지만, 명세 모델 학습에는 생성된 명세가 의도한 동작을 포착하는지에 대한 확장 가능한 피드백이 필요하다. 기존 접근법은 명시적 증명이나 대응 증명이 있는 별도 구현 코드로 이 피드백을 얻는데, 둘 다 비용이 크다.

AuXSpec은 선언적 사후조건(postcondition)을 실행 가능한 대응물과 짝짓는 Lean 프레임워크다. 가능하면 타입 클래스 해상(type class resolution)으로 얻고, 아니면 동치 증명(equivalence proof)과 함께 별도로 정의한다. 그러면 테스트 케이스가 선언적 명세를 실행으로 평가할 수 있어, 실행 일치(agreement)를 강화학습(RL) 보상으로 쓸 수 있다. AuXSpec을 이용해 저자들은 3,037개 LeetCode 문제를 합성하고 Codeforces에서 expert iteration으로 학습을 19.5K 샘플로 확장했다. 모델·데이터와 전문가 검토를 거친 300문제 AuXSpec-Test 벤치마크가 huggingface.co/collections/eth-algopt/auxspec 및 auxspec.org에 공개됐다.

## Key points

- 도메인 내(AuXSpec-Test): 학습으로 SpecGen pass@4가 0.7% → 82.7%(Qwen3.5-9B), 14.3% → 84.3%(Qwen3.8-27B)로 상승. AuXSpec-27B-RL은 SpecGen과 CodeGen의 pass@1·pass@4 모두에서 모든 프런티어 모델을 능가 — SpecGen pass@1 65.7% vs 최강 프런티어 Claude-Opus-5 57.7%. 9B RL 모델도 SpecGen pass@1에서 모든 프런티어 모델(58.6%)을 능가.
- 수리(repair) 과제: 27B RL 모델은 CodeGen-Repair pass@1 최고(88.1%)이고 나머지 지표에서도 최고 결과와 2점 이내; 9B RL 모델은 SpecGen-Repair pass@1에서 대부분의 프런티어 모델을 능가.
- 도메인 외(Verina, 원래 프롬프트): 두 모델이 각각 7.0% → 90.5%, 21.9% → 90.5%로 향상되며, 오픈소스 명세 모델 이전 SOTA인 VeriSpecGen-30B-A3B를 pass@1(73.7%·84.5% vs 47.6%)과 pass@4(90.5% vs pass@10 기준 63.9%)에서 능가.
- 거짓 양성 통제: 채택된 RL 출력의 99.2%에 대해 사후조건 동치 정리가 증명됐고(Appendix H.4), 전문가 검토에서 100개 표본 중 90개가 확인됐으며 오류는 모두 validity predicate에 있었다(Appendix I.2).
- 보상 설계: 실행 가능한 사후조건을 타입 클래스 해상(또는 동치 증명을 곁들인 별도 정의)으로 얻으면 테스트 케이스가 선언적 명세를 값싼 비용으로 평가할 수 있다 — 테스트 케이스마다 Lean 증명이 필요한 기호적 명세 테스트와 대비된다.

## Details

- 파이프라인: LeetCode 문제(3,037개)에 대해 실행 가능+선언적 사후조건 쌍을 합성하고, Codeforces expert iteration으로 학습을 19.5K 샘플로 확장. SFT 이후 실행 기반 일치 보상으로 RL. 오염 제거, 소스 선정, 데이터 분류는 Appendix C.
- 평가: AuXSpec-Test(300문제, 전문가 검토, 정확성 증명)와 Verina OOD. 지표는 SpecGen/CodeGen pass@1/pass@4 및 수리 변형; ICPC-Eval에서의 자기 수리와 일반 능력은 Appendix D, RL 보상 단계 분석은 Appendix E.
