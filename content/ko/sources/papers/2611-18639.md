# SynthDCB: 확장 가능한 기기 제어 벤치마킹을 위한 월드 디스틸레이션

**원문**: [arXiv:2611.18639](https://arxiv.org/abs/2611.18639) · **게시일**: 2026-10-14 (v1), v2 2026-11-19
**저자**: Zichen Zhu, Dingye Liu, Nan Jiang, Danyang Zhang, Hang Zheng, Shijie Zheng, Situo Zhang, Kunyao Lan, Yingzi Ma, Sheng Jiang, Lu Chen, Kai Yu

## 개요

기기 제어 벤치마크는 시뮬레이터가 새로운 기기 capabilities를 따라가지 못할 때 정체된다. 새 capabilities를 추가하려면 일관된 도구 인터페이스, 동작 구현, 월드 구성, 태스크 요구사항, 성공 기준을 동시에 맞춰야 하기 때문이다. SynthDCB는 월드 디스틸레이션(WD)이라는 파이프라인으로 이 문제를 해결한다. WD는 기기 동작, 제약, 환경 효과에 대한 지식을 모듈형 실행 가능 구성요소로 변환한다. 타입이 지정된 capabilities 명세가 구성요소 구현과 검증을 안내하고, 월드 컴포지션이 구성요소를 도메인 레이아웃으로 조립하며, 실행 기반 태스크 합성은 사용 가능한 capabilities에서 요구사항을 도출하고 참조 계획을 재실행해 후보 태스크를 검증한다.

SynthDCB는 Home, Car, Phone 세 월드를 구축한다. 114개 기기 클래스, 1,166개 함수, 95개 이벤트를 포함하며, 5개 태스크 패밀리(쿼리, 제어, 목표, 집계 조합, 프로세스/이벤트 타이밍을 갖는 워크플로)와 32개 서브타입을 지원하고 메모리 및 실현 가능성 변형도 포함한다. 평가 분할은 130개 월드에서 추출한 30,309개 태스크 중 314개 검증 태스크와 2,560개 테스트 태스크(2,289개 실현 가능, 170개 불가능, 101개 부분, 200개 메모리 태스크)로 구성된다. 공통 ReAct 스타일 에이전트와 20턴 제한으로 22개 모델을 평가한 결과, 최고 모델인 Gemini 3.8 Flash가 평균 Pass@1 88.8%를 달성했고, 뒤이어 GPT-5.6 Terra 82.6%, GPT-6 Astra 82.0%, GPT-6.1 Sol 81.7%를 기록했다. 소형 오픈 가중치 모델은 1.6~8.7%에 그쳤다. 순위는 도메인별로 달랐고(Astra가 Phone에서 98.2%로 선두), 실패 분석에서는 강한 모델이 주로 복잡한 의도 해석과 서브태스크 조정에서 실패하는(E6: 가중 실패의 73.5~75.2%) 반면 소형 모델은 프로토콜 준수에서 실패했다(E2만으로 Qwen3.5-2B의 96.8%).

구축 확장성 측면에서, GPT-5.6 Sol로 WD를 이용해 세 도메인을 모두 만드는 데 19.16M 토큰(캐시 할인 전 약 $120.09)이 들고 몇 시간이면 끝난다. 수동 작업으로는 한 달 이상 걸리는 일이다. RobotVacuum 구축 비교에서 세 가지 지식 수준으로 비교한 결과, WD는 가장 풍부한 수준에서 22/23개 속성, 19/29개 기능, 30/39개 이벤트 요구사항을 완전히 커버했고, 완전히 커버된 요구사항당 Codex xhigh보다 51.5~86.7% 적은 토큰을 사용했으며, 1,000개 샘플 태스크가 실제 참조 명령 854개 중 81.6%(172개 분류 의도 중 69.8%)를 의미론적으로 커버했다.

## 핵심 내용

- 월드 디스틸레이션 파이프라인: 기기 지식 → 타입이 지정된 capabilities 명세 → 검증된 실행 가능 구성요소(스키마 검사, 명세-구현 검사, 효과 검증, 단위 테스트) → 월드 컴포지션 → 재실행 검증 태스크 합성. 구성요소는 월드와 태스크 인스턴스 간에 재사용 가능하다.
- 벤치마크 규모: Home/Car/Phone, 114개 기기 클래스, 1,166개 함수, 95개 이벤트; 5개 태스크 패밀리와 32개 서브타입(Query, Control, Goal, Aggregate, Workflow); 130개 월드의 30,309개 태스크에서 314개 검증 + 2,560개 테스트 태스크(실현 가능 2,289 / 불가능 170 / 부분 101).
- 주요 결과: 2,560개 테스트 태스크에서 22개 모델 평가, Gemini 3.8 Flash가 평균 Pass@1 88.8%(Home 86.5%, Car 87.0%)로 선두, GPT-5.6 Terra 82.6%, GPT-6 Astra 82.0%(Phone 98.2%), GPT-6.1 Sol 81.7%; 오픈 가중치 MiniCPM5/Gemma-4 변형은 1.6~8.7%에 불과.
- 명령 스타일 ablation(검증 세트에서 9개 모델 × 8개 스타일): Direct(S2)가 Template(S1)보다 GPT-5.6 Luna 기준 +7.0 pp 우위; Implicit(S8)은 Astra를 36.3 pp(−44.7%) 하락시키지만 부분 점수 지표는 훨씬 적게 감소해 모델이 누락된 요구사항의 일부는 여전히 충족함을 시사.
- 상호작용 예산: 중단된 실행을 20턴에서 50턴으로 늘려도 대부분 모델에 거의 도움 안 됨(GPT +0.13 pp, DeepSeek +3.1 pp, Gemini +14.7 pp); 20턴이 성능과 비용의 균형점.
- 오류 분석(12개 카테고리, 27,252개 실패 시도): 태스크 이해/조정(E6)이 강한 모델 실패의 대부분을 차지(73.5% Sol, 75.2% Astra); 시간/워크플로 추론(E10)은 Workflow 태스크 내 9.3%; 소형 모델은 주로 상호작용 프로토콜에서 실패(E2: Qwen3.5-2B 96.8%).
- 구축 효율성: 세 도메인 전체를 19.16M 토큰 / $120.09 / 몇 시간에 구축; RobotVacuum 전체 프로토콜 입력 기준 22/23 속성, 19/29 기능, 30/39 이벤트 완전 커버; 커버된 요구사항당 Codex xhigh 대비 51.5~86.7% 적은 토큰; 1,000개 태스크로 실제 참조 명령 854개의 81.6% 커버.

## 세부 사항

평가 프로토콜: 모든 모델이 동일한 ReAct 스타일 에이전트(temperature 0)를 사용하며, 시스템 수준 도구로 규칙/기기/스키마를 탐색하고, 쿼리에는 session.submit_answer, 불가능/차단 원자에는 이유 코드를 담은 session.submit_report를 사용한다. 시뮬레이션 시간은 action/turn 비용과 session.sleep_time으로 모델링되며 20턴 제한을 둔다. 성공은 해당되는 모든 상태, 답변, 리포트, 메모리, 시간/워크플로 검사를 통과해야 하며(평균 Pass@1) 달성된다. 효율성 지표 Eff-A/Eff-T는 도구 호출당 및 턴당 충족된 상태 단언과 정확한 답변 수를 센다. GPT-6.1 Terra는 GPT-5.6 Sol의 성공률(79.5% 대 79.1%)과 비슷하면서 캐시 할인 적용 추론 비용의 약 31%만 사용한다. WD 구축은 세 가지 지식 수준(L1 0.06k, L2 0.77k, L3 89.8k chars)에서 동일 GPT-5.6 Sol을 쓰는 Codex(낮음/xhigh)와 비교한다. WD는 Codex low보다 0.9~66.0%, Codex xhigh보다 46.2~92.5% 적은 토큰을 사용한다. 이 문서의 결과는 v2(2026-11-19) 리비전을 기준으로 하며, v1은 2026-10-14에 투고되었다. 코드와 프롬프트는 github.com/X-LANCE/SynthDCB에 공개되어 있다.
