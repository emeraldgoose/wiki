# 하루에 십 년: 인간 중심 소프트웨어 진화에서 에이전트 네이티브 인터페이스 합성하기

출처: Alan Wu, Wei Tao, Yiwen Guo, arXiv:2610.15765, 2026-10-11.

**핵심 요약**: LLM 에이전트는 데스크탑 애플리케이션의 중요한 새 사용자 계층으로 떠오르고 있습니다. 그러나 기존 데스크탑 인터페이스는 인간 최종 사용자나 앱 개발자를 위해 설계되어, 에이전트는 시각적 제어를 해석하거나 저수준 소프트웨어 작업을 발견·조합해야 합니다. 이 불일치는 유능한 에이전트도 방해합니다. 이 논문은 **소프트웨어 진화를 인터페이스 변이의 자연스러운 원천**으로 삼아, 어떤 인터페이스 속성이 에이전트 사용성을 높이는지 측정합니다.

## DeskIF-Bench

6개 데스크탑 애플리케이션에 걸친 **255개 아티팩트 검증 과제** 벤치마크입니다. 과제·에이전트·검증기를 고정한 채 **소프트웨어 릴리스만 바꿔** 인터페이스 변화가 에이전트 성능에 미치는 영향을 측정합니다. 두 모델·6개 앱에서 최신 릴리스가 가장 오래된 릴리스보다 일관되게 더 좋은 성능을 냈습니다.

## 세 가지 인터페이스 속성

궤적 분석은 성능과 관련된 세 속성을 식별합니다. **발견 가능성(discoverability)** 은 에이전트가 필요한 기능을 찾을 수 있는지, **세분성(granularity)** 은 작업이 적절한 단위로 노출되는지, **관찰 가능성(observability)** 은 실행 결과와 상태를 얼마나 잘 볼 수 있는지를 뜻합니다.

## ANIS

이 속성을 바탕으로 **ANIS**는 설치된 애플리케이션의 기능에서 **에이전트 네이티브 인터페이스**를 합성하는 프레임워크입니다. 8개 앱·**368개 과제**로 확장 평가한 결과, 원자적 인터페이스는 네이티브 SDK 사용 대비 성공률을 DeepSeek V4 Flash에서 **3.8%p**, Claude Haiku 4.5에서 **3.5%p** 높였고 온라인 토큰 사용량은 약 **73%** 줄였습니다. 목표 수준 명령은 성공률을 각각 **74.5%·67.4%** 까지 끌어올렸습니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 6~8개 데스크탑 앱에 한정된 결과이므로 웹·모바일·사내 앱으로 일반화하려면 별도 검증이 필요합니다. 인터페이스 합성의 유지보수 비용과 앱 업데이트 시 재합성 전략은 원문을 확인하세요.

## SW 엔지니어와의 관련성

- 에이전트용 인터페이스를 만들 때 기능 목록만 노출하지 말고 발견 가능성·세분성·관찰 가능성을 설계 지표로 삼으세요.
- 릴리스 간 비교로 인터페이스 변경의 인과 효과를 측정하는 벤치마크 설계가 재사용 가능합니다.
- 네이티브 SDK를 그대로 쓰기 전에 원자적·목표 수준 인터페이스를 합성하면 성공률과 토큰 비용을 함께 개선할 수 있습니다.
