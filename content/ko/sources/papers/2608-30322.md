# Ignorance or Incompetence? Constructing Knowledge-Gated, Verifiable Tasks for LLM Agents

: Professional agent tasks depend on conventions that are **absent from public corpora**, yet benchmarks rarely control whether an agent has access to those conventions — so when an agent fails, you cannot tell *ignorance* (it never had the rule) from *incompetence* (it had the rule and could not apply it). This paper introduces a **knowledge-gated task-construction protocol** that separates a task instruction from a compact artefact containing private conventions, reference tables, and utility operators. Across fifteen calibration tasks with **byte-identical instructions** between provided- and withheld-artefact conditions, a frontier configuration moves from a **0% pass rate to 68.0%** once the kilobyte artefact is provided. The point is not that the task is hard; it is that the dependence is *made explicit and testable*.

The diagnosis problem: The paper's title names the ambiguity. When a professional agent fails a task, two very different explanations are available:

- Ignorance — the governing convention was never in the training data, so the agent cannot know it
- Incompetence — the convention was available and the agent could not apply it

These demand opposite responses. Ignorence means supply the missing knowledge. Incompetence means train the capability. A benchmark that does not distinguish them cannot tell you which.

Three asymmetries: The construction protocol rests on what the paper calls an asymmetric position created at construction time. Three asymmetries suffice:

1. Construction privilege — the answer is planted at construction time (an arbitrary internal threshold, a private normalisation table), so it is not derivable from the instruction or environment alone, regardless of the solver's capability
2. Cheap verification — checking a structured output against planted ground truth is easy even when producing that output 

How the gating is enforced: The protocol's methodological care is in the controls:

- The task instruction never references the artefact
- Instructions are held byte-identical between the provided- and withheld-artefact conditions
- A leak audit checks instruction and environment for explicit gated content, with executable per-task audit scripts present for nine of fifteen calibration tasks
- The artefact is authored or adapted by a human curator from a larger domain corpus into a few kilobytes of text
