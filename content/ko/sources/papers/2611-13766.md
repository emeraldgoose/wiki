# FAME-QP: 실시간 모델 예측 제어를 위한 GPU 가속 이차계획법 솔버

**원문**: [arXiv:2611.13766](https://arxiv.org/abs/2611.13766) · **게시일**: 2026-11-10
**저자**: Santosh Mohan Rajkumar, Debdipta Goswami, Stephanie Stockar

## 개요

선형 모델 예측 제어(MPC)는 매 제어 주기마다 볼록 이차계획법(QP)을 풀어야 하고, 이 최적화가 샘플링 주기 안에 끝나야 한다. 내부점·활성집합 솔버는 웜스타트가 어렵거나 제약 수에 따른 확장성이 떨어지고, OSQP·ProxQP 같은 ADMM 계열은 웜스타트가 쉽지만 반복 횟수가 많다. 게다가 최신 로봇 파이프라인은 시뮬레이션·추론·학습이 이미 GPU 위에서 돌기 때문에 매 스텝 CPU 솔버로 QP를 넘기면 전송 지연이 더해진다. GPU용 QP 솔버도 있다. cuOSQP, qpax, CuPIQP, 그리고 가장 가까운 선행 연구인 ReLU-QP(ADMM을 가중치 공유 신경망처럼 재구성하고 조밀 연산자를 사전 역산해 캐시)가 그것인데, 조밀 연산자의 저장·디스패치 부담이 크고 ReLU-QP의 오프라인 사전계산은 온라인 행렬 변경과 상충한다.

오하이오주립대 기계·항공우주공학과의 FAME-QP(Fused ADMM with Multimode Execution for QP solution)는 ReLU-QP의 사전 역산과 페널티 뱅크 아이디어를 유지하면서 부담을 세 방향에서 줄인다. 첫째, 제약 구조 반영 연산자다. 개별 결정변수에만 작용하는 제약 행(박스 제약, 분할 구조의 대각 블록)을 조밀하게 저장하지 않고 요소별 연산으로 흡수해 연산자 저장을 최대 4배, 반복 시간을 최대 3배 줄인다. 둘째, 실행 방식이다. ADMM 반복 전체를 스택형 연산자의 단일 융합 커널이나 인수분해형 연산자의 두 커널로 융합해 CUDA 그래프로 캡처하고, 커널마다가 아니라 검사 구간마다 한 번씩만 호스트 디스패치가 일어나게 한다. 셋째, 적응이다. 10배 간격으로 벌려 놓은 다섯 개 페널티의 사전 역산 연산자 뱅크를 설정 시 탐사(probing)해 시작 페널티를 고르고, 풀이 중에는 저장된 항목을 선택하는 방식으로 전환하며, 문제 행렬이 바뀌면 활성 항목만 다시 역산하는 지연 갱신으로 대응한다.

실행 구성은 문제 형태마다 자동으로 고른다. 커널 노드 오버헤드와 연산자 스트리밍 시간으로 이루어진 반복 시간 모델을 장치별·정밀도별로 한 번 보정해(장치 캘리브레이션) 탐색을 가지치기하고, 살아남은 형태와 타일 구성을 실제 차원의 placeholder 연산자로 CUDA 그래프 안에서 직접 시간을 재어 최종 선택한다. 2커널 형태가 10% 이상 빠르지 않으면 1커널 모드를 유지한다. 정밀도도 관리한다. 페널티 뱅크는 항상 float64로 역산하고, 연산자와 반복 변수는 float32 또는 float64로 돌릴 수 있으며, KKT 행렬 조건수를 멱급수로 추정해 자동 선택하고 단정밀도 잔차가 정체하면 solved_inaccurate로 되돌린다.

실험은 정확도를 맞춘 조밀 랜덤 QP 콜드 솔브, 랜덤 불안정 시스템의 폐루프 LMPC, 그리고 시변 코프만 들어올림 동역학을 쓰는 MuJoCo의 Unitree G1 휴머노이드와 Skydio X2 쿼드로터 제어로 이루어진다. FAME-QP는 모든 테스트 크기에서 GPU 기준선 중 최저 지연을 기록했고(n = 1400에서 float32 기준 1.95ms vs cuOSQP 326ms), 휴머노이드 밀기 복구 과업에서 모든 테스트 지평에서 2ms 제어 주기 아래를 유지한 반면 ReLU-QP는 지평 15부터 예산을 넘었다.

## 핵심 내용

- 문제 클래스: 융합(condensed) 선형 MPC의 조밀 볼록 QP(1/2 zᵀPz + qᵀz 최소화, l ≤ Gz ≤ h). 사전 역산 행렬 M = (P + σI + GᵀρG)⁻¹을 쓰는 ADMM으로 풀며, 데이터는 설정 시 수정 루이즈 균형화를 10회 패스로 한 번 적용하고, 페널티는 ρ·diag(b)로 매개변수화해 등식 제약 행에 b = 10³을 둔다.
- 제약 구조 3분류: 박스(G가 대각, m = n), 분할(G = [D; C], 비특이 대각 D와 조밀 행 C), 일반(전 행 조밀). 표준 융합 아에서 입력 경계만 있으면 박스, 상태 경계를 더하면 분할, LQR 사전 안정화는 입력 제약을 결합시켜 일반 구조를 만든다.
- 연산자 형태: 스택형 W = [M, MGᵀ; GM, GMGᵀ]은 두 결합 업데이트를 융합 커널 하나로 계산하고, 인수분해형은 F = [M, MCᵀ]와 C를 저장해 두 번째 커널에서 s̃ = Cz̃를 계산한다. 인수분해형이 m_c²개 항목을 아끼지만 커널이 하나 더 필요하고, 박스 구조는 저장이 4n²(스택형)·3n²(인수분해형)에서 n² + n으로 줄어든다.
- 페널티 뱅크: 10배 간격 다섯 페널티, 초기 중심 ρ₀ = 0.1. 풀이 중 적응은 OSQP의 잔차 균형 규칙을 적용하고 현재값의 5배 이상 벗어난 제안은 가장 가까운 저장 항목으로 스냅한다. λ의 최적값은 ρ와 무관하므로 전환 시에도 λ를 유지한다.
- 시작 페널티 탐사: 설정 시 각 뱅크 항목이 적응을 켠 채 최대 400회 반복 시행을 돌려 요청 허용오차의 1/100, 1/10, 1배에 도달하는 시간과 반복 수를 기록한다. 가장 빠른 시행이 시작 ρ와 반복 수 추정치 j_est를 정하고, 끝단 항목이 이기면 뱅크를 다시 중심잡아 재탐사한다(최대 2회 재구축). 분할 제약에서는 조밀 행 가중 γ를 10⁻³~10 범위에서 탐사해 고정한다.
- CUDA 그래프 재생: j_chk = 10회 완전 반복과 장치 측 종료 검사를 하나의 그래프로 캡처해 재생마다 호스트 호출이 한 번이고, 호스트는 잔차 노름·척도·정지 플래그 다섯 값만 읽는다. 12회 검사 동안 잔차가 10%도 줄지 않으면 정체(stall)로 선언한다.
- 자동 모드 선택: t_iter ≈ n_ker·τ + t_stream(b_op) 모델의 τ와 스트리밍 시간을 장치·정밀도별로 0.25-64MB 연산자 크기에 걸쳐 한 번 측정해 캐시한다. 스택형은 m_c < √(τ·BW/β)일 때 빠르다고 예측되고, 가용 GPU 메모리의 60%를 넘거나 최적 예측 대비 1.5배 이상 느린 형태는 제외한다. 최종 선택은 CUDA 그래프 안에서 실측하며, 2커널이 10% 이상 빠르지 않으면 1커널을 유지한다.
- 웜스타트와 갱신: 솔브 사이에 새 q, l, h를 저장된 인자로 재척도화하고 r을 다시 만든다. P나 G가 바뀌면 뱅크 전체를 다시 역산하거나, 지연 모드에서는 활성 항목만 재역산하고 나머지는 페널티 전환이 선택할 때까지 stale로 표시한다. 웜스타트는 이전 해를 지평 기준 한 스텝 이동시킬 수 있다.
- 정밀도 정책: 뱅크는 항상 float64. 자동 선택은 멱급수로 κ(K)를 추정해 u₃₂κ(K) ≤ 0.01ε이면 float32, ≥ ε이면 float64, 그 사이면 둘 다 돌려 T_graph로 비교하되 float64가 20% 이내면 float64를 선호한다. 정체된 float32 솔브는 100배 허용오차 검사를 통과하면 solved_inaccurate를 반환한다.
- 랜덤 QP 벤치마크(Clarabel 10⁻¹⁰ 해 기준 ℓ∞ 오차 ≤ 10⁻³로 정확도 정합): FAME-QP float64는 모든 크기에서 GPU 기준선을, n ≥ 220에서는 CPU 기준선도 모두 앞선다. n = 220-1400에서 최고 CPU인 DAQP 대비 1.2-25.9배, 최고 GPU인 ReLU-QP 대비 1.5-4.3배. n = 1400 평균 솔브 시간은 float32 1.95ms, float64 5.01ms vs cuOSQP 326ms.
- 랜덤 시스템 LMPC(n_u = 10-50, n_x = 3n_u, 지평 40, 폐루프 50스텝): 모든 크기에서 최저 평균 스텝 시간(0.658-4.23ms). ReLU-QP 대비 3.2-7.3배, πMPC 대비 3.2-13.8배. 폐루프 비용은 기법 간 0.06% 이내로 일치하고 FAME-QP의 최대 입력 경계 위반은 2.0×10⁻³로 ReLU-QP(1.4-4.3×10⁻²)보다 작다.
- Unitree G1 밀기 복구(MuJoCo, 29관절, 2ms 제어 주기, 80N/0.1s 몸통 밀기): QP 시간이 ReLU-QP보다 2.3-3.1배 낮고(N = 10에서 0.650 vs 1.47ms, N = 20에서 1.04 vs 3.25ms) 모든 테스트 지평에서 제어 주기 아래를 유지한다. ReLU-QP는 N ≥ 15부터 초과하므로 FAME-QP는 예산 안 최대 지평을 10에서 20으로 두 배 늘린다. 복구 성능은 양쪽 비슷하다(CoM RMS 18.7-20.5mm).
- Skydio X2 쿼드로터 KQ-LMPC(코프만 들어올림 동역학, P와 G가 매 스텝 변경, 50Hz, N = 70, n = 280): 행렬 갱신·웜스타트 이동·호스트 전송을 포함한 평균 QP 시간 12.5 ± 3.2ms vs CuPIQP 59.2 ± 4.8ms(4.7배). 99백분위 지연은 17.6ms로 20ms 주기 안(단, CuPIQP 72.1ms). 위치 추적 RMSE는 2.7mm vs 3.4mm, 최대 오차는 양쪽 8.5mm.
- 소거 실험: 융합+그래프 재생은 n = 128에서 반복당 시간을 140μs(비융합 즉시 실행) → 24.6μs(그래프) → 4.37μs(융합 그래프)로 줄이고 반복당 커널 14개를 하나로 바꾼다. 구조 추출은 해를 10⁻¹² 이내로 유지하면서 저장 1.67-4.00배, 반복 시간 1.07-3.03배 절감. n = 512, m_c = 128에서 스택 연산자는 3.12MiB/17.3μs로 ReLU-QP의 24.5MiB/86.3μs보다 작고 빠르다. 자동 모드 선택은 36개 스윕 지점 중 30개에서 더 빠른 형태를 골랐고(빠른 형태를 제외한 적은 없음) 항상 스택형·항상 인수분해형은 최대 2.2배·1.5배 느리다.
- 페널티 탐사 효과: 허용오차 10⁻⁵에서 탐사된 시작값은 반복을 1.6-3.2배, 완전 솔브 시간을 1.4-3.3배 줄이고, 융합과 결합하면 효과가 곱해져 2.8-4.2배가 된다. 설정 비용은 약 36-122회 솔브 후 회수된다. 탐사한 FAME-QP와 기본 ReLU-QP가 비슷한 반복 수(30-38 vs 30-32)로 풀므로 ReLU-QP 대비 속도 향상은 주로 반복당 비용에서 온다.
- 지연 행렬 갱신: 기록된 쿼드로터 KQ-LMPC 시퀀스에서 전체 뱅크 재역산은 갱신이 스텝의 지배 비용이 되지만, 지연 갱신은 갱신·중앙값 스텝 시간을 약 절반으로 줄이고 꼬리를 짧게 하며 반복 수·수치적 정밀도의 해·추적 오차는 동일하다.
- 하드웨어와 기본값: NVIDIA RTX 3080 Laptop(48 SM, 16GB) + Intel i7-11850H. float64, σ = 10⁻⁶, α = 1.6, 절대·상대 허용오차 동일, 10회마다 검사, 반복 한도 2×10⁴(폐루프 LMPC와 G1 실험은 10⁵). 코드: github.com/santoshrajkumar/fame-qp.

## 세부 사항

### 알고리즘 구조

FAME-QP는 박스 제약으로 재정식화한 QP의 표준 이완 ADMM 반복을 구현한다. 1회 수정 루이즈 균형화 이후 설정 단계에서 제약 구조를 감지하고 실행 모드를 고르고, 다섯 항목 페널티 뱅크를 만들고 CUDA 그래프를 캡처하며 시작 페널티(분할 제약이면 γ까지)를 탐사한다. 각 솔브는 들어오는 데이터를 재척도화하고 P·G 변경 시 연산자를 (전체 또는 지연) 갱신한 뒤, z와 λ를 웜스타트하고(Gz를 박스에 사영해 s 재구성), 그래프를 재생하다가 비척도 잔차가 종료 검사를 만족하거나 정체·반복 한도에 이르면 끝낸다. 승수 업데이트가 초기화 후 μ를 영으로 유지하므로 반복은 사전 역산된 M과의 행렬-벡터 곱 한 번과 요소별 이완·클리핑·쌍대 업데이트로 줄어든다. 커널 융합과 페널티 뱅크 전환이 값싸게 되는 이유가 바로 이 구조다.

### 구조가 중요한 이유

모든 제약 행을 조밀하게 다루면 (n + m)² 크기 연산자가 필요하고, 단순히 대각인 행과의 곱에도 비용을 지불한다. FAME-QP의 3분류는 박스 제약을 요소별 산술로 바꾸고 분할 제약의 대각 블록을 연산자에서 떼어내 진짜 결합된 행 C만 실어 나른다. 소거 실험은 이 설계를 확인한다. 대각 행을 추출해도 반복 수와 해가 10⁻¹² 이내로 같으면서 저장은 1.67-4.00배, 반복 시간은 1.07-3.03배 줄고, n = 512, m_c = 128에서 ReLU-QP의 (n + 2m)² 연산자와 같은 그래프 재생 조건으로 비교하면 추출된 스택 연산자가 저장 8배 작고 반복당 5배 빠르다.

### 성능 향상의 출처

소거 실험은 세 가지 곱셈적 효과를 분리한다. 작은 연산자에서 지배적인 융합+그래프 재생(n = 128에서 반복당 최대 32배), 더 큰 문제에서 지배적인 페널티 탐사(n = 1000에서 최대 3.35배, 반복 수가 줄기 때문), 그리고 P·G가 매 솔브마다 바뀔 때 지배적인 지연 행렬 갱신(KQ-LMPC 재생에서 스텝 시간 약 절반). 자동 모드 선택은 대체로 보정 모델의 예측을 따르지만, 모델만으로는 스택형과 인수분해형의 교차점을 2배 정도 어긋나게 잡으므로 최종 선택은 실측으로 한다. 저자들은 조밀 융합 QP 너머의 확장성을 위해 희소 및 지평 구조 공식화를 후속 과제로 꼽는다.
