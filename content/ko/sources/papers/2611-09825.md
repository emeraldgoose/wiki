# BitDecoding-FP4: 알고리즘-시스템 공동 설계를 통한 네이티브 FP4 KV 캐시 디코딩

**게시일**: 2026-11-06 (arXiv v1 기준)

## 개요

긴 컨텍스트 LLM 서빙의 병목은 키-값(KV) 캐시다. 정적인 가중치와 달리 KV 캐시는 시퀀스 길이와 동시성에 비례해 커지고, 디코딩 단계마다 반복해서 읽히기 때문에 GPU 메모리 용량과 대역폭을 지배한다. NVFP4, MXFP4 같은 4비트 마이크로스케일링 포맷은 이 캐시를 줄이고 NVIDIA Blackwell(및 Rubin) GPU의 5세대 Tensor Core에서 네이티브로 실행되어 FP8 대비 대략 2-3배의 처리량을 약속한다. 그러나 알고리즘 양자화와 시스템 가속 사이에는 여전히 간극이 있다. 기존 FP4 KV 시스템은 단순 양자화를 써서 정확도가 크게 떨어지고, 정확도 지향 4비트 기법은 벡터 코드북에 의존해 조회 오버헤드가 디코딩 처리량을 갉아먹는다.

BitDecoding-FP4(Du 등, University of Edinburgh 및 Tencent Hunyuan)는 네이티브 FP4 KV 디코딩을 위한 알고리즘-시스템 공동 설계로 이 간극을 메운다. 알고리즘 측에서는 마이크로스케일링 FP4 양자화의 세 가지 오류 원인을 각각 겨냥하고, 시스템 측에서는 소프트맥스 병목을 제거해 두 어텐션 행렬 곱셈이 paged KV 캐시 위에서 모두 FP4 Tensor Core로 네이티브 실행되도록 한다. 그 결과 정확도와 속도 중 하나를 포기하지 않는 디코딩 경로가 완성된다.

GQA(그룹 쿼리 어텐션)와 MLA(멀티헤드 잠재 어텐션)를 쓰는 dense 및 MoE 모델 전반에서, BitDecoding-FP4는 NVFP4 기준 BF16 KV 대비 정확도 0.5점 이내(MXFP4는 1점 이내)를 유지하며, RL 학습 롤아웃에서도 BF16 KV를 추적한다. NVIDIA B300 GPU 위에서 Qwen3-4B와 Qwen3-30B-A3B로 엔드투엔드 서빙한 결과 BF16 KV 대비 최대 서빙 처리량이 2.4-3.0배 향상됐다. 구현체는 https://github.com/OpenBitSys/BitDecoding-FP4 에서 공개되어 있다.

## 핵심 포인트

- 긴 컨텍스트 서빙의 KV 캐시 병목을 네이티브 FP4(NVFP4 / MXFP4) 실행으로 해결한다. 런타임 역양자화 단계가 없다.
- Dual-Residual Query Quantization은 쿼리를 두 개의 FP4 텐서로 나누어 쿼리 로짓 오차를 60%에서 1%로 줄인다.
- Underflow-Aware Probability Scaling은 E4M3 스케일이 긴 컨텍스트의 확률 값을 0으로 반올림하는 현상을 막는다.
- Outlier-Aware Key Quantization은 정적 스무딩, Hadamard 회전, 스케일 탐색을 결합해 토큰 단위 스케일링 아래 키 아웃라이어를 억제한다.
- 시스템 수준에서는 전치(transposed) 소프트맥스와 확률 양자화 융합, paged KV 캐시 위의 stacked query MMA로 소프트맥스 병목을 제거한다.
- GQA와 MLA를 쓰는 dense 및 MoE 모델로 평가됐으며, NVFP4에서 BF16 KV 대비 0.5점 이내 정확도를 유지한다(MXFP4는 1점).
- NVIDIA B300(Qwen3-4B, Qwen3-30B-A3B)에서 BF16 KV 대비 최대 서빙 처리량 2.4-3.0배. RL 학습 롤아웃에서도 BF16 KV를 추적한다.
- 저자들의 이전 BitDecoding 연구에서 제안한 Tensor Core 인지형 KV 레이아웃과 혼합 정밀도 버퍼 위에 구축됐다.

## 상세

**방법.** BitDecoding-FP4는 어텐션의 두 피연산자(점수 곱의 Q/K, 출력 곱의 P/V)를 모두 마이크로스케일링 FP4로 양자화하고 두 행렬 곱셈 모두를 FP4로 실행한다. 세 가지 복합 오류 원인을 다룬다. (1) *Dual-Residual Query Quantization*: 쿼리를 한 번 양자화한 뒤 잔차(쿼리와 역양자화 근사의 차이)를 두 번째 FP4 텐서로 양자화하고, 두 부분곱을 누적한다. 이로써 쿼리 로짓 오차가 60%에서 1%로 줄어든다. (2) *Underflow-Aware Probability Scaling*: 온라인 소프트맥스에서 긴 컨텍스트의 확률은 매우 작아 E4M3 스케일링 아래 0으로 반올림될 수 있는데, 블록 최댓값이 임계 이하이면 κP를 2로, 아니면 6으로 정하는 적응적 재스케일링으로 E2M1 반올림을 통과시킨다. (3) *Outlier-Aware Key Quantization*: 키에 정적 스무딩(채널별 평균 제거), Hadamard 회전, 스케일 탐색을 전처리로 적용해 토큰 단위 스케일링 아래의 아웃라이어 채널을 억제한다. 커널 수준에서는 확률 양자화가 융합된 전치 소프트맥스와 paged KV 캐시 블록 위의 stacked query MMA가 소프트맥스를 크리티컬 패스에서 벗어나게 하고 Tensor Core를 계속 공급한다. 기존 연구에서 역양자화가 128K 컨텍스트에서 디코드 커널 시간의 7-21%를 차지한다는 지적이 있었는데, 네이티브 FP4는 이 단계를 완전히 없앤다. 이 방법은 BitDecoding 레이아웃을 정확한 FP4 양자화 알고리즘과 Blackwell 네이티브 커널로 확장한 것이며, 부록에서는 teacher-forced KL을 빠른 정확도 프록시로 쓰는 방법, 보정 절제 실험, SageAttention3와의 비교, MXFP4 블록 스케일 탐색, FP4 MLA를 다룬다.

**결과.** GQA와 MLA를 쓰는 dense 및 MoE LLM 전반에서, NVFP4 KV를 쓰는 BitDecoding-FP4는 BF16 KV 대비 정확도 0.5점 이내(MXFP4는 1점 이내)를 유지하며, RL 학습 롤아웃에서도 BF16 KV와 정확도가 비슷하게 추적된다. NVIDIA B300 위의 엔드투엔드 서빙에서 Qwen3-4B와 Qwen3-30B-A3B는 BF16 KV 대비 최대 서빙 처리량이 2.4-3.0배 향상됐다. Blackwell급 GPU에서 네이티브 FP4 피연산자는 FP8 대비 대략 2-3배의 처리량을 제공한다. 이 연구는 조회 오버헤드로 FP4의 처리량 이점을 상쇄하는 정확도 지향 코드북 기법에 대한 알고리즘-시스템 차원의 대안으로 자리매김한다.
