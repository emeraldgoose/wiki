# 빠진 시간 연결고리: 스크립트 기반 오디오-비디오 생성을 위한 시간 컨텍스트 라우팅

출처: Yichen Liu 외 10인, arXiv:2609.02367, 2026-09-02.

**핵심 요약**: 오디오-비디오 공동 생성기는 화질과 오디오-비디오 동기화에서 강해졌지만, 샷 전환이 *언제* 일어나고 대사가 *언제* 말해지는지 제어는 약합니다 — 타이밍 오류가 서사 일관성을 무너뜨리는 스크립트 기반 창작에는 치명적입니다. 진단은 이렇습니다. 현 모델은 비디오와 오디오를 공유 시간축에 정렬하지만, 구조화 프롬프트의 샷·대사 타이밍은 텍스트 표현에만 머물러 어느 모달리티의 시간 좌표와도 정렬되지 않습니다. 그래서 비디오와 오디오는 서로 동기화되면서도 둘 다 스크립트를 놓칩니다. 해법은 **시간 컨텍스트 라우팅(TCR)** 으로, 스크립트 타이밍을 공유 시간축에 올리고 각 프롬프트의 가이던스를 양 모달리티의 대응 위치로 라우팅합니다. 200개 테스트 스크립트에서 TCR은 샷 경계 MAE를 **96%(1.11초→0.042초)** 줄이고 대사 Acc@0.5s를 **28.3%에서 84.1%** 로 올렸으며, 화질·동기화는 베이스라인과 동등합니다 — 사용자 조사 5개 차원 전부에서 선호됐습니다.

## 아무도 재지 않던 오정렬

논문의 개념적 기여는 세 번째 축을 지목한 것입니다. prior는 시간 정렬을 2체 문제(비디오↔오디오)로 다뤘고, TCR은 3체 문제(스크립트↔비디오↔오디오)로 봅니다. 각 프롬프트 구간의 가이던스는 전역 텍스트 조건으로 뿌려지지 않고 양 생성 스트림의 대응 시간 위치로 라우팅됩니다. "스크립트를 따르라"가 프롬프트 엔지니어링 바람에서 아키텍처 보장으로 바뀌는 셈입니다.

## 수치가 말하는 것

| 지표 (200개 테스트 스크립트) | 베이스라인 | TCR |
|---|---|---|
| 샷 경계 MAE | 1.11초 | **0.042초** (−96%) |
| 대사 Acc@0.5s | 28.3% | **84.1%** |
| 화질 / AV 동기화 | — | 동등 |
| 사용자 조사 (5개 차원) | — | 전부 선호 |

두 대표 지표가 함께 움직입니다 — 샷 컷과 대사가 동시에 제시간에 안착합니다. 공유축 라우팅의 예측 그대로입니다. 품질 동등성이 중요합니다. 타이밍 제어에 지각적 품질 비용이 없다는 뜻입니다.

## 주의할 점

이 요약은 초록 기반입니다. 라우팅 메커니즘의 아키텍처 세부, 사용자 조사 5개 차원, 200스크립트 너머 일반화는 본문 확인이 필요합니다. 결과는 논문 자체 베이스라인 대비이며, 다른 제어 가능 생성 기법과의 조합은 언급 없습니다. 대사 정확도 절대값(84.1%)은 여전히 6개 중 1개 대사가 어긋남을 뜻합니다 — 초안용으로 훌륭하나 최종본은 검토가 필요합니다.

## SW 엔지니어와의 관련성

- 스크립트·스토리보드 기반 미디어 도구를 만든다면 전역 텍스트 컨디셔닝으로 타이밍을 강제할 수 없습니다 — 시간 위치로 인덱싱된 프롬프트 가이던스가 필요하고, 그게 TCR의 핵심 패턴입니다.
- 두 출력이 서로 일관돼 보이는데 둘 다 틀렸다면, 쌍별 손실 튜닝이 아니라 빠진 세 번째 정렬축을 의심하세요.
- 품질 동등 하의 96% 오차 감소가 배포 관련 형태입니다. 타이밍 제어는 품질 세금이 아니라 라우팅 변경입니다.
- 평가는 기계 지표(MAE, 윈도우 내 정확도)와 선호 조사를 짝지으세요 — 타이밍 오류는 지각적이라 사용자가 정답입니다.
