# 터미널 에이전트를 위한 환경 진화

출처: Zhiyuan Fan 외 11인, arXiv:2609.04128, 2026-09-03. Hunyuan Team, Tencent.

**핵심 요약**: 터미널 에이전트 훈련에서 RL 환경이 확장성의 핵심 지렛대가 되고 있지만, 처음부터 합성한 환경은 프론티어 모델이 반복 rollout에서 다 풀어버려 학습 신호가 되지 못하고 버려집니다. 기존 공진화(co-evolution) 방법은 온폴리시 rollout에 의존해 rollout 모델에 종속되고 훈련이 포화하면 신호가 마릅니다. 이 논문은 **환경 진화**를 제안합니다. 기존 환경을 **오프폴리시**로 세대를 거듭하며 점진적으로 어렵게 만들고, 훈련 중 계보대로 스케줄링합니다. 단순한 200스텝 장수평 RL만으로 **Qwen3.6-27B는 14.4pp, Qwen3.6-35B-A3B는 18.0pp를 Terminal-Bench 2.1에서 향상**시키며 공진화·앙상블 베이스라인을 넘깁니다.

## 난이도를 측정하지 않고 유도한다

모델의 통과율로 난이도를 재는 대신, 다중 턴 학습 목적식에서 오프폴리시 난이도 정의를 유도합니다. 궤적은 **시나리오**(도달한 상황)와 **스킬**(적용한 행동)의 교대로 분해되며, 정책 독립적인 난이도 요인 세 가지 — **실행 길이**(solver 턴 수), **시나리오 참신성**, **스킬 희귀성** — 이 나옵니다.

이 관점은 온폴리시 공진화의 blind spot을 드러냅니다. 공진화는 시드 환경 안에서 현재 모델이 도달한 시나리오의 스킬 선택 오류만 주로 겨냥하고, 궤적 길이를 제어하지도 시나리오 참신성을 체계적으로 키우지도 않습니다. 환경 진화는 난이도 공간 전체에서 동작합니다.

## 진화의 동작 방식

루프 공학 멀티에이전트 하네스가 한 번에 한 방향 — **길이**(시나리오–스킬 쌍 삽입), **시나리오**(스킬 유지하며 시나리오 교체), **스킬**(스킬 교체) — 로 환경을 진화시킵니다. 루브릭 검토 계획 다듬기와 oracle·무효 테스트·품질 검증의 환경 다듬기, 두 게이트 루프를 거칩니다. **진화 노력**(low/high/max) 파라미터가 편집 범위를 제어하며 high가 기본값입니다. Claude Opus 5 측정 단일 스텝 효과(high):

| 방향 | 통과율 변화 | 평균 턴 변화 |
|---|---|---|
| 길이 | −7.1pp | +9.4 |
| 시나리오 | −4.7pp | +13.5 |
| 스킬 | −4.0pp | +12.5 |

길이가 가장 작은 전체 변이로 통과율을 가장 많이 낮추고, 15세대 계보에서도 방향별 프로파일이 유지됩니다. Hy4 preview, Claude Opus 5, GPT-5.6 Sol rollout에서 진화된 환경은 오프폴리시 합성에도 모델 전반에 걸쳐 일관되게 어려워집니다.

## 훈련 결과

시드는 가차 없이 거릅니다. 47,678개 후보에서 500개 균형 풀을 뽑습니다. **EL(진화 계보) 스케줄러**는 g세대가 임계값(B=8, τ=6/8)을 넘을 때만 g+1세대를 열어 rollout 그룹을 부분 해결 상태로 유지해 GRPO advantage가 0이 되지 않게 합니다. 200스텝 RL 최고 Terminal-Bench 2.1 정확도:

| 방법 | Qwen3.6-27B | Qwen3.6-35B-A3B |
|---|---|---|
| **환경 진화** | **71.5%** | **64.9%** |
| 공진화 | 62.9% | 55.1% |
| 앙상블 | 60.0% | 52.8% |

시드를 SFT에 이미 쓴 뒤에도 진화된 환경은 계속 도전적인 RL 신호를 제공합니다.

## 주의할 점

난이도 추정은 세 가지 특정 rollout 모델 기준이며, 15세대 상한은 zero-pass 구간에서 통과율이 분해능을 잃기 때문입니다. 결과는 Claude Code 하네스 + GRPO + Terminal-Bench 2.1 조합에 묶여 있고, SWE·컴퓨터 사용 에이전트 전이는 향후 과제입니다. 개발 중 human-in-the-loop 검토가 들어갔으므로 품질 기준 일부는 사람의 판단을 증류한 루브릭에 의존합니다.

## SW 엔지니어와의 관련성

- 에이전트 RL 루프에서 "너무 쉬운" 환경을 버리고 있다면 합성 비용을 기울기 0에 쓰고 있는 셈입니다. 처음부터 합성보다 살아남은 환경의 진화가 낫습니다.
- *환경 난이도*와 *모델 약점*을 분리하세요. 특정 모델 기준 난이도는 전이되지 않지만 환경 family 기준 난이도는 전이됩니다.
- 데이터만큼 커리큘럼 스케줄링이 중요합니다. 풀 수 없는 과제를 일찍 열면 전실패 그룹에서 advantage가 0이 됩니다.
- 길이/시나리오/스킬 분해는 코딩 벤치마크 포함 어떤 과제 family를 단단하게 만드는 데도 재사용 가능한 루브릭입니다.
