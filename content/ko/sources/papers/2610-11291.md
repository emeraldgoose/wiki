# 온-정책 증류가 언제 필요한가? 오프라인 학생 롤아웃으로 증류하는 것이 종종 더 낫다

**Source**: Zhao 외, arXiv, 2026-10-08

**핵심**: 온-정책 증류(OPD)는 교사 모델의 역량을 학생 모델로 전이하는 지배적 패러다임으로 부상했으나, 본 연구는 더 단순한 대안인 Semi-OPD—초기(미학습) 학생이 생성한 오프라인 롤아웃에서 증류하는 방식—이 다양한 모델 규모에서 정확도와 학습 효율 모두에서 OPD를 자주 능가함을 보인다.

## 배경

지식 증류는 일반적으로 강한 교사 모델을 모방하도록 학생 모델을 학습시킨다. 온-정책 증류(OPD)는 증류 과정에서 학생이 자체 훈련 데이터를 생성하게 함으로써 이를 확장하며, 이론적으로 학생의 오류 영역을 더 잘 커버한다. OPD는 언어 모델의 온-정책 증류(Agarwal 외, 2024), MiniLLM(Gu 외, 2024), Thinking Machines Lab 및 DeepSeek의 후속 연구들에서 채택됐다. 통념은 온-정책 샘플링이 학생의 현재 약점에 맞춰 훈련 분포를 적응시키므로 효과적인 증류에 필수적이라는 것이다.

## Semi-OPD 대안

저자들은 **반-온-정책 증류(Semi-OPD)**를 제안한다: 각 증류 단계마다 새로운 롤아웃을 생성하는 대신, *초기*(미학습) 학생으로부터 고정된 오프라인 롤아웃 세트를 한 번만 생성하고, 이를 모든 후속 증류 단계에 재사용한다. 이는 반복적인 온-정책 생성의 계산 오버헤드를 제거하면서 OPD를 효과적으로 만드는 학생 유도 분포 이동을 보존한다.

핵심 설계 선택:
- 롤아웃은 무작위로 초기화된 학생으로부터 한 번만 생성
- 동일한 오프라인 데이터셋을 모든 증류 에폭에 재사용
- 증류 중 교사 쿼리 불필요(OPD는 학생 생성 프롬프트에 교사 쿼리)

## 실험 결과

**17개 교사-학생 쌍**(LLaMA, Qwen, DeepSeek 모델 패밀리 포함)에 걸쳐 1.5B~235B 파라미터 범위에서 Semi-OPD는 **14개 경우에서 OPD를 능가**:

| 지표 | Semi-OPD 우위 |
|--------|-------------------|
| 정확도 | OPD 대비 최대 +13.6% |
| 학습 효율 | 최대 11.4배 빠름(반복 롤아웃 생성 불필요) |
| 승률 | 82% (17개 중 14개 쌍) |

OPD가 이기는 3개 경우는 매우 큰 교사(235B)가 매우 작은 학생(1.5B)으로 증류하는 경우로, 학생의 초기 정책이 너무 약해 유용한 롤아웃을 생성하지 못한다.

## OPD가 종종 저조한 이유

저자들은 표준 OPD의 두 가지 실패 모드를 식별:
1. **길이 팽창**: 온-정책 롤아웃이 학습 중 점진적으로 길어지며, 품질 개선 없이 장황한 생성에 컴퓨트 낭비
2. **분포 붕괴**: 학생 정책이 퇴화된 출력(반복, 지름길)으로 드리프트하고 교사가 이를 강화

Semi-OPD는 롤아웃 분포를 초기화 시점에 고정함으로써 둘 다 회피한다.

## 소프트웨어 엔지니어를 위한 시사점

모델 증류 파이프라인을 구축하는 팀에게 Semi-OPD는 실용적 단순화를 제공한다: **롤아웃을 한 번 생성하고, 여러 번 증류**. 이는 인프라 복잡도 감소(온-정책 생성 루프 불필요), 컴퓨트 비용 10배 절감, 최종 모델 품질 향상을 동시에 달성한다. 특히 다음 상황에 매력적:
- 리소스 제약 환경(단일 GPU / 제한된 API 할당량)
- 많은 학생 체크포인트 대상 대규모 증류
- 교사 접근이 비싸거나 레이트 리밋이 있는 시나리오

코드와 롤아웃은 https://github.com/NVlabs/Semi-OPD에서 공개.
