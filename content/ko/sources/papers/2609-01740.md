# 촘촘한 토큰 접두사로 고정밀 3D 토큰화를 하는 ZipTok3D

출처: Mingda Lin 외 9인, arXiv:2609.01740, 2026-09-01.

**핵심 요약**: 3D 생성 파이프라인은 먼저 물체 형상을 잠재 시퀀스로 토큰화하고, 그 시퀀스 길이가 하류 생성 모델링 비용을 직접 결정합니다. 기존 3D 토크나이저는 토큰을 공간 영역에 고정하거나 형상을 고정 크기 전역 토큰 집합으로 압축하는데, 토큰을 몇 개로 줄이면 품질이 급격히 무너집니다. ZipTok3D는 대신 형상을 **점진적으로 유익해지는 전역 토큰 접두사**로 조직하고 **반복 디코딩**으로 펼칩니다. 훈련 중 nested dropout으로 잠재 시퀀스를 무작위 절단해 남은 접두사마다 전체 물체를 복원하도록 강제하므로 핵심 형상 정보가 앞 토큰에 몰리고, 파라미터 공유 Transformer 블록이 공간 표현을 여러 패스에 걸쳐 정제합니다. 동일 토큰 폭에서 ZipTok3D 1개 토큰이 ShapeNet에서 32토큰 COD-VAE와 동등하고, 4개 토큰이 TRELLIS에서 동등합니다 — **32배·8배 짧은 시퀀스**로 같은 품질입니다.

## 소수 토큰 3D 복원이 어려운 이유

토큰 예산이 넉넉하면 전역 토크나이저가 상호보완적 형상 정보를 여러 잠재 벡터에 분산할 수 있습니다. 예산을 1~2개로 줄이면 각 토큰이 물체의 훨씬 큰 부분을 요약해야 해서 전역 구조와 미세 디테일이 작은 잠재 용량을 놓고 경쟁합니다. 고정 예산 토크나이저(VecSet, COD-VAE)는 이 경쟁을 최종 복원 손실로만 암묵적으로 해결하고 무엇을 먼저 보존할지 명시적으로 정하지 않습니다. ZipTok3D는 문제를 추론 시점의 두 조절축으로 나눕니다 — 살아남는 잠재 길이인 **접두사 길이 K**와 이를 푸는 디코더 계산량인 **정제 깊이 L**입니다.

## 내포 접두사 + 공유 정제

훈련은 128토큰·폭 512 잠재 시퀀스에서 지수 간격 예산 {1, 2, 4, 8, 16, 32, 64, 128} 중 유지 길이를 샘플링하고, 접미사를 선택·정제에서 가린 뒤 접두사만으로 전체 형상을 복원하도록 요구합니다. 짧은 접두사가 긴 접두사에 항상 포함되므로 앞 토큰은 물체 전반 형상을 담고 뒤 토큰은 잔여 디테일을 추가합니다. 디코딩은 단일 6층 Transformer 블록을 L패스(주요 결과는 5패스) 재사용하며 중간 감독과 intra-loop 자기 증류를 곁들여, 단계별 파라미터 없이 디코딩 깊이를 늘리고 별도 생성 샘플링 단계도 없습니다.

## 결과가 보여주는 것

ShapeNet에서 **1토큰** 설정은 COD-VAE-32와 반올림 CD·F1이 동일하고 IoU는 0.3p 차이입니다. 더 다양한 TRELLIS 분할에서 **4토큰**은 query IoU 동등, CD·F1 우위입니다.

| 설정 | ShapeNet IoU / CD / F1 | TRELLIS IoU / CD / F1 |
|---|---|---|
| COD-VAE-32 | 97.1 / 0.012 / 97.8 | 75.25 / 0.0172 / 95.67 |
| **ZipTok3D-1** | **96.8 / 0.012 / 97.8** | 75.18 / 0.0168 / 95.81 |
| **ZipTok3D-4** | 96.9 / 0.012 / 97.9 | **75.31 / 0.0166 / 95.92** |

반면 COD-VAE는 2토큰에서 무너지고(ShapeNet IoU 77.7) — 이득이 단순한 "토큰 감소"가 아님을 보여줍니다. 2토큰 코드는 클래스 조건 생성에서도 COD-VAE-32에 근접하며 stage-2 시퀀스는 16배 짧고 샘플링 처리량은 더 높습니다. ablation은 접두사 훈련과 공유 정제가 주 기여자이고 중간 감독은 작은 보너스임을 확인합니다.

## 주의할 점

데이터셋별 모든 동작점은 단일 체크포인트·단일 훈련 시드에서 나왔으므로 실행 간 분산은 보고되지 않습니다. 부트스트랩 신뢰구간은 평가 객체 변동만 반영합니다. TRELLIS IoU 우위(+0.06)는 구간이 0을 포함합니다 — 통계적으로 단단한 것은 CD·F1 승리입니다. 효율 수치는 단일 GPU(H20) 프로토콜 전용입니다. 평가는 복원과 클래스 조건 생성이며 텍스트→3D 프롬프팅은 다루지 않습니다.

## SW 엔지니어와의 관련성

- 3D 파이프라인의 diffusion·자기회귀 단계가 긴 잠재 시퀀스에 막힌다면, 생성기가 아니라 토크나이저가 압축 포인트일 수 있습니다.
- Nested dropout은 범용 저비용 기법입니다. 예산별 모델이 아니라 여러 예산에서 디코딩되는 모델 하나를 훈련하세요.
- 가중치 공유 반복 정제는 파라미터 없이 깊이를 삽니다. 대가는 지연시간(동일 설정에서 형상당 0.98ms→2.65ms)이므로 SLO에 맞춰 K와 L을 함께 예산 배분하세요.
- 이득은 극저토큰 영역에 집중됩니다 — 긴 접두사는 얕은 디코딩을 보완하는 수준이므로 토큰을 늘리기 전에 프로파일링하세요.
