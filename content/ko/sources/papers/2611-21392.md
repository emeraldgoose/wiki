# VideoNexus: 추론 컨텍스트를 넘어서는 비디오 지각

**Source**: [arXiv](https://arxiv.org/abs/2611.21392)
**게시일**: 2026-11-16

## Overview

시간 단위의 비디오 이해는 프런티어 멀티모달 모델의 추론 컨텍스트를 압박한다. 프레임을 플래너에 밀어 넣으면 픽셀이 쌓이고 매 턴마다 다시 읽히면서, 비용은 부풀고 정확도는 그에 미치지 못한다. VideoNexus는 지각을 추론에서 분리한다 — 플래너는 텍스트에 머물고, 별도의 지각 경로가 비디오를 보며 간결한 증거(텍스트와 몇 장의 증거 카드 이미지)를 반환하는 "다른 곳에서 지각하고, 텍스트로 추론하기" 방식이다. 이 분리 덕분에 플래너 컨텍스트에 들어가는 것보다 훨씬 많은 프레임을 매 턴 토큰 비용 없이 활용할 수 있다.

시간 단위 LVBench(103개 비디오, 1,549개 질문)에서 Gemini 3.8 Flash를 쓴 VideoNexus는 질문당 $0.140로 88.6% 정확도를 달성했고, 같은 백본에서 더 저렴하면서 더 정확한 방법은 없었다. Video-GAIA에서는 Kimi K3를 플래너와 지각 모델로 써서 271개 중 163개를 맞혀 공식 ReAct 에이전트(140개, +8.5점)를 앞섰다.

## Key points

- LVBench 주 비교(Gemini 3.8 Flash, 1,549개 질문): VideoNexus 88.6%(1,372/1,549), $0.140/질문. Static 1fps 수집(85.0%, $0.172)보다 +3.6점(90승/34패, McNemar p=5e-7), VideoSeek 재실행(81.4%, $0.188)보다 +7.2점(153승/42패, p=5e-16), Gemini Agentic(87.5%, $0.319)보다 +1.1점이면서 비용은 44%(유의하지 않음, p=0.10).
- 효율성: 오디오를 포함한 621개 원본 비디오 프레임(VideoSeek은 정지 이미지 123개); 플래너에는 질문당 3.3장의 증거 카드만 전달; 질문당 9.7회 모델 호출(플래너 턴 6.1 + 지각 호출 3.6) vs VideoSeek 18.6회; 출력 토큰 12.4k vs 26.2k(출력은 신선 입력 가격의 5배).
- 비용 분해: 입력 토큰은 비슷(118.2k vs 118.7k)하고 비용 차이는 출력량에서 온다. VideoSeek을 최저 이미지 티어로 재산정하면 $0.140 — 측정된 구성이 아니라 가격 민감도 분석이다.
- Video-GAIA(Kimi K3, 271개, LLM 심판): 종합 60.2% vs ReAct 51.7%, 이득은 L2(+11.5)에 집중 — 비디오에서 특정 엔티티를 찾고 웹에서 식별해야 하는 질문이다. L1에서는 한 문제 차이. (이 질문들로 웹/크롭 도구를 개발했으므로 보정된 격차가 아니라 다른 플래너로의 전이 결과로 읽어야 한다.)
- LVBench 여섯 범주 중 다섯에서 선두(추론 +2.7, 요약 +3.6; temporal grounding 예외). VideoNexus 오류 177개 중 122개는 Static·Gemini Agentic도 함께 틀린 것이어서 남은 헤드룸의 상당 부분을 공유한다.

## Details

- 방법: 결합 vs 분리 멀티모달 컨텍스트(Sec. 3.1); VideoNexus는 비디오를 오디오와 함께 원본으로 지각하고 텍스트 증거와 증거 카드를 반환한다. 표적 검색을 위한 "Finding protocol"과 네이티브 타임라인 주소 지정·구현 포함. 절제 실험은 계층화된 dev-200 서브셋에서, 주 비교는 전체 집합에서 수행.
- 설정: LVBench 범주 ER(560), EU(526), KIR(196), Rea(147), Sum(55), TG(65); Video-GAIA L1 62 / L2 209; 비용은 리스트 가격 기준, 질문 간 캐시를 신선 입력으로 재산정한 cold-start 기준; ASR 비용 제외.
