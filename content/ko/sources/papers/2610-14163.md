# AutoEnvScaling: 터미널 에이전트로 데이터 플라이휠 자동화하기

출처: Simon Yu 외 10인, arXiv:2610.14163, 2026-10-09.

**핵심 요약**: 터미널 에이전트는 명령 실행으로 소프트웨어 공학·과학 연구 과제를 풉니다. 강화학습에는 다양하고 검증 가능한 환경이 필요한데, 지금은 대부분 사람 연구자가 설계하므로 환경 공급 속도가 연구자 속도에 묶여 있습니다. **AutoEnvScaling**은 환경 설계 자체를 터미널 과제로 바꿔 에이전트가 데이터 플라이휠을 자동으로 돌리게 합니다.

## 플라이휠 구조

제안자(proposer) 에이전트가 현재 훈련 중인 해결자(solver)의 롤아웃에서 새 RL 환경을 만들고, 해결자의 새 롤아웃이 다음 라운드를 이끕니다. 환경 생성을 터미널 과제로 만들면 프롬프트만으로 생성할 때보다 **유효 환경 비율이 최대 25배** 높아지고, 유효 환경당 비용은 **최대 75%** 낮아집니다.

## 결과

GPT-5.6-sol의 AutoEnvScaling 환경으로 Qwen3.5-35B-A3B를 훈련하면 Terminal-Bench 2.1 점수가 일치하는 Tmax 베이스라인보다 **4.3점** 높습니다. 더 나아가 한 모델이 환경 생성과 과제 해결을 모두 맡는 재귀적 자기 개선을 시도합니다. Qwen3.6-35B-A3B가 두 역할을 함께 수행했을 때 Terminal-Bench 2.1에서 **12.2점** 상승하고 Terminal-Bench 4.0 점수는 **1.6에서 3.2**로 올랐습니다. 파이프라인은 소프트웨어 공학, 컴퓨터 사용, 전문 업무, GPU 커널 프로그래밍으로 일반화됩니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 자기 생성 환경은 해결자가 이미 잘하는 영역에 편향되거나 검증기 허점을 학습할 위험이 있습니다. 환경 다양성, 난도 분포, 보상 해킹 여부와 라운드별 비용은 원문에서 확인해야 합니다.

## SW 엔지니어와의 관련성

- 에이전트 RL 데이터가 부족하다면 사람이 환경을 쓰기 전에, 실패 롤아웃을 환경 후보로 바꾸는 루프를 먼저 설계하세요.
- 환경 생성과 해결을 같은 모델이 맡기면 공진화 이점이 있지만, 검증기와 과제 요구사항을 외부에 고정해 붕괴를 막아야 합니다.
- "유효 환경당 비용"을 핵심 지표로 두면 생성량만 늘리는 낭비를 걸러낼 수 있습니다.
