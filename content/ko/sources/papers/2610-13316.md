# ThinkDrag: 시각 추론을 곁들인 의미론적 드래그 기반 이미지 편집

**Source**: Fortes 외, arXiv, 2026-10-09

**핵심**: 드래그 기반 편집(핸들 점을 타깃으로 끌기)은 직관적이지만 과소 명세되어 있다: 같은 변위도 부품 회전, 패치 이동, 장면 재구성 등 여러 의미를 가질 수 있는데 기존 방법은 드래그를 순수 기하 변위로 취급한다. ThinkDrag는 통합 멀티모달 모델 BAGEL 위에 드래그를 장면 의미로 해석하고—생성 전에 명시적 추론 트레이스를 낼 수도 있고—각 드래그를 드래그 끝점 마커(DEM)라는 학습된 핸들↔타깃 대응 신호로 고정한다. DragBench와 새 DragBench++에서 최고 수준의 생성 품질을 달성하고, 후자에서 사용자 선호 투표의 80%를 얻는다.

## 배경

드래그 편집은 DragGAN의 GAN 잠재 최적화에서 확산 모델의 테스트 시점 최적화(DragDiffusion, DragNoise, DragLoRA), 1단계 방법(FastDrag, GeoDrag), 비디오 유도 움직임의 피드포워드 조건부 생성(InstantDrag, LightningDrag)으로 발전했다. 모두 그럴듯함은 생성 prior에 의존하면서 드래그는 기하로 읽는다. 한편 통합 멀티모달 모델(BAGEL, Transfusion, Show-o)은 시각 이해와 생성을 하나의 틀에 묶는다—모호한 드래그에 정확히 필요한 것이다. 드래그를 실행하려면 객체가 무엇이고 어떻게 움직일 수 있는지 알아야 하기 때문이다. 그러나 통합 모델 라인은 공간 고정 조작에 맞게 조정된 적이 없었다.

## ThinkDrag: 데이터, 마커, 결합 모델링

**데이터셋.** 비디오 유도 지도는 기하적이고 잡음이 많다(옵티컬 플로우 실패, 카메라 움직임). 대신 MLLM 파이프라인으로 원본 영상을 합성하고(Qwen-Image, FLUX.2, Z-Image), 드래그 호환 편집 프롬프트를 제안해 FLUX.2로 타깃을 렌더링하고, MLLM 판정으로 걸러낸 뒤, Gemini 3 Pro로 의미론적 핸들→타깃 키포인트를 복원하고(DINOv3 + 육안 검증), Gemini 3 Flash로 추론 체인을 작성한다. 결과는 7K 원본에서 ~11K 쌍 → 양방향 ~22K 샘플(평균 2.15 드래그, 74% 멀티 드래그, 123단어 트레이스)이다.

**드래그 끝점 마커.** 각 드래그는 구조화된 텍스트 좌표 *더하기* 모든 층 이전에 핸들·타깃 VAE 토큰 위치에 주입되는 가산 마커 벡터 $\mathbf{m}_k = \mathbf{m}_{\mathrm{shared}} + \mathbf{e}_k$로 표현된다. 드래그당 하나의 마커를 공유하므로 타깃 위치가 핸들에 어텐션하도록 편향된다—DEM 적용 시 타깃→원본 어텐션 정점이 핸들에 찍히는 비율이 DragBench++ 드래그의 6%에서 51%로 오른다.

**결합 모델링.** 직접 모드는 멀티모달 프롬프트에서 편집 영상을 바로 생성하고, 추론 모드는 먼저 트레이스를 자기회귀 생성한 뒤($\mathcal{L}_{\mathrm{think}}$) 프롬프트(+트레이스) 조건부 rectified-flow 영상 생성을 한다. 10% 샘플의 텍스트 조건부 학습으로 결합 텍스트-드래그 제어도 가능해진다(텍스트는 모호성 해소, 드래그는 고정).

## 실험

**설정**: BAGEL 기반 LoRA 적응; DragBench(205 샘플)와 새 DragBench++(145 샘플, 샘플당 2.51 드래그, 평균 변위 108px, 의사 정답 참조 편집, 마스크 필요 기준선용 수동 마스크)에서 평가.

**벤치마크**: DragBench와 DragBench++; 지표는 MD(DIFT 점 추적), MD$_{\mathrm{MLLM}}$(GPT-5.5 추적, 의미 변화에 더 신뢰 가능), IF/IF*(입력/참조 대비 충실도), FID, 30명 사용자 연구.

**결과**:

| 벤치마크 | ThinkDrag (직접) | 최고 기준선 |
|-----------|-------------------|---------------|
| DragBench: IF / FID / MD | **0.918** / **30.05** / 28.84 | IF 0.900 (DragNoise); FID 38.90 (DragDiffusion); MD 22.77 (GeoDrag) |
| DragBench++: IF / IF* / MD / MD$_{\mathrm{MLLM}}$ | **0.875** / **0.905** / **47.66** / **34.24** | IF* 0.836 (LightningDrag); MD 48.36 (DragLoRA) |
| 사용자 연구 전체 선호 | **79.7%** (++), **61.0%** (DragBench) | 차순위 7.7% / 17.0% |

추론 모드는 IF*를 0.911까지 더 올리고(참조 프롬프트 시 0.914) 멀티 드래그 샘플의 56%에서 승리한다. DEM만으로 DragBench MD가 45.42에서 28.84로 감소한다. 주목할 점은 정답 참조 편집 자체도 DIFT-MD가 나쁘게 나와, MD$_{\mathrm{MLLM}}$이 더 의미론적인 지표임이 확인된다는 것이다.

## 소프트웨어 엔지니어를 위한 시사점

이식 가능한 아이디어 두 가지: (1) 모호한 공간 지시는 합성 *전에* 의미적으로 해소하라—명시적 추론 트레이스는 감사 가능하고 사용자가 다듬을 수 있는 산출물이 된다; (2) 좌표 텍스트만으로는 대규모 생성의 공간 고정이 부족하지만, 작은 학습 대응 신호(양 끝점에 같은 마커)를 더하면 공간 정밀도가 크게 오른다—토큰 기반 편집기라면 어디든 싸게 붙일 수 있다. 편집 기능을 출시한다면 DragBench++ 같은 참조 기반 벤치마크(정답이 여럿일 때는 그럴듯함의 닻이 필요)와 기존 트래커가 깨지는 곳에서의 MLLM 판정 공간 지표를 도입하라. 비용 참고: 추론 모드는 자기회귀 지연을 추가한다(H200에서 총 ~14초). 직접 모드만으로도 기준선을 넘는다.
