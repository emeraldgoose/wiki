# ForceHarness: 동결된 프런티어 모델을 위한 힘(Force)의 행동화와 물리

**Source**: [arXiv](https://arxiv.org/abs/2611.21099)
**게시일**: 2026-11-16

## Overview

프런티어 멀티모달 모델은 이제 이미지로부터 로봇을 제로샷으로 제어할 수 있지만, 많은 조작(manipulation) 작업은 이미지로는 보이지 않는 접촉 힘(contact force)에 달려 있다. API 전용 동결 모델에 힘을 도입하는 데에는 두 가지 어려움이 있다. 첫째, 접촉은 API 모델이 판단할 수 있는 속도보다 훨씬 빠르게 진화하므로 모델 아래에서 힘 루프를 닫아야 한다. 둘째, 동결 모델은 원시 힘 스트림을 해석할 수 없으므로 힘을 모델이 추론할 수 있는 형태로 반환해야 한다. ForceHarness는 시연이나 미세조정 없이 동결 모델이 힘을 사용할 수 있게 하는 하네스다.

ForceHarness는 세 층으로 구성된다. 모델 아래에서 힘 루프를 닫는 자기 종료(self-terminating) 힘 프리미티브(힘 보정·임피던스 제어·이벤트 기반 종료를 갖춘 스킬), 보정된 힘을 모델이 추론할 수 있는 물리량으로 바꾸는 물리 변환 계층(physics translation layer), 그리고 각 프리미티브 뒤에 모델을 호출해 실패에서 복구하게 하는 model-in-the-loop 프로토콜이다. 손목 힘/토크 센서가 없는 실제 Franka FR3 팔, Isaac Lab의 공개 ForceBench 스위트, MuJoCo의 새 벤치마크 HiddenPhys에서, ForceHarness를 쓴 동결 프런티어 모델은 수작업 전문가 제어기에 필적하고 시연으로 학습한 정책을 능가했다. 프로젝트 페이지: showlab.github.io/ForceHarness.

## Key points

- 실제 로봇(Franka FR3, 손목 F/T 센서 없이 관절 토크로 힘 추정): ForceHarness를 쓴 GPT-6 Astra가 여섯 가지 접촉 작업(화이트보드 닦기, 나사 조이기, 가지 껍질 벗기기, USB 삽입, 무게로 병 분류, 무른 것/단단한 것 구별)에서 0–1/10 → 8–10/10 성공으로 향상. GPT-6.1 Sol도 6–10/10으로 전이됐다. 모든 작업이 p<0.01로 유의(Fisher의 정확 검정).
- ForceBench(접촉이 풍부한 8개 Isaac Lab 작업, 평가기 유지, 처음 10개 시드): Astra와 Sol은 ForceHarness로 87.5%, Claude Fable 5.2는 75.0%에 도달해 최고의 학습된 정책(35.31%)을 상회. 힘의 짝지은 이득은 McNemar p=0.009/0.001로, 주로 Drawer Pull이 0/10 → 10/10이 된 덕분.
- HiddenPhys(새 벤치마크, 숨겨진 물리 변수 — 무게·무게중심·표면 강성 — 를 갖는 7개 MuJoCo 작업, 작업당 20개 테스트 시드): ForceHarness를 쓴 Astra와 Fable 모두 135/140, 손잡이 손상 0으로 수작업 전문가(136/140)에 필적. 학습된 정책들은 65–83/140에 손상이 잦았고, Diffusion Policy·π₀.₅·ForceVLA에 손목 힘을 추가해도 일관된 이득은 없었다.
- 하네스 내 힘의 효과: Astra 87/140 → 135/140, Fable 96/140 → 135/140로 테스트한 8개 OpenAI 모델 모두에서 일관됨. Astra는 손잡이 손상 0, 에피소드당 비용 45% 절감. 네 작업의 분포 이동에서도 ForceHarness 모델은 8%/5% 하락(69/80, 71/80)에 그친 반면 힘 없이 16–19%, 학습 정책은 17–25% 하락.
- 절제 실험: 자기 종료 프리미티브만(이벤트 워드, 힘 값 없음)으로도 Sol 성공률 0.63→0.77, 더 작은 모델 0.18→0.54로 향상되고 Lock 손잡이 손상이 22/25 → 3/25로 감소. 하네스가 계산한 L2 물리량은 소형 모델의 결정 정확도를 0.85로 끌어올려(raw 수치 대비 p=0.023) 힘 플롯(0.56)을 능가. 턴별 피드백은 91%에 도달한 반면 원샷 Code-as-Policies는 힘 인터페이스로 23%→77%.

## Details

- 아키텍처: (1) 자기 종료 힘 프리미티브 — 임피던스 제어, 리드(lead)로부터의 힘 추정, 접촉 이벤트, 백엔드별 상수를 갖춘 공유 루프; 접촉 만들기·힘 유지·찾기/안착·부하 하 회전·측정·회전·위치 이동 프리미티브 포함. (2) 물리 변환 계층 — 유지 하중·접촉·누르기/미끄러짐·삽입·당김·회전 물리량을 공통 레시피로 여러 렌더링 수준에서 제공하고 정확도를 분석. (3) model in the loop — 텍스트 이력과 최근 두 턴의 이미지로 각 프리미티브 뒤에 동결 모델을 호출.
- HiddenPhys 작업: Weight, CoM, Wipe, Stack, Peg, Latch, Lock. 채점에는 힘 손상 임계값을 넘는 손잡이 처리가 포함되며, 작업이 힘에 의존한다는 증거(위치 전용 제어기가 Wipe에서 49회 성공 → 0, Weight에서 50 → 25, 50 시드)가 보고됨. 학습 베이스라인: Diffusion Policy(작업별), π₀.₅·ForceVLA(멀티태스크), 각 200개 시연.
- 한계: 모델 질의가 프리미티브 사이에 수 초를 더해 반응적 조정을 불가능하게 하고, 고정된 프리미티브 메뉴는 새로운 운동 법칙을 제한하며, 절제 실험은 시뮬레이션에서만 수행됐다. 저자: Ke Sun, Kevin Yuchen Ma, Yike Zhang, Yanzhe Chen, Mike Zheng Shou (Show Lab, National University of Singapore).
