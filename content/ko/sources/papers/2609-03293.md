# PACE: 사용자 요청에 숨은 충돌을 드러내기

출처: Yoojin Kim 외 2인, arXiv:2609.03293, 2026-09-03. EMNLP 2026.

**핵심 요약**: 개인화 어시스턴트는 사용자 요청을 따를 뿐 아니라, 사용자 상황에 비추어 요청이 적절한지 판단해야 합니다. 기존 연구는 요청 수행 정확도에 치중하고, 충돌 탐지도 명시적으로 주어진 요소에만 의존했습니다. 이 논문은 **PACE(Personalized Assistants for Conflict Evaluation)** — 겉보기엔 합리적인 요청과 자아 중심 지식베이스를 묶어, 숨은 상황 팩트에서만 충돌 여부가 드러나게 한 데이터셋 — 를 제안합니다. 함께 제안된 **PaceMaker**는 질의 재구성·다중 홉 그래프 탐색·충돌 인식 필터링을 조합한 다중 에이전트 검색 프레임워크로, 근거 검색과 충돌 판단 정확도 모두에서 기존 방식을 일관되게 앞섭니다.

## 숨은 충돌이 어려운 이유

레스토랑 예약은 얼핏 평범해 보입니다 — 동행자의 새우 알레르기와 고정 메뉴라는 KB 사실이 드러나기 전까지는요. 결정적 근거는 원자적 KB 팩트들(질의당 금색 팩트 평균 **4.01개**, 인스턴스당 약 **2,035개** 팩트)에 분산되어 질의와 의미 유사도가 낮아, 표준 dense/sparse 검색은 주제상 유사한 방해 팩트에 묻힙니다. 데이터셋은 **3,249개 질의**, **185개 페르소나 프로필**, **376,448개 팩트**로 구성되며 상황 유형은 셋입니다.

| 상황 유형 | 제약의 원천 | 예시 |
|---|---|---|
| Temporal | 일정·이동 시간·루틴 | 워크숍+서류 수령 뒤 19:00 시험장 도착 불가 |
| Personal | 건강·가치·접근성 | 해산물 식당 vs. 동행자의 갑각류 알레르기 |
| State | 질의 시점의 외부 조건 | 단골 카페의 오후 라이브 공연 |

항상 거부하는 모델이 이득을 못 보도록 비충돌 사례도 포함됩니다. 합성된 타당성 라벨과 인간 판단의 일치율은 **93.3%**입니다.

## PaceMaker의 동작 방식

KB 위에 dense+sparse 인덱스와 k-NN 문서 그래프를 만들고 4단계를 거칩니다. (1) **충돌 인식 질의 계획** — 최대 3개의 충돌 진단 단서를 뽑고 잠재적 충돌을 겨냥한 반론 뷰를 생성, (2) **하이브리드 검색과 가중 융합**(반론 뷰 가중 상향)+사전 필터, (3) 시드 문서에서의 **다중 홉 BFS 탐색**으로 간접 연결 근거 표면화, (4) **충돌 인식 근거 선별** 후 답변 생성.

## 결과가 보여주는 것

| 설정 | 방법 | Pass율 | 충돌 Pass |
|---|---|---|---|
| Qwen3-4B / Qwen3-Embed-8B | Sparse / Dense / **PaceMaker** | 62.73 / 62.39 / **68.82** | 41.80 / 37.78 / **53.20** |
| GPT-5.4-mini | Sparse / Dense / **PaceMaker** | 65.53 / 62.63 / **75.35** | 40.28 / 33.88 / **59.17** |
| Gemini 3.1 Flash-Lite | Sparse / Dense / **PaceMaker** | 67.44 / 63.59 / **77.44** | 57.22 / 49.85 / **75.93** |

검색 없는 전체 KB 입력은 57.49%에 그쳐 — 필터 없는 컨텍스트가 충돌 추론을 해칩니다. 금색 근거 전체 확보가 부분 확보보다 명확히 유리하고, 제거 실험에서 다중 홉 탐색이 가장 중요합니다(제거 시 충돌 Pass 59.17→52.41). GraphRAG·HippoRAG 2 대비 충돌 질의에서 크게 앞서고(54.42 vs. 34.98/43.57) 전체 LLM 호출도 적습니다.

## 주의할 점

HTML 전문을 참조했으나 수치는 논문 표 기준입니다. 응답 품질 심사가 LLM(GPT-5.4-mini, 크라우드 워커와 93.5% 일치)이라 Pass율에 심사 편향이 스며 있습니다. 합성 페르소나 기준이라 실제 개인 KB로의 전이는 미검증이며, 타당성 판단만 평가하고 종단 과제 수행은 다루지 않습니다.

## SW 엔지니어와의 관련성

- 개인화 에이전트의 거부 품질은 검색 문제입니다. 질의와 닮은 게 아니라 틀릴 수 있는 것을 겨냥한 반론 질의를 계획하세요.
- 사용자 컨텍스트 통째 입력(57.49%)보다 표적 검색(68.82%)이 낫습니다 — 추론 전에 필터링하세요.
- 근거 완전성이 순위보다 중요합니다. 근거가 빠진 결정은 틀렸는데 확신에 찹니다. 커버리지를 측정하세요.
- 단계별 제거 실험(계획·탐색·선별)으로 투자처를 정하세요 — 여기서는 탐색이 지배적입니다.
