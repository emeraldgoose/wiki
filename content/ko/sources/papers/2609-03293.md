# PACE: Towards Surfacing Hidden Conflicts in User Requests

: Personalized assistants should not only comply with user requests but assess whether a request is appropriate given the user's circumstances. Prior work focuses on executing requests accurately and detects conflicts only from explicitly provided factors. This paper introduces **PACE (Personalized Assistants for Conflict Evaluation)**, a dataset where each seemingly reasonable request is paired with an egocentric knowledge base, and the conflict status emerges only from hidden situational facts. It also proposes **PaceMaker**, a multi-agent retrieval framework (query reformulation, multi-hop graph traversal, conflict-aware filtering) that consistently outperforms standard retrieval on both evidence retrieval and conflict-decision accuracy.

Why hidden conflicts are hard: A restaurant booking looks trivially executable — until the KB reveals the companion has a shellfish allergy and the venue has a fixed menu. The decisive evidence is distributed across atomic KB facts (avg. 4.01 gold facts per query, ~2,035 facts per instance) and is rarely semantically similar to the query itself, so standard dense/sparse retrieval drowns in topical distractors. Caveats: Full-text HTML was available and consulted, but all numbers above come from the reported tables; the response-quality judge is itself an LLM (GPT-5.4-mini, 93.5% agreement with crowd workers), so Pass rates inherit judge bias. Results are on synthetic personas — transfer to real personal KBs with noisier, messier facts is untested. The benchmark judges feasibility decisions, not end-to-end task execution.
