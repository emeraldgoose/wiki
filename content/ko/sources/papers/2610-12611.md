# SoftwareGym: 다양하게 합성한 소프트웨어 환경으로 컴퓨터 사용 에이전트 학습 확장하기

**Source**: Jin et al., arXiv, 2026-10-08

**핵심**: 컴퓨터 사용 에이전트(CUA)는 실행 가능한 소프트웨어와의 상호작용 데이터가 필요하지만, 네이티브 앱 통합은 비싸고(좁은 커버리지, 과적합 위험), 브라우저 기반 월드는 상호작용 깊이가 얕다. SoftwareGym은 합성 데스크톱 앱을 대규모로 설계·구현·GUI 검증하는 자동 멀티 에이전트 파이프라인이다. 12개 카테고리 182개 앱이 평균 GUI 통과율 91.5%에 도달했고, 그 궤적만으로 학습한 Qwen3.5-9B가 학습에 전혀 쓰지 않은 OSWorld에서 Pass@3 41.39%에서 56.97%로 상승했다.

## 배경

CUA 학습 데이터는 두 출처에서 오며 각각 결함이 있다. 네이티브 데스크톱/모바일 앱(OSWorld, Windows Agent Arena)은 현실적 상태와 복잡한 워크플로를 보존하지만, 앱마다 통합 비용이 커 커버리지가 좁고 고정 풀에 과적합된다. 브라우저 기반 합성 월드(InfiniteWeb, GUI-GENESIS)는 확장과 상태 제어가 쉽지만 단일 브라우저/DOM 기판에 갇혀 워크플로 깊이가 제한된다.

SoftwareGym은 세 요구사항을 함께 노린다: 인터페이스/상호작용 다양성(일반화용), 기능 신뢰성(유효한 다단계 궤적), 확장성(최소 인간 입력으로 배치 합성).

## SoftwareGym 파이프라인

세 단계, 각 단계는 전문화된 에이전트가 담당(Codex CLI + GPT-5.5로 구축, Ubuntu VM에서 Seed 2.1 Pro로 평가):

1. **소프트웨어 설계**: FunctionDesigner가 최소 입력을 기능 명세(사용자, 객체, 연산, 종단 간 워크플로, 승인 체크포인트)로 확장. StyleDesigner가 변형별 Avalonia UI 청사진을 만들되 최소 두 레이아웃 차원에서 다르도록 강제(트리 편집 거리 검사)하고 스타일별 SVG 아이콘 자산 생성.
2. **구현 + 소스 검증**: Coder가 설계 패키지로 전체 앱 구축; DevCoder가 기능 매뉴얼 기준으로 명령 바인딩, 로직, 영속성, 시작 동작을 감사.
3. **GUI 평가 + 수리**: EvalTaskGenerateAgent가 체크포인트 기반 GUI 테스트 작성(v1 후 고정); GUIAgent가 마우스/키보드로 실행(케이스당 최대 50 스텝). 실패는 국소 수리로 되돌아가며, 시각 충실도 점수가 의도된 인터페이스 이탈을 방지. 소스와 GUI 검증을 모두 통과한 앱만 라이브러리에 등록.

**태스크 합성**은 GUI 검증된 기능(근거 기반 기능 트리)만 레벨별 태스크(쉬움/보통/어려움 × 파일 기반/빈 상태)로 변환하고 프로그램 방식 결과 검사를 붙인다—SoftwareGym-Bench(120개 태스크, 카테고리당 10개) 구성.

## 실험

**설정**: 12개 카테고리 182개 합성 앱. SoftwareGym 궤적만으로 Qwen3.5-9B 멀티모달 SFT. 평가: OSWorld(244개 태스크, 8개 도메인, OSWorld 학습 데이터 제로)와 SoftwareGym-Bench; 태스크당 3 롤아웃, 100 스텝 예산, Pass@3.

**벤치마크**: OSWorld Pass@3, SoftwareGym-Bench Pass@3, GUI 태스크 통과율, 청사진 다양성(정규화 트리 편집 거리).

**결과**:

| 결과 | 수치 |
|--------|--------|
| OSWorld 전체(베이스 → 학습) | Pass@3 41.39% → 56.97%(+15.58%p), 전 도메인 향상, OSWorld 데이터 미사용 |
| SoftwareGym-Bench(베이스 → 학습) | Pass@3 25.8% → 40.0%, Qwen3.7-Plus와 대형 특화 CUA 다수 상회 |
| 수리 라운드별 GUI 신뢰성 | v1 54.9% → v2 81.1% → v3 91.5% 평균 통과율 |
| 스타일 다양성(전체 vs 단순 설계) | 매크로 평균 4.9 → 83.6 |
| GUI 유도 vs 소스 한정 수리 | 동일 50.4% 출발 → 83.1% vs 48.8% |
| 앱당 합성 비용(20개 표본) | ~237분, 1480만 토큰, 1718 호출, ~$70.76 |
| SoftwareGym + OSWorld 데이터 결합 | SoftwareGym-Bench 47.5%(중복이 아닌 보완) |

## 소프트웨어 엔지니어를 위한 시사점

- **합성 환경을 학습 데이터로**: 실제 앱 통합이 병목일 때 검증된 합성 앱이 전이 가능한 지도 신호 제공—학습에 쓰지 않은 실제 앱(OSWorld)까지 이득 전이
- **코드가 아니라 동작을 검증**: 소스 수준 검사는 ~49%에서 정체; GUI 실행 체크포인트 테스트만이 신뢰성을 91.5%로 견인—UI 자동화 테스트 전반에 통하는 패턴
- **다양성은 기대가 아니라 강제**: 무제약 생성은 유사 레이아웃으로 수렴; 명시적 쌍별 거리 제약(2개 이상 레이아웃 차원 상이)이 다양성 17배 향상
- **근거 기반 태스크 생성**: 통과한 GUI 근거가 있는 기능에서만 평가 태스크 합성, 그렇지 않으면 미구현 동작을 테스트하게 됨
- **비용 모델**: 검증된 앱당 ~$71, ~4시간—사설 CUA 학습 풀 구축 예산 산정 가능
