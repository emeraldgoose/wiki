# 하나의 모델로 전부 루프하기: 언어 모델의 탄성 잠재 재귀

**Source**: Ladhak 외, arXiv, 2026-10-08

**핵심**: 잠재 재귀(루프) 언어 모델은 공유 층 블록을 반복 적용하므로 하나의 체크포인트로 루프 수에 따라 추론 연산과 정확도를 교환할 수 있다—하지만 1회 루프에서는 같은 크기 비재귀 모델에 뒤지는 경우(*1회 루프 세금*)가 잦아, 지연 민감 구간에서는 별도 dense 모델이 낫다. 탄성 잠재 재귀(ELR)는 세금을 없애는 훈련 레시피다: 1회 루프에서는 고유 층을 정확히 한 번씩 실행해 베이스라인 동등 정확도를 내고, 루프를 추가할 때마다 정확도가 오른다. 세 가지 선택이 이를 만든다—게이트 적응 델타 상태 업데이트, 옵티마이저 스텝 *내* 루프 수 혼합, 패스별 루프 인덱스/예산 조건화—여기에 비용 통제(지연 혼합 깊이 훈련, 교차 루프 경로 재생, 최종 루프 KV 캐싱)와 후훈련 증명 모델 Koi-4B가 더해진다.

## 배경

탄성 깊이(여러 깊이로 서빙되는 하나의 체크포인트)는 배포에 매력적이다: 루프 수는 chain-of-thought처럼 품질–연산 노브가 되지만 추가 토큰을 생성하지 않는다. 기존 루프 모델(Huginn, Parcae, Ouro)은 1회 루프 세금을 낸다—예: Huginn은 800B 토큰 후에도 ARC-Easy에서 베이스라인 46.4 대 34.9—작은 루프 범위나 1회 루프 샘플 확률 상향만으로는 세금이 안 없어진다. 스텝마다 루프 수 하나를 샘플하는 방식(Huginn의 locked-step)은 1회 루프를 1/3 확률로 뽑아도 1회 루프 끝점을 보존하지 못한다.

## ELR 레시피

백본을 입력·공유 재귀(약 중간 절반 층)·출력 블록으로 나누어, 1회 루프에서는 고유 층이 정확히 한 번씩 실행되어 파라미터·연산이 베이스라인과 같다. (1) **적응 델타 업데이트**: 재귀 블록 출력으로 상태를 대체하는 대신, 제안된 수정 방향으로 학습된 토큰·채널별 스텝 크기의 게이트 스텝을 밟는다(0 초기화, 초기값 ~0.35). (2) **1회 루프 랭크 오버라이드를 곁들인 혼합 깊이 훈련**: 루프 수를 균일 샘플하되, 회전하는 일부 데이터 병렬 랭크는 매 마이크로배치마다 1회 루프를 강제 실행해, 1회 루프와 깊은 그래디언트가 같은 옵티마이저 업데이트를 공유한다(1회 루프 확률 ~1/3). (3) **루프 조건화 변조**: 각 패스를 진행률 $\tau_i = i/k$와 예산 $\kappa = k/K$에 조건화한다(AdaLN/FiLM식 스케일·시프트, 저랭크 보정, 출구 게이팅)—0 초기화라 graft 시점에 체크포인트가 정확히 보존된다.

비용 통제: **지연 혼합 깊이 훈련**(앞 75%는 1회 루프, 마지막 1/4만 혼합 깊이: 베이스라인 대비 훈련 FLOPs ~1.16배, 전체 혼합의 1.62배 대비), MoE용 **교차 루프 경로 재생**(첫 루프 라우터 배정을 뒤 루프에 재사용: 혼합 깊이 업데이트 시간 −11.7%, 정확도 변화 없음), 추론 시 **최종 루프 KV 캐싱**(루프당 덮어쓰는 공유 캐시 하나: 어텐션 KV 메모리가 전 루프 수에서 1회 루프 수준 유지, 다중 루프 이득 대부분 보존).

## 실험

**설정**: GDP-Hybrid-4B dense(1T 토큰, AdamW)와 GDP-Hybrid-30B-A3B MoE(300B 토큰), 동일 데이터·토큰 예산의 매칭 비재귀 베이스라인과 비교, 지연 스케줄 $k \in \{1..4\}$, 오버라이드 10%($p_1 = 0.325$). 10개 과업 평균(MMLU, MMLU-Pro, ARC-C, GSM8K, WinoGrande, CSQA, RACE-high, HumanEval, MBPP, MATH-500). Koi-4B: 7T 토큰 + 256K 문맥 중간 훈련 + SFT/RLVR 후훈련에 전체 레시피 적용, 저자 하네스에서 Artificial Analysis Intelligence Index v4.1 스위트로 평가.

**결과**:

| 모델 | 1회 루프 대 베이스라인 (10과업 평균) | 1→4 루프 이득 |
|-------|-----------------------------------|----------------|
| GDP-Hybrid-4B ELR (65.13) | 65.65 대비 −0.52pp | +7.25pp |
| GDP-Hybrid-30B-A3B ELR (66.08) | 65.04 대비 +1.04pp | +4.75pp |

이득 대부분이 일찍 온다: 2회 루프가 1→4 개선분의 79–87%를 차지한다. 4회 루프 지연은 베이스라인 대비 TTFT 2.33배·디코드 2.06배이며, 3회 루프가 이득의 96%를 TTFT 1.87배에 달성한다. Koi-4B의 AA-Index 추정치는 $k = 1..4$에서 18 → 26 → 28 → 29로 오르고(1회 루프 ≈ Qwen3.5-4B, 4회 루프는 ~6.5배 큰 모델을 +3으로 앞섬), 루프가 늘수록 오히려 *짧게* 생성한다(출력 토큰 −21.8%/−29.5%/−32.7%): 잠재 깊이가 chain-of-thought 토큰을 대체하므로 2회 루프의 롤아웃당 디코드 시간 증가는 ~6%에 그친다. 최종 루프 KV 캐싱 비용은 4회 루프에서 벤치마크당 0–3pp다(KV 메모리 2.5배 → 1배: 128K 토큰 요청당 7.5 → 3.0 GiB). 0.5B 모델 ablation 결과 각 선택이 확인된다: 독립 랭크 혼합이 동기 샘플링보다 낫지만 스텝 시간 36% 증가(오버라이드가 일부 회수), 조건화는 추가 루프마다 손실을 낮추고 지연 스케줄을 처음부터의 혼합 깊이 훈련보다 낫게 만든다.

## 소프트웨어 엔지니어를 위한 시사점

ELR은 서빙 팀에 단일 체크포인트 다층화 이야기를 준다: 4B 아티팩트 하나로 지연 민감 트래픽은 1회 루프, 품질 민감 트래픽은 2–4회 루프에 서빙하고, KV 메모리는 일정하며, 짧아진 생성 덕에 2회 루프의 롤아웃당 비용은 거의 일정하다. 루프 수는 추가 토큰을 내뿜지 않는 reasoning-effort 다이얼처럼 동작한다—출력 토큰 예산이나 스트리밍 지연이 지배적인 곳에 유용하다. 훈련 측면에서는 지연 스케줄(추가 FLOPs ~16%)과 경로 재생으로 탄성을 싸게 개조할 수 있고, 0 초기화 grafting 기법이 일반화된다: 훈련된 체크포인트에 새 조건화를 추가하되 day-zero 동작은 비트 단위로 동일하게 한 뒤, 벗어남을 학습시킨다. 실무자가 유의할 열린 문제: 루프 2 이후 수확 체감, 요청별 적응 깊이(요청당 고정 루프 수 대비)는 향후 과제다.
