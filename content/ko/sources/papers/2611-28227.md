# 잠재 피드백 트랜스포머를 위한 추측 디코딩, Feedback Shortcut

**원문**: [arXiv:2611.28227](https://arxiv.org/abs/2611.28227) · **게시일**: 2026-11-20 (v1)
**저자**: Benhao Huang, Xuezhe Ma, Hector Liu

## 개요

잠재 피드백 트랜스포머(latent feedback Transformer)는 위치 t의 입력을 토큰 임베딩에 이전 위치의 최상위 은닉 상태를 사영한 것을 더한 형태(u_t = e_t + W·RMSNorm(h_{t-1}))로 만든다. 이 순환 구조 덕분에 같은 메모리 비용의 일반 트랜스포머보다 성능이 높지만, 추측 디코딩(speculative decoding)이 깨진다. 초안 토큰을 검증하려면 앞 위치의 실제 최상위 상태가 필요한데, 병렬 검증 패스에서는 근사 stand-in만 쓸 수 있기 때문이다. 모델이 stand-in에 적응하도록 학습시키면 exact 디코딩의 품질 천장이 낮아질 수 있고, 추론 시에만 stand-in을 쓰면 근사 오차가 추가된다.

Feedback Shortcut은 기반 모델 학습을 건드리지 않고 두 병목을 따로 해결한다. 첫째, State alignment는 MTP(multi-token prediction) 헤드 상태를 초안 위치에 들어갈 stand-in a_{t+k}로 사영하는 경량 프로젝션 P를 학습한다. 학습 중 in-place substitution(각 위치의 윈도우가 해당 위치를 0.75 확률로 넘어가게 확장)으로 처리한다. 둘째, Pipelined correction은 대기 중인 각 초안을 선행 위치의 새로 계산된 상태(실제 피드백에 훨씬 가까운 프록시)로 후속 초안의 검증 패스 안에서 다시 평가해, 보정에 추가 모델 호출이 전혀 들지 않는다. 초안은 커밋된 토큰과 일치하고 상태가 D회 이상 보정된 경우에만 커밋되며, 대기 위치는 최대 (K+1)(D+1)개 슬라이딩 윈도우만 유지하므로 메모리와 배치 크기는 거의 변하지 않는다.

## 핵심 내용

- 설정: 135M·780M 파라미터의 잠재 피드백 트랜스포머에 K=3 MTP 헤드, Dolma 3 한 에폭(135M은 13.4B 토큰, 780M은 77.8B 토큰), 3개 시드로 학습. 품질은 bits per byte(BPB, 낮을수록 좋음)를 Paloma 7개 하위 집합에서 평균하고, 속도는 배치 서빙 엔진의 정상 상태 처리량으로 측정.
- 배치 크기 1에서의 제공 품질(Table 1, D=1): 135M에서 일반 트랜스포머는 Paloma BPB 1.0065에 2.49배 속도, exact 잠재 피드백은 0.9950(학습 FLOPs 1.10배)이고 Feedback Shortcut은 1.13배 FLOPs로 0.9951을 2.36배 속도로 제공한다. 780M에서는 트랜스포머 0.8379/2.93배, exact 피드백 0.8288(1.17배), Feedback Shortcut 0.8287를 1.19배 FLOPs로 2.75배 속도 — exact 디코딩 천장과 1e-4 BPB 이내다.
-순효과: exact 잠재 피드백 대비 약 2%의 추가 학습 계산만으로 2.4~2.8배 디코딩 가속. 배치 크기가 클 때는 보정을 아예 건너뛰어도 트랜스포머 수준의 속도를 유지하면서 잠재 피드백 이득의 80% 이상을 지킨다.
- 프로젝션 P는 작다: 135M에서 3.7M, 780M에서 14.9M 파라미터(은닉 폭 2048/4096, 학습 스케일 없는 RMSNorm).
- Spec-Bench 480개 질문의 단일 요청 타이밍(그리디/샘플링): D=1에서 모든 태스크가 그리디 대비 속도 저하 0.15배 이내이며, 두 규모 모두 약 2.40~2.45배(135M에서 2.45 ± 0.02배 등). 일반 트랜스포머는 정확히 검증하므로 보정이 필요 없다.
- 메커니즘: 보정은 학습에 쓰인 것과 같은 고정점 업데이트(u_j = e(x_j) + W·RMSNorm(h_{j-1}))를 반복한다. D=0은 보정 없는 검증, D=∞는 exact 디코딩이며, 각 호출은 최소 한 토큰을 커밋한다.

## Details

두 실패 모드를 의도적으로 분리한다. State alignment는 학습 시점의 천장 하락을 없애고(기반 모델은 stand-in으로 학습되지 않고 P만 학습), Pipelined correction은 추론 시점의 근사 오차를 없앤다. 이미 존재하는 호출 위에서 stand-in을 갓 계산된 상태로 승격하기 때문이다. 부록에는 학습/평가 세부사항, 단일 요청 타이밍과 1,024 토큰 생성, 초안 품질과 가독성, 추측 디코딩이 실제로 제공하는 품질 등이 담겨 있다. 코드는 https://github.com/ifm-ai/LoRM 에 공개.
