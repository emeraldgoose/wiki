# From Repositories to Training Environments: Environment Evolution Loop로 장기 지평 코딩 에이전트 확장하기

**Source**: [arXiv](https://arxiv.org/abs/2611.21152)
**게시일**: 2026-11-17

## Overview

장기 지평(long-horizon) 작업을 위한 코딩 에이전트 학습에는 검증 가능한 피드백을 제공하는 환경이 필요하다. 기존 파이프라인은 검증으로 끝나는 선형 과정이라 사용 가능성은 보장하지만 학습 가치를 높이는 방향의 안내는 거의 없고, 재귀적 자기 개선(RSI)은 비용이 큰 모델 롤아웃과 다운스트림 평가가 필요해 장기 지평 작업에서 피드백 지연이 증폭된다. RepoFactory는 실제 저장소를 검증 가능한 환경으로 바꾸는 자동화 파이프라인으로, 에이전트가 언어 명세만 주어진 상태에서 완전한 프로젝트를 처음부터 빌드하게 한다. Environment Evolution Loop는 검증과 코드 분석에서 얻는 시기적절하고 저렴한 프록시 피드백으로 유효성(validity), 구조적 결합(structural coupling), 구현 범위(implementation scope)를 결합한 곱셈 목적함수를 최적화하며, 오라클 구현·과제 명세·테스트를 함께 수정한다.

RepoFactory는 17개 소프트웨어 도메인에 걸친 10,159개의 환경을 생성한다(모든 구성 에이전트는 Qwen3.8-Max 사용). 이 환경으로 Qwen3.5-35B-A3B를 학습한 RepoHorizen-35B-A3B는 NL2Repo-Bench에서 22.6점(23.8 → 46.4), 실제 프로덕션 장기 지평 코딩·에이전트 작업의 다섯 벤치마크 평균에서 8.5점 향상을 보였으며, environment evolution이 없을 때보다 각각 17.5점, 6.4점 향상이다.

## Key points

- NL2Repo: 23.8 → 46.4(+22.6)로 200B 미만 오픈웨이트 모델 중 최고 성능. GPT-5.5(45.1), Gemini-3.1 Pro(33.4), DeepSeek-V4-Pro(38.5), MiniMax-M3(42.1)를 능가. Terminal-Bench 2.1의 이슈 해결·교차 도메인 장기 지평 작업에서도 1.3–6.8점 향상.
- Environment evolution은 evolution 없는 변형 대비 NL2Repo에서 5.1점, 평균 2.1점을 추가로 올려 프록시 지표가 evolution 안내에 유효함을 뒷받침한다.
- 스케일링: 23.8%(RepoFactory 데이터 없음)에서 5,577개 환경의 46.4%까지 꾸준히 향상되며, 3,000개를 넘으면 이득이 더 커지고(36.5% → 46.4%) 테스트한 최대 규모에서도 포화 증거는 없다.
- 모델 크기: 9B, 27B, 35B-A3B에서 NL2Repo 12.2–22.6점 향상. 27B가 더 높은 베이스라인을 가짐에도 35B-A3B가 가장 큰 이득을 보여, 초기 성능이 높다고 학습 이득이 큰 것은 아니다.
- 17개 소프트웨어 도메인의 10,159개 환경으로 Python 생태계 커버리지와 학습 궤적의 개발 연산을 다룬다. 구성 비용은 저장소 검색·필터링, 런타임 구성, 과제 합성 및 테스트 materialization에 집중된다.

## Details

- 파이프라인: 저장소 검색·필터링 → 런타임 구성 및 저장소 분석 → 과제 합성 및 환경 materialization, 이를 닫는 Environment Evolution Loop가 곱셈 목적함수(유효성 × 구조적 결합 × 구현 범위)에 대해 오라클 구현·과제 명세·테스트를 수정한다.
- 학습: Qwen3.5-35B-A3B를 필터링·정제된 궤적으로 SFT(궤적 필터링·하이퍼파라미터는 Appendix A). 벤치마크는 NL2Repo-Bench, Terminal-Bench 2.1 및 장기 지평 코딩/에이전트 벤치마크 세 가지를 포함한다.
