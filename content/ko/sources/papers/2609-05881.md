# Broken on Arrival: 공개 레지스트리 양자화 LLM 아티팩트의 비기능성과 포착 방법

출처: Aditi Patodiya, arXiv:2609.05881, 2026-10-25.

**핵심 요약**: 개발자는 공개 레지스트리에서 양자화 LLM을 내려받아 로컬에서 실행하지만, 조사한 레지스트리 어느 곳도 파일의 **기능 테스트**를 문서화하지 않았습니다. Ollama 공식 라이브러리의 15개 모델 라인에서 코드 가능한 GGUF 태그 305개와 Hugging Face 커뮤니티 파일 22개를 감사한 결과, 15개 문제 코드 스크리닝으로 의심 파일을 골라낸 뒤 164개 HumanEval+ 문제로 재검사했을 때 **공식 태그 7개(2.3%)가 최대 6문제만 해결**했습니다. 모두 40억 매개변수 이하 모델의 저비트 양자화였습니다. 원본 가중치에서 다시 빌드한 5개 의심 파일이 레지스트리 파일과 **텐서 단위로 일치**해 파일 손상은 없었고, 재현 가능성 자체가 기능성을 보장하지 않는다는 뜻이었습니다. 가중치·도구 체인·텐서 구성을 고정한 뒤 **importance matrix를 추가**하면 Qwen2.5-Coder-3B 점수가 세 양자화 수준에서 0에서 76–113/164로 올랐지만, 같은 비보정 레시피는 더 작은 Qwen2.5-Coder-1.5B를 functionality하게 두었습니다. 스크리닝을 통과한 66개 표본 태그 중 비기능 파일은 없었습니다. 저자는 감사 데이터와 `quantcheck` 도구를 공개하고, 저비트 태그는 출판 전 스크리닝한 뒤 실패를 보정하거나 철회할 것을 권합니다.

## 핵심 내용

- 조사한 레지스트리는 양자화 파일에 대한 기능 테스트를 문서화하지 않았다.
- 7개 공식 저비트 양자화 태그(2.3%)가 HumanEval+ 164문제 중 최대 6문제만 해결했다.
- 재빌드 의심 파일이 레지스트리 텐서와 일치해 파일 손상이 원인이 아니었다.
- importance matrix를 추가하면 Qwen2.5-Coder-3B가 세 양자화 수준에서 0에서 76–113/164로 올랐다.
- v3 개정은 한 커뮤니티 파일 쌍의 실패가 백엔드가 아니라 챗 템플릿 누락 때문임을 명확히 했다.

## 상세

15문제 코드 스크리닝 뒤 전체 164문제 HumanEval+로 재검사하는 2단계 구조입니다. 의심 공식 태그는 모두 40억 매개변수 이하 모델의 저비트 양자화였습니다. 통제된 재빌드는 레지스트리 파일과 새로 빌드한 파일의 텐서 단위 일치를 보여, 실패 원인이 파일 손상이 아니라 모델 크기에 따라 달라지는 보정되지 않은 레시피일 가능성을 시사합니다. 스크리닝을 통과한 66개 표본 태그에 비기능 파일이 없어 스크리닝의 위음성 위험이 제한적임을 보입니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 정확한 레시피 세부와 레지스트리별 차이는 원문을 함께 확인해야 합니다.

## SW 엔지니어와의 관련성

- 배포 전 양자화 파일은 크기만 믿지 말고 실제 태스크로 기능 스크리닝하세요.
- 텐서 일치 여부는 정확성 검사가 아니라 무결성 검사에 불과합니다.
- importance matrix 같은 보정 단계는 작은 모델과 큰 모델에 다르게 작동할 수 있습니다.
