# InstantFusion: 이종 이미지 생성기를 위한 공유 잠재 인터페이스

**Source**: Dai 외, arXiv, 2026-10-09

**핵심**: 최신 이미지 생성기는 잠재·아키텍처·학습법이 제각각인 고립 시스템으로 배포된다. 저자들은 독립 학습 모델 간 부분 호환성을 발견했다—유사한 잠재 공간 구조와, 정렬 없이 중간 디노이징 상태를 넘겨도 거친 레이아웃이 유지된다는 점이다. InstantFusion는 이를 재사용 인터페이스로 만든다: 동결된 각 생성기에 경량 모델별 잠재 오토인코더(LAE)를 달아 중간 상태를 공유 공간에 매핑하고 되돌리며, 상태와 디노이징 속도 모두 정렬해 모델 쌍별 매핑 없이 궤적 중간에 모델을 전환한다.

## 배경

기존 교차 모델 잠재 정렬은 모델 쌍별 고립 상태 매핑에 그치고 디노이징 궤적 진화는 다루지 않으며, 궤적 스티칭은 동일 잠재 공간을 가정한다. 이종 잠재 공간 간 디노이징 궤적 전이는 미해결 문제였다. InstantFusion의 전제는 상태 대응만으로 부족하고, 번역된 상태가 수신자의 디노이징 동역학을 따라야 한다는 것이다.

## 방법: LAE와 동역학 정렬

$M \geq 2$개 동결 생성기(공유 VAE)에 시간 조건 컨볼루션 LAE를 장착한다: $z_t^m = E_m(x_t, t)$, $\tilde{x}_t^m = D_m(z_t^m, t)$. 동일 이미지·동일 노이즈 수준의 쌍 상태로 $\mathcal{L} = \mathcal{L}_{rec} + \mathcal{L}_{align} + \lambda_{reg}\mathcal{L}_{reg} + \lambda_{dyn}\mathcal{L}_{dyn}$를 학습한다—쌍별 상태 정렬, 자명 붕괴 방지용 재구성, 노름 일관성, 1스텝 변위(속도) 정렬(없으면 UMAP 변위 클러스터가 분리된 채 남는다). 추론 시 송신 상태는 $x_{t_k}^{A\to B} = D_B(E_A(x_{t_k}^A, t_k), t_k)$로 번역되고, 송신자의 예측 클린 잠재가 단계 간 안정화되면 적응 기준으로 핸드오프한다—쌍별 튜닝 불필요, 신규 모델은 자체 LAE로 합류.

## 실험

**설정**: SD3·FLUX.1·Qwen-Image(가속용 Z-Image-Turbo·FLUX.2-Klein 추가), 백본 동결 50k VisPrompt 쌍으로 LAE 학습, 지표 GenEval-v2·CVTG-2K·HPSv2·OneIG-Bench·PSNR/SSIM/LPIPS.

**결과**:

| 설정 | 결과 |
|---------|---------|
| 재구성(왕복 1회) | PSNR >31dB, SSIM >0.94, LPIPS ~0.03–0.04 |
| 교차 모델 전이(Qwen→SD3 / Qwen→FLUX.1) | GenEval-v2 +12.92 → 35.06 / +13.68 → 36.54, CVTG-2K +0.28 / +0.18 |
| 가속 | Qwen-Image 18.84초 → 4.37초(Z-Image-Turbo 혼합) / 2.55초(FLUX.2-Klein), +DiCache 10.64초 → 5.70초 동등 품질 |
| 교차 아키텍처 on-policy 증류(Qwen→SD3) | HPSv2 26.27 → 26.46, $\mathcal{L}_{dyn}$ 제거 시 학습 발산 |
| 다중 선호 조합 | GenEval+HPSv2 전문가 30.97 / 30.68로 공동 다중 보상 GRPO에 근접, 공동 학습 불필요 |
| 3단계 롤아웃 순열 | 6개 모델 순서 전부 안정 |

핸드오프는 디노이저 추가 호출 없이 잠재만 번역하므로 이론적 NFE가 늘지 않는다. 한계: 공유 오토인코더와 호환 시간 파라미터화가 필요하고, 혼합 추론 시 다중 백본을 동시 상주시킨다.

## 소프트웨어 엔지니어를 위한 시사점

생성 모델의 조합 배포 패턴을 시사한다:

- **강점별 디노이징 라우팅**: 빠른 모델이 초반을 그리고 강한 모델이 마무리(또는 역)하게 해 수 배 지연 단축과 두 자릿수 벤치 향상을 함께 노려라.
- **공동 재학습 없이 전문가 조합**: 비싼 다목적 학습 대신 공유 공간 경유로 단일 보상 전문가들을 합쳐라.
- **상태가 아닌 동역학까지 정렬**: 모델을 이을 땐 1스텝 속도도 맞춰라—정적 잠재 브리지는 on-policy 사용에서 발산한다.
- **다중 백본 서빙 예산**: 혼합은 참여 모델 전부 상주를 요구하므로 모델 오프로딩·단계적 호스팅과 병행하라.
