# Institutional Newspapers Pipeline: Deriving Billions of High-Quality Tokens from Historical Newspapers

: Historical newspapers are an abundant record of public life, but their dense, irregular, sometimes noisy layouts make computational access both hard and limited. This paper presents a modular system built jointly with the **Boston Public Library** that extracted a structured dataset from historical scans, architected so every step stays interpretable and customizable and so the whole pipeline runs on **workstation-class hardware**. The released OCR output is **16.3 billion o200k_base tokens across 83.1 million individual crops, from 1,473,635 public-domain scans published between 1795 and 1930**. The novelty is less the scale than the architecture: interpretable, replaceable stages, each backed by a small trained model, with per-crop reading order, type classification, NER, subject classification, language detection, and pre-computed embeddings.

The problem with newspaper scans: Newspapers are one of the richest public records of how societies actually lived, but they are hostile to computational access:

- Dense and irregular layouts — multi-column stories, boxes, advertisements interleaved with articles
- Noisy — fading, bleed-through, stains, warping, torn folds
- Long-tail typography — historical fonts, ligatures, and typefaces that modern OCR rarely handles

Naive whole-page OCR produces a wall of interleaved text with no idea which column belongs to which article.

Architecture: interpretable, modular, frugal: The design goals, stated plainly, are the interesting part of the paper:

1. Each step interpretable and customizable — you can inspect and swap any stage
2. Computationally frugal — runs on workstation hardware, not a cluster
3. Modular — designed jointly with a real institution (BPL), so the interfaces reflect what an actual archive needs

The processing chain: Every crop is pushed through the full chain:

1. Segmentation into type-agnostic crops
2. OCR on each crop
3. Text analysis on the resulting text
4. Type classification — what kind of content is this crop (article, ad, obituary, editorial, etc.)
5. Reading order detection — where does this crop sit in the page's sequence
6. Named entity recognition
7. Subject classification — what is this about
8. Language detection
9. Pre-computed embedding generation

16.3B tokens is a serious pretraining or retrieval corpus. What makes it more useful than a raw dump is that each of the 83.1M crops carries type, reading order, NER, subject, language, and an embedding — so you can query by structure and meaning, not just string match.
