# T1: 장기 터미널 에이전트를 위한 강화학습 (Terminal Agent Reinforcement Learning for Long-Horizon Tasks)

**저자**: Junyao Yang, Yucheng Shi, Zhongzhi Li, Ruhan Wang, Zongxia Li, Haitao Mi, Leowei Liang · **발행일**: 2026년 9월 10일 · **arXiv**: [2609.11042](https://arxiv.org/abs/2609.11042) · **HuggingFace**: [https://huggingface.co/papers/2609.11042](https://huggingface.co/papers/2609.11042)

## 초록 (Abstract)

자율 AI 에이전트의 활용 영역이 코딩 및 과학적 탐구와 같은 장기(Long-Horizon) 과제로 이동하고 있으며, 그중에서도 터미널 환경을 다루는 과제는 매우 중요합니다. 본 논문에서는 강화학습(RL)으로 훈련된 총 1,220억(122B) 매개변수 규모의 Mixture-of-Experts(MoE) 모델인 **T1**을 소개합니다. T1은 클라우드 샌드박스 내부의 실제 쉘(Shell) 환경에서 과제당 최대 300회 이상의 도구 호출(Tool-Call) 턴을 수행하며, 각 과제 자체의 검증기(Verifier) 실행 결과에 의해 보상을 받습니다.

본 논문은 다음과 같은 포괄적인 RL 훈련 레시피를 제공합니다:
1. **강력한 워밍스타트(Warm-Start)**를 통해 액터-크리틱(Actor-Critic) 훈련을 안정화하고, 통과된 검증기의 절대 수에 따라 궤적을 평가하는 조밀한 프로세스 보상(Dense Process Reward)을 적용합니다.
2. **TITO(Turn-by-Turn Exact Token Identifier)** 구조를 통해 턴 경계에서의 드레이프 보정과 정확히 샘플링된 토큰 ID 기반 훈련을 수행하며, **롤아웃 라우팅 리플레이($R^3$)**를 도입하여 샘플러의 매 MoE 레이어별 토큰당 전문가 선택을 기록하고 훈련 중 이를 그대로 재현하여 안정적인 최적화를 달성합니다.
3. **완전한 분포 외(Out-of-Distribution) 훈련 코퍼스**: Terminal-Bench 2.1과 완전히 분리된 격리된 시드 및 합성 과제를 사용하여 벤치마크 오버피팅이 아닌 진정한 능력 전이를 보장합니다.

TITO와 $R^3$의 결합을 통해 훈련-추론 간 로그 확률 오차를 0.021에서 0.013으로 단축시켰으며, 손실 영역 내 토큰 드리프트를 정확히 0으로 정렬했습니다. Terminal-Bench 2.1에서 베이스 모델의 해결률을 43.8%에서 T1 적용 후 **64.0%**로 향상시켰습니다. 또한 Long-Horizon Terminal Bench에서 T1은 **27.9%**의 해결률을 기록하며 GPT-5.4 및 GLM-5.1을 능가했습니다.

## 배경 및 문제 제기 (Background and Problem Setup)

자율 AI 에이전트는 명령어 라인 인터페이스(CLI Shell)와 같은 상호작용 환경에서 복잡한 다단계 워크플로우를 수행하도록 발전하고 있습니다. 이러한 터미널 환경에서 에이전트는 쉘 명령어를 실행하고, 구조화되지 않은 stdout/stderr 출력을 해석하며, 오류 발생 시 적절히 수정하여 수백 턴 동안 일관된 추론을 유지해야 합니다.

대형 언어 모델(LLM)을 장기 터미널 환경에 맞춰 강화학습(RL)으로 사후 훈련(Post-Training)하는 과정에는 다음과 같은 심각한 기술적 난제가 존재합니다:
1. **오프폴리시 드리프트(Off-Policy Drift) 및 RL 불안정성**: 다중 턴 도구 상호작용 시 롤아웃 샘플링과 훈련 순전파 패스 간의 미세한 불일치(토큰화 드리프트, 부동소수점 오차, MoE 전문가 라우팅 변동 등)가 발생하면 정책(Policy) 성능이 급격히 저하되고 액터-크리틱 수렴이 불안정해집니다.
2. **희소한 보상 신호(Sparse Reward)**: 과제 완수에 100~300턴 이상이 소요되는 경우, 최종 성공/실패 여부만으로 보상을 부여하면 탐색 효율성이 극도로 낮아집니다.
3. **벤치마크 오버피팅(Overfitting)**: 벤치마크와 유사한 데이터로 훈련할 경우, 모델이 문제 해결 능력 대신 특정 명령어 패턴이나 환경 숏컷을 암기하는 현상이 발생합니다.

이러한 문제를 해결하기 위해 T1은 122B MoE 아키텍처와 장기 터미널 상호작용에 특화된 RL 사후 훈련 파이프라인을 도입했습니다.

## 방법론 (Methodology)

T1은 아키텍처 스케일링, 알고리즘적 RL 안정화 장치, 엄격한 데이터 격리 파이프라인을 통합했습니다.

### 모델 아키텍처 및 샌드박스 실행 환경
- **122B Mixture-of-Experts (MoE) 베이스**: 토큰당 일부 매개변수만 선택적으로 활성화하여 연산 효율성과 대용량 표현 능력을 동시에 확보했습니다.
- **실제 Linux Shell 클라우드 샌드박스**: 롤아웃 동안 에이전트는 격리된 클라우드 컨테이너 내부의 실제 Linux 쉘과 직접 상호작용하며, 에피소드당 최대 **300회 이상의 도구 호출 턴**을 수행합니다.
- **자동화된 프로그램 검증기**: 모든 훈련 및 평가 과제는 파일 상태, 테스트 수트 실행 결과, 시스템 상태를 컨테이너 내에서 직접 검증하는 전용 검증 스크립트와 쌍을 이룹니다.

### 안정적인 RL 사후 훈련 레시피
1. **워밍스타트 액터-크리틱(Warm-Started Actor-Critic)**: RL 훈련 초기 붕괴를 방지하기 위해 정제된 다중 턴 터미널 궤적으로 정책 및 가치 네트워크를 워밍스타트합니다.
2. **조밀한 프로세스 보상 함수(Dense Process Reward)**: 단일 최종 결과 보상 대신, 각 상호작용 턴마다 통과된 세부 검증기(Sub-Verifier)의 절대 개수를 점수화하여 중간 환경 상태를 실시간 평가합니다.
3. **TITO (Turn-by-Turn Token Identifier Tracking with Drift Repair)**: 다중 턴 쉘 세션 동안 발생할 수 있는 롤아웃-훈련 간 불일치를 방지하기 위해:
   - 상호작용 중 샘플링된 정확한 토큰 ID를 기록합니다.
   - 도구 호출 및 환경 관찰 경계에서 명시적 드리프트 보정을 수행하여 롤아웃 토큰 시퀀스와 손실 계산 영역 간의 완벽한 일치를 보장합니다.
4. **롤아웃 라우팅 리플레이 ($R^3$, Rollout Routing Replay)**: MoE 아키텍처에서는 순전파 패스 시 동적 전문가 라우팅이 샘플링과 훈련 시점에 달라질 수 있습니다. $R^3$는 롤아웃 중 매 MoE 레이어에서 샘플러가 선택한 토큰별 전문가 경로를 직접 로깅하고, 역전파 훈련 시 동일한 라우팅 경로를 강제 재현합니다.

### 분포 외 합성 데이터 생성 파이프라인
- **격리된 과제 합성**: 공개 벤치마크와 완전히 분리된 시드 프롬프트 및 프로그램 과제 합성기를 통해 훈련 데이터를 생성합니다.
- **벤치마크 오염 제로**: Terminal-Bench 2.1 및 Long-Horizon Terminal Bench와의 완전한 도메인 격리를 통해 측정된 성능 향상이 단순 암기가 아닌 진정한 능력 전이임을 입증합니다.

## 실험 결과 (Results)

T1은 표준 및 장기 터미널 실행 벤치마크에서 평가되었습니다:

- **훈련 안정성 지표**:
  - TITO와 $R^3$의 결합으로 훈련-추론 간 로그 확률 차이가 **0.021에서 0.013으로 단축**되었습니다.
  - 정책 손실 영역 내 토큰 드리프트가 **정확히 0**으로 유지되어 300턴 이상의 환경에서 안정적인 RL 최적화가 가능해졌습니다.

- **Terminal-Bench 2.1**:
  - 베이스 모델: **43.8%** 해결률.
  - **T1 (사후 훈련 완료)**: **64.0%** 해결률 (**+20.2%p** 향상).

- **Long-Horizon Terminal Bench**:
  - T1은 **27.9%** 성공률을 달성했습니다.
  - 상용 프론티어 모델인 **GPT-5.4** 및 **GLM-5.1**의 다중 턴 터미널 실행 성능을 상회했습니다.

## 한계점 및 열린 질문 (Limitations and Open Questions)

- **인프라 비용**: 에피소드당 최대 300턴에 달하는 병렬 RL 롤아웃을 수천 개의 컨테이너 환경에서 처리하기 위해서는 상당한 클라우드 컴퓨팅 및 컨테이너 오케스트레이션 인프라가 요구됩니다.
- **검증기 작성의 복잡성**: 조밀한 프로세스 보상의 품질은 세밀하고 견고한 검증기 스크립트에 의존합니다. 임의의 오픈엔드 코딩 및 시스템 관리 과제에 대해 해킹 불가능한 자동 검증기를 작성하는 것은 쉽지 않은 과제입니다.
- **테스트 시점 연산 비용**: 100턴 이상의 도구 호출이 필요한 과제의 경우 추론 지연 시간이 길어지므로, 롤아웃 시점의 병렬 탐색 및 컨텍스트 압축 기법이 추가로 연구되어야 합니다.

## 소프트웨어 엔지니어를 위한 시사점 (Relevance to Software Engineers)

자율 코딩 에이전트, 쉘 자동화 시스템, RL 파이프라인을 구축하는 엔지니어에게 T1은 다음과 같은 실용적 지침을 제공합니다:

1. **MoE 에이전트의 롤아웃-훈련 정밀 정렬**: MoE 모델을 강화학습할 때 샘플링과 훈련 시점의 동적 라우팅 차이는 정책 경사 업데이트를 교란합니다. $R^3$와 같은 라우팅 로깅 및 TITO 토큰 정렬 기법 적용이 필수적입니다.
2. **시뮬레이터 대신 실제 컨테이너 환경 활용**: 가상의 상태 전환 모델은 실제 쉘의 복잡성을 대체할 수 없습니다. 실제 검증기와 결합된 경량화된 Linux 컨테이너 내부에서 롤아웃을 수행해야 견고한 도구 사용 능력이 형성됩니다.
3. **세부 검증기 기반의 보상 설계**: 자동화된 과제나 평가 시스템 구축 시, 결과 검증을 여러 세부 검증기(Sub-Verifier)로 분할하십시오. 단계별 검증 통과 개수에 기반한 프로세스 보상은 RL의 샘플 효율성을 대폭 향상시킵니다.
4. **장기 세션 지속성**: 턴 경계의 드리프트를 보정하는 구조를 적용하면, 터미널 에이전트가 300턴 이상의 긴 세션에서도 추론 일관성을 유지하며 복잡한 시스템 관리 및 디버깅 작업을 완수할 수 있습니다.
