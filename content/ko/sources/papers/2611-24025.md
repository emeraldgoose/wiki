# 의도 계약: 에이전트에게서 도구를 빼앗아

**원문**: [arXiv:2611.24025](https://arxiv.org/abs/2611.24025) · **게시일**: 2026-11-18
**저자**: Ziyuan Wang, Genliang Zhu, Xiaobo Chen, Chu Wang

## 개요

의도 계약은 계획 모델이 도구를 전혀 갖지 않는 도구 사용 LLM 에이전트를 위한 권한 부여 인터페이스다. 각 단계에서 계획 모델은 목표, 사용자 발화의 있는 그대로 인용, 범위 필드를 담은 짧은 로그 계약을 제출한다. 코드가 계약을 검증하고 작은 신뢰 모델이 사용자 발언과 비교해 도구 호출을 직접 작성한다. 검증 및 디스패치 코드가 올바르다면 실행된 모든 호출은 신뢰 모델이 작성하고, 계획 모델의 영향은 호출 이전에 기록된 계약으로 제한되며, 신뢰 측이 요청 중 얼마나 실행할지 결정한다. gpt-6.1-terra를 계획 모델로, GLM-5.3-Flash를 신뢰 모델로 사용해 AmPermBench 작업군에서 블라인드 및 의도 가시 리뷰어와 비교한다.

## 핵심 내용

- 계획 모델은 환경 도구에 접근하지 못하며 목표, 사용자 인용, 허용 egress 호스트, 쓰기 접두사, 오류 정책을 담은 계약을 제출한다.
- 검증 코드가 인용, 범위, 목표 형식을 확인한 뒤 신뢰 모델이 단계당 최대 하나의 도구 호출을 작성한다.
- 계약 하에서는 변경된 모든 객체가 해당 변경을 만든 계약의 목표에 명시된다. 리뷰에서는 객체가 명령에 명시되고 목표에는 거의 명시되지 않는다.
- 계획 모델이 사용자가 요구하지 않은 작업을 추가할 때, 계약은 30회 중 27회에서 사용자 작업을 완료하고 의도 가시 리뷰어는 16회에서 완료한다.
- 계약은 무단 동작을 줄이지 않으며 모호한 참조에서는 블라인드 리뷰와 구분되지 않는다. 환경 용어가 명확해지면 상태 변경 조건의 40-49%가 잘못된 대상을 타격한다.
- 오류는 환경 가시성 없이는 신뢰 모델이 확인할 수 없는 모호한 참조에 대한 객체 선택에서 비롯된다.

## 상세

이 인터페이스는 계획과 실행을 분리해 계획 모델의 영향을 제한한다. 신뢰 측은 원본 사용자 메시지, 플러그인 구성, 도구 디스패치 코드를 보유한다. 강력한 계획 모델은 범위에 대해 신뢰할 수 없고, 작은 모델은 사용자를 따르려 시도한다는 가정 하에 신뢰되며 오류를 낼 수 있다. 신뢰 모델이 모든 실행 호출을 작성하고 로그 계약이 모든 호출에 선행한다는 속성 등은 검증 및 디스패치 코드가 정확할 때 구성상 보장된다.

블라인드 리뷰는 리뷰어가 사용자 단어와 제안 명령만 보며, 의도 가시 리뷰는 목표와 검증된 인용도 함께 본다. 계약 실행은 부분 실행에서 개선을 보인다. 신뢰 모델은 전체 명령이 아닌 단계의 일부를 거부할 수 있기 때문이다. 평가는 적대적 계획 모델이 아닌 한 쌍의 모델로 급한 과도 실행을 사용한다.

저자들은 플러그인과 실행 기록을 공개한다. 한계는 환경 가시성 없이는 모호한 참조를 해결할 수 없고, 블라인드 리뷰 대비 무단 동작 감소가 없다는 점이다.
