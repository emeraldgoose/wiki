# Evolving Infra: 에이전트 적응형 대규모 LLM 서빙

**원문**: [arXiv:2611.12304](https://arxiv.org/abs/2611.12304) · **게시일**: 2026-11-09
**저자**: Hao Kang, Weili Xu, Ziyang Li, Zheng Du, Hanchen Li, Tian Xia, Song Bian, Tushar Krishna, Huizi Mao, Ion Stoica, Song Han

## 개요

에이전틱 워크로드는 이제 LLM 추론 수요의 큰 축이다. 그러나 기존 프리필–디코드(PD) 분리 서빙은 두 방향에서 압박을 받는다. 첫째, 연산 수요는 에이전트마다, 시간에 따라 다르다. PutnamBench, Claude Code, OSWorld 에이전트는 요청당 프리필–디코드 비중이 달라 최적 고정 분할이 2P7D에서 6P3D까지 벌어지고, 워크로드 구성이 이동하면 10분 창별 최적 분할이 3P6D에서 7P2D로 움직인다. 단일 고정 분할은 처리량의 최대 24%를 잃는다. 둘째, 에이전트의 컨텍스트 관리가 KV 캐시의 가치를 바꾼다. 하네스는 서브에이전트를 만들고, 도구를 기다리고, 히스토리를 압축하므로 최근 접근 여부는 재사용을 예측하지 못한다. Claude Code 트레이스에서 359초 서브에이전트 호출 뒤 프롬프트의 98%가 기존 KV와 겹치지만, 12초 압축 뒤에는 14%만 겹친다.

Evolving Infra는 최초의 에이전트 적응형 서빙 프레임워크로 소개된다. 기존 시스템 실패의 두 근원을 겨냥한다. 연산 배분과 KV 캐시 관리가 결합되어 있어(노드의 캐시 KV가 로컬 상태에 색인되어 위상을 바꾸면 버려지거나 묶인다) 플래너·라우터·메모리 풀이 큐 깊이, 입력 길이, 접근 최근성 같은 조악한 신호에 의존한다는 것이다. 설계는 두 평면을 분리한다. 모든 노드는 어느 위상이든 서빙할 수 있는 대칭 엔진을 돌리고 재시작 없이 런타임에 재배치되며, KV는 전 노드 호스트 메모리로 이루어진 공유 풀에 살고, 각 복사본을 참조하는 활성 브랜치 수를 기록하는 클러스터 전역 디렉터리가 색인한다. 이 데이터 평면 위에서 온라인 플래너가 캐시 토큰과 비캐시 토큰을 구분하는 프리필·디코드 반복시간 모델을 학습하고, 예측 이득이 600초 계획 창 전체에서 지속될 때만 PD 분할을 재배치한다. 라우터는 대기 중 비동기 KV 인출과 함께 각 요청을 예측 TTFT가 가장 짧은 노드로 보내고, 축출은 활성 브랜치가 참조하지 않는 KV(대체된 히스토리, 종료된 서브에이전트 컨텍스트, 전송 부산물 중복 복사본)를 먼저 제거한다.

GLM-5.2와 Kimi K2.6을 코딩·수학·컴퓨터 사용 에이전트로 36장의 GB300 GPU에서 서빙한 평가(256 GPU 확장 실험, 3,072 GPU 시뮬레이션 포함)에서 Evolving Infra는 NVIDIA 프로덕션 프레임워크 Dynamo를 전 항목에서 앞선다. 고정 부하에서 처리량 1.10~2.73배, KV 재사용 손실 81~95% 감소, 평균 종단 지연 최대 4.12배, P95 TTFT 최대 13.92배 개선이고, 수학→컴퓨터 사용 구성 이동에서는 Dynamo의 2.14배, 최적 고정 분할의 1.28배 처리량을 낸다. 위상 전환은 평균 6.2초로 Dynamo 재기동보다 100배 이상 짧다.

## 핵심 내용

- 기존 PD 시스템의 세 실패 모드: 비싼 위상 전환(Dynamo는 Claude Code 측정에서 전환당 평균 681초, Arrow는 34회 제자리 전환에서 가용 KV 재사용의 55.5% 상실), 잘못 추정된 연산 수요(오프라인 프로파일링 고정 분할은 낡고, 큐 깊이·TTFT 기반 온라인 플래너는 서브에이전트 버스트에 흔들리며 입력 전체 길이로 프리필 작업을 추정하면 KV 재사용을 무시해 과대계산), 잘못 판단된 KV 재사용(캐시 인식 라우터가 접두어를 쥔 소수 프리필 노드를 과부하시켜 P95 TTFT를 높이고, LRU 축출은 도구·사용자 대기 브랜치의 KV를 버리면서 압축으로 쓸모없어진 히스토리와 종료된 서브에이전트 컨텍스트는 남긴다).
- 분리 메커니즘: 대칭 엔진이 모든 노드를 프리필·디코드 양립 가능하게 만들고 플래너가 재시작 없이 런타임에 위상을 재배치한다. KV는 전 노드 호스트 메모리의 공유 풀로 옮겨지고(노드별 호스트 계층이 GPU 계층보다 4배 많은 토큰을 캐시), 클러스터 전역 KV 디렉터리가 에이전트 컨텍스트 관리와 노드 간 전송에 맞춰 갱신되는 활성 브랜치 참조 수를 추적한다. 위상 전환 후에도 KV는 모든 노드가 읽을 수 있다.
- 에이전트 적응형 계획: 프리필·디코드 반복시간 모델을 오프라인 프로파일링 없이 온라인으로 학습하되 프리필 모델은 KV 재사용을 명시적으로 반영한다. 플래너는 계획 창(600초, 10개 조각)의 요청 평균 작업량 위에서 모델을 평가하고 예측 이득이 창 전체에서 지속될 때만 전환한다. 짧은 버스트는 전환을 유발하지 않는다. 런당 평균 전환은 2.0회로 Dynamo의 3.6회보다 적고, Dynamo가 측정 구간의 41~100% 동안 최적 고정 분할에서 벗어나는 것과 대조된다.
- 에이전트 인식 KV 관리: 대기 중 비동기 KV 인출 덕에 라우터는 접두어 지역성 대신 예측 TTFT 최소 노드를 겨냥한다. 가장 바쁜 프리필 노드의 대기 시간은 평균 노드의 1.75~1.85배로, 캐시 인식 라우팅의 2.29~2.61배보다 낫다. 디렉터리 기반 축출은 활성 에이전트가 여전히 필요로 하는 KV를 거의 모두 지키는 반면, Dynamo의 LRU는 CC에서 잃은 재사용의 34~46%에 해당하는 대기 브랜치 KV를 버리고, 캐시 없이 프리필하는 프롬프트 토큰 비율은 Evolving Infra의 최대 2.99배다.
- 고정 부하 결과(워크로드 3종 × 동시성 3단계): 처리량 Dynamo의 1.10~2.73배, KV 재사용 손실 81~95% 감소, 평균 종단 지연 Putnam 1.15배·OSWorld 2.34~2.69배·CC 3.80~4.12배 감소, P95 TTFT 최대 13.92배 감소. 각 워크로드 최저 동시성에서는 SGLang 최적 고정 분할 대비 처리량 0.98~1.38배.
- 플래너의 선택: CC에는 3P6D~4P5D, OSWorld에는 8P1D. 대칭 엔진이 최적점을 옮기므로 SGLang 최적 고정 분할(4P5D, 6P3D)과 다르다. 디코드 위주 Putnam에서는 프리필 노드를 한두 개만 유지해 P95 TTFT(세 동시성 중 두 곳에서 Dynamo보다 높음)를 처리량과 낮은 평균 지연에 의도적으로 맞바꾼다.
- 구성 이동(288 Putnam → 144 Putnam + 72 OSWorld → 144 OSWorld, 3시간 연속): 분할이 10분 창별 최적을 따라가며 OSWorld 구간에서 8P1D로 수렴한다. 처리량은 Dynamo의 2.14배, 최적 고정 분할의 1.28배, 평균 종단 지연은 각각 2.15배·1.33배, P95 TTFT는 3.58배·1.88배 개선이며 모든 구간에서 최고 처리량이다.
- 전환 비용: 전환 노드의 진행 중 요청 대기(계속 서빙됨)를 포함해 평균 6.2초로, 노드를 서빙에서 빼는 Dynamo 재기동 754초보다 100배 이상 짧다. 초기 분할에 둔감하다. 3P6D~6P3D 네 초기 분할에서 CC 평균 종단 지연 편차는 1.8% 이내이고 모두 4P5D로 수렴한다.
- 소거 실험: 인프라와 KV 재사용 인식 라우팅·축출만으로(4P5D 고정) 최적 고정 분할 대비 처리량 1.37배. SGLang 라우팅 아래 비동기 인출만으로 상류 대비 1.12배(프리필 노드 유휴 시간 23.6% → 14.4%). 같은 분할에서 캐시 인식 라우팅과 비교하면 KV 재사용 손실이 2.4% 대신 0.7%이고 캐시 없이 프리필하는 토큰이 31% 적다. ThunderAgent식 에이전트 일시정지는 GB300에서 KV 용량이 병목이 아니라 0.95배에 그친다.
- 적응의 비용: 이미 최적인 고정 분할에서 온라인 위상 분할 적응을 켜도 처리량 손실은 0.3%뿐이다. 비교용 오프라인 프로파일링은 3시간 CC 트레이스를 256 GPU로 이진 탐색을 써도 10,752 GPU시간이 든다. 반복시간 모델은 학습 1분 안에 낮은 평균 오차로 수렴한다.
- 평가 인프라: PutnamBench의 mini-SWE-agent(디코드 위주, 문제당 단일 브랜치, 컨텍스트 관리 없음), OSWorld 2.0의 Anthropic 컴퓨터 사용 에이전트(프리필 위주 멀티모달 다중 에이전트, 매 단계 스크린샷 추가), 실사용자 Claude Code 트레이스(서브에이전트·압축·긴 대기가 섞인 가장 동적인 워크로드)를 대기와 접두어 공유를 보존하는 Trie 재생기로 재생. Putnam·CC에는 GLM-5.2, OSWorld·구성 이동 런에는 Kimi K2.6. 두 모델 모두 NVFP4 양자화, FP8 KV 캐시, 다중 토큰 예측(MTP) 추측 디코딩, 4장 GPU GB300 노드 아홉 개에 TP4.

## 세부 사항

- 베이스라인 구성: Dynamo v1.5.1은 최신 오픈소스 동적 PD 분리 시스템으로 소개되며, SGLang Model Gateway에 캐시 인식 프리필 라우팅과 라운드로빈 디코드 라우팅(논문 자체 측정에서 P95 TTFT가 가장 낮은 구성)을 얹어 비교했다. 노드는 LRU 축출의 HiCache를 돌린다. SGLang 런타임 역할 전환은 추측 디코딩을 거부해 제외했고, Llumnix는 GB300의 Arm CPU에서 구동 불가해(H200 비교는 부록) 제외했다.
- 워크로드 현실성: 인용된 1,170만 요청 프로덕션 연구에 따르면 사용자 발화 과업 시작은 근무일 리듬을 따르고 자동 발화 시작은 하루 고르게 분포한다. 고정 분할이 아니라 구성 이동에 대한 온라인 적응이 필요한 근거다.
- 최근성 신호가 실패하는 이유: 브랜치는 도구·서브에이전트·사용자를 기다리며 멈췄다가 기존 접두어를 재사용하고, 압축은 직전에 접근한 히스토리를 이후 요청에서 떼어낸다. 긴 서브에이전트 대기와 빠른 압축 사이 98% 대 14% 접두어 일치 대비가 재사용이 최근성이 아니라 컨텍스트에 따른다는 가장 날카로운 증거다.
- 확장성 연구(부록): 256장 GB300 GPU까지의 평가, 3,072 GPU 시뮬레이션, 오픈루프 도착(도착률이 오르면 플래너가 프리필 노드를 늘려 최적 고정 분할의 2배 도착률을 견딘다), 프리필·디코드 상이 병렬화.
- 연구진: 조지아공대, 일리노이대(UIUC), UC 버클리, NVIDIA, OpenAI, MIT가 참여했으며 Tushar Krishna, Ion Stoica, Song Han 등 시스템 분야 베테랑이 포함되어 있다.
- 표기: xPyD는 프리필 x개·디코드 y개 노드, L1/L2는 노드의 GPU 메모리·호스트 메모리 KV 계층이다. 계획 창은 600초에 10조각이며 측정에서 제외되는 30분 워밍업이 선행된다. 고정 부하 런은 각 워크로드를 고정 동시성으로 1시간 서빙하며 끝난 에이전트는 새 에이전트로 교체한다.
