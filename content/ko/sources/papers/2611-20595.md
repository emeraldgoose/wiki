# 무시된 API 오류로부터 LLM 에이전트를 보호하는 불변식 기반 하네스 강제 기법

**Source**: [huggingface](https://arxiv.org/abs/2611.20595)
**게시일**: 2026-11-16

## 개요

LLM 에이전트는 점점 더 많은 작업을 도구를 통해 수행합니다. 문헌 데이터베이스를 검색하고, 유전자와 단백질을 조회하고, 샘플 카탈로그를 질의하며, API를 호출해 여행을 예약한 뒤 그 API가 돌려준 결과로 답변을 만듭니다. 대부분의 고장 난 도구 호출은 API가 오류를 반환하거나 시간 초과되거나 잘못된 형식의 데이터를 보내기 때문에 쉽게 알아볼 수 있습니다. 그러나 어떤 실패는 아무런 흔적도 남기지 않습니다. 예를 들어 카탈로그 API에 잘못 표기된 필터 이름이 전달되면, API는 그 필터를 조용히 무시한 채 HTTP 200과 함께 그럴듯하지만 틀린 결과를 반환합니다. 저자들은 이를 '조용한 API 실패(silent API failure)'라 부르고, 그 원인을 '조용한 결함(silent fault)'이라 부릅니다.

기존의 방어책은 판단을 모델에 맡깁니다. 체크리스트 프롬프트, 검토자 모델, 결과 모니터, LLM 심판 등은 모두 에이전트(또는 다른 모델)가 문제를 잡아내도록 요구합니다. 저자들은 이 방식이 대체로 통하지 않음을 보입니다. 모델은 불일치를 알아채고도 그냥 답해 버리는 경우가 많습니다. 이들이 제안하는 SilentGuard는 판단을 모델에서 도구 호출을 실행하는 하네스로 옮깁니다. 각 결과를 올바른 API라면 반드시 만족해야 하는 불변식에 비추어 검사하고, 이를 깨뜨리는 값은 공개하지 않고 차단합니다.

보고된 결과는 인상적입니다. 조사한 15개 공개 연구 API 중 11개에서 조용한 실패가 발견되었고, 반환된 개수 값이 최대 691배까지 부풀려졌습니다. 7개의 오픈 모델에서 SilentGuard는 대상 결함에 대한 오답률을 74.0%에서 1.7%로 줄였으며, 결함이 없는 작업에서는 성능 손실이 없었습니다. 세 개의 프런티어 모델에서는 70.2%에서 0.5%로 떨어졌습니다. 특히 같은 검사로 경고만 보내는 경우에는 오답이 70.1%로 남아, 핵심은 조언이 아니라 강제라는 점이 드러났습니다.

## 핵심 내용

- 조용한 API 실패는 흔하고 눈에 띄지 않습니다. 15개 공개 연구 API 중 11개가 잘못 표기된 필터를 무시하거나, 오타가 있는 필터 값을 누락하거나, 페이지를 조용히 잘라 반환하면서도 HTTP 200을 유지했습니다.
- 이런 결함 아래에서 반환되는 개수 값은 최대 691배까지 부풀려질 수 있으며, 에이전트는 심판이 지적한 개수 중 77.4%를 그대로 보고합니다.
- 모델 중심의 해결책(체크리스트 프롬프트, 검토자 모델, 결과 모니터, LLM 심판)은 오답을 70% 이상으로 남기며, 무방비 에이전트의 74.0% 기준선과 크게 다르지 않습니다.
- SilentGuard는 검사를 모델이 아니라 하네스에서 실행합니다. 정확 검사(모든 필터 위치에서 평가되는 개수 항등식, 레코드별 필터 부합 여부, 중복 레코드 없음, 목록 크기와 보고된 총합의 일치, 스펙/파라미터 검사)와 깨끗한 추적에서 채굴한 학습 기반 검사를 사용합니다.
- 각 검사에는 추정 오경보율이 붙습니다(성공 규칙, 1/(n+2); 정확 검사는 0). 한 번의 재검사 후 결과는 공개(release), 차단(withhold, 실패한 검사의 오경보율 ≤ 1%), 또는 경고와 함께 통과(warn)로 처리됩니다.
- 학습에 없던 새로운 결함 유형에서도 하네스만으로 오답이 61.1%에서 24.5%로 줄었고, 잘못된 답을 복구하기보다 답변을 보류함으로써 오답을 피합니다.
- 같은 검사의 경고만으로는 70.1%가 오답으로 남아, 알림이 아니라 강제가 개선의 핵심입니다.

## 상세

**방법.** SilentGuard는 탐지와 조치를 분리합니다. 개수 질의의 경우 하네스가 직접 추가 질의 두 개를 발행하여 조건 목록의 모든 위치에서 N(F) + N(F_{<k} ∧ ¬C_k) = N(F_{<k}) 항등식을 검증하므로, 목록 어느 위치의 필터가 무시되더라도 잡아냅니다. 목록을 반환하는 엔드포인트에 대해서는 반환된 모든 레코드가 필터를 만족하는지, 중복 레코드가 없는지, 목록 크기가 보고된 총합과 일치하는지를 검사합니다. API가 파라미터 목록을 공개한 경우, 목록에 없는 파라미터가 포함된 요청은 실행 전에 거부됩니다. 깨끗한 추적에서 채굴한 학습 기반 검사는 필드 존재 여부와 타입, 에코된 인자, 양수 값, 범주형 값, 필드 간 선형 관계, 날짜 순서를 다룹니다.

탐지와 조치는 분리되어 있습니다. 각 검사는 결과를 통과/실패로 매핑하며, 추정 오경보율 α̂ = 1/(n+2)(n은 해당 검사가 버텨낸 깨끗한 예시 수, 정확 검사는 n = ∞)를 가집니다. 한 번의 재검사 후, 모든 검사를 통과한 결과는 그대로 공개하고, 실패한 검사의 오경보율이 임계값 τ = 1% 이하면 해당 결과를 차단하며, 그 외에는 경고와 함께 통과시킵니다. 새로운 검사는 이 정책을 바꾸지 않고 바로 끼워 넣을 수 있습니다. 13개 공개 API의 문서화된 84개 연산 중 61개에서 정확 검사가 가능했고, 모두 스펙 검사가 가능했습니다.

**결과.** 저자들의 평가에서 조용한 실패는 15개 공개 연구 API 중 11개에서 발견되었습니다. 현재의 모델 중심 해결책은 오답을 70% 이상으로 남기고, 에이전트는 심판이 지적한 개수의 77.4%를 그대로 보고합니다. 일관성 검사 증거를 보여 준 심판은 결함이 있는 실행의 82.4%를 지적했고(깨끗한 실행의 13.9%도 지적), 이는 문제가 인지 가능하지만 모델이 무시하고 답한다는 것을 보여 줍니다. 7개의 오픈 모델에서 SilentGuard는 대상 결함에 대한 오답률을 74.0%에서 1.7%로 줄였으며 결함 없는 작업에서의 손실은 없었습니다. 세 개의 프런티어 모델에서는 70.2%에서 0.5%로 떨어졌습니다. 같은 검사의 경고만으로는 70.1%가 오답으로 남았습니다. 검사가 다루지 않는 새로운 결함 유형에서도 하네스만으로 오답이 61.1%에서 24.5%로 감소했습니다. 이 시스템은 잘못된 답을 복구하는 것이 아니라 답변을 거부(보류)함으로써 오답을 피합니다.
