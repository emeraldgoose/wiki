# WebArena-Pro: 웹 에이전트를 위한 이질적·멀티모달·재현 가능 벤치마크

**원문**: [arXiv:2611.17955](https://arxiv.org/abs/2611.17955) · **게시일**: 2026-11-13
**저자**: Imene Kerboua, Fatemeh Pesaran Zadeh, Xing Han Lù, Weijian Qi, Alexander Miller, Junyi Song, Yunjia Tian, Dongjin Kang, Seyeon Choi, Marzia Nouri, Ewen Gueguen, Matteo Boglioni, Fengyuan Liu, Zeyi Liao, Mengqi Yuan, Yue Li, Alexandre Lacoste, Alexandre Drouin, Spandana Gella, Huan Sun, Gunhee Kim, Siva Reddy

## 개요

대규모 언어 모델과 비전-언어 모델로 구동되는 웹 에이전트는 메시지 분류와 발송, 비즈니스 애플리케이션의 레코드 갱신, 대시보드 분석, 미디어 편집처럼 실제 브라우저 업무를 점점 더 많이 맡는다. 그러나 이 진전을 측정하는 벤치마크는 뒤처져 있다. 재현 가능한 셀프 호스팅(self-hosted) 벤치마크는 소수의 소프트웨어 범주에서 몇 개 웹 애플리케이션만 다루고 모달리티를 텍스트와 비전으로 제한하는 반면, 실제 서비스 중인 웹사이트를 대상으로 하는 라이브 벤치마크는 커버리지를 넓히는 대신 실행마다 페이지·데이터·레이아웃이 흘러가 재현성을 잃는다. 기존 평가는 웹 과제 속에 박힌 오디오와 비디오 콘텐츠를 에이전트가 이해하고 활용할 수 있는지도 뜻 있게 살피지 않는다.

WebArena-Pro는 McGill 대학교와 Mila – 퀘벡 AI 연구소 주도로 ServiceNow AI Research, 오하이오주립대학교, INSA Lyon, 에스커, 서울대학교 연구자들과 함께 이 공백을 동시에 메운 벤치마크다. 생산성, 커뮤니케이션, 분석, 비즈니스 운영, 디자인·미디어, 여행의 6개 도메인 범주에 걸쳐 20개 셀프 호스팅 웹 애플리케이션과 300개 과제를 배치했고, 각 애플리케이션은 Notion, Slack, Spotify, Figma, Airbnb 같은 널리 쓰이는 서비스를 본뜬 워크플로를 재현하되 데이터와 기능 범위는 벤치마크가 통제한다. 과제마다 전용 템플릿을 하나씩 두어 공유 템플릿에서 인스턴스를 대량 찍어내는 방식과 구별되며, 300개 과제는 단일 사이트 204개·교차 사이트 96개, 텍스트/비전 221개·오디오/비디오 79개로 나뉜다.

결과는 에이전트가 인간 수준의 브라우저 업무에서 아직 멀었음을 보여준다. 브라우저 액션 50회 예산에서 최고 구성인 Codex + GPT 6.1 Sol과 Claude Code + Claude Opus 5.5가 62.3%로 공동 1위를 기록하고, 가장 강한 GenericAgent 구성인 Gemini 3.1 Pro omni와 Gemma4 31B도 30.3%에 그친다. 저자들은 재현 가능하고 사람이 큐레이션한 웹 에이전트 벤치마크 가운데 WebArena-Pro가 지금까지 가장 넓은 애플리케이션 커버리지와 가장 포괄적인 멀티모달 지원을 제공한다고 본다.

## 핵심 내용

- 범위: 6개 도메인 범주의 20개 셀프 호스팅 애플리케이션에 걸친 300개 과제. WebArena-Pro는 과제마다 전용 템플릿을 두는 반면 선행 벤치마크 WebArena는 241개 템플릿으로 812개 인스턴스를 만들었으므로, 평가 다양성이 템플릿 재사용이 아니라 응용의 폭에서 나온다.
- 오디오·비디오를 핵심 관측으로: 미디어 소스가 접근성 트리(accessibility tree)에 노드로 나타나고, 비전-언어 에이전트에는 로컬 Whisper 기반 transcribe()(음성 전사)와 extract_frames()(균등 간격 프레임 추출), 옴니(omni) 모델에는 listen()과 watch()(오디오·비디오 직접 입력)가 주어진다. 전사문은 접근성 트리에 합성 노드로 병합되고 프레임은 이미지 콘텐츠로 반환된다.
- 재현 가능한 격리: 각 애플리케이션은 시드 데이터와 고정 로그인 자격증명을 갖춘 Docker 컨테이너로 실행되며 과제마다 상태를 시드 기준으로 초기화해 오염 없는 병렬 평가가 가능하다. 20개 사이트 가운데 9개는 오픈소스 애플리케이션을 개조했고 11개는 AI 지원으로 새로 만든 커스텀 사이트다.
- 주요 결과: Codex + GPT 6.1 Sol과 Claude Code + Claude Opus 5.5가 62.3%로 공동 선두이고 OpenCode + Kimi 3.1 Pro가 60.7%, OpenCode + Qwen 3.8 Max Prime이 55.7%로 뒤따른다. GenericAgent 최고 기록은 Gemini 3.1 Pro omni와 Gemma4 31B의 30.3%이며, 가장 강한 구성도 과제의 38%는 풀지 못한다(별도의 더 쉬운 100과제 개발 세트에서는 같은 Gemma4 31B가 74.0%까지 오른다).
- 도메인·커버리지 효과: 코딩 에이전트에게 커뮤니케이션 도메인이 가장 쉽고(Codex 81.8%) 여행이 가장 어렵다(최고 57.7%). 교차 사이트 과제가 단일 사이트보다 일관되게 어려워 Gemma4 31B는 38.2%에서 13.5%로 24.7포인트 떨어지고, Claude Code가 교차 사이트 최고 기록 55.2%로 격차를 10.5포인트로 가장 좁게 유지한다.
- 미디어 도구 소거: AcidWave와 YT-Lite의 오디오/비디오 과제 79개 중 제목·메타데이터·썸네일만으로는 풀 수 없는 43개 하위 집합에서, 미디어 도구를 빼면 Gemini 3.1 Pro와 Qwen 3.6 27B는 오디오 과제에서 0%로 떨어진다. Claude Code + Opus 5.5는 도구 없이 14.0%, 도구를 쓰면 48.8%로 오른다.
- 루브릭(rubric) 기반 채점: 과제마다 사람이 작성한 액션·결과 기준을 방향성 비순환 그래프로 묶고, 백엔드 상태를 조회하는 결정론적 검사, 방문 URL과 액션의 휴리스틱 매칭, 마지막에 판정하는 LLM 심사자(judge) 순서로 채점한다. 심사자는 Qwen 3.6 27B로, 인간 주석과의 전체 일치율이 89.5%이고 300과제 평가당 채점 비용이 4달러 미만이어서 선택됐다.
- 비용: 300과제 전체 평가의 기록된 API 비용은 Codex + GPT 6.1 Sol 166달러, Claude Code + Opus 5.5 386달러, OpenCode + Qwen 3.8 Max Prime 689달러, GenericAgent + Claude Opus 4.7 약 800달러에 이른다.

## 상세

평가는 BrowserGym 호환 환경에서 이뤄진다. 에피소드마다 새 웹사이트 컨테이너를 띄우고 준비를 기다린 뒤 UI 로그인을 수행하고 과제 시작 URL로 이동하며, 에이전트는 done()이나 send_msg_to_user()를 호출하거나 브라우저 액션 50회 한도에 이를 때까지 행동한다. GenericAgent는 접근성 트리와 Set-of-Mark로 보강한 스크린샷을 다루는 ReAct 방식 에이전트로, BrowserGym의 bid 액션 집합에 done(), transcribe(), extract_frames()를 덧붙여 쓴다. OpenCode, Codex, Claude Code 코딩 에이전트는 Harbor 하네스(harness)로 평가하며, 브라우저 제어용 Playwright MCP와 미디어 함수를 얹은 MCP를 받는다. 백본은 오픈소스 7개와 클로즈드 5개 등 총 12개 모델(Qwen·Gemma4·Kimi 계열과 Gemini·Claude·GPT 계열)이고, 모두 높은 추론 강도의 확장 사고(extended thinking)와 온도 1.0으로 실행되며 GenericAgent에는 단계당 4만 토큰 상한이 둬진다.

과제 제작은 사람 검증이 관문이다. 전용 어노테이터 인터페이스에서 작성자가 자연어 의도를 쓰고 사이트를 고르며 루브릭 초안을 작성하면, 자동 트리아지(triage) 단계는 LLM 에이전트가 후보를 실제로 풀어보게 하여 첫 시도에 정답을 낸 사소한 과제를 걸러낸다. 통과한 후보는 두 번째 어노테이터가 실제 애플리케이션에서 실현 가능성을 확인하고 루브릭 항목과 난이도를 확정하며, 이 검증을 통과하지 못한 과제는 공개되지 않는다. 실패 분석도 흥미롭다. 2,400회의 GenericAgent 테스트 실행 가운데 실패한 1,683회 중 878회(52.2%)가 50회 한도를 채웠지만, 코딩 에이전트의 633회 실패 중 50회 한도에 도달한 것은 14.5%뿐이고 그 실패의 59.2%는 부분 루브릭 보상을 받았다.

저자들은 행동 공간 확장이 사전 녹화된 오디오 구간과 이산 비디오 프레임에만 걸쳐 있고, 성능 차이를 모델 능력이나 하네스 설계 중 무엇 탓인지 분리해 말할 수 없다는 점을 한계로 적는다. 공유된 50회 예산도 에이전트 간 연산량을 균등하게 만들지 못한다. 같은 인프라는 루브릭 기반 검증기가 과제별 보상을 제공하는 학습 환경으로 확장될 수 있으며, 강화학습이나 기각 샘플링(rejection sampling), UI 드리프트·프롬프트 주입에 대한 강건성 연구의 기반이 될 수 있다. 프로젝트 페이지는 webarena-pro.github.io에 있다.
