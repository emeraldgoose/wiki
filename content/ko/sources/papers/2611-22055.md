# Weight-Space Programming에는 Transformer가 필요하지 않다

**Source**: [arXiv](https://arxiv.org/abs/2611.22055)
**게시일**: 2026-11-17

## Overview

Transformer 같은 표준 신경 아키텍처는 기울기 하강으로 잘 학습되고 GPU에서 빠르게 실행되기 때문에 선택돼 왔다. 그러나 weight-space programming(WSP)에서는 LLM이 기울기 기반 학습 없이 대상 모델의 가중치를 직접 손으로 쓴다. 그러면 그런 이유는 더 이상 적용되지 않는다. Transformer를 계속 유지해야 할까? 최소한의 안내, 열 개의 레이블된 예시, 샌드박스만 주어진 상황에서 세 프런티어 LLM(Claude Opus 5.5, GPT-6.1 Sol, GPT-6 Astra)에게 고정 아키텍처의 가중치를 생성하거나 아키텍처를 직접 설계하게 하고, 주로 ARC 객관식 과학 문제에서 평가했다.

설계의 자유를 주면 세 모델 모두 평문 팩트를 희소 표로 컴파일하고 고정 절차로 조회하는 구조를 선택해 최대 54.4%의 테스트 정확도를 기록했다 — LLM이 설계한 모델은 같은 LLM이 쓴 가장 정확한 공개 Transformer를 능가하면서 파라미터는 약 1,800배 적게 썼다. 기울기 없이 쓸 때 작성자들은 표를 선택하는데, LLM이 각 가중치가 무엇을 의미하는지 진술할 수 있고 잘못된 것을 찾아 다시 쓸 수 있기 때문이다. 각 오답은 한 행을 가리키고, 한 행을 제거하면 다른 답 하나 정도만 바뀐다. 이를 바탕으로 저자들은 같은 크기의 Transformer보다 GPU에서 최대 17배 빠른 연합 기억(associative memory) 기반 모델을 제안한다. 사전학습 LLM이 전체적으로는 더 정확하며, 이 주장은 가중치를 쓸 때 어떤 구조를 만들 것인가에 관한 것이다. 코드와 프로젝트 페이지는 논문에서 링크된다.

## Key points

- 조율 없는 수렴: 자유롭게 설계하게 하면 세 LLM 모두 희소 표 연합 기억으로 독립적으로 수렴한다 — attention도, MLP도, dense 임베딩도 없다(ARC 객관식 과학 문제).
- 크기 효율: 연합 기억 설계는 같은 LLM이 쓴 가장 정확한 공개 아키텍처보다 약 680배 작고, LLM 설계 모델은 같은 LLM이 쓴 최고 공개 Transformer를 ~1,800배 적은 파라미터로 능가한다.
- 국소 편집 가능성: Claude Opus 5.5의 모델에서 옵션당 최고 매칭 행 하나만 남겨도 전체 모델 정확도에 거의 근접하고, 한 행을 삭제하면 대략 한 예측만 바뀐다. 반면 같은 팩트를 Transformer에 쓰면 BM25 키워드 검색에도 못 미치며, dense 키 간 간섭과 일치하는 결과다.
- 속도: 제안된 연합 기억 기반 모델은 LLM 설계 모델 정확도에서 약 3%p 이내를 유지하면서 GPU에서 같은 크기의 Transformer보다 최대 17배 빠르게 답한다(질문당 고정된 수의 행만 읽는다).
- 범위/한계: 사전학습 가중치, 수학 문제, 개방형 생성, 여러 과제 동시 수행, 시각 과제도 시험했다 — 이미지는 WSP가 작동하지 않는 영역이며, 사전학습 LLM이 전체적으로는 훨씬 더 정확하다. 주장은 WSP 하의 아키텍처 선택에 관한 것이지 사전학습 모델을 이긴다는 것이 아니다.

## Details

- 설정: 최소 안내 — 열 개의 레이블된 문제, 실행 샌드박스, 객관식 문제(주로 ARC 과학); 두 체제 (i) 무작위 초기화의 다양한 공개 아키텍처(Transformer, SSM, RNN)에 대한 WSP, (ii) 자유 아키텍처 설계. 작성자: Claude Opus 5.5, GPT-6.1 Sol, GPT-6 Astra.
- 분석: LLM이 먼저 도메인 팩트를 평문 문장으로 표현하고, 각 문장을 희소 표의 행으로 변환하는 빌드 스크립트를 작성; 고정 조회 절차가 질문/옵션 토큰을 행과 매칭해 최고 점수 답을 선택. 행 제거 테스트, BM25 대조군, 테스트셋 중첩 검사, 행 유지(retention) 테스트로 검증.
