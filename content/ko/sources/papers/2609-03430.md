# Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning

: Long chains of thought make the KV cache a severe memory bottleneck, and every existing eviction method shares one paradigm: score each cached token by estimated future importance and keep the top scorers. This paper shows the selection signal contributes almost nothing. **Random Attention** keeps the prompt and evicts uniformly at random within each attention head, computing no score at all. Across four models (Qwen3-4B/14B/32B, Phi-4-reasoning) and six reasoning tasks at ~4x compression, it matches the strongest baseline (TriAttention) on accuracy — significantly ahead in 31 of 60 baseline cells, behind in only one — while delivering **32–43% higher serving throughput** on vLLM.

Two rules and nothing else: Random Attention is a signal-free policy: (1) protect the question — the entire prefill (system prompt, template, question) is never evicted; (2) scatter the rest per head — every other cached position gets an i.i.d. uniform score, each KV head keeping its top-K independently. An eviction costs one rand and one topk. It doubles as a null hypothesis: any signal-based selector that cannot beat it at matched budget is not extracting usable information.

Why the signal buys so little: Two controlled experiments explain the result. First, the prompt is the fragile part: prior evictors differ in whether the prompt survives (some pin it, others leave it to the score). Giving every method the same keep-the-prompt rule erases most gaps — SnapKV gains up to +22.5 points on Phi-4-reasoning GPQA-D, while R-KV (which already retained the prompt) gains at most 1.9. Caveats: Full-text HTML (v2) was consulted. The one significant baseline win (TriAttention on Qwen3-32B code) traces to long prompts consuming the budget — protecting the whole prompt is itself wasteful when much of it is scaffolding. The one thing random cannot do: a fact stated once, never restated, 57 compression rounds before the question (R-KV recovers it 84% of the time, random 0%). Comparison is restricted to training-free evictors.

Relevance to SW engineers: - When serving reasoning models under a memory budget, start with the cheapest policy that protects the irreplaceable input — complexity must justify itself against a random baseline at matched budget.
- The accuracy of an evictor is decided by what it protects, not how it ranks the rest — audit protection regimes before comparing scores across papers.
- Skipping the scoring pass is worth 32–43% in paged serving because compressions pile up at synchronization points across concurrent requests.
