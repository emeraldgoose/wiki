# 랜덤 어텐션: 효율적 추론을 위한 KV 캐시 축출의 재고

출처: Heng Wang 외 10인, arXiv:2609.03430, 2026-09-03 (v2 2026-09-28).

**핵심 요약**: 긴 생각의 사슬은 KV 캐시를 심각한 메모리 병목으로 만들고, 기존 축출법은 모두 "캐시된 토큰마다 미래 중요도를 점수화해 상위만 유지"라는 하나의 패러다임을 공유합니다. 이 논문은 선택 신호가 거의 기여하지 않음을 보입니다. **랜덤 어텐션**은 프롬프트를 고정하고 각 어텐션 헤드 안에서 균일 무작위로 축출하며 점수를 전혀 계산하지 않습니다. 4개 모델(Qwen3-4B/14B/32B, Phi-4-reasoning)×6개 추론 과제, 약 4배 압축에서 최강 베이스라인(TriAttention)과 동등한 정확도(60개 셀 중 31개 유의하게 앞서고 1개만 뒤짐)를 내며 vLLM 서빙 처리량은 **32–43% 높습니다**.

## 두 가지 규칙, 그 외는 없음

신호 없는 정책입니다. (1) **질문 보호** — 프리필 전체(시스템 프롬프트·템플릿·질문)는 절대 축출하지 않음, (2) **나머지는 헤드별 분산** — 나머지 캐시 위치마다 독립 균일 난수를 부여해 각 KV 헤드가 상위 K개 유지. 축출 비용은 `rand` 한 번과 `topk` 한 번뿐입니다. 동등 예산에서 이를 못 이기는 신호 기반 선택기는 신호에서 usable 정보를 뽑지 못하는 셈이라, 귀무가설 역할도 합니다.

## 신호가 하찮은 이유

두 통제 실험이 설명합니다. 첫째, **프롬프트가 깨지기 쉬운 부분**입니다. 기존 축출기들은 프롬프트 생존 처리가 제각각이라(고정 vs. 점수에 맡김), 모두에 동일 보호 규칙을 주면 격차가 대부분 사라집니다 — SnapKV는 Phi-4 GPQA-D에서 **+22.5점**, 프롬프트를 이미 유지하던 R-KV는 최대 1.9점. 둘째, **추론 흔적은 스스로를 보호**합니다. 텍스트 내 중복(모델이 필요한 것을 재진술)과 헤드 간 중복(각 헤드가 토큰별 복사본 보유)의 2단계 여유가 있어, 심은-사실 탐색에서 1개 헤드 보유 시 회수율 ~3%가 3개 헤드 83%, 8개 전부 99%가 됩니다. 프롬프트만 안전하면 무작위 추출로 충분한 복사본이 남습니다.

| 설정 | 발견 |
|---|---|
| MATH500 / GPQA-D | 어떤 선택기도 유의하게 못 이김. TriAttention의 0.3–0.6점 리드는 잡음 안 |
| AIME / HMMT | 유의하게 앞선 선택기 없음(60문제, 실행 간 표준편차 ~4점) |
| LiveCodeBench(코드) | 격차 최대. 프롬프트 평균 557토큰이 예산 잠식. 그래도 유의한 승리는 TriAttention 1셀뿐 |
| vLLM 서빙, 32k 생성 | 전체 어텐션 대비 1.6–2.7배, TriAttention 대비 **+32–43%**(점수 패스 생략 효과) |

## 주의할 점

HTML 전문(v2)을 참조했습니다. 유일한 유의한 베이스라인 승(Qwen3-32B 코드)은 긴 프롬프트가 예산을 갉아먹은 탓 — 프롬프트 통째 고정은 발판 코드 같은 군더더기까지 예산을 씁니다. 무작위가 못 하는 것은 딱 하나, 한 번만 진술되고 57번 압축 뒤에 필요한 사실(R-KV 84% 회수 vs. 무작위 0%)입니다. 학습 불필요 축출기끼리의 비교입니다.

## SW 엔지니어와의 관련성

- 메모리 예산 하의 추론 서빙은 대체 불가 입력 보호+최저가 정책부터 시작하세요. 복잡도는 동등 예산의 무작위 베이스라인 대비 정당화되어야 합니다.
- 축출기의 정확도는 순위 매기기가 아니라 무엇을 보호하느냐로 갈립니다 — 논문 간 비교 전 보호 체계를 먼저 감사하세요.
- 점수 패스 생략이 페이징 서빙에서 32–43%인 이유: 동시 요청들의 압축이 동기화 지점에 몰리기 때문입니다.
- 코드 같은 장문 프롬프트 과제는 고정(pin)이 아니라 예산 편성이 필요합니다.
