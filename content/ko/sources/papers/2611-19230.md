# CompoundingKernel: Zero to First로 자기 개선하는 시스템

**출처**: [arXiv:2611.19230](https://arxiv.org/abs/2611.19230) · **게시일**: 2026-11-14

## 개요

CompoundingKernel은 검색을 통해 GPU 커널을 작성하는 자기 개선 에이전트 시스템이다. 2026-11-11 기준, 해당 시스템이 생성한 커널은 NVIDIA B200에서 SOL-ExecBench의 공개 L1, L2 및 양자화 리더보드에서 1위를 기록하고 있으며, L1 부문에서는 2026-10-27부터 1위를 유지했고 2026-11-07에 단 한 차례 하락했다. 벤치마크 내 235개 문제 모두 사이트 검증된 올바른 커널을 보유하고 있으며, 공개 문제 209개에서는 생성 커널이 기준 대비 4.40배 빠르다.

검색은 제로 상태에서 시작된다. 에이전트는 각 문제의 PyTorch 정의만 받고 참조 커널이나 공식 점수는 제공받지 않는다. 올바른 커널과 그 계보는 모델 외부의 문제별 아카이브에 보관된다. LLM 컨트롤러가 아카이브를 읽어 부모 설계를 선택하거나 새로운 방향을 제안하고, 병렬 자식 에이전트 각각에게 한 가지 방향을 할당한다. 정확성은 모델이 아닌 외부 검사가 결정한다.

## 핵심 내용

- PyTorch 정의만으로 GPU 커널을 위한 자기 개선 검색을 수행하며, 참조 커널 없이 동작한다.
- 2026-11-11 기준 SOL-ExecBench L1, L2, 양자화 부문 1위; 공개 문제 209개에서 기준 대비 4.40배 빠름.
- 문제별 아카이브가 모든 올바른 커널과 계보를 보관하고, LLM 컨트롤러가 부모를 샘플링해 병렬 에이전트를 지시한다.
- 동일 벽시 시간에서 코딩된 UCB 스타일 트리 탐색 대비 38개 문제 중 35개에서 우세, 올바른 시도 횟수가 2.4배 많음.
- 1,000개 이상 에이전트가 병렬 실행되며, 웜 리스타트 수정으로 평가 속도가 3.6배 증가.
- 에이전트 수보다 신뢰할 만한 측정 속도(rate)가 검색 확장 한계를 결정한다.

## 상세

이 시스템은 컨텍스트 내 학습만 하는 방식이 아니라 지속적인 아카이브를 통한 누적 개선을 강조한다. 컨트롤러는 아카이브 이력을 이용해 어떤 계보를 확장할지, 언제 새로운 설계를 탐색할지 결정하며, 정확성 검사는 외부에 두어 보상 해킹을 방지한다. 실험 결과, 에이전트를 단순히 늘리는 것보다 신뢰할 만한 측정 속도를 높이는 것이 진전을 더 크게 만든다. 코드와 커널은 공개된다.
