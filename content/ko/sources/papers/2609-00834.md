# 훈련을 기억으로 대체하기: Text-to-SQL의 리스트와이즈 선택

출처: Yeonseok Jeong 외 3인, arXiv:2609.00834, 2026-09-01. Findings of EMNLP 2026.

**핵심 요약**: 최신 Text-to-SQL은 생성-실행-선택 파이프라인을 따릅니다. 후보 쿼리를 여럿 만들고 최고를 고르는데, 후보를 합동 비교하는 리스트와이즈 선택이 널리 쓰이지만 파인튜닝이 비쌉니다. 이 논문은 **파인튜닝 없는 리스트와이즈 선택기**를 제안해 두 핵심 파인튜닝 목적을 추론 시점 전략으로 대체합니다. 첫째, 선택 행동을 가중치에 굽는 대신 훈련 데이터에서 증류한 재사용 가능한 **정형 기억(structured memories)** 을 검색합니다. 자연어가 스키마 요소·SQL 연산·예상 출력에 어떻게 매핑되는지를 담은 명시적 판단 기준이라 리스트와이즈 평가에 씁니다. 둘째, 리스트와이즈의 **순서 편향**을 여러 입력 순열에 걸친 랭킹 집계로 완화하고, 실행 결과와 pointwise 채점으로 추론 비용을 통제합니다. BIRD-dev에서 기존 최강 선택기 **R^3-SQL을 같은 후보 집합에서 평균 실행 정확도 2.02점 차이로 넘기고 토큰은 2.92배 적게** 씁니다.

## 절약처가 선택 단계인 이유

베이스 모델이 좋아지며 후보 생성은 점점 싸지지만, 선택기에 파인튜닝 비용이 집중됩니다. 스키마 계열·워크로드가 바뀔 때마다 심판 재훈련이 필요해서입니다. 학습된 선택 기준을 검색된 기억으로 바꾸면 훈련 문제가 검색 문제로 바뀝니다. 기억은 들여다볼 수 있고 모델 across 재사용되며 그래디언트 없이 갱신됩니다. 파인튜닝이 없으니 기존 LLM과 그대로 호환됩니다.

## 훈련 없이 순서 편향을 다스리기

리스트와이즈 심판은 순서에 악명 높게 민감합니다. 후보를 섞으면 판결이 바뀝니다. 논문의 답은 순열 집계 — 여러 입력 순서로 랭킹하고 결합 — 이며, 실행 결과와 pointwise 점수로 가지치기해 전체 리스트와이즈 비교를 줄여 비용을 낮춥니다. 기존 방법보다 불필요한 비교는 적게, 선택은 더 안정적이라는 보고입니다.

## 결과가 보여주는 것

| 지표 (BIRD-dev, 동일 후보 집합) | 결과 |
|---|---|
| R^3-SQL 대비 실행 정확도 | 평균 +2.02점 |
| 토큰 비용 | 2.92배 적음 |
| 안정성 | 파인튜닝 없이 더 안정적 선택 |

동일 후보에서 기존 선택기를 이겼다는 점이 기여를 분리합니다. 이득은 쉬운 후보 생성이 아닌 선택 품질에서 옵니다.

## 주의할 점

이 요약은 초록 기반입니다. 데이터셋별 분해, 순열 수, 지연시간(토큰은 줄었지만 왕복 횟수는 다를 수 있음)은 본문에 있습니다. 결과는 BIRD-dev 중심 Text-to-SQL 벤치마크 — 다른 정형 생성 과제로의 전이는 미확인입니다. 기억 품질이 모든 것을 bound합니다. 오래되거나 안 맞는 기억은 오래된 few-shot 예제처럼 선택기를 정확히 그만큼 오도합니다.
