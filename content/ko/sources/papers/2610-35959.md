# AgentBaton: 에이전트 작업에서의 효율적인 모델 협업

**원문**: [arXiv:2610.35959](https://arxiv.org/abs/2610.35959) · **게시일**: 2026-10-25
**저자**: Junlong Li, Jindong Jiang, Yonggan Fu, Jiarui Yao, Hanrong Ye, Wonmin Byeon, Peter Belcak, Hao Zhang, Pavlo Molchanov

## 개요

장기 호라이즌(long-horizon) 에이전트 작업은 환경과의 반복적인 상호작용, 즉 도구 호출과 피드백 관찰, 행동 수정을 통해 해결되며, 이런 루프에 필요한 신뢰성은 대개 값비싼 성능형 클라우드 모델에서 나온다. 반면 더 저렴한 효율형 모델(하위 티어 클라우드 모델이나 로컬 하드웨어에 올라가는 소형 오픈웨이트 모델)은 단독으로 쓰면 정확도가 떨어진다. 이 논문은 쿼리 단위 라우팅으로는 답할 수 없는 질문을 던진다. 하나의 장기 작업 안에서 성능형 모델과 효율형 모델이 협업해 비용을 크게 줄이면서 정확도를 유지할 수 있는가? 논문이 다루는 협업의 단위는 한 모델이 다른 모델로부터 작업을 넘겨받는 핸드오프다.

에이전트의 행동이 작업 공간을 바꾸고 동적인 피드백을 만들어 내므로 작업에 필요한 역량은 턴마다 변한다. 따라서 첫 쿼리만 보고 모델을 고르는 방식으로는 충분하지 않다. 저자들은 두 가지 설계 선택을 연구한다. 핸드오프 방향(효율형에서 성능형으로, 또는 성능형에서 효율형으로)과 컨텍스트 전달 방식(전체 상호작용 이력을 받는 모델의 컨텍스트에 넣는 방법과, 구조화된 실행 로그를 기록해 받는 모델이 cat, grep, sed 같은 도구로 필요할 때 확인하는 방법)이다. 두 경우 모두 받는 모델은 이전 모델이 만들어 둔 작업 공간에서 이어서 작업한다.

실험은 두 방향 사이의 뚜렷한 비대칭을 보여 준다. 효율형에서 성능형으로의 핸드오프는 로그 파일 전달이 더 유리한 경우에도 대체로 성능형 단독 실행보다 성능이 낮았고 비용 절감도 제한적이거나 없었다. 반대로 작업 진행의 적절한 단계에서 성능형에서 효율형으로 넘기는 핸드오프는 성능형 단독 실행의 정확도를 대체로 유지하면서 비용을 크게 줄였다. 이는 일방향 의존성을 뜻한다. 성능형 모델이 쌓아 둔 진행 상황이 효율형 모델이 단독으로는 풀기 어려운 작업을 마무리하게 해 준다는 것이다. 또한 빈번한 턴 단위 전환은 누적된 궤적 오류를 성능형 모델이 계속 복구해야 하므로 실용적이지 않다는 결론으로 이어진다.

## 핵심 내용

- 사례 연구는 핸드오프 적기를 규정한다. 성능형 모델이 이미 실질적인 구현이나 산출물을 만들고 작업 관련 피드백을 확보한 상태여서, 남은 일이 주로 국소적인 수정과 검증, 마무리에 그치는 시점이다.
- AgentBaton은 손으로 쓴 규칙이 아니라 실행 이력에서 반복되는 패턴을 학습한 경량 탐지기다. 성능형 모델이 작업을 시작하고 AgentBaton이 매 턴 진행 상황을 평가하며, 적합한 핸드오프 지점을 예측하면 효율형 모델이 종료까지 이어서 수행한다.
- 11개의 성능형·효율형 모델 조합과 Terminal Bench 2.1, DeepSWE v1.1 두 벤치마크에서 AgentBaton은 API 비용을 평균 65.9% 줄이면서 정확도를 대체로 유지했고, 성능형 단독 실행 대비 최대 8.8%포인트의 정확도 향상도 보였다.
- 저자들은 방향별로 컨텍스트 전달 방식도 비교했고, 선호되는 방식이 모델마다 다르다는 점을 확인했다. 컨텍스트에 이력을 넣는 방식은 받는 모델이 이전 진행을 재사용하는 데 도움이 되지만 핸드오프 시점의 프리필 길이와 이후 턴의 입력 길이를 늘리고, 이전 모델의 추론과 행동에 노출되어 편향될 수 있다.
- 추론 강도 설정을 바꾼 실험에서도 AgentBaton은 하나의 고정 예산이 아니라 실제 정확도·비용 파레토 프런티어를 확장하는 것으로 나타났다.
- 잘 맞춘 한 번의 핸드오프로 충분하다는 것이 결론이다. 결과는 단 한 번의 단순하고 시점이 좋은 전략이 더 복잡한 협업 방식보다 비용 효율적인 에이전트 실행에 유리하다는 것을 보여 준다.

## 상세

평가는 여러 성능형·효율형 조합에서 두 핸드오프 방향을 모두 다루며, 컨텍스트 전달은 두 가지 변형으로 비교한다. 이전 상호작용 이력을 받는 모델의 컨텍스트에 직접 넣는 방식과, 구조화된 실행 이력을 로그 파일로 남겨 받는 모델이 필요할 때 읽는 방식이다. 논문에 따르면 효율형에서 성능형으로의 핸드오프는 로그 파일 전달의 이점을 얻고도 성능형 단독 실행을 넘지 못했지만, 성능형에서 효율형으로의 핸드오프는 훨씬 낮은 비용으로 정확도를 유지했다. 다만 어떤 전달 방식이 더 나은지는 관여한 모델에 따라 달랐다. 탐지기의 동기로 저자들은 이질적 모델 조합에 대한 기존 연구가 개별 요청의 쿼리 단위 라우팅과 캐스케이딩에 집중해 왔고, 그래서 궤적 중간에 새로 생기는 역량 요구를 포착하지 못한다고 지적한다.
