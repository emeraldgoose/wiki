# EditAgent: 에이전틱 이미지 편집 재고

출처: Haiyang Xu, arXiv:2610.39664, 2026-10-29.

**핵심 요약**: 에이전틱 이미지 에디터는 복잡한 요청을 단계로 분해하지만 단계가 실패하면 같은 좁은 도구 집합으로 재시도하고 심사자가 눈으로 각 출력을 직접 채점합니다. 저자들은 이런 에이전트가 두 공간에 제한된다고 봅니다. **에이전트가 할 수 있는 것**(행동 공간)과 **심사자가 볼 수 있는 것**(관찰 공간)입니다. 전문가 주석 벤치마크에서 범용 에디터는 40% 이상 케이스에서 사용 가능한 결과를 내지 못했고, 어떤 심사자도 모든 편집 유형에서 신뢰할 수 없었습니다. **EditAgent**는 두 공간을 확장합니다. 각 단계를 범용 에디터와 특화 메서드로 라우팅하고, 각 후보에 **검증 기록**을 붙입니다. 이 기록 덕분에 off-the-shelf VLM 심사자가 finetuned reward model을 앞섭니다. 후보들은 병렬 생성되고 한 번의 listwise 호출로 채점되며, 전문가들은 이를 순차 정제보다 **78.5% 결정 비교에서 선호**했고 심사 호출은 절반 이하로 줄였습니다. EditAgent는 3개 벤치마크에서 두 open-weight 에디터를 개선하고 더 강한 에디터 훈련용 데이터 엔진으로도 작동합니다.

## 핵심 내용

- 기존 에이전트는 전문가 벤치마크에서 40% 이상 실패했다.
- 어떤 단일 심사자도 모든 편집 유형에서 신뢰할 수 없었다.
- EditAgent는 단계를 범용·특화 메서드로 라우팅한다.
- 검증 기록이 심사자의 관찰 공간을 확장한다.
- 기록이 있으면 VLM 심사자가 finetuned reward model보다 좋다.
- 병렬 생성 + 하나의 listwise 심사를 78.5%에서 더 선호했다.
- 심사 호출이 순차 정제 대비 절반 이하로 줄었다.

## 상세

후보 생성이 순차 정제가 아닌 병렬로 이루어져 심사 호출을 줄이고 전문가 선호가 listwise 방식에 쏠렸습니다. 확장된 행동·관찰 공간으로 실패 복구가 더 안정적이고, 수집 데이터는 더 강한 에디터 훈련에 쓸 수 있습니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 검증 기록 구성과 라우팅 규칙 세부는 원문을 함께 확인해야 합니다.

## SW 엔지니어와의 관련성

- 이미지 편집 에이전트는 도구 다양성과 검증 기록으로 실패 복구가 개선됩니다.
- 심사자 강건성은 edit type별로 측정해야 합니다.
- 병렬 후보 + listwise 채점은 호출 비용을 줄입니다.
