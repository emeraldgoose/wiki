# RSI-Anything: 월드 모델로 재귀적 자기 개선 열기

**Source**: Cui 외, arXiv, 2026-10-09

**핵심**: 재귀적 자기 개선은 상호작용 경험을 지속적 향상으로 바꿔야 하지만 외부 피드백은 비싸고 정책이 바뀌면 월드 모델 예측이 낡는다. 도메인 범용 JEPA-Anything 예측기 기반의 RSI-Anything는 월드 모델 예측으로 행동·학습 데이터 선택을 안내하고, 관측 피드백으로 정책/워크플로 업데이트와 조건부 월드 모델 적응을 수행한 뒤, 요소·호환성 검사를 통과한 정책–모델 쌍만 유지한다. 코드 수리·GUI 에이전트·실험실 계획·반응 최적화·면역 과학 적용에서 매 루프가 유지된 개선을 다음 학습으로 연결한다.

## 배경

태스크 내 피드백은 해를 다듬고 라운드 간 자가 학습은 정책을 갱신하지만, 재귀성은 업데이트가 지속되어 이후 상호작용을 바꿔야 한다. 월드 모델은 후보를 사전 순위화해 피드백 예산을 아끼지만, 정책 업데이트는 예측기의 데이터 분포를 바꾸고 예측기 업데이트는 선택되는 후보를 바꾼다—한쪽만 개선해선 결합 성능이 보장되지 않는 결합 업데이트 문제다. RSI-Anything는 진화하는 정책 하의 예측 신뢰도를 명시적 설계 요구로 둔다.

## 프레임워크: 예측·업데이트·유지

각 사이클은 3단계다. **예측 안내 선택**은 월드 모델 판독 $R_d(\hat{\tau}) = \sum_j w_{d,j} r_{\tau,j} - \Delta_d(\hat{\tau})$(불확실성 패널티 선택)로 정책 제안 후보를 점수화하고 감당 가능한 것만 실행하며, 고효용 상상 궤적은 별도 근거 게이트로 학습 데이터에 편입한다. **피드백 기반 개선**은 관측을 정책 업데이트(시범·선호·워크플로 탐색)로 바꾸고, 현 버전 예측 기반 신뢰도 판정이 "불신뢰"이고 데이터·예산이 충분할 때만 예측기를 적응시킨다. **재귀적 유지**는 각 요소 검사와 조립 시스템의 결정 동작에 대한 쌍 검사를 매칭 평가 조건에서 수행하고, 실패 시 현 버전을 유지하므로 통과한 쌍만 다음 라운드를 빚는다.

## 실험

**설정**: 고정 ReasonFlux-Coder-7B로 200개 CodeContests 과제(3시드, 최대 3회 피드백, 라운드당 4후보), GUI는 MiniWoB++ 체크박스·OSWorld, LabHorizon F200 Level-2(200과제)에서 연속 4B 정책 5버전, 베이지안 최적화와 동일 실험 횟수의 Suzuki–Miyaura 반응 스크린 2종.

**결과**:

| 영역 | 기준 | RSI-Anything | 비고 |
|--------|----------|--------------|------|
| 코드 수리(히든 통과율) | 26.3% 정적 검증기 | 29.2% 고정 WM → 31.2% 적응 WM | 온라인 호출 동일 ~3.7회/과제, 순위 66.5→72.8%, Brier 0.488→0.358 |
| GUI 체크박스 | 51% 성공, 5.30 액션/에피소드 | 99% 성공, 3.21 액션/에피소드(−39.4%), 반복 클릭 0 | OSWorld는 RLAnything 대비 +5.5% 상대 향상 |
| 실험실 계획(Final Score) | 21.80% v1 | 46.01% v5 (+24.21pp) | Actor–Simulator–Selector 45.32% 상회 |
| 반응 GC 스크린(20회) | 87.5% BayesOpt | 93.0% (+5.5pp) | 플로우 스크린 40회: 96.15% vs 82.16% (+13.99pp) |
| APPS Intro / LiveCodeBench | 무작위·정적 하회 | 46.37% / 33.05% | 동일 코더·예산 |

면역 과학 종단 적용은 워크플로 진화·면역 월드 모델 구축·자가 수정 분석·치료 가설 생성을 연결한다(실험 검증 대기).

## 소프트웨어 엔지니어를 위한 시사점

피드백 예산이 빠듯한 자가 개선 에이전트 시스템의 청사진이다:

- **비싼 행동 앞에 학습 예측기를**: 실제 실행·테스트·실험 전에 저비용 월드 모델로 후보를 순위화하라—동일 온라인 사용량에서 향상이 유지됐다.
- **각 요소가 아닌 정책–예측기 쌍을 버전 관리**: 조립 동작의 호환성 검사가 "더 좋은" 예측기의 배포 루프 악화를 막는다—검사 실패 시 현 버전 유지.
- **예측기는 조건부 적응**: 현 버전 예측 기반 판정이 불신뢰이고 새 데이터가 충분할 때만 재적합해 churn과 낡은 풀링을 피하라.
- **유지 버전별 지표 추적**: 실험실 계획 5버전 연속 향상처럼 유지된 개선마다 누적 승을 측정하면 수용 게이트 단계적 롤아웃에 맞는다.
