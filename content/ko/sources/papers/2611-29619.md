# Wactorz: 엣지에서 스스로를 발견·복구·이전하는 자기 작성 LLM 에이전트

**Source**: [arXiv:2611.29619](https://arxiv.org/abs/2611.29619) · **게시일**: 2026-11-22 (v1)
**Authors**: Panagiotis Kasnesis, Lazaros Toumanidis, Amalia Contiero Syropoulou, Christos Chatzigeorgiou

## 개요

대부분의 LLM 에이전트 프레임워크(AutoGen, CrewAI, LangGraph)는 작업을 실행하고 끝나는 크루를 모델링하는 반면, 엣지 자동화 도구(Home Assistant 규칙, Node-RED)는 오래 살지만 정적이다. 물리 환경에는 수개월 동안 살아남고 자신의 버그를 견디며 기존 저전력 하드웨어에서 도는 에이전트가 필요하다. Wactorz는 세 가지 전통을 결합한다. Erlang/OTP의 액터 모델과 트리, 런타임에 자신의 동작을 작성하는 코드 생성 LLM 에이전트, 그리고 유일한 조율 기판으로서의 MQTT pub/sub다. 결과는 Mosquitto 브로커만 따로 두는 단일 프로세스 asyncio 액터 시스템이다. 모든 에이전트는 inbox, 메시지 루프, 10초 하트비트, persist()/recall() 키-값 API(SQLite, 모델/넘파이/텐서용 블롭 파일, 나머지는 pickle)를 가진 Actor이며 name@node로 주소가 매겨져 두 머신에 같은 이름의 에이전트가 존재할 수 있다.

채팅 요청은 MainActor가 분류한다(직접 구동, Home Assistant 질의, 파이프라인, 채팅). 파이프라인은 요청별 임시 PlannerAgent로 가서 JSON 계획과 단계별 Python 소스(setup()/process()/handle_task())를 내놓는다. 각 블록은 재시작 없이 DynamicAgent로 스폰된다. InstallerAgent가선언된 종속성을 pip 설치하고(허용목록, 아니면 대시보드에서 운영자 승인), 신뢰할 수 있는 레시피 카탈로그가 일반적인 요구를 커버한다. 에이전트는 결코 이름으로 서로를 부르지 않는다. TopicBus가 토픽마다계(생산자, 소비자, 캡처된 샘플 페이로드)을 등록해, 나중 플래너에게 실제 계약이 전달되므로 소비자는 실제로 존재하는 페이로드 필드를 읽는다. 이는 두 LLM이 필드 이름에서 다투는 고전적 실패를 없앤다.

## 핵심 내용

- 감독과 자동 치유: 생성 코드는 사전 실행 AST 차단목록(쉘 실행, 파일 삭제, eval 금지)을 통과한다. 새니타이저가 동기 메서드를 await하는 흔한 실수를 고친다. setup()/process()/구독 콜백의 반복 런타임 오류는 트레이스백과 함께 LLM에 전달되어 제자리에서 복구되고 스폰 레지스트리에 저장된다. process() 호출은 타임아웃으로 보호된다. 그 위에서 Supervisor는 ONE_FOR_ONE 재시작을 적용한다. 충돌한 에이전트만 혼자 재시작되고 저장된 상태를 다시 불러오며, 연속 충돌 시 백오프가 분 단위로, 최대 1시간까지 늘어난다. MonitorActor는 하트비트를 추적하며, 컴파일에 실패한 에이전트는 고의로 재시작하지 않고 사용자에게 보고한다. 스폰 레지스트리가 영속되므로 재부팅 후에도 모든 dynamic 에이전트가 돌아온다.
- 토픽 그래프 관찰성: 대시보드 Wiring 뷰(GET /api/wiring 제공)는 에이전트와 토픽을 머신별로 묶어 그리고, 고아 토픽, 생산자 없는 구독자, 선언과 관찰 페이로드 사이의 필드 불일치를 표시한다. 에이전트나 토픽을 선택하면 마지막 페이로드를 보여준다.
- 운영자 개입: 에이전트는 notify_user / ask_operator로 대시보드, 텔레그램, 디스코드, 왓츠앱을 통해 운영자에게 알리거나 질문할 수 있고, 대기 상태는 재시작 후에도 유지되며 대시보드 Inbox에 대기 중인 질문과 패키지 승인이 나열된다.
- 엣지 노드와 실시간 이전: Python 3.11이면 어떤 머신도 wactorz --node로 노드가 된다. /deploy는 SSH로 프로비저닝한다(venv, systemd 유닛 + 와치독, 브로커에 하트비트가 닿은 후에야 성공 보고). /migrate AGENT NODE는 에이전트를 멈추고 상태를 JSON으로, 블롭을 자체 토픽에서 SHA-256 검증 청크로 보내고, 목적지가 시작을 확인하기 전까지 소스 복사본을 유지한다. 노드에서 떠나는 에이전트는 항상 메인의 프로그램 복사본에서 재시작되며 노드가 넘겨준 코드로는 재시작되지 않는다. 상태 상한 8 MiB, 블롭 64 MiB.
- 보안 모델: API 키 없이는 loopback에만 바인딩; 노드 명령은 서명; 브로커 연결은 TLS; 노드별 브로커 계정과 접근 목록; 메인은 해당 노드의 회신만 수용; 모델 작성 에이전트는 자격 증명이 없고 브로커에만 닿는 샌드박스 컨테이너에 가둘 수 있다.
- 모델 비종속/오프라인: 제공자(Anthropic, OpenAI, Gemini, NVIDIA NIM, Ollama)를 호출 위치별로 설정(저렴한 로컬 4B는 라우팅, 코드 생성은 호스티드); 내장 평가 하네스가 호출 위치별로 모델을 채점(라우팅 정확히 일치, 구동은n예상되는 거부를 포함한 행동 집합 일치, 계획 유효성, 컴파일 검사)하고 정확도/지연/비용을 보고한다. 결정적 가짜 제공자와 --minimal 프로필은 모델 없이 실행된다.
- 라이브러리로서의 Wactorz: 데코레이터가 수작성 함수를 같은 종류의 감독/영속/토픽 배선/이전 가능 에이전트로 바꾼다. SUBSCRIBES/PUBLISHES/스키마를 가진 Actor 서브클래스도통합된다. LangGraph/AG2 그래프도 에이전트로 돌며 me.llm을 통해 모델을 호출하고 비용이 집계된다.
- 엣지의 모델: wactorz-artifacts가 메인에 이름+버전으로 모델을 저장(SHA-256 중복 제거). load_model은 npz/npy/safetensors/state_dict/ONNX를 파일 코드를 실행하지 않고 읽고, pickle/joblib/전체 torch 모듈은 allow_code=True 없이는 거부한다. 이전 시 정확한 모델 버전을 고정하고 노드는 캐시에 없는 것만 받아 해시를 검사한다. active/shadow 포인터와 감사된 프로모션 정책(지표, 마진, 최소 일수, 레이블된시행에서 precision/recall/F1/오경보)이 트레이너/드리프트 에이전트(PSI, KS, ADWIN)와 함께 루프를 닫는다.
- 데모: 채팅 하나로 카메라 사람 감지 -> 램프 구동; 토픽으로 자동 배선된 카운터가 4초간 3번 ZeroDivisionError를 일으키고 LLM이 코드를 복구해 10, 11, 12...로 계속됨; bare Raspberry Pi를 /deploy하고 카운터를 그 위로 /migrate — 4분 미만, 총 모델 비용 $0.13, 모든 호출에 Claude Sonnet 5.
- 한계(저자 명시): 검증기는 AST 차단목록이지 샌드박스가 아니다(간접 이름은 통과, 한 프로세스 내 모든 에이전트는 같은 권한 — 격리는 배치로 달성). 복구는 생존성을 복원할 뿐 의도는 아니다. 직렬화 불가 상태는 강제하지 않으면 이전을 막는다. 메인과 노드는 같은 릴리스 계열을 실행해야 한다. 복구 성공률에 대한 체계적 측정은 아직 없다(평가 하네스가 그 향후 연구의 도구).

## 세부 사항

아키텍처(MainActor, PlannerAgent, DynamicAgent, InstallerAgent, Supervisor, MonitorActor, TopicBus, Mosquitto), Wiring 뷰, 감독/자동 치유 파이프라인, 운영자 채널, /deploy와 /migrate 프로토콜과 일관성 규칙, 보안 모델, 호출 위치별 제공자 설정과 평가 하네스, 라이브러리 API, wactorz-artifacts 모델 저장/전송/교체(active/shadow, 프로모션 정책, 트레이너/드리프트 에이전트)를 설명한다. 데모 섹션은 녹화된 5단계를 따라간다. pip 패키지, Docker 이미지, Home Assistant 애드온으로 Apache-2.0에배포되며 500개 파일 테스트 슈트를 포함한다. 코드: github.com/waldiez/wactorz.
