# MORSE: 오픈 월드 자동 연구를 통한 스트리밍 메모리 설계 최적화

**원문**: [arXiv:2611.30011](https://arxiv.org/abs/2611.30011) · **게시일**: 2026-11-23 (v1)
**저자**: Ce Zhang, Jianshu Zhang, Jinxi He, Xiyuan Yang, Pan Wang, Han Liu, Katia Sycara, Yaqi Xie

## 개요

스트리밍 비디오 시스템은 진행 중인 스트림에 대해 단 한 번의 패스로 답변해야 하며, 제한된 프레임 저장 공간만 가지므로 어떤 증거를 보존할지 미래 질문을 알기도 전에 결정해야 합니다. 보존된 증거를 선택·정리하는 쓰기 정책과 질문 시 증거를 검색해 VLM에 넘기는 읽기 정책을 합쳐 '스트리밍 하네스'라고 부르는데, 이는종래 연구자가 직접 설계했고 재귀적 자가 개선 방법도 에디터가 사전 지식과 미리 정해진 도구 안에서 고안한 수정안만 자동화했습니다. MORSE(Memory Optimization with Recursive Self-Evolvement)는 오픈 월드 자동 연구로 이 간극을 메웁니다. 학습 비디오들에서 실패가 반복되면 LLM 기반 에디터가 논문, 모델 페이지, 코드를 온라인에서 검색해 적응 가능한 해결책을 찾고,사전학습된 지각 모델을 요청할 수도 있습니다(호스트가 출처를 검토하고, 벤치마크 데이터와 정답 주석 접근은 브로커가 차단해 유출을방지합니다).

프레임워크는 두 역할을 가집니다. 스트리밍 솔버는 동결된 답변 VLM 주위에서 하네스를 실행하고, 에디터는 학습 궤적을 검사해 실패를 원인별로 묶습니다. 각 라운드는 4단계 루프를 따릅니다. 진단(궤적으로부터 실패 그룹 도출, 저장 누락과 검색/지각 실패를 구분), 조사(예산 B_res 안에서 외부 컬렉션 W의 논문·모델 페이지·코드 검색), 제안(최대 B개의 실행 가능 후보와 도구 요청; 승인된 도구는 도구 집합 T에 추가), 검증(호스트가 비공개 검증 스트림에서 후보를 채점하며 에디터는 집계 점수만 봅니다).

선택은 홀드아웃 스트림에서 두 단계의 게이트로 이뤄집니다. 정확도 라운드 K_acc개는 후보의 정답 선택지 확률 평균 P̄가 최소 δ 이상 오를 때만 수용하고, 그다음 효율성 라운드 K_eff개는 지연이 부모의 ρ 비율 이하로 떨어지면서도질 손실이 회차당 ε, κ(및 총 ε_tot, κ_tot) 이내일 때만 수용합니다. 정확도 단계는 P̄를 최대화(동률은 저지연우선), 효율성 단계는 지연 ℓ을 최소화(동률은 고P̄우선)하며, 같은 부모를 가진 통과 후보는 병합 후 재검증할 수 있고 정확도 라운드는 아카이브된 미선택 후보도 풀에 포함합니다.

## 핵심 내용

- 세 스트리밍 벤치마크 모두에서 같은 동결 백본 내 최고 답변 정확도. OVO-Bench(1,468문항, 실시간+역추적): Qwen3-VL-8B + MORSE 75.1%(RT 82.4/BT 65.3)로 MemEvo 72.0, StreamScout 69.7, OASIS 69.2, FluxMem 61.6, 원본 백본 60.1을 앞섬. Qwen2.5-VL-7B + MORSE 69.9(MemEvo 64.4), Qwen3.8-27B + MORSE 79.4(MemEvo 71.1, FluxMem 75.8). StreamingBench 질문 가중 평균은 Qwen2.5-VL-7B에서 75.8(MemEvo 71.9, StreamScout 71.3).
- 빠름: OVO-Bench에서 Qwen3-VL-8B 하네스는 평균 0.30초에 답변 — MemEvo보다 6.0배, OASIS보다 3.5배, 샘플 프레임 직접 답변보다 1.6배 빠름. 정확도 라운드 후 하네스는 답변당 0.82초가 필요했는데, 효율성 라운드는 재사용 계산을 메모리구축으로 옮겨(쓰기 비용 8초 비디오당 0.87→1.19초, VLM 호출 1.49→0.77초가 차감되어 MemEvo보다 여전히 33% 낮음) 답변 지연을 0.30초로 단축(정확도 후 하네스보다 2.7배 빠름).
- 구성 요소 절제(OVO-Bench, 동일 시드에서 25라운드, 시드 전체 67.4%): 온라인 조사 제거 시 72.9%(+5.5), 도구 요청 제거 시 70.6%(+3.2), 전체 MORSE 75.1%(+7.7). 두 오픈 월드 구성 요소가 모두 기여하며 조사가 도구보다 더 큼.
- 설정: 비디오 1fps 샘플링, 영구 저장소 64프레임 + 16초 최근 윈도, VLM 호출당 최대 32프레임/프레임당 256 비주얼 토큰, 시드 하네스는 16초 VLM 캡션 + 최근 4프레임으로 답변, 초기 지각 도구는 CLIP ViT-L/14와 OCR, 에디터는 라운드마다 새로운 샌드박스 Claude Code 세션의 Claude Opus 5.5.
- 데이터 무결성: 에디터는 780개 학습 질문/370개 스트림(NExT-GQA, STAR, ReXTime, COIN, YouCook2, OVBench-COIN)에서 진단, 후보 선택은 분리된 388개 문항/182개 스트림 검증세트에서 집계 점수만 노출, 테스트 벤치마크(OVO-Bench, StreamingBench, StreamBench)는 개발에 사용하지 않음. 브로커가 벤치마크 저장소·데이터셋 페이지·정답 주석을 차단하고, 평가 비디오로 학습된 모델은 제외되며 비생성형 도구 추가만 허용됩니다.

## 상세

P̄(H)는 검증 질문 전체에서 정답 선택지의 확률을 답변 위치의 유효 선택지들로 재정규화한 평균으로, 단순 정답률 c/N과 달리 예측이 뒤집히기 전에 향상을 감지합니다. 게이트: 정확도 g_acc는 ΔP̄ ≥ δ, 효율성 g_eff는 ℓ' ≤ ρℓ(H), ΔP̄ ≥ −ε, Δc ≥ −κ를 요구하고, 둘 다 ℓ' ≤ L, ω' ≤ 1,질문 수 변화 없이 모든 검증 스트림 완료를 요구합니다. 테스트 프로토콜: OVO-Bench와 StreamingBench는 질문 가중 다지선다 정확도, StreamBench는 공식 LLM 심사 자유 응답 프로토콜, 모든 질문은 해당 시점까지의 관측만 봅니다. 답변 모델은 vLLM 그리디 디코딩으로 서빙됩니다.
