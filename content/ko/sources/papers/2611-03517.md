# 물어보고, 장비로 무장하지 말라: 심층 커널 최적화를 위한 질문 주도 코딩 에이전트

**원문**: [arXiv:2611.03517](https://arxiv.org/abs/2611.03517) · **게시일**: 2026-11-02
**저자**: Gabriele Oliaro, Jaeseong Lee, Zhaoyuan Su, Sreeram Vennam, Zhihao Jia, Samyam Rajbhandari

## 개요

GPU 커널 최적화를 위한 LLM 에이전트는 구조-자유도 tradeoff의 양 끝에 위치한다. 스크립티드 에이전트는 학습된 정책, optimization menu, 고정 역할로 매 step 모델이 할 일을 고정하며, recipe가 맞으면 sample-efficient하고 아니면 stall한다. open-ended 에이전트는 self-directed 모델이 kernel population을 변형하고 그 자유도 비용을 수천 번 평가, 반복 편집, wrong candidate로 지불한다. 둘은 더 어려운 목표에 parsed profiler output, disassembly analysis, documentation/library retrieval, lesson stores 같은 더 많은 장비로 응답한다. 논문은 둘 모두 "남은 gap이 어디인지" 가설, 즉 방향이 부족하며, 적절한 시점에 짧은 질문 하나가 에이전트가 다음에 무엇을 할지 좁히지 않으면서 그 방향을 제공한다고 주장한다. 기존 CUDA kernel을 더 빠르게 만드는 KernelSeek를 제시한다: operator-specific 지식이나 모방할 faster implementation 없이, general-purpose coding agent, verifiable goal을 강제하는 minimal harness, decision point에서의 질문(처음은 human, 이후 agent가 itself에 적용하는 bank)으로 구성된다. 동일 task/evaluator/hardware/주에서 tool-rich autonomous agent는 133 model-driven steps 후 0.50x FlashAttention-3에 plateau했으나 KernelSeek는 1.13x에 도달했다. 이어 CUTLASS/CuTe/cuBLAS/cuDNN 없는 단일 CUDA 파일, Hopper/Blackwell 의존성 없는 FlashAttention forward kernels를 만들어 각 architecture 182 scenarios에서 all correct와 geometric mean 1.16x/1.46x를 얻었다. 162 human messages와 11.5K agent tool calls 전반에서 모든 큰 gain은 정보를 공급한 질문이 아니라 에이전트를 다른 layer로 옮기거나 claimed limit을 reject한 질문 뒤에 발생했다. 논문은 kernels, harness, question bank, all traces를 공개한다.

## 핵심 내용

- scripted agent는 recipe에 잘 맞으면 efficient하지만 맞지 않으면 stall한다.
- open-ended agent는 freedom을 주지만 evaluation/edit/오답 비용이 크다.
- 방향(remaining gap hypothesis)의 부재가 핵심이며 더 많은 도구가 이를 대체하지 못한다.
- 적절한 decision point의 짧은 질문은 자유를 좁히지 않고 방향을 준다.
- KernelSeek는 0.50x에서 정체한 tool-rich agent와 달리 1.13x에 도달하고 dependency-free kernels에서 1.16x/1.46x를 달성했다.

## 상세

평가 예산은 고정 task/evaluator/hardware/one-week이다. 162 human messages와 11.5K tool calls이 기록되었다. 공개 artifacts는 kernels, harness, question bank, traces; 상세 분석은 연결된 원문을 참고한다.
