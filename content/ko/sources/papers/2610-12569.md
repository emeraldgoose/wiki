# SWE-Duel: 코딩 에이전트를 위한 자기 확장 아레나

**Source**: Minn 외, arXiv, 2026-10-08

**핵심**: 정적 코딩 벤치마크는 공개되는 순간 훈련 데이터에 유출되기 시작하고 에이전트에 뒤처지며, 지속 갱신형 변형도 난이도는 인간 이슈 수준에 고정된다. SWE-Duel은 *자기 확장* 아레나를 제안한다: 두 코딩 에이전트가 거울형 Red–Blue 턴으로 서로를 평가하고, Red 에이전트가 평가 시점에 숨은 버그가 포함된 새 기능을 작성하며, Blue 에이전트는 이를 블라인드로 리뷰·수리해야 한다. 1,500턴 토너먼트 결과 이 형식은 에이전트 순위를 일관되게 매기고, 과업 작성 능력과 해결 능력을 분리하며, 작성자 역량에 따라 과업 난이도가 올라감을 보인다.

## 배경

저장소 수준 벤치마크(SWE-bench와 후속작)는 공개된 고정 과업 세트를 써서 결국 훈련 코퍼스에 흡수되고, 갱신 기반 변형(SWE-bench-Live, SWE-rebench)은 새롭지만 어렵지는 않은 과업을 모은다. 모델 생성 과업 접근(BugPilot, SwingArena)도 고정된 인간 작성 과업 풀에 의존한다. 요구 조건은 두 가지다: 과업과 오라클을 *평가 시점에* 생성할 것(사전에 존재해 유출될 것이 없음), 난이도를 릴리스 시점이 아니라 *참가자*가 정할 것.

## Red–Blue 대결 프로토콜

과업은 저장소, 기능 명세, 풀 리퀘스트 diff(기능 + 숨은 버그), 기능 테스트, 봉인된 버그 유발 테스트의 튜플이다. Blue는 공개 묶음만 받고 버그 존재조차 듣지 못하며, 기존 테스트·기능 테스트·봉인 버그 테스트가 모두 통과해야만 턴에서 이긴다(엄격한 논리곱, 부분 점수 없음). 버그가 새 기능 안에 살므로 PR을 되돌리는 것으로는 이길 수 없다.

Red는 문맥이 격리된 세 세션과 실행 가능한 검증 게이트로 과업을 만든다: (A) 기능 구현—기능 전용 diff에서 기존·기능 테스트 통과, (B) 버그 삽입—버그가 모든 가시 테스트를 녹색으로 유지하면서 봉인 테스트는 깨끗한 기능에서 통과·버그 diff에서 실패, (C) 블라인드 자기 수리—같은 에이전트의 새 세션이 공개 묶음만으로 버그를 고쳐야 하며, 이를 통과해야 풀이 가능함이 보장된다. 통과한 과업은 뱅크에 저장돼 모든 상대에게 동일하게 제시된다. 매치는 같은 저장소에서 양 역할을 수행하고, 빈 슬롯(소진)은 생존자 편향을 피하려고 Blue 승리로 처리한다. 토너먼트는 라운드로빈 + Bradley–Terry 평점이며, 신규 참가자는 적극 샘플링된 $\lceil \log_2 M \rceil + 1$ 매치로 합류한다.

## 실험

**설정**: 11개 모델–하네스 참가자(GPT-5.5, Claude Opus 4.8, Kimi K2.7 Code, DeepSeek-V4-Pro, GLM-5.2, Qwen3.7-Max, Nemotron-3-Ultra, MiniMax-M3, 뒤늦은 참가자 Gemini 3.1 Pro; 하네스 mini-swe-agent, Codex CLI, Claude Code), 5개 언어 15개 저장소(Python, Java, Go, JavaScript, C/C++). 50매치 × 30턴 = 1,500턴. 총 API 비용 $2,109(매치당 ~$26), 신규 참가자 온보딩 $243.

**결과**:

| 참가자 | BT 평점 | Red 승률 | Blue 승률 |
|-------------|-----------|-----------|------------|
| GPT-5.5 + Codex CLI | +2.82 | 11.3 | 98.7 |
| Claude Opus 4.8 + mini-swe-agent | +2.46 | 27.3 | 88.7 |
| GPT-5.5 + mini-swe-agent | +2.13 | 10.4 | 97.0 |
| Kimi-K2.7-Code + mini-swe-agent | +1.82 | 15.6 | 90.4 |
| DeepSeek-V4-Pro + mini-swe-agent | +1.50 | 18.5 | 91.9 |

선두는 서로 다른 방식으로 이긴다: GPT-5.5는 최강의 해결자(Blue 승률 98.7%), Claude Opus 4.8은 최강의 과업 작성자(Red 승률 27.3%, GPT-5.5의 2배). 경합 턴에서 Blue 성공률은 85.1%(깨끗한 수리 1,037건, 버그 출하 158건, 붕괴 24건)다. 언어별로는 Java가 가장 수리 쉽고(89.2%) Node가 가장 어려우며(82.9%), 로직 오류가 가장 고치기 어렵다(81.9% 수리). 난이도는 작성자 역량에 따라 확장된다: GLM-5.3의 과업은 고정 DeepSeek-V4-Pro 해결자를 42.9% 이기지만 GLM-5.1/5.2 과업은 8.3%/0.0%다(추세 검정 $p = .015$). 품질 검증도 통과한다: 재실행 풀드 자기 수리율 91.7%, 수동 감사 봉인 테스트 오탐률 6.0%. Gemini를 5매치로 뒤늦게 합류시켜도 기존 순위는 그대로다(Kendall $\tau = 1.0$).

## 소프트웨어 엔지니어를 위한 시사점

SWE-Duel은 코딩 에이전트를 만들거나 도입하는 팀에 바로 쓸 수 있다: 과업 내용을 미리 선별하는 대신 평가 시점에 생성하는 오염 방지 평가를 실행하는 공개 툴킷이다. Red–Blue 패턴(작성자가 결함을 숨기고, 리뷰어가 블라인드로 고치며, 봉인 테스트가 판정)은 벤치마킹을 넘어 일반화된다—리뷰 봇·결함 위치 특정 에이전트·수리 파이프라인의 적대적 테스트나 수리 모델의 훈련 데이터 생성에 쓰라. 역할 분리도 채용식 렌즈다: 해결 능력과 과업 작성(테스트 작성, 버그 발견) 능력은 다르며 따로 측정해야 한다. 실무상 주의점: 통과한 과업은 정의상 작성자 자신이 풀 수 있는 수준이므로 난이도 상한은 작성자 역량에 묶인다.
