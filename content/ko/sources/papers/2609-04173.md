# 마지막 번역 벤치마크

출처: Vilém Zouhar 외 259인, arXiv:2609.04173, 2026-09-03 (v2 2026-09-29). Typst 조판.

**핵심 요약**: 기계번역 평가는 막혔습니다. 모델이 강해지며 표준 벤치마크는 포화되고, 자동 지표는 믿기 어렵고 불투명하며 해킹 가능하고, gold 인간 평가조차 재현성·객관성·확장성이 부족합니다. **마지막 번역 벤치마크(LTB)**는 **최고 기계번역 모델을 깨뜨리는 인간 작성·동료 검토 예제(텍스트·이미지·오디오·비디오)**를 모으고, 각 예제에 **수제 검증 규칙**으로 구체적 실패 양상을 기술합니다. 기여를 계속 받는 **라이브 데이터셋**이며, **LTBv1**은 2026-09-01 이전 수락분을 담습니다.

## 깨지는 예제 + 규칙인 이유

설계는 두 아이디어의 결합입니다. 첫째, 예제는 작정하고 적대적입니다. 현 SOTA를 꺾기 때문에 제출됐으므로 포화된 중간이 아니라 capability frontier를 찌릅니다. 멀티모달 입력(이미지·오디오·비디오)으로 텍스트 번역을 넘습니다. 둘째, 각 예제가 알려진 실패 모드의 수기 검증 규칙을 حمل하므로 이후 평가는 **신뢰 가능**(지표 추측이 아닌 규칙 검사)하고 **실행 가능**(실패가 구체적 케이스를 지목해 수정 방향을 가리킵니다)합니다.

## 얼린 스냅샷이 아닌 라이브 벤치마크

모델이 외우거나 넘어서면 삭는 정적 릴리스와 달리, LTB는 버전 관리되며 지속 수집됩니다. LTBv1이 첫 절단이고 후속 릴리스가 예정돼 있습니다. 260인 저자 목록이 커뮤니티 기여 모델을 보여줍니다. 진척 추적이 일회성 릴리스가 아니라 공유되는 지속 프로세스가 됩니다.

## 주의할 점

이 글은 초록 기반입니다. arXiv HTML판이 없고(Typst 원본, PDF만) 예제별 통계·규칙 스키마·LTBv1 규모/구성 수치를 검증하지 못했습니다. 적대적 커뮤니티 벤치마크는 기여자의 언어·관심 현상에 coverage가 치우칠 수 있고, 수제 규칙은 모델의 실패 모드가 바뀌면 유지보수가 필요합니다. 수치를 인용하기 전에 프로젝트 저장소의 현행 LTBv1 내용을 확인하세요.

## SW 엔지니어와의 관련성

- 번역 기능을 낸다면 포화한 BLEU/COMET 뒤에 frontier 실패가 숨어 있습니다. 적대적·규칙 검증 스위트가 aggregate 지표를 보완합니다.
- 예제별 검증 규칙은 이식 가능한 패턴입니다. 내부 eval set에도 알려진 실패 케이스를 실행 가능한 검사로 함께 두면 회귀가 스스로 이름을 밝힙니다.
- 빨리 움직이는 모델 추적에는 얼린 벤치마크보다 라이브 버전 벤치마크가 낫습니다. 보고에는 버전(LTBv1 등)을 핀하세요.
- 기여물 동료 검토는 내부 eval set 품질 게이트로 복사할 만합니다.
