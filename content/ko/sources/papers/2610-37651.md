# GEPA-Curator: 자기 개선 에이전트를 위한 큐레이션 학습

**원문**: [arXiv:2610.37651](https://arxiv.org/abs/2610.37651) · **게시일**: 2026-10-27
**저자**: Zack Yu, Nicholas Lee, Minjae Lee, Lakshya Agarwal, Luca Manolache, Wonjun Kang, Matei Zaharia, Michael W. Mahoney, Kurt Keutzer, Sehoon Kim, Amir Gholami

## 개요

대형 언어 모델 에이전트는 점점 더 복잡한 환경과 상호작용하는 multi-turn agentic workload를 수행한다. GEPA와 같은 reflective prompt optimizer는 실패한 rollout로부터 학습하지만, agentic 실패는 prompt 약점만이 아니라 harness 한계, stochastic execution, 불안정한 환경, noisy judge에서도 발생할 수 있다. 따라서 Reflector는 실패 원인을 잘못 귀인하고 prompt를 해치는 수정을 만들 수 있다.

GEPA-Curator는 기존 prompt optimizer 위에 얹는 에이전틱 data Curator로 제시된다. 두 가지 역할을 한다. 첫째 task curation은 minibatch에 필요한 깨끗한 신호를 제공할 task를 고르고, noisy하거나 faulty한 task를 버린다. 둘째 selective retrieval은 필요한 경우 이전 성공 trajectory를 선택적으로 재활용한다. 평가는 WebArena 사이트, ALFWorld, AppWorld, tau-bench에서 수행된다.

## 핵심 내용

- 모든 failed rollout이 실제 prompt 약점을 드러내는 것은 아니므로 reflective optimizer는 잘못된 attribution에 취약하다.
- GEPA-Curator는 task를 무작위로 고르지 않고 curator를 통해 minibatch를 정제한다.
- 이전 성공 trajectory를 선택적으로 retrieval하여 mutation 품질을 높인다.
- 네 개의 WebArena 사이트, ALFWorld, AppWorld, tau-bench에서 평가 baseline에 match하거나 이를 초과한다.
- GEPA 대비 최대 20.7%, ACE 대비 최대 21.2% 개선을 보고한다.
- 큐레이션의 이점은 단일 설정뿐 아니라 optimizer model 전반으로 확장된다고 설명한다.

## 상세

논문은 결과가 agent prompt와 무관한 이유로 발생할 수 있음을 예로 든다. 예를 들어 구매 버튼이 동작하지 않는 broken environment에서는 agent가 실패할 수 있고, 그 실패는 prompt 약점이 아니다. validation set은 나쁜 mutation을 막을 수 있지만 minibatch 수준의 curation은 attribution 문제의 원인에 더 직접적으로 개입한다.

GEPA-Curator는 GEPA 같은 optimizer를 대체하지 않고 그 위에서 harness로 동작한다. curation role은 reflection 전에 misleading task를 걸러내고, selective retrieval은 mutation에 도움이 될 때 이전 성공 trajectory를 가져온다. 이 두 메커니즘은 multi-turn, tool-mediated 환경에서 reflected prompt change를 더 신뢰할 수 있게 만드는 것을 목표로 한다.
