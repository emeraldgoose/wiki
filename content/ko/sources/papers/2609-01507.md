# LatentPress: 텍스트와 비전을 넘어선 컨텍스트 압축

출처: Zhengze Zhou, Hejian Sang, arXiv:2609.01507, 2026-09-03.

**핵심 요약**: 압축 컨텍스트는 보통 사람이 읽는 텍스트나 디코딩이 필요한 렌더 이미지로 운반됩니다 — 그 유일한 소비자가 언어 모델인데도. **LatentPress**는 대화 기록과 긴 문서를 세 번째 표현, 즉 동결 디코더가 입력 임베딩 인터페이스로 직접 읽는 **연속 기억 토큰**으로 씁니다. 추론 때 텍스트 복원 없습니다. 작은 reader-matched writer가 **4–16배** 압축하면서 훈련은 어댑터 **4.2M–26.2M 파라미터(디코더의 ~0.1%)** 만 합니다. LongMemEval에서 **7.70배 압축에 정확도 0.504 대 압축 없음 0.490**으로 텍스트 요약(0.184)과 OCR 기반 압축(0.426에서 0.312까지)을 이깁니다. LongBench-QA에서는 in-domain writer가 4–8배 압축에서 원시 컨텍스트 읽기과 대등 이상이고, 16배는 원시에 못 미칩니다. 쓰기는 **대화당 43ms** — 요약·OCR 복원보다 한 자릿수 빠름 — 읽기는 원시·캐시된 OCR보다 **5–9배 빠릅니다**.

## 컨텍스트의 세 번째 표현

텍스트 요약은 사람이 읽을 수 있게 세부 사항을 버리고, 렌더 이미지 컨텍스트는 아무도 안 보는 픽셀에 인코딩·디코딩 비용을 치릅니다. LatentPress는 소비자가 기계임을 봅니다. 압축 형태가 기계 네이티브면 됩니다. 동결 디코더의 임베딩 인터페이스로 바로 들어가는 soft 토큰. writer 쪽 어댑터만 reader에 맞춰 학습하니 훈련 비용이 미미합니다.

## 결과가 보여주는 것

| LongMemEval | 정확도 |
|---|---|
| LatentPress (7.70배 압축) | 0.504 |
| 압축 없음 | 0.490 |
| OCR 기반 압축 | 0.426 ~ 0.312 |
| 텍스트 요약 | 0.184 |

| 기타 결과 | 세부 사항 |
|---|---|
| LongBench-QA (in-domain writer) | 4–8배에서 원시와 대등 이상. 16배는 원시 미달 |
| 쓰기 비용 | 대화당 43ms |
| 읽기 속도 | 원시·캐시 OCR보다 5–9배 빠름 |
| 전이 | zero-shot UltraChat→LongMemEval, LongMemEval-QA→미확인 LongBench 도메인 검증 |

헤드라인은 압축이 LongMemEval에서 원시를 *이긴 것*(0.504 vs 0.490) — writer가 토큰뿐 아니라 잡음도 걸러낸 모양 — 이고, 16배 결과는 현재 품질 절벽을 표시합니다.

## 주의할 점

이 요약은 초록 기반입니다. 과제별 분해, 디코더 정체, 풀링/토큰 버짓 메커니즘은 본문에 있습니다(구현은 github.com/HJSang/LatentPress). writer는 reader-matched라 기억 토큰은 어댑터 재훈련 없이 다른 디코더로 이식이 안 됩니다. 압축률 고르기 전에 16배 저하와 OCR 범위 분산(0.426~0.312)을 확인할 만합니다.

## SW 엔지니어와의 관련성

- 장수명 대화 에이전트라면 기계 네이티브 기억 토큰이 원시 기록·요약 둘 다를 품질 *과* 지연시간에서 이길 수 있습니다. 요약 파이프라인 만들기 전에 고려하세요.
- 43ms 쓰기와 5–9배 읽기 단축은 세션 기억 경제를 바꿉니다. 원시 transcript가 아닌 대화별 압축 기억을 persist하세요.
- 안전 운전 범위는 4–8배로 잡으세요. 이 결과에서 16배는 원시에 못 미칩니다.
