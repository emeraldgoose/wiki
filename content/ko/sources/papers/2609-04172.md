# 온폴리시 증류 다시 생각하기 II: 단 하나의 훈련 예제

출처: Zixuan Fu 외 12인, arXiv:2609.04172, 2026-09-03. 29페이지, 20개 그림. 코드 github.com/Thinking-Space/One-Shot-OPD.

**핵심 요약**: 온폴리시 증류(OPD) — 학생 rollout + 토큰 단위 교사 밀집 supervision — 는 프론티어 후훈련의 표준(Qwen3, MiMo, GLM-5, DeepSeek-V4, Kimi K3)이지만 기존 연구는 알고리즘 동작만 보고 훈련 데이터의 역할은 보지 않았습니다. 이 논문은 **단일 쿼리**로 훈련해도 one-shot OPD가 수백 스텝 계속 오르며 **4개 도메인·3개 모델 family에서 전체 데이터 OPD 이득 대부분을 회복**함을 보입니다. 설명은 **데이터 과잉·알고리즘 기아(data-overfed but algorithm-starved)** — rollout이 넓은 supervision을 빨리 노출하는데 학생의 흡수가 점점 느려집니다.

## 한 예제로 충분한 이유: 상태 커버리지

쿼리는 rollout이 도달하는 **상태**를 통해 학생에게 작용합니다. 토큰 prefix마다가 supervision 상태라서, 스텝당 64 rollout이면 단일 쿼리에서도 수만 상태가 나옵니다. **상태 커버리지**(전체 데이터 OPD가 방문한 200개 의미 클러스터 중 도달 비율) 측정:

| 쿼리 집합 | 상태 커버리지 | 검증 효과 |
|---|---|---|
| 1개 쿼리 | 71.5% (처음 100스텝에 65.9%) | 300스텝에 전체 이득의 87% (68.5 vs 69.8) |
| 16개 의미 다양 쿼리 | 98.9% | 전체 학습과 동등 |
| 멀티교사 16개/도메인 | — | 전체 MOPD 이득의 101% |

효과는 강건합니다. 쉬움(8/8)·중간(4/8)·한 번도 못 푼 어려움(0/8) 쿼리 모두 되고, 코드·지시 따르기·도구 사용에서 교사–학생 격차의 73%·66%·64%를 회복합니다. 내용 없는 템플릿과 도메인 밖 WildChat 쿼리도 실제 쿼리 베이스라인에 근접합니다. 입력은 내용 때문이 아니라 **학생의 추론을 시작시키기 때문에** 유용합니다.

## 오래 걸리는 이유: 느린 정렬

**흡수율**(한 업데이트가 남은 교사–학생 격차를 얼마나 메우는지)은 **1개 쿼리든 17k개든 동일하게** 훈련 내내 하락합니다. 고정된 상태 집합도 흡수에 수백 스텝이 걸리니, run 길이는 데이터셋이 아니라 OPD의 속성입니다. 같은 쿼리의 one-shot RLVR과 비교하면, OPD의 토큰 단위 신호는 쿼리가 거의 매 rollout 풀린 뒤에도 지속되어 **1000스텝 검증 이득이 2배 이상**입니다.

## 주의할 점

실험은 동 family 교사와 1.5B급 학생 조합이며, 70B+ 규모에서도 커버리지가 이렇게 빨리 포화하는지는 미검증입니다. 커버리지는 전체 데이터 OPD 자체가 방문한 상태 기준(자기 참조 상한)이며 교사 시그니처 공간의 K=200 클러스터입니다. 빈 템플릿 붕괴 사례처럼 입력의 최소 비계는 여전히 필요합니다.

## SW 엔지니어와의 관련성

- 증류한다면 **문제 개수가 아니라 상태 다양성**으로 큐레이션하세요. 의미가 다른 16개가 17k와 동등했습니다. 풀을 클러스터링해 클러스터당 하나씩 뽑으세요.
- 느린 증류는 손실이 아니라 흡수율(업데이트당 메운 격차)로 진단하세요. 거리와 흡수율이 함께 떨어지면 병목은 데이터가 아니라 알고리즘입니다.
- 교사가 있다면 outcome 보상보다 밀집 토큰 supervision을 쓰세요. 검증 가능한 outcome이 포화된 뒤에도 오래 살아남습니다.
- 쿼리 수만 세는 평가는 supervision을 자릿수 단위로 과소평가합니다. 방문 상태를 세세요.
