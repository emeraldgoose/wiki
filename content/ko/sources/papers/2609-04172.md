# Rethinking On-Policy Distillation of Large Language Models II: One Training Example

: On-policy distillation (OPD) — student rollouts plus dense token-level teacher supervision — is now standard in frontier post-training (Qwen3, MiMo, GLM-5, DeepSeek-V4, Kimi K3), but prior work studied only its algorithmic behavior, never the role of training data. This paper trains on a **single query** and finds one-shot OPD keeps improving for hundreds of steps, recovering **most of full-data OPD's gain across four domains and three model families**. The explanation: OPD is **data-overfed but algorithm-starved** — rollouts quickly expose broad supervision while the student absorbs it ever more slowly.

Why one example is enough: state coverage: A query acts on the student through the states its rollouts reach — every token prefix is a supervised state, so 64 rollouts per update yield tens of thousands of states from one query. Measuring state coverage (fraction of full-data OPD's 200 semantic state clusters reached):

 Query set  State coverage  Validation effect 
---------
 1 query  71.5% (65.9% within first 100 steps)  87% of full-data gain at step 300 (68.5 vs 69.8) 
 16 semantically diverse queries  98.9%  Matches full-data trainin

Why it takes so long: slow alignment: The absorption rate — the fraction of remaining teacher–student gap one update closes — declines throughout training identically whether training on 1 query or all 17k. Even a fixed set of states takes hundreds of steps to absorb, so run length is a property of OPD, not the dataset. Versus one-shot RLVR on the same query, OPD's token-level signal persists after the query is solved on nearly every rollout, giving more than 2x the validation gain over 1000 steps.

Caveats: Runs use 1.5B-scale students with same-family teachers; whether state coverage saturates as fast at 70B+ scale is untested. Coverage is measured against states full-data OPD itself visits (a self-referential ceiling), with K=200 clusters in teacher-signature space. The empty-template collapse case shows inputs still need minimal scaffolding.

Relevance to SW engineers: - If you distill models, curate for state diversity, not problem count: 16 semantically distinct queries matched 17k. Cluster your pool and pick one representative per cluster.
- Diagnose slow distillation with absorption rate (gap closed per update), not loss — a falling rate with falling distance means the algorithm, not the data, is the bottleneck.
- Prefer dense token-level supervision over outcome rewards when the teacher is available: it survives long after verifiable outcomes saturate.
