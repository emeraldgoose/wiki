# WHALE: A Simple Recipe for Joint Harness-Weight Optimization

: Agent performance depends **jointly** on model parameters and the executable harness code that manages context and control flow. Optimising either alone leaves the system bottlenecked by its frozen counterpart: weight updates change *which* harness is effective, harness updates change *which* model capabilities are exposed. Existing joint-adaptation methods optimise weights and textual prompts but leave the broader harness fixed. WHALE (**W**eight-**H**arness **A**lternating **LE**arning) is a simple recipe alternating two phases — update the model under the current harness, then search for a better harness under the updated model — instantiating them with online rejection-sampling fine-tuning and Meta-Harness. Across Qwen3.5-2B/4B agents on search QA, math and chess, it beats weight-only, harness-only and Fast–Slow Training by **4.15–24.38 points** of mean@8 accuracy, while small interleaved updates also beat stagewise weight-then-harness on **both** accuracy and rollout cost.

The two halves: The framing the paper insists on: model weights are only half of an agentic system. The other half is the harness — the code deciding which observations enter context, how tools are exposed and invoked, how execution errors are handled, and when an interaction terminates.

The coupling is the problem. Consider a QA agent with a retrieval tool:

- Stronger weights cannot use evidence a brittle harness never retrieves
- Better retrieval cannot help a model that cannot synthesise the returned evide

Why alternation, not concurrency: Coordinating the two is awkward because the phases run on different timescales: harness search is a long proposal-and-accept cycle conditioned on many rollouts, while online fine-tuning alternates rollout collection with gradient updates.

Running them concurrently has a real cost: every update gets evaluated against a moving counterpart, which confounds credit assignment — you cannot tell whether a gain came from the weight change or from the harness having drifted. Synchronisation barriers are

The scheduling question: Once you alternate, the obvious design question is: when do you switch?

The constraint is two-sided. Each phase must gather enough evidence to distinguish real improvement from noise — but must stop before it over-optimises against a fixed counterpart. WHALE offers both answers:

- Fixed phase durations — hyperparameters shared across cycles
- Adaptive patience — switch after a minimum duration once the current phase's training signal stops improving

Results: Qwen3.5-2B and 4B agents across three domains: search question answering, mathematical reasoning, and chess puzzles.
