# TPHC: 텐서 병렬 그룹 업데이트로 Hyper-Connections 개선하기

**Source**: [arXiv](https://arxiv.org/abs/2611.23026)
**게시일**: 2026-11-17

## Overview

Hyper-Connections(HC)는 Transformer의 residual stream을 N개의 병렬 스트림으로 확장하고, manifold-constrained HC(mHC)는 이를 대규모에서 안정화한다. 그러나 mHC는 스트림이 넷을 넘으면 이득이 거의 없는데, 이는 각 서브레이어가 모든 스트림에 단일 출력을 쓰기 때문에 스트림들이 서로 다르게 업데이트될 수 없기 때문이다. TPHC는 텐서 병렬(TP) 샤드를 HC 스트림과 통합해 스트림 간 독립성을 높인다. 스트림의 별도 혼합을 샤드마다 라우팅하고, write-back 때 개별 샤드 출력을 분리해 유지함으로써 각 스트림이 그 출력들의 서로 다른 혼합을 받게 한다.

이 설계는 어텐션·FFN 서브레이어에 파라미터나 FLOPs를 추가하지 않으면서 residual stream 업데이트의 표현력을 높인다. TP 하의 스트림 샤딩을 네이티브로 지원해, 네 스트림 기준 8B 모델에서 mHC보다 학습 시간이 9%만 더 든다. 스트림을 넷에서 열여섯으로 늘려도 학습 시간은 19%만 증가한다. 100B 토큰으로 학습한 1.1B 모델에서 TPHC는 매칭된 스트림 수 N ∈ {4, 8, 16}에서 mHC 대비 검증 손실을 0.7–1.0% 낮추고 여섯 commonsense 추론 벤치마크 평균 제로샷 정확도를 0.3–0.7%p 높인다. 코드: https://github.com/wuyou2002/TPHC.

## Key points

- 주요 결과(1.1B, 100B 토큰): N=4에서 TPHC4 검증 손실 2.0819/2.0838 vs mHC4 2.0967/2.0985(mHC-TFA4 2.0904/2.0923); N=8에서 TPHC8 2.0689/2.0706 vs mHC8 2.0907/2.0924(mHC-TFA8 2.0841/2.0859); N=16에서도 선두 또는 동급. 여섯 벤치마크 평균 제로샷: TPHC는 스트림 수에 걸쳐 48.9–49.3 범위.
- 효율: 네 스트림(8B, TP)에서 mHC보다 학습 시간이 9%만 더 들고, 열여섯 스트림으로 확장해도 19%만 더 든다. 어텐션/FFN에 파라미터·FLOPs 추가 없음 — 오버헤드는 스트림 라우팅과 sparse update에 있다.
- 방법: TP 샤드별 read mixture, 개별 write-back(각 스트림이 샤드 출력의 고유한 혼합을 받음), 문서 인식 스케줄링의 sparse update, 전용 초기화, TP 네이티브 구현(replicated·sharded 스트림 변형).
- mHC가 포화되는 이유: 각 서브레이어가 모든 스트림에 하나의 출력을 쓰므로 스트림이 받는 것을 서로 다르게 만들 수 없다. TPHC의 그룹 업데이트는 서브레이어 연산을 건드리지 않고 스트림별 차별화를 복원한다.
- 절제 실험은 grouped read/write, read-only, write-only, update 변형과 스트림 다양성 분석을 다룬다(Sec. 4.3–4.4).
