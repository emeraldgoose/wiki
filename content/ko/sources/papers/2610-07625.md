# 상태 없는 언어 에이전트: 장거리 자동화 연구 확장

**Source**: Qizheng Zhang 외, arXiv, 2026-10-06

**Lead**: 장거리 LLM 에이전트는 히스토리 재생, 작업 중복, 토큰 소비하며 정체하는 실패 모드를 보입니다. 상태 없는 언어 에이전트(SLA) 프레임워크는 모든 내구적 연구 상태(후보 해법, 측정 결과)를 하네스가 소유하고 에이전트는 상태 없이 유지—각 호출마다 하네스에서 재구성된 신선한 역할별 컨텍스트를 받게 함으로써 이를 해결합니다.

## 배경

자동화 연구(AutoResearch) 시스템은 LLM 에이전트를 반복 실행해 해법을 제안, 구현, 평가합니다. 현재 프레임워크(GEPA, CodeEvolve, AdaEvolve 등)는 에이전트가 호출 간 대화 히스토리를 유지하게 합니다. 이는 스케일에서 세 가지 실패 모드를 유발합니다:
1. **히스토리 팽창**: 컨텍스트가 실행 길이와 함께 증가해 중복 컨텍스트에 토큰 낭비.
2. **중복**: 에이전트가 독립적으로 알려진 실패를 재발견.
3. **정체**: 에이전트가 실험을 멈추면서 토큰 예산만 소진.

평가는 보통 조기 포화하는 짧은 호라이즌을 사용해 이러한 병리를 놓칩니다.

## SLA 프레임워크

SLA는 엄격한 분리를 강제합니다:
- **하네스**: 연구 상태 소유—후보 해법, 평가 결과, 탐색 궤적. 각 에이전트 호출마다 최소한의 역할별 컨텍스트 재구성.
- **어드바이저(상태 없음)**: 하네스가 요약한 증거를 검토해 검색 방향 전반에서 구체적 실험을 워커에 할당.
- **워커(상태 없음)**: 할당된 실험(코드 편집, 커널 튜닝, 알고리즘 변형) 실행, 이전 호출 기억 없음.

각 에이전트는 하네스가 명시적으로 제공하는 것만 봄—히스토리 우연이 아닌 명시적 설계 선택.

## 결과

**최대 10억 토큰** 예산으로 세 도메인 평가:
- **소프트웨어 엔지니어링** (SWE-bench 스타일)
- **커널 최적화** (CUDA/Triton)
- **알고리즘 설계** (알고리즘 발견)

SLA는 **모든 태스크에서 최고 최종 결과** 달성하고, 최강 커널 베이스라인 최종 성능을 **84% 이상 적은 토큰**으로 도달.

공유 체크포인트에서의 에이블레이션 결과:
- 집중된 컨텍스트와 명시적 할당 각각 기여.
- 전체 실행에서 효과 복합.
- 어드바이저는 **총 토큰의 < 0.6%**만 소비.

짧은 호라이즌 평가는 연구 시스템을 오판—SLA 이점은 예산 증가와 함께 성장.

## SW 엔지니어 관점에서의 의의

- **에이전트 아키텍처**: 상태 없음은 확장 가능한 설계 패턴—상태는 모델 컨텍스트가 아닌 오케스트레이션 계층에 속함.
- **토큰 효율**: 10억 토큰 스케일에서 84% 감소는 직접적 비용 절감으로 직결.
- **관찰 가능성**: 하네스 소유 상태는 결정적 재현, 디버깅, 감사 추적 가능하게 함.
- **병렬성**: 상태 없는 워커는 사소하게 병렬화; 어드바이저는 병목 없이 조정.
- **평가 엄밀성**: 장거리 예산은 짧은 벤치마크에서 보이지 않는 실패 모드 노출.
