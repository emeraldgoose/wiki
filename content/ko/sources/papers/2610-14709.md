# Vela: 사용자 행동을 감독 신호로 삼아 LLM 지능 깨우기

출처: Yang Xiao 외 19인, arXiv:2610.14709, 2026-10-10.

**핵심 요약**: LLM은 개인 비서부터 추천·광고 시스템까지 **사용자의 장기 행동 이력**에 기반해 행동하는 응용에 배치되고 있습니다. 이런 응용은 몇 주에서 몇 년의 행동 데이터로 개인의 선호·의도·향후 행동을 추론하는 **사용자 차원의 지능**을 요구합니다. 그러나 현재 모델은 정적 텍스트나 합성 데이터로 훈련돼 사용자 행동이 시간에 따라 진화하는 방식을 담지 못합니다.

## 사용자 행동을 감독으로

콘텐츠 플랫폼과 개인 비서 에이전트에 이미 대규모로 존재하는 실제 행동 기록이 자연스러운 감독 신호가 됩니다. **Vela**는 실제 사용자 행동 데이터를 훈련 가능한 과제와 궤적으로 바꾸는 프레임워크입니다. **10만 사용자**의 익명 행동 기록에서 **91개 실제 과제 템플릿**에 걸쳐 **10만 과제**를 생성하고, 난도 기반 필터링과 궤적 수용 기준으로 약 **7만5천 과제**와 선별된 훈련 궤적을 남깁니다.

## 결과

이 궤적으로 Qwen3.6-35B-A3B를 미세조정하면 사용자 관련 과제에서 베이스 모델보다 최대 **11.5점**, 일반 벤치마크에서 평균 **4점** 향상됩니다. 사용자 행동 데이터를 더 쓸수록 사용자 관련 성능이 더 개선되고, 미세조정 후 강화학습은 베이스 모델에서 시작한 RL보다 최대 **7.7점** 앞섰습니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 개인 행동 데이터 훈련은 프라이버시·동의·편향·과적합 위험이 큽니다. 익명화 수준, 사용자별 데이터 분리, 일반 성능 향상의 원인(데이터 양인지 사용자 신호인지)은 원문과 정책 검토가 필요합니다.

## SW 엔지니어와의 관련성

- 사용자 이력을 활용하는 제품이라면 행동 로그를 곧바로 프롬프트에 넣지 말고, 훈련·평가 가능한 과제로 변환하는 파이프라인을 설계하세요.
- 사용자 관련 지표와 일반 지표를 분리해, 개인화가 범용 능력을 해치지 않는지 확인하세요.
- 개인 데이터는 목적 제한·최소 수집·삭제 절차를 훈련 파이프라인에 내장해야 합니다.
