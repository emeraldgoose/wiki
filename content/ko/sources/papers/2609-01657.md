# NeoMME: 효율적 파인튜닝·추론을 위한 단일 타워 다중모달 다국어 파운데이션 인코더

출처: Aurélien Lac, Tony Wu, arXiv:2609.01657, 2026-08-31.

**핵심 요약**: 다중모달 모델은 보통 생성형 vision-language 모델링용 아키텍처 — 따로 사전 훈련한 비전 인코더를 causal 언어 모델에 볼트로 고정한 것 — 위에 서고, ColPali 같은 시각 문서 검색기는 한 단어도 생성하지 않는 일에 그 파라미터·연산 오버헤드를 물려받습니다. **NeoMME**는 다국어 텍스트와 원시 이미지 패치를 단일 Transformer 타워에서 처리하는 **260M·800M 파라미터** 다중모달 다국어 **양방향 인코더** 계열로, 처음부터 masked discrete-diffusion 텍스트 목적함수(다중모달 예제는 보이는 이미지 패치 조건)로 사전 훈련하고, 표준 4K UHD 이미지 두 장이 들어가는 **16,384 토큰 컨텍스트**를 지원합니다. 합동 훈련한 dense·late-interaction 헤드로 파인튜닝하면 NeoMME-Retriever 260M이 **ViDoRe v3에서 0.523 nDCG@10으로 800M 미만 전 모델 1위**, 800M은 **0.556**에 도달합니다. NVIDIA L40S에서 2048×2048 동일 입력에 NeoMME-260M은 **ColModernVBERT의 약 2배 처리량**으로 페이지를 인코딩하고, 계층적 토큰 풀링과 비대칭 양자화가 late-interaction 문서 임베딩을 **255배 압축하면서 기준 nDCG@10의 95% 초과를 유지**합니다. 백본과 검색 체크포인트 모두 Apache 2.0으로 Hugging Face Transformers에 공개됩니다.

## 검색에는 검색용 아키텍처가 필요한 이유

생성형 VLM을 인코더로 전용하면 검색 호출마다 생성용 causal 장치와 생성용 크기 비전 타워 값을 치릅니다. 인코더로서 처음부터 훈련한 단일 양방향 타워는 그 세금을 구조상 제거합니다. 텍스트 + 원시 패치에 한 번의 forward pass, 생성 장치 없음, 다국어·장문맥(16K 토큰)은 개조가 아닌 내장.

## 결과가 보여주는 것

| 결과 | 수치 |
|---|---|
| NeoMME-Retriever 260M, ViDoRe v3 | 0.523 nDCG@10 (800M 미만 1위) |
| NeoMME-Retriever 800M, ViDoRe v3 | 0.556 nDCG@10 |
| ColModernVBERT 대비 처리량 (2048×2048, L40S) | ~2배 |
| late-interaction 임베딩 압축 | 255배에 기준 nDCG@10의 95% 초과 |
| 컨텍스트 | 16,384 토큰 (≈ 4K UHD 2장) |

조합이 이야기입니다. 동급 최고 정확도 *와* 2배 처리량 *과* 255배 인덱스 압축 — 운영 시각 검색의 세 비용(품질·서빙·저장)이 한 번에 움직입니다.

## 주의할 점

이 요약은 초록 기반입니다. 사전 훈련 데이터, 언어별·서브셋별 ViDoRe 분해, 파인튜닝 레시피는 본문에 있습니다. 처리량 주장은 한 GPU 기종(L40S)의 동일 입력 크기 기준이고, 95% 유지 수치는 논문 자체 베이스라인 대비입니다. 오디오 요약과 코드 링크는 arXiv 페이지에 있습니다.

## SW 엔지니어와의 관련성

- 문서 시각 RAG(스캔 PDF·슬라이드·스크린샷)라면, 목적 제작 인코더가 VLM 파생 검색기 대비 서빙 비용을 절반으로 하면서 품질은 올릴 수 있습니다 — ColPali식 스택을 기본값 삼기 전에 NeoMME를 평가하세요.
- 95% 초과 품질 유지의 255배 임베딩 압축은 페이지 수준 late interaction의 usual 스케일 벽인 벡터 인덱스 저장·메모리 대역폭을 직접 줄입니다.
- 4K 이미지 두 장 커버의 16K 컨텍스트는 고해상도 페이지의 타일링 꼼수를 줄입니다.
- Apache 2.0 + Transformers 통합이라 도입 마찰이 낮습니다.
