# Last Secure Code Benchmark: 바이브 코딩한 코드는 안전한가?

출처: Tianyi Wu 외 14인, arXiv:2610.14766, 2026-10-10.

**핵심 요약**: AI 코딩 에이전트가 출시 코드의 상당 부분을 작성하지만, 그 코드가 안전한지는 불명확합니다. **Last Secure Code Benchmark**는 코딩 에이전트의 보안 코드 생성을 포괄 평가합니다. **150개 실제 취약점**에서 만든 **450개 과제**가 7개 언어(Java·C·C++·JavaScript·Python·PHP·Go), 2025 CWE Top 25 중 21개와 Top 10 KEV 약점 중 8개를 포함한 24개 CWE를 다룹니다. 비교한 어떤 벤치마크보다 범위가 넓습니다.

## 세 가지 바이브 코딩 시나리오

함수 채우기, 파일 작성, 저장소 소스 트리를 처음부터 구축하기의 세 시나리오를 평가합니다. 모든 과제는 **보안을 언급하지 않는 명세**로 기능만 요구하고, 숨은 기능·보안 테스트가 결과를 채점합니다. 즉 에이전트가 보안을 스스로 고려해야 합니다.

## 결과

6개 프런티어 에이전트에서 **73.6~91.3%** 과제가 기능적으로 통과했습니다. 그러나 가장 강한 **Claude Fable 5도 기능과 보안을 모두 만족한 비율이 25.1%** 에 그쳤고, 나머지는 16.4~24.7%였습니다. 가장 좋은 모델도 모든 바이브 코딩 설정의 취약점 시나리오에서 **12%만 통과**해, 바이브 코딩 코드의 보안에 강한 우려를 제기합니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 벤치마크 과제가 실제 저장소의 복잡한 의존성·프레임워크를 모두 반영하지는 않습니다. 숨은 테스트의 현실성, 언어별 편중, 에이전트 하네스 차이는 원문을 확인하세요.

## SW 엔지니어와의 관련성

- AI 생성 코드를 머지하기 전에 보안 테스트를 **별도 필수 게이트**로 두세요. 기능 테스트 통과는 보안을 보장하지 않습니다.
- 프롬프트에 보안을 명시하지 않은 상태에서의 결과이므로, 보안 요구를 명세에 넣는 것만으로도 일부 개선될 수 있습니다.
- 에이전트별 비교는 동일 하네스·예산에서 수행하고, 언어·CWE별 실패 분포를 기록하세요.
