# MillBill: 기하 피드백을 갖춘 가공 에이전트

**Source**: [arXiv](https://arxiv.org/abs/2611.22565)
**게시일**: 2026-11-18

## Overview

CAD 모델을 가공 프로그램으로 바꾸려면 공정 지식과 기하학적 정밀도가 모두 필요하다. 언어 모델은 부품마다 기하·툴패스 코드를 작성해 이런 워크플로를 생성할 수 있지만, 그러면 수치 실행이 모델의 과제가 된다 — 단 하나의 잘못된 숫자가 실행은 되지만 잘못 가공하는 프로그램을 만든다. MillBill은 가공 결정과 기하 실행·검증을 분리한다. 경계 표현(B-rep) 부품, 재료, 재료 블록(stock)이 주어지면, 로컬에서 호스팅되는 중형 오픈 모델이 인덱싱 3축 가공의 작업(operation)과 절삭 파라미터를 제안하고, 기하 하네스가 툴패스를 생성하고 재료 제거를 시뮬레이션하며 계획 개선을 위한 피드백을 반환한다. 셋업 계획은 가시성만이 아니라 사용 가능한 커터가 물리적으로 도달할 수 있는지를 고려한다.

MillBill은 시뮬레이션된 가공 후 허용오차 이내의 목표 표면적 비율로 평가된다. 로컬에서 호스팅되는 오픈 모델 Qwen3.8-27B로, 평가된 가공 과제에서 자체 기하·툴패스 워크플로를 구성하는 프런티어 모델 접근법을 능가한다. 코드: https://github.com/kulibinai/millbill.

## Key points

- 주요 결과(100개 부품 GrabCAD 벤치마크, τ = 0.1 mm): MillBill은 목표 표면의 97.4%를 허용오차 이내로 남겼다 vs 94.3%(GPT-6 Astra 코드 작성 에이전트), 83.0%(Opus 5.5), 42.3%(CNC-Net); gouge 면적도 최소(0.54% vs 최고 베이스라인 1.50%)이자 과잉 재료 면적도 최소(2.1%). 순수 코드 작성 에이전트로서 Qwen3.8-27B는 7.9%에 그쳐(가공 전 stock 10.6%보다도 아래) — 하네스가 중형 오픈 모델을 실용적으로 만든다.
- 하네스의 기여: LLM 없이 기준 계획+하네스만으로 97.0% 달성; reach-aware 셋업 계획이 결정적 — +z 고정 셋업으로 바꾸면 정확도가 66.4%로 떨어지고 과잉 재료가 33.1%로 급증.
- 셋업 선정: GNN이 B-rep에서 가공 특징을 인식; 여섯 개의 축 정렬 방향 중 사용 가능한 커터가 도달 가능한 셋업을 선택(홀더 오버행과 도달 거리를 전체 공구 라이브러리에 대해 height-map dilation으로 스크리닝, 탐욕적 선정, 시뮬레이션된 이전 셋업이 남긴 stock 위에서 계획) — 깊고 좁은 영역은 보이지만 홀더를 고려하면 도달 불가일 수 있다.
- 모델의 역할을 최소로 유지: LLM은 특징·공구 라이브러리·절삭 데이터 모델에서 도출한 표준 실무(standard-practice) 기준 작업·공구·절삭 파라미터를 수정하며, 작업에 쓰는 공구는 라이브러리에 존재해야 하고 절삭 데이터는 기계 한계로 클램프된다 — 좌표·오프셋·swept volume은 절대 계산하지 않는다.
- 개선 루프: 하네스는 가능한 것을 스스로 수정하고(예: rest finishing 추가), 남은 편차를 모델에 반환하며, 최대 세 번의 빌드 중 최고를 유지; 편차는 특징과 작업에 귀속된다.
- 공개 벤치마크: 밀링 stock과 짝지은 4,294개 GrabCAD 부품과 어떤 플래너의 G-code든 시뮬레이션으로 채점하는 프로토콜.

## Details

- 파이프라인: 특징 인식(B-rep GNN) → reach-aware 셋업 계획(여섯 방향, 인덱싱 3축) → LLM의 기준 계획 수정(특징+라이브러리+절삭 데이터 모델로부터의 작업/공구/절삭량) → CAM 툴패스 생성 → 재료 제거 시뮬레이션 → 표면 편차 측정 → 귀속 및 개선(최대 3회, 최고 유지).
- 코드 작성 에이전트의 실패 모드: ±x/±y 셋업 변환과 공구 오프셋 오류가 주; 일부는 부품을 파고드는 디버링(deburring) 패스를 추가한다.
- 한계: reach-aware 선정은 여섯 축 정렬 방향으로 한정; 절제 실험은 시뮬레이션에서 수행; GrabCAD 100개 채점 부품(실패 사례·허용오차 민감도·개선 라운드 분석은 Sec. 5와 Appendix S).
