# Glance: 생성기가 스스로 reranker가 되는 법

출처: Adilet Metinov, arXiv:2610.40454, 2026-10-29.

**핵심 요약**: RAG는 보통 reranking과 답변을 위해 **별도 모델**을 사용해 모델 상주와 패시지 처리를 중복합니다. **Glance**는 생성기에 경량 **결정 어댑터**와 포인터 헤드를 장착해 shared prefill에서 후보 패시지를 점수화합니다. 짧은 relevance probe가 cached context에서 분기해 query-passage 쌍마다 prefill을 따로 하지 않고 패시지당 하나의 점수를 냅니다. 단일 **9B backbone**이 생성·일반 결정·reranking을 모두 지원하며 결정 스킬당 추가 메모리는 약 0.1 GiB입니다. MS MARCO 39분 파인튜닝 후 Glance는 SciFact nDCG@10 **0.741**, NFCorpus **0.345**를 달성해 bge-reranker-v2-m3의 0.721, 0.326을 넘어섰습니다. HotpotQA 300문제에서 Glance가 고른 문맥은 같은 기반 생성기 아래 cross-encoder 선택 문맥보다 **답변 F1을 0.045** 올렸습니다(paired bootstrap 95% CI [0.014, 0.076]). scaling study에서 reranking 품질은 shared prefill 하나로 200 후보(43k 토큰)까지 계속 올랐고 cross-encoder를 nDCG@10 0.058 앞섰으며, probe-only adapter로 생성은 원래 패시지 캐시에서 계속될 수 있습니다. 이 초기 결과는 one resident backbone으로 generator-based reranking을 보여주며, 평가는 두 retrieval 데이터셋, 한 QA 데이터셋, 한 backbone 계열을 다룹니다.

## 핵심 내용

- RAG는 별도 reranker·generator로 상주와 prefill을 중복하는 경우가 많다.
- Glance는 생성기에 결정 어댑터와 포인터 헤드를 추가한다.
- 점수는 shared prefill에서 짧은 relevance probe로 나온다.
- 9B backbone 하나가 생성·reranking을 지원한다.
- SciFact 0.741, NFCorpus 0.345 nDCG@10을 달성했다.
- bge-reranker-v2-m3보다 두 데이터셋에서 높았다.
- 200 후보까지 cross-encoder보다 0.058 nDCG@10 높았다.

## 상세

점수 경로는 각 query-passage 쌍을 별도 prefill하지 않습니다. probe-only 활성화 어댑터로 reranking 후에도 원래 패시지 캐시에서 생성을 계속할 수 있어 single-model 배포가 가능합니다.

## 주의할 점

## SW 엔지니어와의 관련성

- RAG에서 별도 reranker 배포를 피하면 메모리와 prefill 비용을 줄일 수 있습니다.
- shared prefill은 대후보 scale에서 효율적입니다.
- 생성과 reranking을 one backbone으로 통합할 수 있습니다.
