# AutoPILOT: 실시간 게임 플레이를 위한 시각 에이전트 하네스

**원문**: [arXiv:2611.28202](https://arxiv.org/abs/2611.28202) · **게시일**: 2026-11-20 (v1)
**저자**: Mark Zhao, Pengcheng Wang, Rui Yang, Jiarui Yao, Xirui Jiang, Yuxi Chen, Bingxuan Li, Hanyang Chen, Ke Yang, Manling Li, Tong Zhang, Huan Zhang

## 개요

멀티모달 기반 모델은 게임이 기다려 줄 때는 잘 플레이하지만, 게임이 계속 굴러가는 실시간 상황에서는 자주 실패한다. 저자들은 이 격차의 상당 부분이 하네스(harness), 즉 모델이 무엇을 보고 무엇을 기억하며 출력이 시간에 따라 어떻게 행동으로 전환되는지를 결정하는 계층에 있다고 본다. VISTA 같은 기존 하네스는 지각과 기억을 개선하지만 모델 호출당 최대 하나의 행동만 내보내므로, 에이전트는 모델이 생각하는 만큼밖에 행동하지 못한다.

AutoPILOT은 이 세 번째 부분을 바꾼다. 모델 호출 한 번에서 모델은 (1) 기본(primitive) 행동을 게임에 바로 보내거나, (2) open-loop 매크로(모델이 작성한 일련의 행동)를 시작하거나, (3) closed-loop 컨트롤러를 작성할 수 있다. 컨트롤러는 실행 시점에 모델이 작성하는 짧은 Python 프로그램으로, 이후 모델 호출 없이 스크린샷을 읽어 약 0.4초마다 행동하며, 웨이크 이벤트(매크로/컨트롤러 종료, 핸드오프 요청, 작성되지 않은 화면 감지)가 발생할 때까지 계속 플레이하다가 모델에 제어를 돌려준다. 모델과 컨트롤러 모두 게임 상태가 아니라 스크린샷만 본다.

## 핵심 내용

- 벤치마크: AFK-Bench("Away From Keyboard") — 비활성에 어떻게 반응하는지에 따라 그룹화된 120개의 다양한 브라우저 게임으로, 실시간 또는 시계 일시정지 상태에서 플레이하며 실시간 환경이 에이전트에 어떤 비용을 초래하는지 측정한다.
- 결과(GPT-6.1 Sol, 동일 예산): AFK-Bench에서 실시간 성공률 68.6%로 VISTA의 38.3%를 크게 앞섬; GameWorld에서는 실시간 80.0%를 유지하는 반면 VISTA는 일시정지 84.1%에서 실시간 42.9%로 급락.
- 비용: AutoPILOT은 VISTA의 최종 성공률을 약 1/5의 API 비용으로 달성; 이득은 다른 기반 모델에서도 유지되며, AFK-Bench에서는 시계를 일시정지한 상태에서도 AutoPILOT이 이긴다.
- 분석: 실행 모드, 행동 예산, 추론량(노력), 생성 속도 등 각 구성 요소의 기여를 분해해, 하네스가 모델 출력을 시간에 걸친 행동으로 바꾸는 방식이 에이전트 설계에서 중요하지만 아직 덜 탐구된 부분임을 주장한다.

## 상세

이 하네스는 시간에 걸친 행동을 설계 선택으로 다룬다. 컨트롤러는 스크린샷에 대해 로컬로 실행되는, 모델이 작성한 Python 코드이므로 저수준 제어 루프가 더 이상 모델 호출을 소비하지 않는다. 모델은 웨이크 이벤트에서 제어를 되돌려받고 일상적인 제어를 다시 위임할 수 있다. 논문에는 실행 모드 사용, 행동 예산, 모델 백본에 대한 ablation과 정성 트레이스(예: 3번 지고 나서 컨트롤러가 인계받아 1:26에 승리)가 포함된다. AutoPILOT과 AFK-Bench는 "기다려 주지 않는 세상"을 위한 에이전트의 기반을 지향한다.
