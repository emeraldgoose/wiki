# RealSWE: A Compositional Evaluation of Coding Agents under Realistic User Requests

: SWE-bench 계열 벤치마크의 태스크는 큐레이션된 GitHub 이슈에서 만들어졌기 때문에 길고 구조화되어 있고 정보가 풍부합니다. 실제 사용자 요청은 정반대입니다. 실사용자 프롬프트의 **88%는 문제 진술 하나뿐**인데 반대로 벤치마크 문제의 **7%**에 불과하고, 실제 프롬프트의 87%는 비격식 문체인 반면 벤치마크는 94%가 격식 문체입니다. 저자들은 이 갭을 정량화하고, 같은 태스크·같은 정답 패치를 정보 구성과 문체만 달리한 381개 변종으로 재구성한 RealSWE를 제시합니다. 7개 모델 평가 결과 현실적 입력이 해결률을 평균 6.4%p 떨어뜨리고 순위 자체를 뒤집을 수 있으며, **원하는 동작과 동기(동기부여)를 명시하는 것**이 실질적 이득을 주고 환경 정보나 재현 단계는 토큰만 늘린다는 점이 핵심입니다.

The gap being measured: SWE-bench가 코딩 에이전트를 평가하는 사실상 표준이 되었지만, 그 태스크는 실제 배포 소프트웨어에서 온 것이 아니라 정리된 GitHub 이슈입니다. 결과적으로 태스크는 길고, 구조화되어 있고, 정보가 풍부합니다. 프로덕션에서 실제로 도착하는 요청은 그렇지 않습니다.

이 차이를 정량화하기 위해 저자들은 두 가지를 정의합니다:

1. 6범주 정보 분류 체계 — 문제 진술, 원하는 동작, 동기부여, 환경 정보, 재현 단계, 그리고 그 외
2. 4차원 언어 스타일 — 문법적 정합성, 명령 강도, 전문성 수준, 형식성

이를 SWE-chat의 실제 사용자 프롬프트와 SWE-bench Verified / Pro의 문제 진술에 각각 적용해 비교했습니다.

The measured gap: 축  실제 사용자 프롬프트  벤치마크 문제 
---------
 문제 진술만 (맥락 없음 또는 최소)  88%  7% 
 비격식 문체  87%  4% 
 격식 문체  —  94% 

즉 벤치마크는 실제로 성공하기 쉬운 입력 형태에 불필요하게 집중합니다. 이건 평가가 쉬운 쪽으로 치우쳐 있다는 뜻이지, SWE-bench가 나쁘다는 뜻이 아닙니다 — 실제 세계의 분포를 재현하지 못한다는 뜻입니다.

RealSWE design: RealSWE는 SWE-bench Verified와 Pro에서 파생한 381개 다변종 태스크 패밀리입니다. 각 패밀리 안의 변종들은:

- 동일한 기반 태스크를 공유하고
- 동일한 정답 패치를 가지며
- 오직 정보 구성과 언어 스타일만 다릅니다

즉 하나의 태스크를 N가지 "어떻게 요청할 것인가"로 확장한 것입니다. 이 설계는 성분 분해(compositional) 평가입니다 — 전체 성능이 떨어진 것이 정보 부족 탓인지 문체 탓인지 분리할 수 있습니다.

Findings: 1. 현실적 입력은 해결률을 평균 6.4%p 낮추고, 모델 순위를 바꿀 수 있습니다. 이것이 이 벤치마크의 존재 이유입니다.
2. Desired Behavior와 Motivation을 포함하는 것은 성능에 유의미한 영향을 미칩니다. 반면 Environment Information과 Reproduction Steps는 측정 가능한 이득 없이 토큰만 추가합니다. — 재현 단계가 여기에 포함된다는 점이 실용적인 함의를 만듭니다.
3. 언어 스타일의 효과는 작고 모델에 의존적입니다. 비격식 문체라는 사실 자체가 큰 문제는 아닙니다.
