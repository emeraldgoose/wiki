# Accelerate Bench: 애플리케이션 수준 프로그램 최적화를 위한 에이전트 평가

**원문**: [arXiv:2611.20882](https://arxiv.org/abs/2611.20882) · **게시일**: 2026-11-16
**저자**: Bowen Liu, Yuhan Li, Nuo Chen, Weile Luo, Miao Peng, Qintong Zhang, Qifan Zhang, Jia Li, Ziqi Gao, Lydell Huang

## 개요

애플리케이션 수준의 최적화는 코딩 에이전트에게 가장 어려운 작업 중 하나다. 유용한 변경을 찾아내는 것뿐 아니라 완전한 프로그램 전반에 걸쳐 이를 조율하면서, 프로그램이 수행해야 할 정확한 계산을 보존해야 하기 때문이다. 국소적인 코드 수정만으로는 부족하며, 유효한 패치라도 종단 간 실행 시간은 그대로일 수 있고, 효과적인 속도 향상은 여러 소프트웨어 계층의 변경이 상호작용한 결과로 나타나는 경우가 많다.

Accelerate Bench는 바로 이 능력을 측정하기 위해 만들어진 벤치마크다. 과학 애플리케이션과 슈퍼컴퓨팅 대회에서 가져온 32개의 CPU 최적화 과제로 구성된다. 각 과제는 작동하는 프로그램과 함께 워크로드, 정합성 요구사항, 타이밍 경계, 허용된 수정 범위를 명시하고, 어디를 어떻게 최적화할지는 에이전트가 스스로 판단하게 한다. 실행 중에는 공개 테스트로 반복 개발을 지원하고, 별도의 숨겨진 검증기가 최종 제출물을 다시 빌드해 채점한다.

벤치마크 버전 1.1에서 저자들은 모델과 하니스를 짝지은 16개 코딩 에이전트를 평가했다. 핵심 결과는 대부분의 에이전트가 정합한 프로그램을 만들어내며, 정확성이 아니라 속도 향상의 크기가 에이전트를 갈라놓는다는 점이다.

## 핵심 내용

- 과학 애플리케이션과 슈퍼컴퓨팅 대회에서 가져온 32개의 CPU 최적화 과제로 구성되며, 의존성·빌드 스크립트·실행 진입점을 표준화해 격리된 컨테이너에서 실행한다.
- 대회용 워크로드는 여러 노드에서 수 시간 돌던 것을 단일 노드 CPU 환경으로 축소해 에이전트가 실용적인 예산 안에서 반복할 수 있게 했다. 축소된 과제는 원래 애플리케이션의 주요 계산 단계, 단계 간 의존성, 수치 정합성 기준을 그대로 유지한다.
- 벤치마크 v1.1에서 16개의 코딩 에이전트(모델+하니스 쌍)를 평가했으며 Score@1은 25.5%에서 67.4%까지 분포한다.
- 상위 두 에이전트는 32개 과제 중 22개 이상에서 최소 2배의 속도 향상을 달성한 반면, 나머지 열네 개는 2배 도달 과제가 8~17개에 그쳤다.
- 뒤처진 열네 에이전트의 정합 실행 412건 중 125건(약 30%)은 속도 향상이 1.25배에도 미치지 못했다.
- 통제된 재생 실험에서 동일한 소스 코드가 빌드·실행 설정만 바꿔도 0.29배~2.12배로 달라졌고, 어떤 코드 변경은 다른 변경에 따라 1.01배 또는 6.4배의 가치를 보였다. 즉 고립된 수정이 아니라 계층 간 조율이 실제 성능을 만든다.
- 이 벤치마크는 실행 가능한 워크로드와 에이전트가 만든 프로그램 및 실행 궤적을 함께 제공해, 성능 향상뿐 아니라 그 과정까지 함께 평가하도록 설계되었다.
- 프로젝트 페이지: https://acceleratebench.com/

## 상세

방법. 각 과제는 패치할 단일 함수가 아니라 애플리케이션과 워크로드를 정의한다. 에이전트는 성능 병목을 진단한 뒤 구현 코드, 컴파일러 옵션, 실행 시간 설정을 함께 수정하며, 공개 테스트를 통해 반복적으로 개선한다. 실행 중 에이전트는 공개 테스트를 여러 번 호출할 수 있다. 이 테스트는 현재 프로그램을 다시 빌드하고 소수의 공개 입력(보통 2개)으로 실행해 정합성, 실행 시간, 그리고 대부분의 과제에서 기준 실행 시간이나 속도 향상(또는 실패 단계)을 보고한다. 에이전트는 프로그램의 빌드 여부, 요구 출력 생성 여부, 속도 향상 여부는 알 수 있지만 검사 코드 자체는 볼 수 없다. 실행이 끝나면 숨겨진 검증기가 제출된 파일을 다시 빌드해 같은 종류의 비공개 입력(보통 4개, 종종 더 크거나 매번 새로 무작위화된 입력)으로 실행한다. 보상은 오직 검증기의 반복 타이밍과 검사로만 결정되므로, 점수는 에이전트가 본 적 없는 입력에 달려 있다.

정합성은 타이밍보다 먼저 강제된다. 제출물은 과제별 수치 허용오차를 만족하고, 완전한 출력 파일을 생성하며, 저장된 체크포인트에서 새 프로세스로 올바르게 복구하는 것 같은 상태 유지 요구사항도 충족해야 한다. 모든 검사를 통과한 제출물만 실행 시간으로 채점된다. HPCG 파생 과제와 페이지드 생성 과제에서 계획된 14개의 통제 실험에서는 유효한 변형이 모두 통과했고, 8개의 무효 변형은 위반한 검사에서 모두 실패했다.

채점. 과제가 제공한 구현을 기준선으로 삼고, 정합성을 유지한 채 절약한 실행 시간의 비율을 과제별 보상으로 정의한다. 보상은 r = C(a) × max(0, 1 − T(a)/B)이며, C(a)는 정합성 검사 통과 여부를 나타낸다. 정합한 2배 속도 향상은 0.5점을, 정합하지만 더 빠르지 않은 프로그램은 0점을, 실패하거나 실행 시간을 측정할 수 없는 결과도 0점을 받는다. 각 실행에서 에이전트는 여덟 시간 동안 검토·수정·빌드·테스트를 수행할 수 있다.

결과. 벤치마크 v1.1에서 16개 에이전트의 Score@1은 25.5%~67.4%에 분포한다. 대부분의 에이전트가 정합한 프로그램을 만들기 때문에, 변별 요인은 속도 향상의 폭이다. 상위 두 에이전트는 32개 중 22개 이상 과제에서 최소 2배를 기록한 반면, 나머지 열네 개는 2배 도달이 8~17개에 그쳤고 정합 실행 412건 중 125건이 1.25배 미만이었다. 부록에는 실행 간 분산과 타이밍 잡음, v1.0 결과와 실행 선정, 타이밍 보정 및 점수 민감도 분석이 포함되어 있다.
