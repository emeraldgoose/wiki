# 언어 에이전트와 비언어 에이전트의 협업 탐색

출처: Harini S I 외 5인, arXiv:2609.00474, 2026-09-02. EMNLP 2026 게재.

**핵심 요약**: LLM은 자연어로 전문 서브에이전트를 조율하는 오케스트레이터로 점점 더 배치되지만, 게임·로보틱스 같은 도메인의 최강 에이전트는 *언어 모델이 아니므로* 통합에는 풍부한 연속 표현을 매 단계 희소한 텍스트 요약으로 압축하는 **언어화(verbalization)** 가 필요합니다. 이 논문은 언어화가 병목인지 묻고 **LLAMIA-Bench**로 답합니다. 세 측면(행동 모방, 상태 평가, 자연어 설명)에 걸친 6개 협업 체스 과제로, LLM도 체스 엔진도 단독으로는 풀 수 없게 설계됐습니다. 해법은 **잠재 상태 내재화(latent state internalization)** 입니다. 서브에이전트의 연속 표현을 학습된 상태 토큰으로 LLM 토큰 스트림에 직접 투영하고, 환경 상태가 전진함에 따라 동적 재인코딩합니다. 내재화와 언어화의 격차 — **verbalization debt** — 는 훈련 내내 벌어지고 4B에서 14B 파라미터까지 유지되며, 14B 단일 **LLAMIA** 모델은 모든 과제에서 과제별 전문가와 도구 사용 GPT-5.1 포함 프론티어 모델과 대등 이상이고, 과제별 파인튜닝이 무너지는 분포 외(out-of-distribution)에서도 일반화됩니다.

## 언어화가 의심스러운 이유

오늘날 오케스트레이터-도구 상호작용은 전부 텍스트를 거칩니다. 서브에이전트 상태를 단어로 요약하고 LLM이 추론하는 루프의 반복. 이 텍스트 병목은 정밀도가 가장 중요한 순간에 서브에이전트 표현의 대부분을 버립니다. 체스가 이상적 테스트베드인 이유는 비언어 전문가(엔진)가 초인적이면서도 진짜로 말주변이 없기 때문 — 지식은 문장이 아닌 연속 상태에 살므로, 협업의 이득·손실을 약한 파트너가 아닌 인터페이스 탓으로 돌릴 수 있습니다.

## 잠재 상태 내재화

상태를 단어로 번역하는 대신, 내재화는 서브에이전트의 연속 표현을 **학습된 상태 토큰**으로 LLM 토큰 스트림에 직접 투영합니다. 환경 상태가 행동에 따라 전진하면 동적 재인코딩합니다. LLM은 살아 있는 서브에이전트 상태를 단어처럼 어텐션합니다 — 요약 단계도, 경계에서 정보를 버리는 일도 없습니다.

## 결과가 보여주는 것

| 발견 | 세부 사항 |
|---|---|
| 벤치마크 | 6개 체스 과제 × 3 측면(모방, 평가, 설명). 어느 쪽도 단독 해결 불가 |
| Verbalization debt | 내재화-언어화 격차가 훈련 내내 벌어지고 4B–14B 스케일에서 유지 |
| 14B 단일 LLAMIA | 모든 과제에서 과제별 전문가·도구 사용 GPT-5.1과 대등 이상 |
| 분포 외 | 과제별 파인튜닝이 무너지는 곳에서 일반화 |

두 주장이 하중을 받칩니다. 빚은 구조적이라서(4B→14B로 LLM을 키워도 안 닫힘) 대책은 인터페이스에 있고, 대책은 일반성을 보존합니다(하나의 모델로 전 과제 + 전문가가 없는 OOD 강건성).

## 주의할 점

이 요약은 초록 기반입니다. 효과 크기, 과제별 분해, 훈련 비용은 본문에 있습니다. 협업 근거는 전부 체스 — 이산적 완전관측 도메인 — 라서 잡음 많은 로보틱스 환경의 빚 크기는 미확인입니다. "도구 사용 GPT-5.1과 대등"은 이 벤치마크 과제 한정이지 일반 능력 주장이 아닙니다.

## SW 엔지니어와의 관련성

- 오케스트레이터가 전문 모델·센서와 텍스트 요약으로 대화한다면 verbalization debt를 내고 있을 수 있습니다. 오케스트레이터 LLM을 키우기 전에 텍스트 인터페이스와 풍부한 표현 전달을 벤치마크하세요.
- 빚이 훈련과 함께 벌어진다는 발견이 실행 지침입니다. 손실 많은 인터페이스에 훈련을 더하면 격차가 좁혀지지 않고 벌어지므로, 훈련 예산보다 인터페이스 설계가 먼저입니다.
- 과제별 전문가를 이기는 하나의 제너럴리스트 + OOD 강건성이 표현 수준 통합에 투자할 때 노릴 payoff 모양입니다.
