# 모바일 AI 팩토리: 당신의 모바일 기기를 위한 특화 언어 모델 만들기

**Source**: [arXiv:2611.13509](https://arxiv.org/abs/2611.13509) · **게시일**: 2026-11-10
**Authors**: Evan Li, Krishna Deshpande, Wen Cheng, Shyamnath Gollakota

## 개요

휴대폰에서 도는 소형 언어 모델(SLM)은 서버가 줄 수 없는 두 가지를 준다. 사용자 데이터가 기기 안에 머무르고, 연결 없이도 앱이 동작한다. 최신 SoC와 llama.cpp, MNN 같은 모바일 추론 엔진은 양자화된 SLM을 실용적으로 구동할 수 있게 했다. 그러나 SLM은 대상 과제에 파인튜닝되고 대상 기기에 맞는 크기로 조일 때만 잘 동작한다. 이 결합 관계를 오늘날 맞추려면 기반 모델, 양자화, 학습 데이터, 런타임 구성에 걸쳐 전문가의 반복 튜닝이 필요하다. 논문은 질문을 정면으로 던진다. 과제 명세와 목표 폰이 주어졌을 때, 과제의 정확도 목표와 폰의 자원 예산을 모두 만족하는 파인튜닝·양자화 SLM을 자동으로 만들어낼 수 있는가?

Mobile AI Factory의 답은 학습 데이터를 큐레이션하고, 모델을 파인튜닝·평가하고, 다음 시도를 결정하는 에이전트 루프다. 오케스트레이터 LLM은 반복마다 정확히 하나의 개입을 고른다 — 하이퍼파라미터 튜닝(LoRA 랭크, 스케일링, 학습률, 가중치 감쇠, 에포크), 과제 소스에서 실데이터 추가 마이닝, 또는 정확도를 가장 깎는 실패 범주를 겨냥한 교사 모델의 합성 예시 생성. 고정 규칙은 LLM 판단이 맡으면 안 되는 것을 처리한다. 정확도를 낮추는 변경은 지금까지의 최고 모델로 롤백되고, 예산이 강제되며, 모델 확장은 작은 것부터 큰 것 순의 버킷 일정을 따른다. 루프를 둘러싼 세 지원 구성요소가 있다. 합성 데이터를 만드는 교사, 학습 전에 홀드아웃 세트를 준비하고 오케스트레이터에게 집계 결과만 공유하는 홀드아웃 데이터 에이전트(오염 검사가 테스트셋에 등장하는 행을 제거), 그리고 기반 모델·양자화·런타임(llama.cpp 또는 MNN)·백엔드(CPU 또는 GPU) 조합 전부를 폰당 한 번 벤치마크하는 폰 프로파일러다.

설계는 폰이 서버 쪽 가정을 깨는 네 지점을 반영한다. 정확도만 극대화하는 탐색은 가장 큰 모델을 편애하므로, 팩토리는 기반 모델과 양자화를 하나의 선택으로 묶고 작은 것부터 탐색하며 현재 버킷이 개선을 멈출 때만 올라간다. 전체 정밀도로 평가한 모델은 폰에서 아예 못 돌릴 수 있다 — 같은 가중치에서 MNN 기본 4비트 익스포트가 최대 0.19 정확도를 잃는다 — 그래서 모든 모델을 양자화 후에 채점한다. 같은 모델이 어떤 폰에서는 앱 한계를 만족하고 다른 폰에서는 실패하므로, 탐색과 배포 결정은 실측 프로파일에서 나온다. 그리고 과제 난이도가 천차만별이므로 정확도 목표는 교사의 5-shot 점수(하한 0.8)로 정하고 너무 쉽게 달성되면 올린다.

## 핵심 내용

- (저자들이 아는 한) 하나의 모델에서 정확도만 최적화하는 대신, 주어진 과제와 주어진 폰을 위한 파인튜닝·양자화 SLM을 만드는 첫 에이전트 시스템.
- 탐색 공간: 135M~4B 파라미터의 9개 기반 모델(SmolLM2, Gemma 3, Qwen3, Qwen3.5 계열)을 4/8/16비트로 — 총 27조합을 디스크 크기 기준 5개 버킷(경계 300MB, 750MB, 1.5GB, 2.5GB)으로 묶어 가장 작은 버킷부터 탐색.
- 폰 프로파일링: 5년에 걸친 4대 안드로이드 폰 — OnePlus 15(SD 8 Elite Gen 5, 16GB), Galaxy S23(8 Gen 2, 8GB), OnePlus 8 Pro(865, 12GB), Redmi 9A(Helio G25, 4GB, GPU에 OpenCL이 없어 CPU 전용) — 에서 모델·양자화·런타임·백엔드 364구성(GPU 폰당 104개, Redmi 9A 52개) 측정. 16비트 Qwen3.5-4B는 네 폰 중 두 대의 RAM을 초과.
- 미관측 테스트셋 정확도: 팩토리의 온디바이스 모델이 10개 과제 중 5개에서 예시 5개를 받은 Claude Sonnet 5와 DeepSeek v4 Flash를 0.024~0.342 차로 앞서고 3개에서 대등하다.
- 이득은 출력 형식이 엄격한 곳에 집중된다. 생물의학 개체명 추출에서 517MB 모델이 0.828, Claude 5-shot은 0.652.
- 탐색 효율: 개체명 추출 과제에서 팩토리의 결과가 27개 변형 전수 학습 대비 0.03 이내이면서 GPU 시간은 19배 적게 든다.
- 폰이 루프 안에 있으면 답이 바뀐다. 최적 구성은 폰·모델·양자화 수준마다 다르다. Galaxy S23의 한계가 통화 요약용 최고 모델을 배제하자, 팩토리는 그 모델과 0.013 이내인 모델을 돌려준다.
- 측정은 추론으로 대체할 수 없다. 하드웨어·모델 사양 전부를 주고 실측은 주지 않으면, 높은 추론 노력을 켠 Claude Opus 5.5도 쉬운·보통 사례의 25%, 어려운 사례의 60%에서 앱 요구를 벗어난다 — 런타임 메모리와 백엔드 선택을 잘못 판단한다.
- 구현: 오케스트레이터로 Claude Sonnet 5, 실행마다 L40S GPU 두 장(한 장은 후보 학습·채점, 한 장은 합성 데이터를 만드는 로컬 교사 Qwen3.6-35B-A3B 호스팅). 적응형 목표는 교사 5-shot 점수(하한 0.8)이며 너무 쉽게 달성되면 상향.
- 10개 평가 과제: 생물의학 개체명 추출, 세분화 개체명 추출, 캘린더 일정 추출, 함수 호출, 명령 구문 분석, 151방식 의도 분류, 스팸 판별, 감정 탐지, 문법 오류 교정, 대화 요약.

## 상세

### 개입 루프와 롤백 규율

각 학습 시도는 데이터셋·하이퍼파라미터·학습 전략의 파이프라인으로 모델링된다. 오케스트레이터가 반복마다 하나의 개입을 확정하면 팩토리가 학습·평가하고, 그 결과를 데이터 에이전트가 준비한 홀드아웃 세트와 비교한다. 대부분의 개입은 도움이 되지 않으므로 롤백 규칙이 루프의 척추다. 정확도를 낮추는 변경은 오케스트레이터가 다른 시도를 하기 전에 최고 모델로 되돌아간다. 홀드아웃 데이터 에이전트의 경계가 신뢰를 지킨다. 오케스트레이터는 집계 점수만 보므로 개별 테스트 행에 과적합할 수 없고, 오염 검사가 홀드아웃 테스트셋에도 나오는 학습 행을 떨어뜨린다.

### 양자화가 사후 처리가 아니라 탐색의 일부인 이유

논문은 배포 형식이 답을 바꾸기 때문에 모든 후보를 양자화 후에 채점한다. 4비트 2B 모델이 16비트 0.8B 모델보다 디스크에서 작고, 같은 가중치에서 MNN 기본 4비트 익스포트는 최대 0.19 정확도를 잃는다. 디스크 크기 버킷화는 이런 상충을 같은 잣대에 놓게 하고 작은 것부터 큰 것 순의 일정에 순서를 준다. 프로파일러의 실측은 어떤 모델이 돌아갈 수 있는지(Redmi 9A는 GPU를 전혀 못 쓰고, 두 폰은 16비트 4B 모델을 못 올림)뿐 아니라 최종 모델을 어떻게 구동할지도 결정한다. 최적 런타임과 백엔드는 폰·모델·양자화 수준마다 다르기 때문이다.

### 적대적 측정 연구가 보여주는 것

가장 날카로운 결과는 프로파일러를 숨긴 연구다. 완전한 하드웨어·모델 사양을 받고도 실측이 없으면(높은 추론 노력 활성화) 프론티어 모델 Claude Opus 5.5도 쉬운·보통 사례의 4분의 1, 어려운 사례의 60%에서 앱 요구를 위반하며, 특히 런타임 메모리와 백엔드 선택에서 실패한다. 이 실패 양상은 프롬프트 산물이 아니라 구조적이다. 이기종 모바일 하드웨어의 런타임 동작은 사양서에서 추론되는 것이 아니라 측정으로 결정된다. 예측기나 룩업 테이블로 지연을 추정하는 대신 실제 폰을 루프에 유지해야 한다는 것이 논문의 논거다.

### 범위와 출처

평가는 출력 엄격성이 다른 10개 과제, 플래그십부터 보급형까지 4대 폰, 3정밀도 27개 모델 변형, 런타임 2개 × 백엔드 2개를 포괄하며, Claude Sonnet 5 오케스트레이터와 쌍둥이 L40S GPU의 로컬 Qwen3.6-35B-A3B 교사로 구현됐다. 이 문서는 arXiv HTML v1(2026-11-10 제출)을 기준으로 작성했다. 코드는 공개되어 있다. 저자는 시스템을 일회성 모델 릴리스가 아니라 과제 명세에서 배치된 온디바이스 모델까지의 반복 가능한 파이프라인, 곧 팩토리로 위치시킨다.
