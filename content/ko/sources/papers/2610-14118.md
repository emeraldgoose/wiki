# ClawLoop: 하네스 네이티브 훈련 루프를 통한 자기 개선 에이전트

출처: Hansi Yang 외 6인, arXiv:2610.14118, 2026-10-09.

**핵심 요약**: LLM 발전으로 에이전트는 샌드박스 작업공간에서 파일 시스템·셸과 직접 상호작용하는 **범용 하네스 환경**으로 배치되고 있습니다. 도구 사용 에이전트의 사후학습 파이프라인은 많지만, 하네스 기반 에이전트용은 드물고 대부분 **일회성·교사 의존**입니다. 더 강한 외부 모델이 과제를 합성하고 궤적을 모은 뒤 대상 에이전트를 한 번 훈련하고, 평가 결과는 연구자가 소비할 뿐 루프로 되돌아가지 않습니다. 이런 파이프라인은 외부 모델 능력과 인간 사전지식 범위에 묶여 **자기 개선 여지가 없습니다**.

## 세 단계 순환

**ClawLoop**은 외부 교사 모델 없이 최소한의 사전 의존으로 자기 개선하는 프레임워크입니다. **과제 합성**은 두 가지 상보적 구성 루틴으로 다양한 훈련 과제 풀을 만들고, 진단 조건부 난도 성장과 에이전트 없는·에이전트 기반 검증을 적용합니다. **훈련**은 SFT 및/또는 RL로 에이전트를 갱신합니다. **진단과 피드백**은 롤아웃 행동을 분석해 역량 분석 보고서를 만들고, 이를 다음 반복의 과제 합성 피드백으로 씁니다.

## 결과

Qwen3.6-27B를 루프 모델로 SkillsBench·Claw-Eval-Live·ClawGym-Bench에서 일관된 개선을 냈습니다. 반복 정제된 과제는 더 작은 Qwen3.5-4B·9B 모델로 전이되어 모든 벤치마크에서 이득이 있었고, 이는 데이터 품질이 루프 모델과 독립적임을 검증합니다.

## 주의할 점

이 글은 초록을 바탕으로 정리했습니다. 자기 합성 과제는 난도 붕괴나 검증기 허점 학습 위험이 있습니다. 반복 비용, 과제 다양성 유지, 진단 보고서의 신뢰성은 원문을 확인하세요.

## SW 엔지니어와의 관련성

- 에이전트 훈련을 외부 교사 모델에 묶지 말고, 자체 롤아웃 진단을 다음 과제 합성에 반영하는 루프를 설계하세요.
- 합성 과제는 에이전트 없는 검증과 에이전트 기반 검증을 함께 통과시켜 품질을 거르세요.
- 소형 모델 전이로 데이터 품질을 별도 검증하면 루프 모델 과적합을 발견할 수 있습니다.
