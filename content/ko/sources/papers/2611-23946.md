# 유능한 GUI 에이전트를 학습시키려면 환경은 얼마나 완전해야 하는가?

**원문**: [arXiv:2611.23946](https://arxiv.org/abs/2611.23946) · **게시일**: 2026-11-18 (v1)
**저자**: Jingxing Wang, Teng Wang, Xingyu Lou, Zihan Guo, Jun Wang, Weiwen Liu, Weinan Zhang, Jianghao Lin

## 개요

GUI 에이전트는 실행 가능한 GUI 환경 안에서 강화학습으로 널리 학습되지만, 환경 구축 비용이 크기 때문에 각 연구는 구축 선택을 통해 환경의 일부를 조용히 포기한다. 이 논문은 유능한 에이전트를 학습시키는 데 환경이 얼마나 완전해야 하는지 묻고, 트레이드오프를 세 가지 차원으로 정리한다. 보상 커버리지(검증기가 보상하는 목표 달성 궤적), 데이터 커버리지(작업이 읽고 쓰는 것 beyond로 에이전트에 노출되는 앱 데이터), 기능 커버리지(작업이 사용하지 않는 앱 기능)이다.

저자들은 MobileGym에서 각 차원을 따로 조정한 통제 변형을 만들고, 각 환경에서 Qwen3-VL-4B-Instruct를 학습시킨 뒤 모든 정책을 원래의 완전한 환경에서 465개 인스턴스로 평가한다. 보상 커버리지를 단일 참조 경로로 좁히면 성공률이 51.61%에서 41.08%로 떨어진다(−10.53%p, 240→191건). 그룹 대비 이점(group-relative advantage) 아래에서 유효하지만 거부된 대안 경로가 페널티를 받는 반면 참조 경로만 강화되기 때문이다. 무관한 레코드를 제거하는 것(데이터 커버리지)도 모든 수준에서 손해다(R0/R1/R2: 47.96%, 47.31%, 49.68% vs Full 51.61%). 뜻밖에도 사용하지 않는 앱 기능(기능 커버리지)을 제거하면 성공률이 56.13%로 오르는데, 향상은 환경이 바뀌지 않은 작업에서만 발생한다.

기능 제거 이득의 원인은 에피소드 길이 가중이다. 각 에피소드의 그룹 대비 이점이 모든 응답에 복사되므로, 긴 우회 에피소드가 업데이트를 지배하며 다른 작업의 스킬을 약화시킨다. 에피소드별 가중치(w_i = C/T_i, "에피소드 밸런싱")를 적용하면 이득이 뒤집히고, 제거된 작업의 에피소드만 밸런싱해도 이득이 사라진다. 이 발견에 따라 저자들은 보상·데이터 커버리지를 완전히 유지하면서 불필요한 기능만 제거하는 MobileGym-Lite를 만들었고, 완전 환경보다 낮은 구축 비용으로 완전 환경 평가에서 55.48% vs 51.61%의 성공률을 달성했다.

## 핵심 내용

- 환경 구축 선택은 보상·데이터·기능 커버리지로 분해되며, 기존 연구들은 각 차원을 엔지니어링 근거로만 설정하고 학습에 미치는 영향은 측정하지 않았다.
- 단일 경로(참조 매칭) 보상은 465개 인스턴스에서 성공률 10.53%p 손해를 낸다(41.08% vs 51.61%). 알람 삭제 예시에서 편집 시트를 통한 6개 성공은 −0.354의 이점을 받는 반면 참조 경로인 길게 누르기 성공만 +2.475를 받는다.
- 무관한 앱 레코드를 제거하면 모든 필터링 수준에서 성공률이 떨어진다(R0 47.96%, R1 47.31%, R2 49.68%). 데이터 커버리지는 완전히 유지해야 한다.
- 사용하지 않는 앱 기능을 제거하면 성공률이 56.13%로 오르고(+4.52%p), 향상은 제거된 환경이 바뀌지 않은 작업에서만 발생한다. 즉 이득은 제거된 작업 자체가 아니라 공유 정책 업데이트를 통해 발생한다.
- 메커니즘은 에피소드 길이 × 이점 결합이다. 긴 우회 성공이 과도하게 강화되어 다른 스킬을 약화시키며, 에피소드 밸런싱(w_i = C/T_i)이 제거 이득을 뒤집는다.
- MobileGym-Lite는 보상·데이터 커버리지를 완전히 유지하고 불필요한 기능만 제거한다. 192개 학습 템플릿 중 72개에서 87개 템플릿–모듈 쌍을 생략하고, 앱 소스 코드는 평균 14.05% 감소, 앱 10개 재구축에 필요한 LLM 토큰이 약 33% 절감, 아홉 개 고정 화면의 가시 컨트롤 노드가 126→117(−7.14%)로 감소하며 완전 환경 성공률 55.48%를 달성했다.
- 축소된 환경에서는 학습 후반에 불안정성이 증가한다(스텝 8→16에서 R0 루프 종료 111→135, R1 형식 오류 12→175, Full은 117→109). GSPO 클립 오프셋을 학습 후반에 좁히면(0.2/0.28 → 0.002/0.0028, W→N₈) Lite가 안정화되고 최종 성공이 8건 늘어난다.

## 상세

모든 정책은 원래의 완전한 환경에서 평가되므로 이득이 쉬운 테스트에서 오는 것이 아니다. 보상 커버리지 ablation에서 부호 반전이 구체적으로 드러난다. 스텝 11의 알람 삭제에서 6개 롤아웃은 편집 시트로, 1개는 길게 누르기 참조 경로로 성공하는데, 그룹 내 1개 실패가 있을 때 각 편집 시트 성공은 −0.354를 받는 반면 참조 경로 성공은 +2.475를 받는다.네이티브 목표 검사는 일곱 성공 모두 +0.354를 준다. 레코드 필터링(R0/R1/R2)은 작업에 필요한 레코드만 유지한다. 기능 제거는 F0에서 시작해 인접 내비게이션과 공유 연산을 선택적으로 복원한다(알람 작업에 세계 시계 접근, 날짜 도구에 캘린더 설정, 위챗에 프로필 편집 복원). 이는 36개 템플릿에 영향을 주며 그중 6개는 모든 기능을 유지한다.

길이 가중치 분석은 환경(Full vs F0)과 가중치(응답 평균 vs 에피소드 밸런싱)를 공유 스텝 12 체크포인트에서 교차한다. 환경과 가중치의 상호작용이 길이 가중치를 원인으로 분리해낸다. 축소된 환경에서는 학습 후반에 불안정성이 나타나며(스텝 8부터 16까지), k=8 이후 클립을 좁히는 W→Nₖ는 이미 안정적인 Full 실행에는 변화를 주지 않는다.
