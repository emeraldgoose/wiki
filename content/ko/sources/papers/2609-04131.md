# 검색을 넘어서: 스트리밍 비디오 이해를 위한 점진적 잠재 메모리 진화

출처: Hongyu Qu 외 9인, arXiv:2609.04131, 2026-09-03.

**핵심 요약**: 스트리밍 비디오 이해는 엄격한 인과성과 bounded 메모리 아래 연속 시각 입력을 처리해야 합니다. 기존 무훈련 방법은 히스토리를 외부 메모리 뱅크에 압축하고 질의 관련 증거를 추가 시각 컨텍스트로 검색하는 **store-and-retrieve**에 머물러, 히스토리가 모델의 추론 상태가 되지 못합니다. 이 논문의 **LatentStream**은 히스토리 증거를 작고 고정된 길이의 잠재 메모리 토큰에 점진적으로 흡수하는 retrieve-and-**internalize** 프레임워크입니다. 백본 동결 결과: **OVO-Bench 64.2%(+10.2)**, **StreamingBench 76.9%**, VideoMME 66.6%, MLVU 74.0%, LongVideoBench 62.1% — 피크 메모리 감소와 토큰당 디코딩 지연 절반을 덤으로 얻습니다.

## 세 가지 협동 구성요소

**질의 무관 계층 스트리밍 메모리(HSM)**는 스트림을 단기·중기·장기 3레벨로 고정 토큰 예산(8+64프레임, 전역 2048토큰) 아래 정리하며, Jenks Natural Breaks 분할로 단기→중기는 drop/압축/보존 라우팅, 중기→장기는 공간 중복 병합을 합니다.

**계층 잠재 메모리 진화(HME)**는 잠재 메모리 토큰을 중첩 receptive field(단기 / 단기+중기 / 전체)를 가진 세 그룹으로 나누어 각자 범위에서 top-B 증거를 반복 검색·공동 업데이트합니다. 메모리가 진화하면 검색도 적응합니다.

**점진적 신뢰도 가이드 잠재 메모리 최적화(PMO)**는 REINFORCE식 업데이트로 테스트 타임에 토큰을 다듬으며, 계층 진행 보상(절대 신뢰도 + Es > Em > El 엔트로피 순서 항)을 씁니다. 백본 파라미터는 변하지 않습니다.

## 결과가 보여주는 것

Qwen2.5-VL-7B에서 OVO-Bench Backward Tracing이 44.7%에서 60.0%로 오릅니다. 절제 실험: HSM만으로 54.0→58.1, PMO 추가 62.4, HME 포함 64.2. 핵심은 진화된 잠재 토큰이 검색 증거를 그대로 붙이는 것(64.2 vs 59.7)을 이기고, 검색 토큰은 최종 디코딩 전에 제거된다는 점입니다. 이득은 컨텍스트 부풀리기가 아니라 **내재화**에서 옵니다.

| 지표 (OVO-Bench, 7B) | 베이스라인 | + LatentStream |
|---|---|---|
| 종합 | 54.0 | 64.2 |
| 피크 메모리 | 30.80GB | 21.97GB |
| TPOT | 6.45ms | 3.16ms |
| TTFT | 7.63s | 8.41s |

TTFT 증가(+0.78초)는 답변 전 잠재 메모리 진화 비용이고, 누적 컨텍스트가 bounded라 토큰당 디코딩은 51% 빨라집니다.

## 주의할 점

실험은 전부 Qwen2.5-VL 3B/7B 백본에 1fps이며, 하이퍼파라미터(R=4회 반복, 그룹당 K=22토큰, B=8, σ=10%)는 OVO-Bench 기준이라 전이가 보장되지 않습니다. 엔트로피 진행 보상은 신뢰도가 정답과 일치한다는 가정이며 모호한 질의에서는 어긋날 수 있습니다. 오프라인 장문 비디오 이득은 설계 목표가 아닌 bonus 결과입니다.

## SW 엔지니어와의 관련성

- store-and-retrieve 대 retrieve-and-internalize는 비디오를 넘어 모든 스트리밍 시스템(장수명 에이전트 컨텍스트 포함)의 일반 메모리 아키텍처 선택지입니다.
- 고정 길이 잠재 상태는 서빙 비용을 묶습니다. 컨텍스트 증가가 멈추니 피크 메모리와 토큰당 지연이 함께 내려갑니다.
- 가중치 변경 없는 테스트 타임 최적화는 배포 가능한 패턴입니다. 모델 동결, 요청별 다듬기, 뒤처리 폐기.
- "메모리 토큰"을 붙일 때는 미 최적화 토큰부터 절제하세요. 이 논문에서 raw 추가 토큰은 56.5 대 진화 64.2로, 일하는 것은 용량이 아니라 메커니즘입니다.
