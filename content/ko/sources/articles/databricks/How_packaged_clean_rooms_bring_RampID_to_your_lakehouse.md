# 패키징된 클린룸이 RampID를 레이크하우스로 가져오는 방법

**Source**: [Databricks Blog](https://www.databricks.com/blog/liveramp-rampid-identity-resolution-packaged-clean-rooms)
**게시일**: 2026-11-18

## 개요

역사적으로 고객 레코드를 RampID 같은 개인 기반 ID로 해결한다는 것은 PII를 외부 서비스로 내보내고, 매칭 파일을 기다렸다가, 다시 적재하는 것을 의미했다 — 파이프라인 추가, 민감 데이터 복사본, 지연이 따라왔다. 패키징된 클린룸은 이 왕복을 없앤다. Databricks의 LiveRamp Embedded Identity는 신원 서비스를 데이터 곁으로 가져와, 고객이 자신의 환경에서 Unity Catalog 거버넌스 아래 해결된 RampID 목록을 받게 한다.

## 주요 내용

- 사용 사례: 퍼블리셔가 인증된 시청 데이터로 스포츠 팬 세그먼트를 만들어 광고주의 CRM 잠재 고객 풀(기존 고객 제외)과 규모를 맞춘다. 에이전시가 퍼블리셔들의 스트리밍/디지털 노출 로그를 리테일러의 로열티 연동 구매와 결합해 도달을 중복 제거하고, 노출 쇼핑객의 구매를 측정하며, 홀드아웃으로 증분 매출을 추정해 예산 배분을 정당화한다.
- 패키징된 클린룸이란: Databricks 클린룸은 둘 이상의 당사자가 원시 데이터나 IP를 서로에게 드러내지 않고 결합된 데이터에 대해 승인된 코드를 실행하는 보안 환경이다. 표준(승인 기반) 클린룸에서는 모든 협력자가 동료이며 코드를 함께 승인해야 한다. 패키징된 클린룸은 프라이버시를 분석 전체로 확장한다. 한 당사자(LiveRamp, 신원 제공자)가 분석을 제품으로 출하하고, 고객이 자기 데이터에 대해 실행한다 — 승인 단계가 없고, 어느 쪽도 상대의 데이터 자산을 전혀(테이블 이름이나 스키마조차) 보지 못한다.
- 아키텍처: 세 구성 요소 — LiveRamp(신원 해결 데이터 + 코드: 노트북, JAR), 고객(클린룸 생성, 입력/구성 테이블 추가, 실행 트리거, 결과 수신), Databricks(클린룸 호스팅·격리, 컴퓨트 요금은 생성자 청구).
- 중앙 클린룸: Databricks 관리, 양측 워크스페이스와 분리, 어느 쪽도 관리자 접근 불가; 고객이 선택한 클라우드/리전에 생성(이그레스 완화); 실행마다 서버리스 컴퓨트, 완료 시 해제, 수직·수평 자동 확장; 각 당사자 자산은 OpenSharing으로 읽기 전용 공유; 스토리지 방화벽/프라이빗 엔드포인트 테이블은 SecureConnect가 격리된 프록시로 접근을 중계.
- OpenSharing(구 Delta Sharing)은 복사 없이 읽기 전용 접근을 제공하며, 실시간 테이블을 공유하므로(실행은 지난주 추출이 아니라 현재 버전을 읽음) 양쪽 모두 Unity Catalog 거버넌스를 유지하고 공유 활동이 감사된다. Databricks-투-Databricks 공유이며, 모델·비정형 데이터·JAR·프라이빗 라이브러리·wheel도 공유할 수 있다.
- 실행 절차: 고객이 몇 번의 클릭으로 LiveRamp 패키징된 클린룸을 생성; 승인 후 LiveRamp가 자산을 추가(고객은 분석 이름만 보고 내용은 못 봄); 고객이 터치포인트 입력 테이블(이름·이메일·전화번호·주소 또는 디바이스 식별자)과 속성·메타데이터 테이블을 LiveRamp 문서화된 형식으로 추가; 출력 카탈로그를 선택하고 실행 트리거; LiveRamp 코드가 중앙 룸에서 서버리스로 실행; 해결된 RampID가 고객 출력 스키마에 기록(고객만 읽기 가능, PII는 제거됨).
- 두 개의 출력 스키마: 출력 스키마(고객 전용; 실행 성공 시에만 공유; LiveRamp는 읽을 수 없음)와 공유 출력 스키마(양측; 실행 지표·진단 로그; 최종 상태와 무관하게 실행 중 공유). 둘 다 OpenSharing으로 고객·제공자 소유 환경에 전달된다(Catalog Explorer → 받은 공유).
- 신원 해결이 패키징된 클린룸에 적합한 이유는 분할이 양측을 모두 보호하기 때문이다. LiveRamp의 신원 그래프와 매칭 로직은 고객에게 보이지 않는 지적재산이고, 고객의 PII와 해결 결과는 고객에게만 사적이다.

## 상세

- 패키징된 클린룸은 확장된다. 하나의 패키지를 여러 고객에게 제공하고, 각자 별도의 룸에서 검토할 것 없이 턴키 실행을 얻는다 — 반복 가능한 신원 워크로드에는 승인 기반 룸보다 단순하다.
- 결과는 후속 Unity Catalog 작업으로 이어진다: 고객 360 테이블, 오디언스 빌딩, 활성화, 파트너 협업, 측정.
