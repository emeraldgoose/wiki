# 오브젝트 스토리지 위에 빌드하고, 캐시에서 서빙하다

**Source**: [Databricks Blog](https://www.databricks.com/blog/built-object-storage-served-cache)
**게시일**: 2026-11-19

## 개요

오브젝트 스토리지 위의 Postgres에 대한 흔한 반론은 이렇다. Postgres는 작고 지연에 민감한 읽기를 많이 하고, 오브젝트 스토리지는 더 큰 요청과 높은 지연(단일 읽기가 수백 ms)에 최적화되어 있으므로, 오브젝트 스토리지 기반 Postgres는 느릴 수밖에 없다. 전제는 맞지만 결론은 틀렸다 — 오브젝트 스토리지 위의 데이터베이스가 쿼리를 답하기 위해 오브젝트 스토리지를 읽어야 하는 것은 아니며, Lakebase Postgres는 거의 항상 그렇지 않다.

## 주요 내용

- 프로덕션 플릿 페이지 읽기 통계: 컴퓨트 로컬 캐시가 초당 ~11억 페이지 액세스(전체의 ~99.46%), pageserver 로컬 NVMe가 초당 ~600만(~0.54%), 오브젝트 스토리지는 초당 ~39건만 서빙했다.
- 다시 말해 99.46%의 페이지 액세스는 컴퓨트 노드의 로컬 캐시에서 메모리/마이크로초 수준 지연으로 답해진다(따뜻한 전통적 Postgres와 동일). 오브젝트 스토리지에서 가져와야 하는 것은 약 2,800만 건 중 1건뿐이며, 99.99999% 이상이 그것 없이 서빙된다.
- 오브젝트 스토리지 읽기는 대체로 오래 휴면 상태였던 프로젝트를 깨우거나, 복원하거나, 오래된 브랜치를 여는 경우다.
- 오브젝트 스토리지 위에 빌드하면 얻는 것: 내구성(S3는 99.999999999% 내구성 목표), 프로비저닝·디스크 사이징 없이 데이터에 따라 늘어나는 저렴한 스토리지, 불변·주소 지정 가능한 히스토리(브랜칭과 즉시 복원이 메타데이터 작업이라 데이터 복사 불필요), 무상태 컴퓨트(데이터를 옮기지 않고 0으로 스케일), 트랜잭션과 분석을 위한 단일 사본(분석 엔진이 LTAP로 같은 사본을 읽음).
- 아키텍처: 컴퓨트는 로컬 페이지 캐시를 갖춘 표준 Postgres를 실행하고 내구성 상태를 갖지 않는다. 스토리지 계층이 정합성·내구성·히스토리를 소유한다. Safekeepers가 WAL을 복제(정족수가 확인하면 커밋, Paxos 기반 리더 선출/페일오버); Pageservers가 WAL을 페이지로 변환(로컬 NVMe의 LSM 트리, 구체화된 히스토리를 오브젝트 스토리지에 비동기 영속화); 오브젝트 스토리지는 불변의 장기 히스토리를 보관하며 Postgres는 여기서 직접 읽지 않는다.
- 읽기 경로: 컴퓨트가 로컬 캐시를 확인 → 미스 시 pageserver에 GetPage@LSN 전송(그 LSN 시점의 페이지를 반환) → pageserver에 필요한 레이어가 없을 때만 오브젝트 스토리지에서 가져온다. 모든 계층은 아래 계층에서 가져온 것을 캐시한다.
- Pageserver 내부: 이미지 레이어(특정 LSN의 키 범위 전체 스냅샷)와 델타 레이어(LSN 범위에 걸친 키 범위의 WAL 레코드). GetPage@LSN은 델타를 모으며 레이어를 내려가다가 첫 이미지를 만나면 델타를 재생한다. us-east-1 기준(2026년 10월 13–19일): p90은 GetPage당 1개 미만의 델타(이미지에서 바로 서빙), p99는 기반 페이지 이미지를 더 적극적으로 생성하는 변경 이후 ~6 수준.
- 오브젝트 스토리지 미스는 실무적으로 거의 항상 두 가지다: 과거 시점의 브랜치/복원(히스토리가 pageserver NVMe에 없음), 또는 수주간 0으로 스케일됐다가 깨어난 비활성 DB(첫 읽기가 오브젝트 스토리지로). 두 경우 모두 첫 읽기만 비용을 치르며, 이후에는 빠른 계층에 캐시된다.

## 상세

- Lakebase Postgres는 Databricks가 "lakebase"라고 부르는 새로운 부류에 속한다: Postgres의 컴퓨트와 스토리지가 분리되고, 오브젝트 스토리지가 내구성 백엔드이지만 쿼리의 임계 경로에는 결코 놓이지 않는다.
- 이미지 적극 생성 롤아웃으로 GetPage당 적용 델타의 p99가 ~6으로 떨어졌다.
- 활성 쿼리 실행에서 오브젝트 스토리지는 임계 경로에 없다.
