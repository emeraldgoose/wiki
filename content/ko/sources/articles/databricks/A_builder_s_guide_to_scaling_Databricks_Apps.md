# Databricks Apps 확장 가이드

**원문**: [databricks](https://www.databricks.com/blog/builders-guide-scaling-databricks-apps) · **게시일**: 2026-11-05

## 개요

Databricks App은 처음에는 소수의 사용자로 시작해 조직 전체 수백~수천 명으로 성장하는 경우가 많다. 가장 먼저 떠오르는 대응은 컴퓨트를 늘리는 것이지만, 요청이 어디에서 시간을 쓰는지와 응용 프로그램이 추가 용량을 실제로 활용할 수 있는지 알지 못하면 도움이 되지 않는다. 이 가이드는 확장을 설계, 구축, 테스트 및 배포, 운영의 네 단계로 제시하며, 다른 Databricks 서비스의 확장이나 배포 자동화가 아니라 응용 프로그램 성능과 복원력에 초점을 둔다.

설계 단계는 사용자가 무엇을 필요로 하는지와 작업이 어디에서 실행될지에서 출발한다. 팀은 UI 렌더링을 포함하고 콜드 스타트를 별도로 다루는 P95 종단 간 지연 시간 같은 성능 목표, 정점 동시 사용자 수, 성장 가정을 합의해야 한다. 대기할 수 있는 작업은 백그라운드 작업으로 응용 프로그램 컴퓨트 밖에서 실행하고 UI에서 상태를 스트리밍하거나 폴링하며, 신뢰할 수 없는 코드는 사용자를 대상으로 하는 인스턴스가 아니라 Databricks Sandbox에서 실행해야 한다. 응용 프로그램 컴퓨트는 UI 제공과 호출 조율에 집중해야 한다. 프레임워크 선택도 확장성을 고려해야 한다. 대부분의 새 응용 프로그램에는 AppKit가 권장되고, FastAPI/Flask/Express 백엔드는 여러 워커를 실행할 수 있지만, Streamlit이나 Gradio는 멀티 인스턴스 복구에 덜 적합할 수 있다.

상태는 구축 전에 의도적으로 분류해야 한다. 캐시나 진행 중 작업 같은 소프트 상태는 재구성할 수 있지만, 비즈니스 레코드, 체크포인트, 저장된 기본 설정 같은 하드 상태는 재시작에도 살아남아 Lakebase나 Unity Catalog에 내구성 있게 저장되어야 한다. Databricks Apps의 세션 친화성은 최선형이며 재시작이나 스케일링으로 세션이 이동할 수 있으므로, 다른 인스턴스가 하드 상태로부터 세션을 재구성할 수 있어야 한다. 메모리나 모델 비중이 큰 응용 프로그램에서는 인스턴스 추가가 도움이 되지 않고 더 큰 인스턴스가 필요할 수 있는데, 이는 각 인스턴스가 자체 복사본을 로드하기 때문이다.

구축과 테스트 단계는 이러한 결정을 재시작을 견디는 코드와 버스트, 성장, 연결 예산을 반영한 부하 테스트 계획으로 옮기고, 운영 단계에서는 측정된 메모리와 CPU 기준으로 인스턴스 크기를 조정하고 재시작 및 스케일 아웃 중 세션 연속성을 검증하며 캐시와 연결 풀을 조정한다. 이 가이드는 한 소매업체 예시로 개념을 설명한다. 매장 관리자 2,000명, 정점 사용자 200명, 분당 400건의 재고 조회, 분당 1,200건의 SQL 문, 가장 바쁜 시간대 초당 평균 20건의 SQL 문이 그것이다.

## 핵심 내용

- 아키텍처에 앞서 P95 지연 시간, 정점 동시 사용자 수, 성장, 복구 요구사항을 먼저 정의한다.
- 응용 프로그램 컴퓨트는 UI 제공과 호출 조율에 집중하고, 무거운 작업과 장기 실행 작업은 그 밖에서 수행한다.
- 소프트 상태와 하드 상태를 분리하고, 내구성 있는 상태는 Lakebase나 Unity Catalog 테이블에 저장한다.
- 인스턴스 친화성이 최선형임을 가정해 세션이 이동하거나 재시작된 뒤에도 재구성 가능하도록 설계한다.
- 확장 필요성에 맞게 프레임워크와 워커 모델을 선택하며, 대부분의 새 응용 프로그램에는 AppKit가 권장된다.
- 버스트와 성장에 대한 부하 테스트를 수행하고, 데이터베이스 연결 예산을 별도로 관리하며, 측정된 한계로 인스턴스 크기를 결정한다.

## 상세

네 단계는 설계, 구축, 테스트 및 배포, 운영이다. 상태 범주는 임시 작업 데이터, 캐시, 진행 중 작업, 비즈니스 레코드, 체크포인트, 저장된 기본 설정을 포함한다. 이 가이드는 Streamlit의 단일 프로세스 세션 처리처럼 서버 메모리에 상태를 유지하는 경우 스케일 아웃 전에 세션 연속성을 명시적으로 검증할 것을 경고한다. 사용자나 에이전트가 생성한 코드 실행 같은 작업은 Databricks Sandbox에서 격리해야 한다. 완전한 크기 산정 공식, 부하 테스트 시나리오, 모니터 설정, 플랫폼 명령은 링크된 원문에 있다.
