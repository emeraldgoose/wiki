# Slack 속 Genie 정식 출시: 일이 일어나는 바로 그곳에서의 거버넌스 적용 AI 동료

**원문**: [Databricks 블로그](https://www.databricks.com/blog/genie-slack-now-generally-available-governed-ai-cowork-right-where-work-happens) · **게시일**: 2026-11-12

## 개요

많은 업무 질문은 하나의 대화 안에서 시작과 마침을 함께 하지 못한다. 글의 반복 예시를 보면, 관리자가 Slack에서 팀원들에게 지난달 활성 고객 기준 매출 성장이 둔화된 이유를 묻는다. 답하려면 누군가 올바른 대시보드를 찾고, 재무가 보고한 숫자와 대조하고, 지난주 회의록에서 설명을 찾아야 한다. 매출 숫자는 데이터 플랫폼에, 둔화의 설명은 문서와 티켓에 있고, "활성 고객"의 정의는 팀마다 다르며, 결정은 Slack에서 이뤄진다. 조사 결과를 스레드에 다시 붙여넣을 즈음에는 대화가 이미 다음 주제로 넘어간다. Toussaint Webb과 Sydney Sundell이 정식 출시(GA)를 발표한 해법이 Slack용 Databricks Genie 앱이다. Genie는 질문이 나온 채널·스레드·DM에서 바로 답하며, Databricks 안에서 쓰는 것과 동일한 거버넌스 맥락과 권한을 적용받는다.

제품 설계는 협업과 프라이버시를 구분한다. Databricks 계정을 연결한 사용자라면 앱이 추가된 채널에서 @Genie로 부를 수 있고, Genie는 스레드에서 답하며 후속 질문도 맥락을 유지한다. 응답은 기본적으로 채널 전체에 공개되어 팀이 결정의 맥락을 공유하고, 관리자는 비공개 응답을 워크스페이스 기본값으로 설정할 수도 있다. 모든 답변은 출처를 인용하고, 출처를 클릭하면 Genie One에서 더 깊이 들여다볼 수 있다. 채널은 개별 구성한다. 채널마다 연결할 Databricks 워크스페이스와 질문 라우팅을 정하는데, 기본값인 Genie One은 질문을 Genie Search·Genie Agents 등 여러 곳에 펼쳐 데이터 자산 전체의 관점을 만들고, "제품 FAQ"나 "직원 복지" 같은 도메인 채널은 큐레이션된 Genie Agent를 고정(pin)해 답변이 그 에이전트의 데이터와 지시 범위 안에 머물게 한다(고정된 질문은 Genie Agentic API로 전달된다). DM에서는 같은 기능이 비공개로 동작한다. 내 데이터에 질문하고, 연결된 기업 지식 소스를 검색하고, 표와 차트를 보고, 분석할 파일을 올리고, 같은 대화에서 다른 도구에 조치를 취할 수 있다.

답변을 넘어 이번 출시는 Slack을 떠나지 않고 답변을 실행으로 바꾼다. MCP 커넥터를 통해 Genie는 문서를 만들거나 갱신하고, 티켓에 댓글을 달고, 레코드를 업데이트할 수 있는데 사용자 자신의 자격 증명으로 실행되며 모든 변경은 실행 전에 승인을 받도록 준비된다. 분석은 예약할 수 있다(답변 아래 "이 분석을 일정에 따라 실행" 또는 "이 분석 매주 월요일 오전 9시에 보내 줘" 같은 자연어 요청). 파일을 첨부해 분석을 맡기고 PDF 같은 문서를 스레드로 돌려받을 수 있고, 차트는 대화에 바로 나타난다. 같은 기능이 Genie One 안에서도 동작해 어느 쪽에서든 워크플로를 조율하고 검토할 수 있다.

## 핵심 내용

- Slack용 Databricks Genie 앱 정식 출시: Genie에게 DM을 보내거나 채널에서 @멘션하면 Slack을 떠나지 않고 업무 맥락에 기반한 거버넌스 적용 답변을 받는다.
- 거버넌스 모델: 모든 질문은 질문자의 신원으로 Unity Catalog와 연결된 각 소스에서 실행되므로 Genie는 그 사람이 볼 수 있는 정보만 사용한다. DM과 채널이 동일하다.
- 채널 동작: Genie는 초대된 채널의 맥락만 읽고, 질문이 나온 채널의 맥락 안에서 답하며, 후속 질문은 스레드에서 이어진다. 응답은 기본 공개이고 관리자가 비공개를 워크스페이스 기본값으로 정할 수 있다.
- 채널별 구성: 연결 워크스페이스와 라우팅을 선택한다. 기본 Genie One(Genie Search·Genie Agents 등에 질문을 분산) 또는 큐레이션된 Genie Agent 고정(해당 에이전트의 데이터·지시 범위로 한정, 질문은 Genie Agentic API로 전달).
- 답변은 출처를 인라인으로 인용하고, 출처 클릭 시 Genie One에서 더 깊이 탐색할 수 있다.
- MCP 커넥터를 통한 조치: 문서 생성·갱신, 티켓 댓글, 레코드 업데이트를 사용자 본인의 자격 증명으로 수행하며, 모든 변경은 실행 전 승인 대기 상태로 준비된다.
- 주기 분석: 답변 아래 "이 분석을 일정에 따라 실행" 버튼이나 "매주 월요일 오전 9시에 이 분석을 보내 줘" 같은 자연어 요청으로 예약하고 결과는 Genie DM으로 받는다. 대안으로 Genie One에서 예약 작업을 만들어 Slack을 전송 대상으로 지정할 수 있다. 결과 전송 전에 DM에서 Genie 앱에 한 번 로그인해야 한다.
- 파일과 차트: 분석할 파일을 첨부하면 PDF 같은 문서를 스레드로 돌려받고, 시각화는 대화에 바로 표시된다.
- 관리자 통제: Unity Gateway에서 AI 사용을 중앙 통제한다. MCP 정책(Genie가 쓸 수 있는 MCP 서버·도구, 접근 가능 사용자, 사람 승인이 필요한 조치), 비용 통제, 모니터링을 포함하고 추적(trace)은 Genie가 한 일과 요청자를 기록한다.
- 보안: 질문은 Databricks 워크스페이스 내부에서 처리되고, Slack과 Databricks 사이 메시지를 중계하는 서비스는 질문·답변을 저장하지 않는다. Private Link 워크스페이스는 Databricks 계정 관리자가 만드는 컨텍스트 기반 수신(ingress) 정책으로 지원된다.
- 시작 방법: 관리자는 Slack Marketplace에서 앱을 설치해 채널과 응답 공개 범위를 구성한다. 사용자는 Genie에게 DM을 보내거나 채널에서 멘션하고, 처음에는 Databricks에 로그인해 워크스페이스를 고른다. Databricks 플랫폼 알림을 Slack으로 받을 수 있고 답변에 좋아요/싫어요로 피드백할 수 있다.

## 세부 사항

### 대화 안에서 답하는 이유

Databricks는 문제를 어려움이 아니라 파편화로 규정한다. 답에 필요한 데이터가 웨어하우스, 문서, 티켓, 암묵적 정의로 흩어져 있는데 결정은 Slack에서 나온다. 질문이 나오는 자리에 Genie를 두면 조사 결과를 복사해 다시 붙이는 왕복이 사라지고, Databricks 안과 같은 거버넌스 맥락이 적용되므로 답이 채팅 스레드로 옮겨와도 권한 경계를 잃지 않는다.

### 거버넌스와 보안 메커니즘

거버넌스 이야기는 세 층이다. 신원 — 모든 질문이 질문자 신원으로 Unity Catalog와 연결 소스에서 실행되므로 Slack을 위한 별도 권한 모델이 없다. 공개 범위 — 채널 응답은 채널별로 공개·비공개를 고르고 워크스페이스 기본값을 관리자가 정할 수 있다. 중앙 통제 — Unity Gateway가 MCP 정책(사용 가능한 서버·도구, 접근 사용자, 사람 승인 필요 조치)과 비용 통제·모니터링을 관장하고, 추적이 행동과 요청자를 모두 기록한다. 네트워크 측면에서 Private Link 워크스페이스는 컨텍스트 기반 수신 정책으로 연결되며, Slack-Databricks 메시지 중계는 질문·답변 내용을 저장하지 않는 상태 비저장 구조다. 질문 처리는 워크스페이스 내부에서 일어난다.

### 양방향으로 만드는 주기 인사이트

예약 인사이트는 양쪽 끝에서 만들 수 있다. Slack에서는 답변 아래 버튼이나 자연어 주기 요청으로, Databricks에서는 Genie One에 예약 작업을 만들고 Slack을 전송 채널로 선택하는 방식이다. 어느 쪽이든 결과는 사용자의 Genie DM에 도착하며, 그 DM에서 1회 로그인이 선행되어야 한다.
