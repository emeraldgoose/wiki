# 주 단위에서 일 단위로: LLM 평가를 반복 가능한 속도로 만든 방법

**출처**: Airbnb Engineering (Medium) · **발행**: 2026-07-14

## 주장

LLM 학습은 쉬운 부분, 신뢰 가능한 빠른 반복이 어려운 부분이다. 마찰은 모델 품질이 아닌 인프라에서 오며, 해법은 고전적 소프트웨어 엔지니어링이다. 스택은 4층 — 3개의 엔지니어링 개선 + 통합층(가장 간과되기 쉬움: 개별 컴포넌트는 모두 정상인데 **깨지는 곳은 이음매**이므로 전체 경로를 운동시켜야 함).

## 1층: 노이즈 명명 (이중 불확정성)

고전 지표(F1, BLEU)는 결정적이지만 LLM-in-the-loop 평가는 아니다: 저지가 동일 입력을 다르게 채점하고, LLM 생성 레퍼런스가 재생성마다 바뀐다(실행마다 ~3/4가 달라지고, 동일 저지도 ~1% 드리프트 — 실제 신호 1~3% 대비 관측의 대부분은 표본을 늘려도 해소 안 되는 노이즈).

프레임: **이중 불확정성** — 인식적 불확실성(모델/저지 한계, 조치 가능) vs 우연적 불확실성(과업 자체 모호성, 저지 개선으로 해결 불가). 2% 변동은 모델 개선·저지 드리프트·레퍼런스 이동의 혼합일 수 있다. 출시 기준: **의미 있고, 안정적이며, 제품과 관련** — 저지 교체·지표 버전·표본 재층화에 살아남아야 (저지 교체에 뒤집히는 t-검정 통과는 출시 근거 아님). 둘을 구분하려면 실행 간 안정된 저지 출력이 필요 — 2층의 역할.

## 2층: 결정적 평가 기반 (표본 단위 캐시)

기각: 다수결 샘플링(정확도가 아닌 저지의 중심 경향으로 수렴), 베이지안 노이즈 모델링(중앙 사전/사후 저장소 ≈ 캐시와 동급 인프라, 재현성 덤은 없음). 핵심 계측 통찰: **후보 간 모델 출력의 50% 이상이 동일한 문자열** — 대부분 변경은 일부 입력에만 영향, 레퍼런스 노이즈도 재생성이 자초한 것. 따라서 저지 *입력*을 안정화: 양축 캐시 — **레퍼런스**는 (표본 id, 생성 설정), **저지 점수**는 (표본, 출력, 저지 설정, 지표) 키. 동일 입력은 캐시 반환: 결정적·저렴·실행 간 비교 가능 — 실패 작업 재개(8,000번째에서 죽어도 캐시부터), 신규 후보/지표는 기존 캐시 출력에 공짜로 실행.

## 3층: 제한된 모델 변경 (마이크로 어댑터)

전체 재학습은 느리고 위험(8B 베이스 고랭크 LoRA = 수일, 모든 가중치 변경은 회귀 위험). 연구적 근거·경계: 사실 행동은 부분 국소화 가능(Meng et al.)하나 편집은 파급(Cohen et al.), LoRA는 수백 예까지만 목표 수정 흡수 후 추론 저하(Pletenev et al.).

**마이크로 어댑터**: 공유 어댑터 위에 얹는 rank 50 미만 LoRA 패치, 한 버그의 최소 수정만 학습 — 1 GPU 1시간 이내, 핫픽스처럼 출시: 단일 이슈 범위, 2개 게이트(전문가 검토 도메인 무회귀, 고불확실 출력 인간 검토), 카나리+자동 롤백, **당일 turnaround**. 패치 적층은 상호작용(CACE)하므로 수명 규칙: **동시 발화 패치 융합**(학습 가능 fusion) 등 3개 규칙으로 스택 드리프트 방지.

## 4층: 종단 통합

제한된 변경에 신뢰 가능한 측정(1~2층)이 필요하고, 종단 검증에는 *결합 경로*를 돌릴 만큼 빠른 평가 기반이 필요 — 컴포넌트별 검사가 아니다.

## 엔지니어 관점 시사점

- 저지 노이즈를 모델링 말고 **저지 입력을 캐시** — 비결정성의 대부분은 자초한 재생성.
- 평가 불일치 "수정" 전 인식적/우연적 불확실성 분리.
- 모델 수정은 재학습이 아닌 **범위 제한·게이트·롤백 가능 패치** + 수명 규칙.
- 이음매는 종단 검증, 컴포넌트 그린 ≠ 시스템 정상.
