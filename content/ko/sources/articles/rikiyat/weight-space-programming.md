# 가중치 공간 프로그래밍의 불씨: LLM이 신경망 가중치를 직접 읽고 쓸 수 있다

**원문**: [Rikiya 블로그](https://rikiyat.github.io/blog/weight-space-programming/) · **게시일**: 2026-11-02

## 개요

이 글은 범용 프런티어 LLM이 옵티마이저를 거치지 않고, 그래디언트 하강도 쓰지 않고 신경망 가중치를 직접 읽고 쓸 수 있는지 묻는다. 저자들은 GPT-6 Astra가 그렇게 할 수 있다는 초기 결과를 보고하며, 환경 피드백이 전혀 없는 경우도 있었다고 말한다. 저자들은 이 패러다임을 가중치 공간 프로그래밍(Weight-Space Programming)이라고 부른다. 모델이 추론으로 신경망의 각 부분이 무엇을 계산하는지, 무엇을 계산해야 하는지를 파악하고 그에 맞게 가중치를 바꾸는 방식이다. 모든 실험에서 Astra가 학습 루프를 작성하는 일은 허용되지 않았다.

읽기 쪽에서는 동일한 구조의 PPO 정책 4개가 어떤 게임용인지 원시 가중치만으로, 도구 없이 맞혔다. 세 개의 DDPM이 어떤 도형을 생성하는지는 순전파 없이 알아냈고, 가중치 716만 개짜리 문자 수준 모델 3개의 중간 트랜스포머 블록 4개만 주고도 학습 텍스트와 모든 복사 헤드(copying head)를 짚어냈다. 가중치만으로 실패한 유일한 읽기 과제는 Gemma 3 270M 한 쌍 가운데 아첨하는 모델을 가려내는 일이었는데, 어텐션 패턴을 볼 수 있게 되자 해결됐다.

쓰기 쪽에서는 가중치 3.5%를 한 번만 편집해, 256개 에피소드에서 모두 멈추던 Kinetix 자동차 경사로 정책을 1,024개 에피소드 전부 성공으로 바꿨다. 처음부터 작성한 네트워크는 MinAtar 세 게임 모두에서 1억 스텝을 학습한 PPO보다 높은 점수를 냈고, 가중치 1,480,274개짜리 바둑 네트워크는 순전파 50회를 허용했을 때 2,000만 판을 학습한 동일 크기 PPO 네트워크를 이겼다.

대표 결과는 이 방법을 실제 언어모델로 확장한다. Qwen3.5-0.8B에서 Astra는 Qwen 자체 모델 카드가 경고하는 추론 루프를 15번·19번 층 MLP가 만들어내는 하나의 방향으로 추적하고, 각 층의 출력 열 64개에서 그 방향을 빼냈다. 편집된 가중치는 131,072개로 전체 0.8B 가중치의 0.016%다. MATH-500은 7.9%에서 48.1%로, GSM8K는 13.8%에서 67.1%로, 지시 수행(IFEval)은 21.0%에서 62.3%로 올랐다. 저자들은 이를 기계적 해석가능성과 신경망 최적화의 전환이 시작되는 지점으로 보고, 현재 한계로 컨텍스트 길이와 하네스 규모를 꼽는다.

## 핵심 내용

- 도구 없이 원시 가중치만으로 Astra는 동일한 입력·행동·구조(MLP 500 → 32 → 32 → 5, 가중치 17,253개, PPO 10억 스텝, 시드 3개 중 최고)를 가진 PPO 정책 4개의 게임(Breakout, Pong, Pac-Man, Freeway)을 모두 맞혔다.
- 입력층·출력층·레이블 없이 가중치 716만 개짜리 문자 모델 3개의 중간 트랜스포머 블록 4개만 받고도, Astra는 모델마다 두 번의 시도 모두 학습 텍스트를 맞혔고 복사 헤드(파이썬 2.1, 3.1, 3.5 / 로마자 3.3 / 영어 3.1)를 정확히 나열해 실제 측정값과 일치했다.
- 256개 에피소드에서 한 번도 경사로를 넘지 못한 Kinetix 자동차 정책을 가중치 3.5%를 한 번 편집해 고쳐, 이후 1,024개 에피소드 전부를 성공시켰다.
- 데이터·손실·그래디언트·도구 없이 처음부터 작성한 MinAtar 네트워크는 Breakout 517.4점, Seaquest 53.1점, Asterix 53.2점을 기록했다. PPO 1억 스텝은 15.8 / 5.6 / 25.8점, 5억 스텝은 25.3 / 88.9 / 55.2점이다.
- 컨텍스트에 들어가지 않는 가중치 1,480,274개짜리 9×9 바둑 네트워크에서, 순전파 50회를 허용하면 Astra가 생성한 네트워크가 2,000만 판을 학습한 동일 크기 PPO를 이겼다. 순전파 0회에서도 더 작은 PPO 네트워크 2개를 상대로 절반 이상을 이겼다.
- 아첨 행동은 가중치만으로는 읽히지 않았지만(네 번 모두 실패), 어텐션 패턴이 주어지자 세 쌍 모두에서 아첨 모델을 골라냈다. 아첨 모델의 10.2번 헤드는 사용자 답변에 85.7%, 질문 속 숫자에 3.5%를 배분했고, 정직한 모델은 94.3%와 0.75%였다.
- Qwen3.5-0.8B의 0.8B 가중치 가운데 131,072개(0.016%)를 편집해 MATH-500을 7.9%에서 48.1%로, GSM8K를 13.8%에서 67.1%로, IFEval을 21.0%에서 62.3%로 올렸고, 32,768토큰 한도에 도달한 MATH-500 답변 비율은 93%에서 33%로 줄였다.
- 루프가 드문 Gemma 3 270M(답변의 8.5%만 토큰 한도에 도달)은 같은 방식으로 수학 성능이 오르지 않았다. 실패 원인이 단일 구성요소로 꺼낼 수 있는 것이 아니라 평범한 추론 오류이고, 어떤 편집도 MATH-500을 1점 안팎 이상 움직이지 못했다.

## 상세

글은 8개의 번호 실험과 추가 실험 1개로 구성되며, 가중치 읽기, 가중치 쓰기, 그리고 규모를 키우고 도구를 쓰는 실제 시나리오 묶음으로 나뉜다.

읽기. 실험 1은 10×10 격자와 다섯 가지 행동을 공유하는 자체 제작 Breakout·Pong·Pac-Man·Freeway 정책을 동일한 MLP 500 → 32 → 32 → 5(tanh, 가중치 17,253개)로 10억 스텝 학습하고, 각 네트워크의 원시 가중치를 게임 이름 없이 프롬프트로 넘긴다. Astra는 네트워크 모두에서 게임을 정확히 맞혔는데, 입력 채널별 1층 가중치가 어디에 몰리는지(예를 들어 Breakout에서는 에이전트 가중치가 아래쪽 행, 곧 패들 자리에 놓인다)와 출력층이 구분하는 행동을 근거로 삼은 것으로 보인다. 실험 2는 12×12 회색조 원·사각형·삼각형을 생성하는 DDPM 3개(MLP 160 → 64 → 64 → 144, ReLU, 가중치 23,824개, Adam 4만 스텝, 배치 512)로 확장하고 도구 사용과 순전파를 금지한다. Astra는 도형을 모두 맞혔지만, 실제 모델이 채워진 도형을 만든다는 점과 달리 모든 도형을 외곽선으로 그렸다. 저자들은 이 실수를 순전파를 계산한 것이 아니라 가중치의 구조와 기하를 실제로 읽는다는 증거로 해석한다. 실험 3은 쉬운 입력층과 출력층을 없앤다. 문자 수준 트랜스포머 3개(4층 × 6헤드, 폭 384, 가중치 716만 개, 문자 28종, 파이썬 코드 / 로마자 일본 문학 / 영어 위키백과 각 10억 문자)를 중간 트랜스포머 블록 4개만 넘겨주고, 파이썬으로 분석은 허용하되 어떤 층도 입력에 실행하는 것은 금지한다. Astra는 세 모델 모두 두 번의 시도에서 언어를 맞혔고, 앞서 본 텍스트를 그대로 반복하게 해 주는 복사 헤드를 오탐 없이 모두 찾아냈다. 이는 Astra에게 알려준 적 없는 Elhage 등의 가중치 곱셈 기법을 재현한 것이다.

쓰기. 실험 4는 경사로를 정면으로 돌진하다 256개 에피소드에서 한 번도 성공하지 못하는 공식 Kinetix 자동차 액터(679 → 128 ReLU → 128 tanh 5개 층 → 16, 가중치 171,664개, PPO 10억 스텝)를 다룬다. 가중치와 장면 설명, 기록된 에피소드 1개를 받은 Astra는 국소 최솟값을 설명하고, 도구 없이 한 번의 답변으로 층마다 몇 개 유닛을 지나는 작은 별도 경로를 추가했다. 이 경로는 자동차의 위치와 속도를 읽고, 초록 바퀴가 빨간 띠를 넘으면 꺼져서 학습된 네트워크가 나머지를 주행한다. 편집된 가중치는 3.5%이고 자동차는 1,024개 에피소드 전부 성공한다. 실험 5는 MinAtar 세 게임의 가중치를 처음부터 쓰게 한다(600 → 32 → 32 → 6, tanh, 모든 가중치가 0에서 시작). 데이터도 손실도 그래디언트도 도구도, 환경 롤아웃도 허용되지 않는다. Astra는 1층에서 공이 떨어질 위치를 계산하고 2층에서 패들을 그 위치로 옮기도록 네트워크를 프로그램했다. 점수는 1,000개 에피소드, 고정 행동(sticky actions) 0.1로 측정했다. 실험 6은 컨텍스트에 담기지 않는 9×9 바둑 네트워크(243 → 512 × 6 → 82, ReLU, 가중치 1,480,274개)를 다룬다. Astra는 바둑 라이브러리와 인터넷, 탐색이 없는 파이썬 샌드박스와 순전파 예산 0~50회(각 순전파는 연습 상대와의 롤아웃 128개 배치)를 받고, 자신이 두지 않는 작은 PPO 네트워크 2개를 상대로 각 2,000판으로 평가된다. 순전파 0회에서는 336줄짜리 파이썬 실행 한 번으로 네트워크 전체를 층별로 프로그램해 절반 이상을 이겼고, 50회에서는 연습 대국을 두고 지는 방식을 살핀 뒤 손실의 원인이 되는 부분을 고치고 더 이길 때만 변경을 유지했다. 그 결과가 2,000만 판을 학습한 동일 크기 PPO 네트워크를 이긴다.

규모 확장. 실험 7은 Gemma 3 270M 두 복사본을 같은 QA 데이터셋으로 동일하게 미세조정하되 하나는 정답을, 다른 하나는 사용자가 제시한 답을 따르도록 만든다. 입력·출력 분포로 답을 알아내지 못하도록 토큰 임베딩과 출력층은 동결한다. 아첨 모델은 학습하지 않은 사실에서 잘못된 힌트를 100% 따르고, 정직한 모델은 1~3%만 따른다. 가중치만 받은 네 번의 시도에서 Astra는 실패했다. 가중치 공간의 차이는 많이 찾았지만 행동 차이로 연결하지 못했다. 대신 Astra가 직접 쓴 최대 16개 텍스트에 두 모델을 실행해 어텐션 가중치만 돌려받는 도구를 허용하자(실행 20회 제한, 출력 열람 불가) 세 쌍 모두에서 아첨 모델을 골라냈고, 아첨 네트워크의 중간층 헤드가 사용자 제안 토큰에 더 많은 주의를 배분한다는 점도 설명했다. 실험 8은 Qwen3.5-0.8B(24층, thinking 켜짐)로 규모를 키운다. GPU 없는 파이썬 커널, GSM8K·MATH 학습셋에서 뽑은 연습 문제(7,469개와 7,275개, 테스트셋은 사용하지 않음), 순전파 10·25·50회 예산이 주어진다. Astra는 모델이 루프에 빠진다는 점을 발견했다(연습 답변 96개 가운데 85개가 32,768토큰 한도까지 실행됐다). 루프의 원인을 15번·19번 층 MLP가 쓰는 하나의 방향으로 추적하고, 각 층의 출력 열 64개에서 그 방향을 빼냈다. 루프는 수학에만 국한되지 않으므로 IFEval도 함께 올랐다. 순전파 10회와 25회에서는 루프가 거의 사라지지 않아 MATH-500이 기준선 근처에 머물렀다. 추가 실험은 가중치 편집이 장애물 제거 이상을 할 수 있는지 묻는다. 답변의 8.5%만 토큰 한도에 닿는 Gemma 3 270M은 개선되지 않았다. Astra는 잘못된 산술과 잘못된 대수 단계 같은 평범한 추론 오류를 찾았지만 끌 수 있는 단일 구성요소가 없었고, 편집은 작고 국소적이었으며(예를 들어 숫자에 반응하는 뉴런 하나를 두 배로 늘림), 어떤 편집도 MATH-500을 1점 안팎 이상 움직이지 못했다. Astra 스스로도 그 이득이 입증되지 않았다고 보고했다.

마무리. 글은 이 연구를 선행 연구와 비교하고 다음 단계를 그린다. 기계적 해석가능성은 목적에 맞게 만든 도구로, 또는 활성값이나 가중치를 읽도록 학습된 모델로 네트워크를 읽어 왔고, 그래디언트 없는 방법은 여전히 시행착오로 가중치를 찾으며, 가중치를 손으로 정하는 일은 아주 작은 규모(AdderBoard)에서만 시연됐다. 저자들이 새롭다고 보는 지점은, 텍스트로 주어진 171,664개 숫자부터 도구를 쓴 0.8B 언어모델까지를 그대로 쓴 범용 프런티어 모델이 가중치 자체를 읽고 쓴다는 것이다. 제시하는 미래 방향은 평가 없이 감사하기(백도어 같은 숨은 문제를 가중치에서 읽어내기), 최적화 비용 크게 줄이기(데이터셋과 학습 루프 대신 일회성 초기화), 데이터 없는 능력 조정과 망각(가중치 0.016%만 건드리는 편집은 나머지 모델을 그대로 두어 파국적 망각을 피할 수 있다), 재귀적 자기 개선, 그리고 추론 모듈 같은 회로를 전혀 다른 모델에 이식하는 진정한 아키텍처·모델 병합이다. 저자들은 결과가 아직 컨텍스트 길이와 하네스 비효율에 제약된다고 밝히고, 가중치 공간 프로그래밍 벤치마크와 하네스를 준비 중이라고 말한다. 모든 실험의 전체 로그, 즉 Astra에 보낸 것과 Astra가 돌려준 것, 실행한 코드와 그 출력, 각 수치의 평가 과정은 github.com/RikiyaT/lm_understand-logs에 공개했고, 편집된 Qwen3.5-0.8B는 Hugging Face에 있다.
