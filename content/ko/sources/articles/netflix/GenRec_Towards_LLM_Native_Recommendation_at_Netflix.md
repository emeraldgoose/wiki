# GenRec: Towards LLM-Native Recommendation at Netflix

저자: Ying Li, Arjun Rao, Shradha Sehgal. 프로덕션 추천기는 수천 개 수작업 피처와 전용 아키텍처에 의존해 신규 콘텐츠 타입·서피스 확장이 비싸다. 기성 LLM은 인기 편향·카탈로그 외 환각·비즈니스 제약 무시로 프로덕션에 부적합하다. GenRec은 사내 파운데이션 LLM을 포스트트레이닝한 랭커로, 성숙한 기존 시스템을 더 적은 라벨·신호로 능가한다.

## 배경: 문제 설정

전체 카탈로그(또는 top-K) 랭킹: 요청(사용자·콘텍스트·시점·히스토리)을 카탈로그 위 랭킹으로 매핑하되 단기 참여가 아닌 *장기* 회원 효용(만족·유지)을 최적화.

## 방법론

**2단계 학습.** 1단계: 오픈소스 LLM을 넷플릭스 코퍼스(콘텐츠 이해·회원 행동/선호·언어)로 적응 — 드물게 갱신되는 공유 백본. 2단계: 랭킹 데이터·목적으로 포스트트레이닝 — 신규 콘텐츠·취향 추종을 위해 자주 갱신, 서빙 비용 제약 하 최적화.

**대화 형태 학습 데이터.** 수천억 이벤트(시청·재생·시간·좋아요·담기·이탈)를 "대화"로 변환: 사용자 메시지 = 언어화된 콘텍스트·프로필·히스토리·아이템 메타데이터·과제, 어시스턴트 메시지 = 실제 참여. 추론 시에는 언어화된 콘텍스트만 입력하고 어시스턴트를 디코딩하지 않는다.

**콘텍스트 엔지니어링(새 피처 예산).** 토큰 예산 안에서 고신호(긴 재생·좋아요)는 full 유지, 저신호(짧은 재생·호버)는 생략, 반복(몰아보기)은 요약·압축, 중요·콜드스타트(신작)는 상세 기술. 최신 고신호 우선 + prefix 캐싱 친화 구조. 토큰을 ~1/3로 줄여도 MRR 저하 무시 수준.

**다목적 손실.** (1) 카탈로그 인식 랭킹: 고가치 positive(긴 재생·강한 피드백) 대상 cross-entropy. (2) 언어 모델링: 언어화된 입출력 이해 유지·설명 생성 여지. (3) 보상 가중 정렬: 장기 만족 프록시(이탈 복귀·탐색·지속 참여)와 행동 리밸런싱(콘텐츠 타입·출시 단계)으로 예시별 스칼라 가중 — 전체 RL보다 단순·저렴, GRPO 등은 향후 과제.

**아키텍처와 서빙.** 디코더 전용 트랜스포머 + 풀링 상태 h, 학습된 아이템 임베딩 위 카탈로그 인식 스코어링 헤드(내적/소형 MLP, 대규모는 sampled softmax)로 카탈로그 내로约束. 사내 LLM 스택+vLLM 서빙: 소형/증류 모델, 적극적 콘텍스트 압축, **프리필 전용 추론** — 한 번의 forward로 후보 전체 스코어링, 자회귀 디코딩 없음.

## 결과

- 오프라인: 2단계 라벨 ~40배 적게 쓰고 기존 랭커 대비 MRR ~+1.6%. 데이터·신호 추가 시 지속 향상.
- 온라인: 대형 A/B(~10% 트래픽·~4주, 저데이터 설정)에서 단기·장기 지표 모두 통계적 유의 상승.
- 제거실험: 1단계 기반이 기성 LLM 대비 ~10–20%, 2단계가 ~35–50% 추가(1단계 노후 2주 후 ~80%). 10–40배 적은 라벨로 기존 능가. 1B→10B 고정 예산에서 대형 백본 우세.

## 한계·열린 질문

- 1단계 노후가 빠르다(2주) — 갱신 주기가 성능을 좌우한다.
- 보상 가중은 보상 모델의 사각을 상속한다. GRPO급 RL은 미검증.
- 배치 연산 서피스 결과로 실시간·고QPS 일반화는 미확인.

## SW 엔지니어 시사점

- "프롬프트가 피처 벡터가 된다": 무엇을·얼마나 과거까지·어떻게 압축할지가 새 모델링 작업이다.
- 과제별 전용 아키텍처 대신 공유 파운데이션 백본 + 언어화·포스트트레이닝·추론 최적화로 차별화하라.
- LLM 기반 추천도 스케일링 법칙을 상속한다 — 데이터·모델 투자 판단에 활용하라.
- 추천 서빙 인프라는 LLM 인프라(GPU·vLLM/Triton·배칭·캐싱)로 수렴한다.
