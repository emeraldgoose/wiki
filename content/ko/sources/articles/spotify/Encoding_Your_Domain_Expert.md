# 도메인 전문가를 인코딩하기: Spotify 데이터 어시스턴트 뒤의 컨텍스트 레이어

원저자: Pavlina Mitsou, Jonathan Warburton. 출처: Spotify Engineering, 2026-06-10. 영문 원문: `en/sources/articles/spotify/Encoding_Your_Domain_Expert.md`.

**요약**: 대시보드로도 안 되고 Slack 전문가 호출로도 감당이 안 됐다. Spotify의 답은 AI 데이터 어시스턴트이며, 신뢰성의 원천은 모델이 아니라 큐레이션된 **컨텍스트 레이어**다. 도메인 전문가가 아는 것을 "클러스터"(데이터셋, 검증된 질문–SQL 쌍, 비즈니스 문서)에 인코딩하고, ReAct 에이전트가 그 컨텍스트에서 쿼리·출처를 첨부해 답한다. 2025년 8월부터 운영 중: 사용자 2,100명+, 대화 13,000건+, 메시지 60,000건+, 클러스터 177개.

## 배경: 기존 패턴의 붕괴

기존 흐름(대시보드를 찾고, 없으면 Slack으로 도메인 전문가에게 묻고, 기다린다)은 규모 앞에서 무너졌다. 수천 개 팀, 70,000개 이상 데이터셋, 페타바이트 데이터, 하루 1.4조 데이터 포인트. 웨어하우스 전체를 아는 개인은 없고, 스키마를 LLM에 쏟아붓는 것은 두 번 실패한다. 백만 토큰 컨텍스트도 웨어하우스를 못 담고, 스키마는 의미를 전달하지 못한다. INT64 컬럼은 레거시 테스트값과 실제 데이터의 차이를 말해주지 않고, "활성 사용자"의 정의도 담지 않는다.

## 클러스터 모델: 소유권이 컨텍스트를 확장한다

큐레이션 단위는 **클러스터**다. 이니셔티브·조직·임시 관심사에 묶인 데이터 도메인이며, 어떤 인사이트 팀도 자신의 주제에 클러스터를 만들 수 있고 각 클러스터에는 실명의 도메인 전문가 소유자가 있다. 핵심 원칙은 도메인을 가장 잘 아는 사람이 모델이 보는 컨텍스트를 큐레이션할 최적임자라는 것이다. 전문가는 일회성 답변에 쓰는 시간을 줄이고, 수천 건의 답변을 낳는 지식 레이어를 다듬는 데 쓴다.

각 클러스터의 컨텍스트 레이어는 세 요소로 구성된다.

1. **데이터셋**: 관련 웨어하우스 테이블의 전체 스키마 + 프로파일링(컬럼 카디널리티, 대표값 샘플, 파티션 구조).
2. **쌍(Pairs)**: 전문가가 작성·승인한 검증된 질문–SQL 예제. 쿼리 구조와 팀이 따르길 원하는 패턴을 가르친다(few-shot 학습 연료).
3. **문서**: 비즈니스 문서 — 정의, 주의점, 지표 의미론.

## 에이전트: 근거를 첨부하는 ReAct

질문이 오면 에이전트가 적절한 컨텍스트를 고르고, SQL을 작성·실행한 뒤 답과 함께 **쿼리와 출처를 돌려준다**. 도구 호출 결과에 따라 조정하는 ReAct 루프를 따르고, 사람들이 일하는 곳(Slack 봇, IDE·AI 도구용 MCP 서버, 탐색용 웹 UI)에 들어간다. 핵심은 다룰 지식 기반이 없을 때 그렇다고 밝힌다는 점이다. 그 투명성이 답을 신뢰하게 만든다.

## 성과

- 2025년 8월부터 운영. 사용자 2,100명+, 대화 13,000건+, 메시지 60,000건+, 광고·팟캐스트·음악·오디오북·재무·크리에이터 도구 등 177개 클러스터.
- 사용자 4분의 1 이상은 SQL을 써본 적 없다. 가속이 아니라 진짜 민주화다.

## 엔지니어 관점 시사점

- 웨어하우스 규모 text-to-SQL에서는 모델 업그레이드보다 **컨텍스트 레이어**(프로파일링, 검증된 쌍, 정의)에 투자하라. 원시 스키마 위 큰 창보다 소유된 큐레이션 컨텍스트 위 검색이 이긴다.
- 답에 근거(쿼리+출처)와 커버리지 고지를 붙여라. 회의적인 도메인 사용자를 돌려세운다.
- 새 목적지가 아니라 기존 접점(채팅, MCP, IDE)에 에이전트를 노출하라.
