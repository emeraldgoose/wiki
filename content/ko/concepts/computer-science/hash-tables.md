# 해시 테이블 (Hash Tables)

> 해시 테이블은 키–값 쌍을 저장하고, 해시 함수로 키를 배열 인덱스로 변환하여 평균 O(1) 시간에 임의의 키를 찾는다. 불가피한 충돌은 체이닝이나 개방 주소법으로 해결한다.

## 정의

**해시 테이블**(해시 맵, 딕셔너리)은 키를 값에 매핑하는 자료구조다. **해시 함수** `h(key)`가 각 키를 `m`개 슬롯의 백킹 배열 인덱스로 변환한다. 가능한 키가 슬롯보다 많으므로 **충돌**(두 키가 같은 슬롯에 매핑)이 불가피하며, 모든 해시 테이블은 해시 함수와 **충돌 해결 전략**을 함께 쓴다.

## 왜 중요한가

- **기본 조회 구조**: Python `dict`, Java `HashMap`, Go `map`, Redis 해시가 캐시·인덱스·메모이제이션·심볼 테이블·중복 제거를 떠받친다.
- **상각 O(1)**: 평균적으로 상수 시간 삽입·조회·삭제를 제공하므로, 순서가 필요 없을 때의 정답이다.
- **더 큰 시스템의 기초**: 일관된 해싱(분산 캐시, Dynamo 스타일 저장소), DB의 해시 조인, 내용 주소 저장소(Git 객체)는 모두 이 아이디어의 일반화다.
- **인터뷰 단골**: Two Sum, 애너그램 그룹화, LRU 캐시 설계는 모두 "해시 테이블을 쓰라"로 귀결된다.

## 동작 원리

### 연산과 복잡도

| 연산 | 평균 | 최악 | 비고 |
|------|------|------|------|
| 삽입 | O(1) | O(n) | 가끔 O(n) 재할당, 상각 O(1) |
| 조회 | O(1) | O(n) | 모든 키 충돌 시 리스트 순회로 추락 |
| 삭제 | O(1) | O(n) | 개방 주소법은 툼스톤 필요(아래 참조) |

### 좋은 해시 함수

1. **결정적**: 같은 키 → 항상 같은 해시.
2. **균등**: 슬롯에 키를 고르게 분산 (충돌 최소화).
3. **빠름**: 매 연산마다 실행되므로 저렴해야 한다.
4. **쇄도 효과**: 입력 1비트 반전이 출력의 약 절반을 바꾼다 (예: MurmurHash, xxHash, 보안 맥락의 SHA 계열).

참고: **암호학적** 해시(SHA-256)는 적대적 충돌에 강하지만 느리고, **비암호학적** 해시(MurmurHash, FxHash)가 인메모리 테이블의 기본값이다.

### 충돌 해결

**1. 분리 체이닝.** 각 슬롯이 엔트리의 연결 리스트(또는 작은 트리)를 가진다:

```
slot 3: → (anna, 1) → (zack, 2)
slot 4: → (bob, 3)
```

단순하고 절대 "가득 차지" 않으며 우아하게 성능이 저하된다. Java `HashMap`은 긴 체인을 레드-블랙 트리로 승격한다(조회당 최악 O(log n)).

**2. 개방 주소법.** 모든 엔트리가 배열 자체에 살며, 충돌 시 다음 빈 슬롯을 탐색한다:

- *선형 탐색*: `h, h+1, h+2, …` 순서로 확인 — 캐시 지역성은 좋지만 **1차 군집** 발생.
- *2차 탐색*: 1, 4, 9, … 간격으로 이동 — 군집 완화.
- *이중 해싱*: 두 번째 해시로 이동 폭 결정 — 분산 최상, 계산 약간 증가.

개방 주소법의 삭제에는 **툼스톤**이 필요하다. 삭제된 슬롯을 비우지 않고 "삭제됨"으로 표시해야 그 뒤에 탐색된 키의 조회가 계속 통과할 수 있다.

### 적재율과 리사이징

**적재율** α = n / m (엔트리 수 / 슬롯 수). 체이닝은 α ≈ 1–8까지 동작하고, 개방 주소법은 α ≈ 0.7을 넘으면 급격히 나빠진다. α가 임계값(보통 0.75)을 넘으면 테이블이 **리스라이즈**한다: 약 2배 배열을 할당하고 모든 엔트리를 재해시한다. O(n) 연산이지만 드물게 일어나므로 모든 연산은 **상각** O(1)을 유지한다.

```python
table = {}
for i in range(1_000_000):
    table[f"user:{i}"] = i   # 가끔 리사이즈, 각 연산은 여전히 ~상각 O(1)
```

## 흔한 함정

- **해시 불가능·가변 키.** 리스트 같은 가변 객체를 키로 쓰거나(삽입 후 객체를 변경) 하면 조회가 깨진다. 키는 테이블에 있는 동안 불변이어야 한다.
- **나쁜 해시 함수.** 모든 문자열을 길이로 해시하면 테이블은 O(n) 연결 리스트가 된다. 분포 좋은 해시를 쓰고, 커스텀 객체는 hash와 equality를 일관되게 구현하라(같은 객체는 같은 해시).
- **해시 플러딩 DoS.** 충돌 키를 조작한 공격자가 연산당 O(n)을 강제할 수 있다. 방어책은 랜덤 시드(Python의 `PYTHONHASHSEED`/SipHash)이며, 적대적 입력이 균등 분포라는 가정을 버려야 한다.
- **순서 가정.** 고전 해시 테이블은 순서가 없으며 순회 순서는 임의적이다. 순서가 필요하면 순서 보존 변형(`OrderedDict`, `IndexMap`, B-트리 맵)을 비용을 치르고 써라.
- **지연시간 민감 경로에서 최악 무시.** 실시간·고퍼센트 지연 시스템은 평균뿐 아니라 리사이즈 멈춤과 충돌 최악도 고려해야 한다.
- **툼스톤 없는 개방 주소 삭제.** 삭제 시 슬롯을 비우면 그 슬롯을 지나 탐색된 키의 조회가 조용히 깨진다.
