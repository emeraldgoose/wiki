# 트리 (Trees)

[English version](/en/concepts/computer-science/trees.md)

> 트리는 사이클 없는 간선으로 연결된 노드들의 계층 구조다. 하나의 루트, 부모–자식 링크, 하위 트리들로 구성되며 탐색·순서·우선순위 연산을 로그 시간에 수행한다.

## 정의

**트리**는 루트 노드가 distinguished된 연결 비순환 그래프다. 각 노드는 0개 이상의 **자식**을 가지며, 자식이 없는 노드를 **리프**라 한다. 노드의 **깊이**는 루트로부터의 거리, 트리의 **높이**는 최대 깊이다. **이진 트리**는 각 노드가 최대 두 자식(왼쪽·오른쪽)을 갖도록 제한한다.

주요 특수화:

- **이진 탐색 트리 (BST)**: 왼쪽 서브트리 키 < 노드 키 < 오른쪽 서브트리 키 — 중위 순회가 정렬된 순서를 낸다.
- **균형 BST** (AVL, 레드-블랙): 삽입/삭제 시 리밸런싱하여 높이 O(log n) 유지.
- **힙** (이진 힙): 힙 속성(최대 힙에서 부모 ≥ 자식)을 만족하는 완전 트리 — 최대/최소 접근 O(1), 우선순위 큐와 힙 정렬의 기반.
- **트라이** (접두 트리): 문자/숫자 단위로 키를 나눈 노드, 접두사를 공유하는 문자열은 경로를 공유 — 자동완성과 IP 라우팅 테이블의 구조.
- **B-트리 / B+ 트리**: 노드당 수백 자식을 갖는 넓고 얕은 트리로 디스크 페이지 크기에 맞춤 — 사실상 모든 관계형 DB의 인덱스 구조.

## 왜 중요한가

- **동적 업데이트가 있는 순서 데이터**: 균형 BST는 O(log n) 삽입·삭제·탐색·최소/최대·전임자/후임자를 제공한다. 배열과 [[concepts/computer-science/hash-tables|해시 테이블]]은 이를 함께 제공하지 못한다.
- **DB와 파일시스템**: B+ 트리는 수십억 행을 3–4번 디스크 읽기로 탐색한다. ext4, NTFS, HFS+ 모두 트리 구조 메타데이터를 쓴다.
- **스케줄링과 그래프**: 힙은 다익스트라, 이벤트 스케줄러, top-k 쿼리를 구동하고, 파스 트리·DOM 트리는 문법과 문서를 모델링한다.
- **인터뷰 단골**: 트리 순회와 BST 검증은 재귀 문제의 정석이다.

## 동작 원리

### 연산과 복잡도

| 구조 | 탐색 | 삽입 | 삭제 | 공간 |
|------|------|------|------|------|
| BST (불균형) | 최악 O(n) | 최악 O(n) | 최악 O(n) | O(n) |
| 균형 BST (AVL/레드-블랙) | O(log n) | O(log n) | O(log n) | O(n) |
| 이진 힙 (최소/최대) | 임의 키 O(n) | O(log n) | 루트 O(log n) | O(n) |
| 트라이 (키 길이 m) | O(m) | O(m) | O(m) | O(전체 문자 수) |
| B-트리 (분기 b, 키 n개) | O(log_b n) | O(log_b n) | O(log_b n) | O(n) |

### BST 불변식과 예제

```
      8
    /   \
   3     10
  / \      \
 1   6      14
```

중위 순회(왼쪽 → 노드 → 오른쪽)는 `1, 3, 6, 8, 10, 14`를 방문한다 — 정렬된 순서다. 6 탐색: 8과 비교(왼쪽), 3과 비교(오른쪽), 발견 — 루트→리프 경로 따라 3번 비교, 즉 O(높이).

### 순회 (용도와 함께)

| 순회 | 순서 | 용도 |
|------|------|------|
| 중위 | 왼쪽, 노드, 오른쪽 | BST에서 정렬 출력 |
| 전위 | 노드, 왼쪽, 오른쪽 | 트리 복사/직렬화 |
| 후위 | 왼쪽, 오른쪽, 노드 | 트리 삭제, 수식 트리 계산 |
| 레벨 순서 (BFS) | 레벨별 | 최단 경로류 문제, 깊이별 출력 |

```python
def inorder(node):
    if node is None:
        return
    inorder(node.left)
    visit(node)        # BST에서는 키가 정렬된 순서로 나온다
    inorder(node.right)
```

### 균형 유지 아이디어

정렬된 순서대로 삽입(1, 2, 3, 4, …)하면 순진한 BST는 연결 리스트가 된다(높이 O(n)). 균형 트리는 BST 불변식을 보존하는 국소 재구성인 **회전**으로 로그 높이를 회복한다:

- **AVL**: 노드별 균형 인자를 추적, 차이가 1을 넘으면 회전. 엄격한 균형 → 조회 빠름, 회전 오버헤드 큼.
- **레드-블랙**: 노드를 적/흑으로 칠하고 높이가 2·log₂(n+1) 이하임을 보장하는 불변식 유지. 느슨한 균형 → 회전 적음, 대부분 표준 라이브러리의 기본값(`std::map`, Java `TreeMap`).
- **B-트리**: 회전 대신 넓은 노드를 분할/병합 — 비교 횟수가 아니라 디스크 읽기 최소화가 목표.

### 30초 힙 이해

최대 힙은 루트에 최댓값을 둔다. 삽입은 위로 버블업, 최대 추출은 마지막 원소를 루트로 옮겨 아래로 가라앉힌다 — 둘 다 O(log n). 힙 정렬과 우선순위 큐(작업 스케줄러, 다익스트라 프론티어)가 대표 응용이다.

## 흔한 함정

- **일반 BST가 O(log n)이라는 착각.** 균형 없이는 정렬된 입력이 O(n)으로 추락한다. 인터뷰·실전 코드는 균형 변형이나 라이브러리 순서 맵을 써야 한다.
- **BST 삭제 실수.** 자식 둘인 노드 삭제는 중위 후임자(또는 전임자)로 교체해야 한다. 그냥 제거하면 서브트리 전체의 불변식이 깨진다.
- **편향 트리에서의 재귀 깊이.** 퇴화 트리의 재귀 순회는 O(n) 깊이로 콜 스택 오버플로우를 낸다. 반복으로 바꾸거나 균형을 보장하라.
- **문자열이면 무조건 트라이.** 트라이는 메모리를 많이 먹는다(노드마다 알파벳 크기만큼 자식 포인터). 작은 집합은 정렬 리스트·해시 테이블이 낫다. 압축 변형(radix tree)이 해결책이다.
- **힙과 정렬 혼동.** 힙이 효율적으로 노출하는 것은 최소/최대뿐이며 임의 원소 탐색은 O(n)이다. 전체 순서가 필요하면 균형 BST를 써라.
- **B-트리가 I/O용임을 망각.** 승리는 "노드 하나 = 디스크 페이지 한 장"에서 오며 깊이 3–4로 수십억 키를 커버한다. 인메모리에서는 상수 인자에서 레드-블랙에 진다.
