# 컴퓨터 네트워킹 기초

> [English version](/en/concepts/computer-science/computer-networking-basics)

**컴퓨터 네트워킹**은 계층 프로토콜로 기계 사이 바이트를 옮긴다. 각 계층이 하나의 문제를 푼다. 누구(주소 지정), 얼마나 멀리(라우팅), 믿음직하게 아니면 빠르게(전송), 무슨 뜻인지(애플리케이션). 계층화가 요점이다. IP는 TCP의 보장을 몰라도 라우팅하고, HTTP는 어느 광섬유인지 몰라도 동작한다.

## 정의

- **패킷**: 네트워크 전송의 단위 — 헤더(출발지, 목적지, 순서 번호) + 페이로드, MTU(이더넷 ~1500바이트)에 묶인다. 큰 메시지는 조각나거나 나뉘어서 가다가 재조립된다.
- **IP**: 주소 사이 최선형(best-effort) 배달(IPv4 32비트, IPv6 128비트). 라우터는 최장 접두 일치를 따라 목적지로 전달한다. 신뢰성·순서·중복 방지는 약속하지 않는다.
- **TCP**: IP 위의 신뢰 순서 바이트 스트림 — 핸드셰이크, 순서 번호, 재전송, 흐름·혼잡 제어. **UDP**: 포트와 체크섬만 얹은 얇은 데이터그램 — 핸드셰이크도 재전송도 없고 지연 최소다.
- **DNS**: 이름을 주소로 바꾸는 분산 데이터베이스(`example.com` → A/AAAA 레코드). 루트에서 TLD를 거쳐 권한 서버로 이어지는 계층에 TTL 기반 캐싱을 매 단에 둔다.
- **NAT / 방화벽**: 주소를 고쳐 쓰는(사설 호스트 여럿이 공인 IP 하나를 공유) 정책 필터 미들박스 — 종단 간 연결에 홀펀칭이나 릴레이가 필요한 이유다.

## 왜 중요한가

- **지연은 물리 + 큐다**: 광섬유 속 빛(~200 km/ms)이 하한을 정하고(서울–버지니아 RTT ~130 ms), 그 위의 DNS·핸드셰이크·버퍼블로트·재전송은 재고 깎을 수 있는 협상 오버헤드다.
- **신뢰성은 종단 간이다**: 네트워크는 떨구고 복제하고 뒤섞는다. 정확성(멱등 재시도, 앱 계층 체크섬)은 TCP에 완전히 위임할 수 없다. 종단 간 논증이 여전히 API 설계를 지배한다.
- **규모는 라우팅 + 이름이다**: BGP는 ~8만 자율 시스템 사이 도달 가능성을 알리고, DNS는 캐싱 계층으로 수십억 이름을 푼다. 둘 다 나름의 일관성 맞바꿈을 가진 분산 시스템이다.
- **보안은 같은 층을 탄다**: TLS는 TCP 위에서 인증·암호화, DNSSEC은 이름에 서명, 방화벽·보안 그룹은 아래에서 필터. 층마다 위협 모델이 달라 방어는 층을 가로질러 조합된다.

## 동작 원리

### 계층: OSI 대 TCP/IP 현실

```
7 응용        HTTP, DNS, gRPC          (무슨 뜻인지)
4 전송        TCP / UDP + 포트         (어느 프로세스, 얼마나 믿음직하게)
3 네트워크    IP + 라우팅 (BGP/OSPF)   (어느 호스트, 어느 경로)
2 링크        이더넷, Wi-Fi, ARP       (선 위의 어느 이웃인지)
1 물리        광섬유, 전파, 구리       (신호로서의 비트)
```

- 유명한 7계층 OSI 모형은 교육용이고, 인터넷은 4계층쯤 되는 TCP/IP 스택(링크, 인터넷, 전송, 응용)으로 돈다. 캡슐화가 중첩한다. 이더넷 프레임 → IP 패킷 → TCP 세그먼트 → HTTP 메시지.
- **포트**(16비트)는 프로세스로 역다중화한다. 443/HTTPS, 53/DNS, 22/SSH. 소켓은 (IP, 포트, 프로토콜) 튜플이고, NAT는 이 튜플을 고쳐 써서 호스트를 다중화한다.

### TCP: 신뢰 장치

- **핸드셰이크**: SYN → SYN-ACK → ACK가 순서 번호를 교환하고 MSS/윈도 스케일링/SACK을 협상한다. 비용은 데이터 전 RTT 하나(TLS 1.3은 하나 더, QUIC는 둘을 ~1 RTT로 합친다).
- **슬라이딩 윈도 + 누적 ACK**: 송신자는 수신자 광고 윈도 안에서 미확인 바이트를 유지하고, 잃은 세그먼트는 중복 ACK(빠른 재전송)나 RTO 타임아웃(지수 백오프) 뒤 재전송한다.
- **혼잡 제어**: slow start가 용량을 지수적으로 탐색하고, AIMD(가산 증가, 승산 감소)가 흐름들을 공정으로 수렴시킨다. Reno, CUBIC(Linux 기본), BBR(모델 기반, Google)은 보는 신호가 다르다(손실 대 RTT 대 병목률).
- **흐름 대 혼잡**: 수신 윈도는 상대 버퍼를 지키고, 혼잡 윈도는 네트워크를 지킨다. 송신자는 둘 중 작은 쪽을 따른다.

### DNS, 라우팅, NAT

- **DNS 해석**: 스텁 → 재귀 해석기 → 루트 → TLD → 권한 서버, 매 홉 TTL 키 캐싱. `dig +trace`가 사슬을 보여준다. 낡은 TTL이 이전이 "전파되는 데 시간이 걸리는" 이유다.
- **라우팅**: 도메인 안 OSPF/IS-IS(링크 상태, Dijkstra)가 가장 싼 내부 경로를 고르고, 도메인 사이 **BGP**(TCP/179 위 경로 벡터)가 AS 사이 정책을 건다. BGP 가로채기/누출이 인터넷의 단골 무결성 사고다.
- **NAT 통과**: 바깥 방향 매핑은 사설 호스트의 발신을 열어주고, 안쪽은 포트 포워딩, STUN 홀펀칭, TURN 릴레이(WebRTC 사다리)가 필요하다. IPv6는 종단 주소를 되돌리지만 방화벽은 여전히 안쪽 기본 거부다.

## 흔한 함정

1. **먼 거리 수다 프로토콜**: 페이지당 수십 순차 RPC가 매번 RTT 전액을 낸다. 50 왕복 × 130 ms = 6.5초다. 묶고, 파이프라이닝하고, 캐시하고, 일을 데이터 곁(엣지, CDN)으로 민다.
2. **타임아웃/재시도 예산 없음**: "무한" 기본 소켓 타임아웃이 느린 의존성 하나를 스레드풀 고갈로 바꾼다. 연결/읽기/데드라인 타임아웃을 걸고, 멱등 호출은 지터 백오프로 재시도하고, 나머지는 차단기로 끊는다.
3. **MTU/조각 무시**: 1500바이트 경로 MTU에 9 KB 페이로드는 조각난다. 조각 하나를 잃으면 데이터그램 전체가 죽는다. 경로 MTU 탐색을 쓰고 송신자에서 나눈다.
4. **DNS TTL 함정**: 이전 중 7일 TTL은 일주일 갈라진 트래픽, 도처의 5초 TTL은 해석기 부하와 꼬리 지연이다. 이사 *전에* TTL을 낮추고 끝나면 올린다.
5. **행두 차단**: 잃은 TCP 패킷 하나가 뒤의 다중화 스트림 전부를 멈춘다. 스트림별 재전송의 QUIC 위 HTTP/3(UDP 기반)이 존재하는 큰 이유가 이것이다.
6. **WAN에서 LAN 가정**: 브로드캐스트 탐색, 평문 무인증, "내부 = 신뢰"는 노트북이 사무실을 벗어나는 순간 무너진다. 제로 트러스트. 모든 홉을 인증·암호화한다(mTLS, WireGuard).
