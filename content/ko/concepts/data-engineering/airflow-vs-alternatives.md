# Airflow vs Alternatives (에어플로우 대안 비교)

## 정의
데이터 파이프라인 오케스트레이션 도구들 간의 비교 분석입니다. 각 도구의 핵심 차이점와 적합한 사용 사례를 다룹니다.

## 핵심 비교 차원

| 차원 | Apache Airflow | Dagster | Prefect | DagModel |
|------|---|---|---|---|
| **핵심 개념** | DAG (유향 비순환 그래프) | 소프트웨어 정의 자산 | 플로우 (Flow) | 함수형 파이프라인 |
| **스케줄링** | 별도 스케줄러 프로세스 | 이벤트 기반 / 트리거 | 경량 스케줄러 | 내장 스케줄링 |
| **API 모델** | Python 코드 as 코드 | 데코레이터 + API | Python 파이썬 함수 | 순수 함수 조합 |
| **테스팅** | unittest/pytest + mock | 단위 테스트 내장 | pytest + fixture | 함수 테스트 용이 |
| **UI** | 내장 웹 UI (상세) | 리소스 기반 UI | 미니멀 UI | 기본 대시보드 |
| **학습 곡선** | 낮음 (초보자 친화) | 높음 (소프트웨어 엔지니어링 마인드) | 낮음 (파이썬 개발자 즉시) | 낮음 (함수형 마인드) |
| **에코시스템** | 방대 (플러그인, 커넥터) | 성장 중 (dbt 연계 강점) | 중간 (마이크로소프트 생태) | 작음 (니치) |

## 언제 Airflow를 선택하는가
- **상황**: 기존 인프라가 이미 Airflow를 사용 중일 때
- **장점**: 플러그인 생태계가 가장 풍부, 매트리 서비스와 통합 용이, 오래된 시스템 마이그레이션 용이
- **단점**: DAG 코드가 복잡해지기 쉬움, 테스트가 어려움, UI가 무거움

## 언제 Dagster를 선택하는가
- **상황**: 데이터 품질과 재현성이 최우선일 때, dbt와 연계할 때
- **장점**: 소프트웨어 엔지니어링 원칙 적용, 테스트 내장, 자산 추적 용이, dbt 파이프라인 Native 지원
- **단점**: 학습 곡선 가파름, 커넥터 생태계는 Airflow 대비 미흡

## 언제 Prefect를 선택하는가
- **상황**: 민감한 데이터 거버넌스가 필요하고 클라우드 네이티브할 때
- **장점**: 클라우드 서비스 기본 지원, 세밀한 권한 관리, 흐름의 가벼움, GitHub Actions 연동
- **단점**: 엔터프라이즈 기능은 구독 필요, 커스텀 확장성은 Airflow/Dagster에 비해 제한됨

## 언제 DagModel을 선택하는가
- **상황**: 극도로 간단한 파이프라인이나 함수형 프로그래밍을 선호할 때
- **장점**: 코드가 가장 간소함, 테스트가 용이, 경량
- **단점**: 기능이 매우 제한됨, 에코시스템이 조성되지 않음, 엔터프라이즈급 기능 부재

## 요약 비교표

| 결정 요소 | Airflow | Dagster | Prefect | DagModel |
|-----------|---------|---------|-----------|----------|
| **최적의 사용자** | 전통적인 데이터 엔지니어, 운영팀 | 데이터 엔지니어, 분석 엔지니어 | 클라우드 네이티브 팀, 빠른 플로우 구축 필요 | 함수형 프로그래밍 선호, 극소규모 파이프라인 |
| **테스트 접근성** | 어려움 (mock 다수 필요) | 내장된 테스팅 프레임워크 | 쉽다 (pytest + fixture) | 매우 쉽다 (순수 함수) |
| **UI 중요도** | 중요 (운영 모니터링) | 중요 (리소스 추적) | 낮음 (간단한 대시보드) | 낮음 (기본 대시보드) |
| **학습 투자** | 낮음 | 높음 | 낮음 | 낮음 |
| **확장성** | 높음 (클러스터 운영 필수) | 중간 (플랫폼 의존) | 중간 (클라우드 위임) | 낮음 (소규모 전용) |
