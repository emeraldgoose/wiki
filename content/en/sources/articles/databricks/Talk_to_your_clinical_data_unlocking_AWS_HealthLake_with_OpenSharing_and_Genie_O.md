# Talk to your clinical data: unlocking AWS HealthLake with OpenSharing and Genie One

**Source**: [databricks](https://www.databricks.com/blog/talk-your-clinical-data-unlocking-aws-healthlake-opensharing-and-genie-one) · **Published**: 2026-11-16

## Overview

Many healthcare and life sciences organizations standardize on AWS HealthLake for clinical data, but extending that data to other platforms for analytics and AI has traditionally required export pipelines, data duplication, and separately managed governance. That limited the interoperability of HealthLake-managed FHIR data across tools.

Databricks presents a new integration leveraging OpenSharing (a Linux Foundation AI & Data project) for a first-of-its-kind HealthLake–Databricks integration: users can query HealthLake data live from Databricks, bringing Databricks governance, analytics and AI capabilities to clinical datasets — and explore the same data in natural language with Genie One, without duplication.

## Key points

- **FHIR and HealthLake**: FHIR is the data-exchange standard for health information; HealthLake is a managed service storing FHIR data as Apache Iceberg tables in a HealthLake-owned S3 bucket. Customer IAM roles cannot read that bucket directly.
- **The gap**: Unity Catalog cannot request the temporary Lake Formation credentials HealthLake issues for direct Iceberg access, so external access previously required export pipelines.
- **The fix**: a custom OpenSharing server runs as a Databricks App (managed serverless). On every table request it uses Lake Formation credentials, resolves the table's current Iceberg snapshot, pre-signs the data files, and returns them in a standard OpenSharing response — Databricks compute reads files directly from S3; no data passes through the server.
- **No stored credentials**: an IAM role in the AWS account trusts the app's Databricks identity via OIDC federation; no AWS credentials are stored in Databricks.
- **Unity Catalog mount**: Databricks mounts the share like any other share — governed analytics, notebooks, dashboards, AI, and Genie One exploration.
- **Shared governance responsibility**: once HealthLake data is read into Databricks, you are responsible for governing it there, including PHI; review AWS and Databricks shared responsibility models and compliance requirements before using real patient data.
- **Governance features**: grants, fine-grained access control (FGAC), attribute-based (ABAC) and role-based (RBAC) access controls on the shared catalog, plus audited access and usage.
- **Genie One**: curated Genie Agents over the shared catalog — clinical teams define core tables, plain-language descriptions and concepts like A1C; users ask questions like "How is average A1C trending by month?" and get SQL-generated answers with tables and charts, respecting Unity Catalog permissions.

## Details

HealthLake stores its analytics tables as Apache Iceberg tables in an S3 bucket owned by the HealthLake service, and customer IAM roles cannot read it directly — the only path to direct access is temporary credentials generated by Lake Formation, which Unity Catalog cannot request on its own. The integration fills exactly that gap.

**Architecture**: the OpenSharing server (a Databricks App) receives table requests, obtains Lake Formation credentials, resolves the current Iceberg snapshot, pre-signs the data files, and returns them in a standard OpenSharing response. Databricks compute then reads the files directly from S3 — data never transits the server. Identity flows through OIDC federation: an IAM role in the customer's AWS account trusts the app's Databricks identity, so no AWS credentials are persisted in Databricks. The result mounts in Unity Catalog as a normal share, which means the full governance surface applies: grants, FGAC/ABAC/RBAC, lineage and audit.

**Natural language on top**: with the shared catalog mounted, organizations can build Genie Agents scoped to clinical domains — defining core clinical tables, adding plain-language descriptions, and teaching interpretation of clinical concepts (e.g., A1C). A clinician or operator can then ask a trending question in plain language; Genie One locates the curated agent, generates the SQL, and returns a summarized answer with a table and chart, honoring Unity Catalog permissions. Questions that once required SQL skills or a dashboard request now resolve in seconds.

The post is explicit about the shared-responsibility boundary: Databricks governs the data once it is read in, including PHI handling — compliance review is required before using real patient data.
