# PACE: Towards Surfacing Hidden Conflicts in User Requests

Source: Yoojin Kim and 2 other authors, arXiv:2609.03293, Sep 3, 2026. EMNLP 2026.

**Lead**: Personalized assistants should not only comply with user requests but assess whether a request is appropriate given the user's circumstances. Prior work focuses on executing requests accurately and detects conflicts only from explicitly provided factors. This paper introduces **PACE (Personalized Assistants for Conflict Evaluation)**, a dataset where each seemingly reasonable request is paired with an egocentric knowledge base, and the conflict status emerges only from hidden situational facts. It also proposes **PaceMaker**, a multi-agent retrieval framework (query reformulation, multi-hop graph traversal, conflict-aware filtering) that consistently outperforms standard retrieval on both evidence retrieval and conflict-decision accuracy.

## Why hidden conflicts are hard

A restaurant booking looks trivially executable — until the KB reveals the companion has a shellfish allergy and the venue has a fixed menu. The decisive evidence is distributed across atomic KB facts (avg. **4.01 gold facts per query**, **~2,035 facts per instance**) and is rarely semantically similar to the query itself, so standard dense/sparse retrieval drowns in topical distractors. The dataset covers **3,249 queries** over **185 persona profiles** with **376,448 facts**, split into three situation types:

| Situation type | Constraint source | Example |
|---|---|---|
| Temporal | Schedules, travel time, routines | Exam at 19:00 unreachable after workshop + document pickup |
| Personal | Health, values, accessibility | Seafood restaurant vs. companion's shellfish allergy |
| State | External conditions at query time | Usual cafe hosting a live-music event that afternoon |

Non-conflict cases are included so models cannot win by always refusing. Human evaluation agrees with the synthetic feasibility labels at **93.3%**.

## How PaceMaker works

PaceMaker builds dense + sparse indexes and a k-NN document graph over the KB, then runs four stages: (1) **conflict-aware query planning** — a planner emits up to three probing cues (scheduling, commitments, resources) and a generator produces counter-views targeting latent conflicts; (2) **hybrid retrieval with weighted fusion** (counter-views weighted higher) plus pre-hop filtering; (3) **multi-hop BFS graph traversal** from seed documents to surface indirectly connected evidence; (4) **conflict-aware evidence selection** keeping only decision-relevant facts for the answer generator.

## What the results show

| Configuration | Method | Pass rate | Conflict Pass |
|---|---|---|---|
| Qwen3-4B / Qwen3-Embed-8B | Sparse / Dense / **PaceMaker** | 62.73 / 62.39 / **68.82** | 41.80 / 37.78 / **53.20** |
| GPT-5.4-mini / text-embed-3-small | Sparse / Dense / **PaceMaker** | 65.53 / 62.63 / **75.35** | 40.28 / 33.88 / **59.17** |
| Gemini 3.1 Flash-Lite | Sparse / Dense / **PaceMaker** | 67.44 / 63.59 / **77.44** | 57.22 / 49.85 / **75.93** |

Full-KB context without retrieval scores only 57.49% (open setting) — unfiltered context actively impairs conflict reasoning. Full gold-evidence coverage adds a clear gain over partial coverage, and ablation shows multi-hop traversal is the most critical component (removing it drops Conflict Pass from 59.17 to 52.41). PaceMaker also beats GraphRAG and HippoRAG 2 on conflict queries (54.42 vs. 34.98 / 43.57) with fewer total LLM calls.

## Caveats

Full-text HTML was available and consulted, but all numbers above come from the reported tables; the response-quality judge is itself an LLM (GPT-5.4-mini, 93.5% agreement with crowd workers), so Pass rates inherit judge bias. Results are on synthetic personas — transfer to real personal KBs with noisier, messier facts is untested. The benchmark judges feasibility decisions, not end-to-end task execution.

## Relevance to SW engineers

- If you build personalized agents, refusal quality is a retrieval problem first: the deciding facts rarely match the query, so plan counter-queries for what could go wrong, not just what was asked.
- Dumping the whole user context into the prompt underperforms targeted retrieval (57.49% vs. 68.82%) — filter before reasoning.
- Completeness matters more than ranking: partial evidence yields wrong-but-confident decisions, so measure evidence coverage, not just top-1 relevance.
- Ablation discipline (planning vs. traversal vs. selection) tells you which stage to invest in — here traversal dominates.
