# AMLworld-Compact: Importance-Weighted Downsampling for Cost-Effective LLM Evaluation and Error Diagnosis

**Source**: Nitarach et al., arXiv, 2026-10-09

**Lead**: Evaluating LLMs on AMLworld's smallest test splits costs over a million graph prompts per pass, since each transaction needs its own prompt. The authors introduce AMLworld-Compact, an evaluation set built with the HT-Coreset protocol: retain every illicit test transaction, sample benign ones from supervised-score difficulty strata, and use Horvitz–Thompson inclusion weights to estimate full-test metrics. Under these prompts, seven open-weight LLMs show weighted precision near the predict-all-illicit baseline—high recall with almost no selectivity.

## Background

AML detection asks whether a transaction belongs to illicit activity, with evidence spanning multi-hop account/transfer neighborhoods (e.g. gather-scatter patterns). AMLworld's HI-Small and LI-Small test splits each exceed a million transactions with illicit rates of only 0.12% and 0.05%. A small class-proportional sample keeps too few illicit cases for recall analysis, while a balanced sample distorts unweighted precision and F1. Prior work evaluated LLMs on a small balanced subset, whose scores reflect the enriched illicit share rather than real-world prevalence. The goal: fewer model calls, all rare cases kept for diagnosis, and full-test metric estimates.

## HT-Coreset Construction

The protocol takes the full test partition plus supervised scores (LightGBM, XGBoost, GCPAL over GFP graph features) as input:

1. **Retain all illicit edges** (1,251 HI-Small, 756 LI-Small), preserving recall signal and all 8 typologies.
2. **Stratify benign edges by difficulty** $d(e) = 1 - 2\lvert\bar{p}(e) - 0.5\rvert$ from mean scorer probabilities; reserve up to 30% of the benign budget for hard negatives (high-score benigns) and split the rest into three difficulty terciles, so every benign edge keeps positive inclusion probability.
3. **Weight with inverse inclusion probabilities** $w_e = 1/\pi_e$: weighted confusion counts estimate full-test counts (unbiased for fixed predictions); recall is exact, precision and F1 are ratio estimates. Unweighted counts describe the enriched 1:2 subset for diagnostics.

Each target ships with GFP features, a typed-subgraph prompt (BFS depth 2 from the target's source account), and its weight; neighborhoods come from the full graph, so sampling targets never shrinks per-case context.

## Experiments

**Setup**: Released sets of 3,753 HI-Small and 2,268 LI-Small targets (1:2 illicit-to-benign), a 271x and 611x target reduction. Sampling error validated over 500 draws per configuration with one booster family held out of stratum construction; LLMs evaluated are seven open-weight thinking models (GPT-OSS, Nemotron-3, Qwen3.5; 3–27B active params) in few-shot and zero-shot variants over 5 runs.

**Sampling results**: At released sizes, HT-Coreset F1 RMSE is 0.00–2.58pp vs. 4.44–7.41pp for uniform sampling with HT weights, lowest in all 12 dataset–direction–budget comparisons; conservative 95% intervals still span 27–55pp wide, so point estimates improve without guaranteeing precise estimation for every predictor.

**LLM detection results (HI-Small)**:

| Metric | LLM range | Reference |
|--------|-----------|-----------|
| HT-weighted F1 | 0.230–0.253% | 0.246% (predict-all) |
| Precision lift | 0.94–1.03 | 1.0 (predict-all) |
| Zero-shot recall | 97.8–100% (82.9% one model) | — |
| Unweighted F1 | 40.7–50.6% | 68.1% (ML booster) |

Few-shot demonstrations help typology identification more consistently than detection. In a 1,000-output audit, lexical self-check markers pass for 84.5% of correct but also 56.2% of incorrect binary verdicts—so a passing check does not establish correctness.

## Relevance to Software Engineers

The paper is a template for cheap, honest LLM evaluation on imbalanced workloads:

- **Keep all rare cases, stratify the rest**: retaining every positive and importance-sampling negatives by a cheap scorer's difficulty beats uniform subsampling for metric fidelity.
- **Report weighted and unweighted numbers separately**: subset scores on enriched data look respectable (40–50% F1) while full-prevalence estimates sit near the trivial baseline—publish both to avoid fooling yourself.
- **Don't trust self-check markers**: lexical "verified against graph" traces pass on most wrong answers too; audit checks against ground truth rather than treating a pass as proof.
- **Release weights with the subset**: shipping inclusion probabilities lets anyone reproduce full-population estimates on identical cases.
