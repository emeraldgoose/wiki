# Interactive Visual Gym: Evaluating Visual Interaction Models with Simulated Users in Interactive Worlds

**Source**: [arXiv:2611.08286](https://arxiv.org/abs/2611.08286) · **Published**: 2026-11-05

## Overview

Visual interaction models watch a video stream of a user's ongoing physical activity and guide it — planning the next step, spotting execution errors, steering recovery. Evaluating them properly requires closed-loop rollouts, because each assistant response can change what the user does next and how the task ends. Offline-replay benchmarks cannot capture that. Building the closed loop for physical assistance is hard for two reasons: physical tasks must be reconstructed digitally with visual observations, world state, and a human-aligned action space; and the user, not the model, is the acting agent, so user simulation must plan, act, and make plausible mistakes while interpreting advice.

Interactive Visual Gym supplies exactly that. Three simulators recreate everyday tasks across cooking (CookSim), household manipulation (VHSim), and mobile interfaces (ScreenSim), and a persona-conditioned user harness collaborates with the assistant while injecting controlled execution errors, temporal questions, plan changes, and other out-of-plan behaviors. Instantiated as IVG-Bench, the framework provides 315 interaction scenarios and evaluates assistants on in-time task success, error detection recall, and a multi-dimensional interaction-quality score (factual grounding, situational relevance, actionable guidance, user intent uptake, guidance conciseness).

The benchmark's verdict on fifteen VLMs — frontier API models, real-time streaming APIs, and open-weight streaming and non-streaming models — is sobering. Gemini 4 Argon leads on task success yet completes only 53.4% of tasks within the time limit averaged across environments, and it trails GPT-6 Astra, GPT-6.1 Sol, and Gemini 3.8 Flash on interaction quality. Latency compounds the problem: when measured response latency replaces the fixed two-tick setting, Gemini 4 Argon's CookSim in-time success falls from 60.9 to 33.1 (−27.8 points), with every frontier model losing 11.8–27.8 points and detection recall dropping by up to 16.7 — assistants are often too slow to prevent errors before the user acts.

The framework is also validated and useful for training. A human study with 45 participants in CookSim finds the interaction-quality metric agrees with participant preferences in 78.5% of comparisons (pooled Kendall's tau +0.57), and simulated users reproduce most human behavioral signatures (utterance-length similarity 0.89, guidance requests 0.98, disagreement 0.88). In a proof-of-concept GRPO run, twelve updates lift Qwen3.5-4B's in-time success on CookSim from 33.3% to 42.2% (+8.9 points) with a Gemini 3.7 Flash user — the environments deliver real learning signal.

## Key points

- Three executable simulators with human-aligned action spaces: CookSim (cooking), VHSim (household manipulation), ScreenSim (mobile interface); the persona-conditioned user harness plans, acts, errs, asks temporal questions, and changes plans.
- IVG-Bench: 315 interaction scenarios scored on in-time success, error detection recall, and interaction quality across five dimensions (factual grounding, situational relevance, actionable guidance, user intent uptake, guidance conciseness).
- Best model, Gemini 4 Argon: 53.4% average in-time task success — less than half of tasks finish inside the time limit even for the leader.
- Interaction quality ranks differently: Gemini 4 Argon trails GPT-6 Astra, GPT-6.1 Sol, and Gemini 3.8 Flash despite its task-success lead, and open-weight models cluster far below (Qwen3.8-27B is the strongest open-weight entrant).
- Latency is not a footnote: swapping the fixed two-tick setting for measured latency cuts frontier in-time success on CookSim by 11.8–27.8 points (Gemini 4 Argon 60.9 to 33.1, Gemini 3.8 Flash 46.4 to 29.8, GPT-6.1 Sol 42.9 to 30.0) and error detection recall by up to 16.7.
- The evaluation is human-validated: 45 participants ranked three anonymized assistants in CookSim; the interaction-quality metric matches participant preferences in 78.5% of comparisons (pooled Kendall's tau +0.57).
- Simulated users behave human-like where it matters: similarity to real participants is 0.98 for guidance requests, 0.89 for utterance length, 0.88 for disagreement, 0.82 for ignored interruptions and action efficiency, though speech rate and responsiveness remain weak (0.05).
- Closed-loop RL works: GRPO on Qwen3.5-4B (120 train / 30 validation CookSim scenarios, shaped reward over success, prevented errors, false flags, and turn count) raises in-time success from 33.3% to 42.2% with a Gemini 3.7 Flash user, and from 64.4% to 67.8% with a Gemini 3.8 Flash user plus interaction quality from 24.3 to 30.2.
- RL reshapes behavior, not only scores: detection recall declines in both settings while false flags fall from 517 to 391 across 90 episodes — the reward favors selective flagging that can miss uncertain errors.

## Details

- Interaction-quality judging is rubric-based and evidence-grounded, aggregated over five dimensions; the evaluation unit is the interaction trajectory with assistant observations and memory settings fixed per environment (Appendix H).
- The user harness couples persona construction with scheduled-event control: progress-conditioned events trigger execution errors, temporal questions, and plan changes at controlled points (CookSim includes errors, temporal questions, and a plan change; VHSim a wrong object and a pause; ScreenSim two incorrect settings changes and their repair).
- Latency experiments compare measured-latency rollouts against the fixed two-tick setting on identical tasks, personas, and scheduled events, averaged over three independent runs; the benchmark reports results averaged across three runs throughout.
- GRPO setup: 24 episodes per update (6 scenarios times 4 episodes); the shaped reward r adds 0.30 for a prevented error, subtracts 0.02 per false flag up to 15, and subtracts 0.05 times min(T/200, 1) for excess turns, so successes score at least 0.65 and completed failures at most 0.30.
- Model coverage: frontier API (Gemini 4 Argon, Gemini 3.8 Flash, GPT-6.1 Sol, GPT-6 Astra), real-time streaming API (GPT-Realtime 2.1, Gemini 3.8 Live), open-weight non-streaming (Muse Glimmer, Qwen3.8-27B, InternVideo3-8B, Kimi-VL-Thinking, Molmo2-8B), and open-weight streaming (Qwen3-Omni-30B, MiniCPM-o 4.5, StreamingVLM, Proact-VL).
