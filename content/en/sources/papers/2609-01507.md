# LatentPress: Context Compression Beyond Text and Vision

Source: Zhengze Zhou, Hejian Sang, arXiv:2609.01507, Sep 3, 2026.

**Lead**: Compressed context is usually carried as human-readable text or rendered images that must be decoded — even when its only consumer is a language model. **LatentPress** writes conversational histories and long documents into a third representation: **continuous memory tokens** that a frozen decoder reads directly through its input-embedding interface, with no text reconstruction at inference. A small reader-matched writer compresses **4–16x** while training only an adapter of **4.2M–26.2M parameters (~0.1% of the decoder)**. On LongMemEval it reaches **0.504 accuracy at 7.70x compression versus 0.490 for uncompressed evidence**, beating text summaries (0.184) and OCR-based compression (0.426 down to 0.312). On LongBench-QA, in-domain writers match or exceed raw-context reading at 4–8x compression, while 16x trails raw. Writing takes **43ms per conversation** — an order of magnitude faster than summarization or OCR reconstruction — and reading is **5–9x faster** than raw context or cached OCR.

## A third representation for context

Text summaries throw away detail to stay readable by humans; rendered-image context pays encode-and-decode costs for pixels nobody looks at. LatentPress observes the consumer is a machine, so the compressed form can be machine-native: soft tokens straight into the frozen decoder's embedding interface. Training cost stays tiny because only the writer-side adapter is learned, matched to its reader.

## What the results show

| LongMemEval | Accuracy |
|---|---|
| LatentPress (7.70x compression) | 0.504 |
| Uncompressed evidence | 0.490 |
| OCR-based compression | 0.426 to 0.312 |
| Text summaries | 0.184 |

| Other results | Detail |
|---|---|
| LongBench-QA (in-domain writer) | Matches or exceeds raw at 4–8x; 16x trails raw |
| Write cost | 43ms per conversation |
| Read speed | 5–9x faster than raw or cached OCR |
| Transfer | Validated zero-shot UltraChat→LongMemEval and LongMemEval-QA→unseen LongBench domains |

The headline is that compression *beats* raw context on LongMemEval (0.504 vs 0.490) — the writer apparently filters noise, not just tokens — while the 16x result marks the current quality cliff.

## Caveats

This summary is abstract-based; per-task breakdowns, decoder identities, and the pooling/token-budget mechanics live in the full text (implementation at github.com/HJSang/LatentPress). The writer is reader-matched, so memory tokens are not portable across decoders without retraining the adapter. The 16x degradation and OCR-range variance (0.426 to 0.312) both deserve a look before picking a compression ratio.

## Relevance to SW engineers

- For long-lived conversational agents, machine-native memory tokens can beat both raw history and summaries on quality *and* latency — consider them before building a summarization pipeline.
- 43ms writes and 5–9x faster reads change session-memory economics: persist compressed memory per conversation, not raw transcripts.
- Treat 4–8x as the safe operating range; 16x is where quality trails raw in these results.
