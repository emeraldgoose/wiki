# NeoMME: A Single-Tower Multimodal-Native Multilingual Foundation Encoder for Efficient Fine-Tuning and Inference

Source: Aurélien Lac, Tony Wu, arXiv:2609.01657, Aug 31, 2026.

**Lead**: Multimodal models are usually built for generative vision-language modeling — separately pretrained vision encoders bolted onto causal language models — and visual document retrievers like ColPali inherit that parameter and compute overhead for a task that never generates a word. **NeoMME** is a family of **260M and 800M-parameter** multimodal, multilingual **bidirectional encoders** that process multilingual text and raw image patches in a single Transformer tower, pretrained from scratch with a masked discrete-diffusion text objective conditioned on visible image patches, with a **16,384-token context** that fits up to two standard 4K UHD images. Fine-tuned with jointly trained dense and late-interaction heads, NeoMME-Retriever 260M tops all evaluated models strictly below 800M parameters on **ViDoRe v3 with 0.523 nDCG@10** while the 800M reaches **0.556**. At matched 2048×2048 input on an NVIDIA L40S, NeoMME-260M encodes pages at about **2x the throughput of ColModernVBERT**, and hierarchical token pooling with asymmetric quantization compresses late-interaction document embeddings **255x while preserving over 95% of baseline nDCG@10**. Both backbone and retrieval checkpoints are released under Apache 2.0 with Hugging Face Transformers support.

## Why retrieval deserves its own architecture

Repurposing a generative VLM as an encoder means paying for causal machinery and a vision tower sized for generation at every retrieval call. A single bidirectional tower trained from scratch as an encoder removes that tax by construction: one forward pass over text plus raw patches, no generation apparatus, with multilinguality and long context (16K tokens) built in rather than retrofitted.

## What the results show

| Result | Number |
|---|---|
| NeoMME-Retriever 260M, ViDoRe v3 | 0.523 nDCG@10 (best under 800M params) |
| NeoMME-Retriever 800M, ViDoRe v3 | 0.556 nDCG@10 |
| Throughput vs ColModernVBERT (2048×2048, L40S) | ~2x |
| Late-interaction embedding compression | 255x at >95% of baseline nDCG@10 |
| Context | 16,384 tokens (≈ two 4K UHD images) |

The combination is the story: best-in-class accuracy *and* 2x throughput *and* 255x index compression — the three costs of production visual retrieval (quality, serving, storage) all move at once.

## Caveats

This summary is abstract-based; pretraining data, per-language and per-subset ViDoRe breakdowns, and fine-tuning recipes live in the full text. The throughput claim is at a matched input size on one GPU type (L40S), and the 95%-retention figure is relative to the paper's own baseline. Audio summary and code links are on the arXiv page.

## Relevance to SW engineers

- For document-visual RAG (scanned PDFs, slide decks, screenshots), a purpose-built encoder can halve serving cost versus VLM-derived retrievers while improving quality — evaluate NeoMME before defaulting to ColPali-style stacks.
- 255x embedding compression at >95% quality retention directly shrinks vector-index storage and memory bandwidth, the usual scaling wall for page-level late interaction.
- A 16K-token context covering two 4K images means fewer tiling hacks for high-resolution pages.
- Apache 2.0 plus Transformers integration keeps adoption friction low.
