# CompoundingKernel: Self-Improving from Zero to First

**Source**: [arXiv:2611.19230](https://arxiv.org/abs/2611.19230) · **Published**: 2026-11-14

## Overview

CompoundingKernel is a self-improving agent system that writes GPU kernels by search. As of 2026-11-11, kernels generated by the system rank #1 on the public L1, L2 and Quantization leaderboards of SOL-ExecBench on NVIDIA B200 hardware, holding #1 on L1 since 2026-10-27 with a brief loss on 2026-11-07. All 235 problems in the benchmark have a site-verified correct kernel, and on the 209 public-board problems the generated kernels are 4.40× faster than the benchmark’s reference baseline.

The search starts from zero. Agents receive only each problem’s PyTorch definition and no reference kernels or official scores. Correct kernels and their lineage are stored in a per-problem archive outside the model. An LLM controller reads the archive, selects a parent design or proposes a new direction, and assigns one direction to each parallel child agent. Correctness is decided by external checks, not by the model.

## Key points

- Self-improving search for GPU kernels from PyTorch definitions only, no reference kernels provided.
- #1 on SOL-ExecBench L1, L2 and Quantization boards as of 2026-11-11; 4.40× faster than reference baseline on 209 public problems.
- Per-problem archive holds every correct kernel and lineage; LLM controller samples parents and directs parallel child agents.
- At equal wall time, the system beats a coded UCB-style tree search on 35 of 38 problems, making 2.4× as many correct attempts.
- Over a thousand agents run in parallel; a warm-restart fix raises evaluation rate 3.6×.
- Reliable measurement rate, not agent count, limits scaling of this search paradigm.

## Details

The system emphasizes compounding improvements via a persistent archive rather than in-context learning alone. The controller uses archive history to decide which lineage to extend or when to explore a new design, while correctness checks remain external to avoid reward hacking. Experiments show that increasing the rate of reliable measurements improves progress more than simply adding agents. Code and kernels are released publicly.
