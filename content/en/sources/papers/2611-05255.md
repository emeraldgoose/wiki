# Going Deeper With Memories

**Source**: [arXiv:2611.05255](https://arxiv.org/abs/2611.05255) · **Published**: 2026-11-03
**Authors**: Afshin Khadangi

## Overview

Byte-level language models avoid tokenizer dependence and provide universal coverage, but processing every byte at full resolution is expensive. DeepMem is a causal multiscale architecture separating semantic compression from exact byte preservation. A learned invertible subband transform constructs a hierarchy of shorter sequences, while a lossless carrier and explicit detail sidebands preserve byte identity. Fast weight memory blocks operate along the encoder, iterative shared-state computation happens at the compressed bottleneck, and an attention-based super-resolution decoder restores byte-resolution representations. DeepMem achieves stronger language modeling than a matched byte-level Transformer on FineWeb-Edu and PG19 and obtains the best macro average across evaluated Flores languages, while keeping competitive performance on code, multiple-choice reasoning, and byte-level corruption robustness.

## Key points

- The architecture separates semantic compression from exact byte preservation.
- An invertible subband transform builds a shorter-sequence hierarchy.
- Lossless carrier and sidebands preserve exact byte identity.
- Fast weight memory blocks operate along the encoder.
- Iterative shared state computation occurs at the compressed bottleneck.
- Bottleneck refinement uses far fewer counted FLOPs than full-resolution reasoning.

## Details

DeepMem improves PIQA accuracy and remains competitive on code modeling, multiple-choice reasoning, and byte-level corruption robustness. Bottleneck refinement requires approximately 7,600 times fewer counted FLOPs than equivalent full-resolution reasoning while maintaining competitive evaluation throughput. The efficiency gains depend on hardware mapping and layer implementation, so micro-level benchmark results should be reproduced before large-scale deployment.
