# Accelerate Bench: Evaluating Agents for Application-Level Program Optimization

**Source**: [arXiv:2611.20882](https://arxiv.org/abs/2611.20882) · **Published**: 2026-11-16
**Authors**: Bowen Liu, Yuhan Li, Nuo Chen, Weile Luo, Miao Peng, Qintong Zhang, Qifan Zhang, Jia Li, Ziqi Gao, Lydell Huang

## Overview

Application-level optimization is one of the hardest things to ask of a coding agent: it must find useful changes and coordinate them across a complete program, changing build settings, compiler options, algorithms, and runtime configuration together, while preserving exactly the computation the application is supposed to perform. Localized code edits are not enough, because a valid patch can leave end-to-end runtime unchanged and effective speedups often depend on interactions across layers of the stack.

Accelerate Bench is a benchmark built to measure that ability. It comprises 32 CPU optimization tasks adapted from scientific applications and supercomputing competitions. Each task hands the agent a working program plus a precise specification of the workload, the correctness requirements, the timing boundaries, and the permitted edits — but leaves the agent to decide where and how to optimize. Public tests support iterative development during the run, and a separate hidden verifier rebuilds the submitted files and scores the final submission.

On benchmark version 1.1, the authors evaluate 16 coding agents, each pairing a model with a harness. The headline finding is that most agents produce correct programs, and it is the size of the speedup — not correctness — that separates them.

## Key points

- 32 CPU optimization tasks, adapted from scientific applications and supercomputing competitions, with standardized dependencies, build scripts, and execution entry points in isolated containers.
- Workloads were scaled from multi-node, hours-long competition settings down to single-node CPU runs so agents can iterate within a practical evaluation budget; the adapted tasks retain the main computational stages, inter-stage dependencies, and numerical correctness criteria of the originals.
- 16 coding agents (model + harness pairs) evaluated on benchmark v1.1; Score@1 ranges from 25.5% to 67.4%.
- The two leading agents achieve at least 2x speedup on 22 or more of the 32 tasks; the other fourteen reach 2x on 8 to 17 tasks.
- 125 of the 412 correct outcomes from the trailing fourteen agents land below 1.25x speedup.
- Controlled replays show identical source code running between 0.29x and 2.12x depending only on build and runtime settings, and one code change being worth 1.01x or 6.4x depending on another change — evidence that cross-layer coordination, not isolated edits, drives real speedups.
- The benchmark pairs executable workloads with agents' programs and execution trajectories to evaluate both the gains and the process behind them.
- Project page: https://acceleratebench.com/

## Details

Method. Each task defines an application and a workload rather than a single function to patch. Agents diagnose performance bottlenecks, then modify implementation code, compiler options, and runtime configuration, guided by complete public tests. During a run the agent may call the public test repeatedly: it rebuilds the current program, runs it on a few public inputs (typically two), and reports correctness, runtime, and usually the baseline runtime or speedup, or the failing step. The agent never sees the checking code. After the run, a hidden verifier rebuilds the submission and runs it on private inputs of the same kind (typically four), which are often larger or freshly randomized per evaluation. Only the verifier's repeated timings and checks set the reward, so the score depends on inputs the agent has not seen.

Correctness is enforced before timing: submissions must meet task-specific numerical tolerances, produce complete output files, and satisfy stateful requirements such as recovering from a saved checkpoint in a new process. Only submissions passing all checks are scored on runtime. In 14 planned controls on HPCG-derived and paged-generation tasks, every valid variant passed and all eight invalid variants failed the check they violated.

Scoring. Using the task-provided implementation as baseline, per-task reward is the fraction of baseline runtime saved by a correct submission: r = C(a) * max(0, 1 - T(a)/B), where C(a) is 1 if the submission passes correctness checks. A correct 2x speedup earns 0.5; a correct but no-faster program earns zero; failed or unscored outcomes earn zero. Each run gives the agent eight hours to inspect, edit, build, and test.

Results. On benchmark v1.1, Score@1 across the 16 agents spans 25.5% to 67.4%. Most programs agents produce are correct, so the discriminating factor is speedup magnitude: the two leaders are at least 2x faster on 22+ of 32 tasks, while the remaining fourteen reach 2x on only 8 to 17 tasks and leave 125 of their 412 correct outcomes below 1.25x. Appendix analyses cover run-to-run variance and timing noise, benchmark v1.0 results and run selection, and timing calibration and score sensitivity.
