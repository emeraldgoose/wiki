# LEANGUARD: Lean-Verified Guardrails for Tool-Using Agents

**Source**: [arXiv:2611.02332](https://arxiv.org/abs/2611.02332) · **Published**: 2026-11-02
**Authors**: Sreehari Sankar, Debargha Ganguly, Vikash Singh, Mohsen Hariri, Weicong Chen, Yanyan Zhang, Shouren Wang, Wang Yang, Chaoda Song, Alexander Nemecek, Osama Zafar, Idan Davidovich, Yuting Shao, Kai Ye, Biyao Zhang, Xinpeng Li, Joe Stubbs, Erman Ayday, Jing Ma, Vipin Chaudhary

## Overview

Tool-using language-model agents can execute actions that domain policies forbid. LeanGuard is a runtime that checks every proposed tool call against a policy written in Lean4 before the call reaches the environment. Policies combine state predicates with scoped past-time temporal operators over execution history. Evaluation is fail-closed, and the decision procedure is proved equivalent to a LeanLTL semantics. A denied call can be corrected with feedback or proof-guided repair, where metaprogramming searches for a better call.

## Key points

- Tool calls are checked before execution.
- Policies are written in Lean4.
- Policies combine state and temporal history constraints.
- Evaluation fails closed.
- The semantics are verified against LeanLTL.
- Denied calls can receive feedback or be repaired.

## Details

The motivation is that domain safety constraints should not rely only on model behavior. LeanGuard separates policy specification from execution and uses formal verification to make denial decisions trustworthy. Two correction paths give the agent actionable information: direct feedback identifying the violated rule, or proof-guided repair that searches for an acceptable alternative call. The design emphasizes verifiable guardrails for tool-using agents.
