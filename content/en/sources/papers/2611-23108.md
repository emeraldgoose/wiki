# FMT: Lossless Image Compression in a Fixed Number of Parallel Steps

**Source**: [arXiv](https://arxiv.org/abs/2611.23108)
**Published**: 2026-11-17

## Overview

Learned lossless codecs make smaller files than classical codecs, yet the images we archive and train on still use classical codecs. A main reason is time: a learned codec takes seconds to decode a photo a classical codec opens in milliseconds, and its faster variants give up most of the size gain. The authors argue much of this time is spent waiting, not computing — the network waits for values it conditions on, and the arithmetic decoder reads them one at a time. FMT (Fixed-step Multiscale Tree) is a lossless image format whose decoding order and entropy coder are designed together so neither wait grows with the image.

FMT stores an image as a coarse-to-fine tree whose steps hold independent values: a GPU predicts each step at once and decodes it in parallel rANS lanes that carry their states from step to step, so an image of any size decodes in a fixed number of sequential steps. On this tree the authors build a family of bit-exact codecs, from a network-free rule to large networks, and no codec they ran on the same GPU beats any of them on both size and speed.

## Key points

- Frontier result: without a network, FMT beats NVIDIA's HTJ2K on both size and speed; with a large one, it decodes Kodak photos 9–61× faster than learned codecs run on the same A100, at the same size or smaller.
- Against one-model-for-all learned codecs (Kodak): HPAC-Fast (2.95 bpsp, 0.40 s) → FMT −5.9% size at 7.5× faster; HPAC (2.73, 0.90 s) → FMT +1.7% at 17×; DLPR (2.86, 1.42 s) → FMT −3.0% at 27×; LC-FDNet (2.94, 1.00 s) → FMT −5.6% at 17×; ArIB-BPS (2.78, 3.6 s) → FMT −0.2% at 61×.
- Adapted-to-each-image codecs: FNLIC 2.88 / 0.52 s → FMT 512×4 −10.2%, 8.8× faster; HPAC-Fast-FT and HPAC-FT / CALLIC remain smaller but take tens of times longer.
- Few steps: value-by-value coders need 1,179,648 sequential steps on a 1,179,648-pixel image; JPEG XL groups 196,608; HTJ2K blocks 5 (but 4,096 values per step); FMT's tree steps hold fully independent values, enabling parallel prediction and rANS decoding with states carried step to step.
- FMT offers a frontier of codecs: dense (shared histogram), neural (learned probabilities), per-photo tuning, and a fast mode with no entropy coder; bit-exact probabilities guarantee losslessness on any GPU.

## Details

- Design: multiscale tree of pixels (predict-then-correct), three coding modes (dense/shared histograms, neural/learned probabilities, fast/no entropy coder), parallel exact decoding (one step decodes all its values at once; lanes carry rANS states; bit-exact probabilities).
- Evaluation: Kodak, DIV2K and large-photo sets; size (bpsp) and decode time on the same A100; comparison vs HTJ2K, JPEG XL, DLPR, LC-FDNet, FNLIC, ArIB-BPS, HPAC family; large-photo and CPU frontiers in S1.
- Limitations: see Sec. 5 (encoder choices, tuning cost, small images, encoding time — S4); decoding order, root/lane/tuning and network size ablations in Sec. 4.4 and S3.
