# OpenVLHarness: Real World Visual Agentic Tool-Use with Multimodal Memory

Source: Yu Zhou, Cheng-Fu Yang, Rui Sun, Di Wu, Sibo Peng, Mingyang Zhang, Zhen Yang, Ruiyi Zhang, Nanyun Peng, Zhe Gan, Kai-Wei Chang. arXiv:2610.26860, Oct 19, 2026.

**Lead**: Multimodal large language models (MLLMs) have made rapid progress on visual reasoning, yet many tasks require external evidence — grounded perception, external knowledge, numerical measurements — that internal reasoning alone cannot provide. The authors' controlled study on 22 benchmarks shows that simply increasing the base model's inference budget yields only modest gains. OpenVLHarness addresses this with a capability layer (task-level tool interfaces + evidence rendering) and persistent multimodal memory that retains images, structured data, and web references as addressable artifacts across reasoning steps. A coding interface executes generated programs over stored data, enabling computations that combine results from multiple tools. On 22 benchmarks with eight open and proprietary backbones, OpenVLHarness improves average scores by 9.7-12.6 points over matched no-tool baselines (+11.2 Qwen3-VL-8B, +9.7 Kimi K3, +9.9 GPT-6 Astra).

## The gap: reasoning without evidence

Visual reasoning benchmarks have grown, but many tasks need more than inference-time scaling: they need grounded perception, external knowledge retrieval, and numerical measurements from heterogeneous tools. A base MLLM's internal reasoning, even with increased budget, hits a ceiling because it has no mechanism to acquire, inspect, or compose external evidence across steps.

## OpenVLHarness design

The harness is organized around two components:

- **Capability layer** — combines task-level tool interfaces with evidence rendering, providing consistent access to heterogeneous backends (vision APIs, web search, calculators, etc.) and converting their outputs into model-readable observations.
- **Persistent multimodal memory** — retains corresponding images, structured data, and web references as addressable artifacts throughout each query, rather than discarding them after a single turn.

A coding interface then executes generated programs over stored data, enabling computations that combine results from multiple tools iteratively.

## Results and significance

On 22 benchmarks (eight backbones), OpenVLHarness improves over matched no-tool baselines: +11.2 (Qwen3-VL-8B), +9.7 (Kimi K3), +9.9 (GPT-6 Astra). The persistent memory mechanism is notable — by retaining evidence artifacts across reasoning steps, the model can compose multi-tool results rather than treating each as a one-shot observation. For SW engineers, the design aligns with production agent patterns: external tool use + memory layer, with a coding interface that lets agents execute computed plans over accumulated observations.
