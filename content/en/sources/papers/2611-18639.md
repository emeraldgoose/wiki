# SynthDCB: World Distillation for Scalable Device Control Benchmarking

**Source**: [arXiv:2611.18639](https://arxiv.org/abs/2611.18639) · **Published**: 2026-10-14 (v1), v2 2026-11-19
**Authors**: Zichen Zhu, Dingye Liu, Nan Jiang, Danyang Zhang, Hang Zheng, Shijie Zheng, Situo Zhang, Kunyao Lan, Yingzi Ma, Sheng Jiang, Lu Chen, Kai Yu

## Overview

Device-control benchmarks stall when simulators cannot keep pace with new device capabilities: adding a capability requires consistent tool interfaces, behavior implementations, world configurations, task requirements, and success criteria all at once. SynthDCB addresses this with world distillation (WD), a pipeline that transforms knowledge of device behaviors, constraints, and environmental effects into modular executable components. Typed capability specifications guide component implementation and validation; world composition assembles components into domain layouts; execution-grounded task synthesis derives requirements from available capabilities and validates candidate tasks by replaying a reference plan.

SynthDCB instantiates three worlds — Home, Car, and Phone — with 114 device classes, 1,166 functions, and 95 events, supporting five task families with 32 subtypes (query, control, goal, aggregate combinations, and workflow with process/event timing) plus memory and feasibility variants. Its evaluation splits contain 314 validation and 2,560 test tasks (2,289 feasible, 170 infeasible, 101 partial; 200 memory tasks) sampled disjointly from 30,309 tasks over 130 worlds. Evaluating 22 models with a shared ReAct-style agent and a 20-turn limit, the best model, Gemini 3.8 Flash, achieves 88.8% mean Pass@1, followed by GPT-5.6 Terra (82.6%), GPT-6 Astra (82.0%), and GPT-6.1 Sol (81.7%); small open-weight models reach only 1.6–8.7%. Rankings vary by domain (Astra leads Phone at 98.2%), and failure analysis shows strong models fail mainly on interpreting complex intent and coordinating subtasks (E6: 73.5–75.2% of weighted failures), while small models fail on protocol following (E2 alone 96.8% for Qwen3.5-2B).

On construction scalability, building all three domains with WD using GPT-5.6 Sol consumes 19.16M tokens (~$120.09 before cache discounts) within a couple of hours — versus over a month of manual work. In a RobotVacuum construction comparison at three knowledge levels, WD fully covers 22/23 properties, 19/29 functionalities, and 30/39 event requirements at the richest level, uses 51.5–86.7% fewer tokens per completely covered requirement than Codex xhigh, and 1,000 sampled tasks semantically cover 81.6% of 854 real-world reference instructions (69.8% of 172 categorized intents).

## Key points

- World distillation pipeline: device knowledge → typed capability specifications → validated executable components (schema checks, spec–implementation checks, effect validation, unit tests) → world composition → replay-validated task synthesis; components are reusable across worlds and task instances.
- Benchmark scale: Home/Car/Phone, 114 device classes, 1,166 functions, 95 events; five task families with 32 subtypes (Query, Control, Goal, Aggregate, Workflow); 314 validation + 2,560 test tasks (2,289 feasible / 170 infeasible / 101 partial) from 30,309 tasks over 130 worlds.
- Main results: 22 models on 2,560 test tasks; Gemini 3.8 Flash leads at 88.8% mean Pass@1 (Home 86.5%, Car 87.0%), GPT-5.6 Terra 82.6%, GPT-6 Astra 82.0% (Phone 98.2%), GPT-6.1 Sol 81.7%; open-weight MiniCPM5/Gemma-4 variants only 1.6–8.7%.
- Instruction-style ablation (9 models × 8 styles on validation): Direct (S2) beats Template (S1) by +7.0 pp for GPT-5.6 Luna; Implicit (S8) drops Astra by 36.3 pp (−44.7%) though partial-credit metrics decline far less, showing models still satisfy parts of omitted requirements.
- Interaction budget: extending truncated runs from 20 to 50 turns helps most models little (GPT +0.13 pp, DeepSeek +3.1 pp, Gemini +14.7 pp); 20 turns balances performance and cost.
- Error analysis (12 categories, 27,252 failed attempts): task understanding/coordination (E6) dominates failures for strong models (73.5% Sol, 75.2% Astra); temporal/workflow reasoning (E10) is 9.3% within Workflow tasks; small models fail mostly on interaction protocol (E2: 96.8% for Qwen3.5-2B).
- Construction efficiency: all three domains in 19.16M tokens / $120.09 / a couple of hours; RobotVacuum at full-protocol input: 22/23 properties, 19/29 functionalities, 30/39 events fully covered; 51.5–86.7% fewer tokens per covered requirement vs Codex xhigh; 81.6% coverage of 854 real reference instructions with 1,000 tasks.

## Details

Evaluation protocol: all models use the same ReAct-style agent (temperature 0), system-level tools to discover rules/devices/schemas, session.submit_answer for queries, session.submit_report with reason codes for infeasible/blocked atoms, simulated time via action/turn costs and session.sleep_time, and a 20-turn limit; success requires passing all applicable state, answer, report, memory, and temporal/workflow checks (mean Pass@1). Efficiency metrics Eff-A/Eff-T count satisfied state assertions and exact answers per tool call and per turn; GPT-6.1 Terra matches GPT-5.6 Sol's success (79.5% vs 79.1%) at ~31% of its cache-discounted inference cost. WD construction compares against Codex (same GPT-5.6 Sol) at low/xhigh effort across three knowledge levels (L1 0.06k, L2 0.77k, L3 89.8k chars): WD uses 0.9–66.0% fewer tokens than Codex low and 46.2–92.5% fewer than Codex xhigh. This version (v2, 2026-11-19) is the revision the results above are taken from; v1 was submitted 2026-10-14. Code and prompts are released at github.com/X-LANCE/SynthDCB.
