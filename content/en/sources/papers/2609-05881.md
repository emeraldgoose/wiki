# Broken on Arrival: Non-Functional Quantized LLM Artifacts in Public Model Registries and How to Catch Them

**Source**: [arXiv:2609.05881](https://arxiv.org/abs/2609.05881) · **Published**: 2026-10-25
**Authors**: Aditi Patodiya

## Overview

Developers download quantized large language models from public registries to run them locally, yet none of the examined registries documented functional testing of their files. This study audited all 305 eligible code-capable GGUF tags across 15 model lines in the official Ollama library plus 22 popular Hugging Face community files. A 15-task code screen identified suspects, which were retested on all 164 HumanEval+ tasks. Seven official tags (2.3%) solved at most six tasks, and all were low-bit quantizations of models with at most four billion parameters. The authors rebuilt five suspect files from the original weights; all matched the registry files tensor for tensor, so none was corrupted, and exact reproducibility did not imply function. Holding the weights, toolchain, and tensor mix fixed, adding an importance matrix raised Qwen2.5-Coder-3B scores from zero to 76–113 of 164 tasks at three quantization levels, while the same uncalibrated recipe left the smaller Qwen2.5-Coder-1.5B functional. None of 66 sampled tags that passed the screen was non-functional. The audit data and a `quantcheck` tool are released, with a recommendation to screen low-bit tags before publication and then calibrate or withhold failures.

## Key points

- No examined registry documented functional testing of quantized model files.
- Seven official low-bit quantized tags (2.3%) solved at most 6 of 164 HumanEval+ tasks.
- Rebuilt suspect files matched registry tensors, so the failures were not due to file corruption.
- Adding an importance matrix raised Qwen2.5-Coder-3B scores from zero to 76–113 of 164 tasks.
- The paper releases audit data and `quantcheck`, recommending pre-publication screening and calibration.

## Details

The benchmark is a 15-task code screen followed by full 164-task HumanEval+ retesting. Suspect official tags were all low-bit quantizations of models with at most four billion parameters. Controlled rebuilds established tensor-for-tensor equality between registry files and fresh builds, shifting blame from corruption to the uncalibrated recipe itself for some model sizes. A v3 revision clarifies that one community file pair failed because of a missing chat template rather than a backend issue. The work also notes that none of 66 sampled passing tags was non-functional, bounding the false-negative risk of the screen.
