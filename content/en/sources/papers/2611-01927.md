# Is Your Long-Horizon Benchmark Really Deep? Measuring and Synthesizing Depth in Terminal Tasks

**Source**: [arXiv:2611.01927](https://arxiv.org/abs/2611.01927) · **Published**: 2026-11-01
**Authors**: Yu Jiang, Yue Huang, Hang Hua, Yuyang Wu, Zixuan Weng, Olexandr Isayev, Yue Zhao, Zinan Lin, Xiangliang Zhang

## Overview

Long-horizon terminal tasks have become a standard way to evaluate and train agents, but human-curated datasets for them are scarce, so synthetic generation has proliferated. Most existing pipelines measure a task's length by the number of turns a model needs to pass it and its difficulty by labels assigned by the generating LLM. This paper identifies a problem with both proxies: turn count largely reflects the habits of the model being evaluated rather than the demands of the task itself, and the LLM labels barely track how often models actually pass.

To fix this, the authors describe a terminal task along two axes. Work is the number of operations the task requires. Depth is the number of turns that must occur in sequence, because the command in each turn can only be chosen after reading the output of the previous one. They estimate depth as the smallest turn cap, stated to the agent, under which the task still passes.

## Key points

- Auditing 734 tasks from six existing datasets shows that synthesis has mostly added work, not depth: 94% of the solved synthetic tasks pass within three turns.
- Depth predicts difficulty beyond work, whereas turn count conflates task demands with model behavior.
- The authors propose DEPTH, a generation method in which an agent writes each task one segment at a time in a real software environment, executes the segment before writing it, and starts the next segment from the resulting state.
- DEPTH's 105 tasks exceed every audited dataset in both depth and work, and none of six current models passes half of them.
- Fine-tuning Qwen3-8B on runs from DEPTH tasks improves it on two terminal benchmarks.

## Details

A terminal agent issues shell commands each turn, reads their output, and decides what to run next, which is enough to install software, configure services, and debug programs. Because the model can batch independent commands or take shortcuts, the total number of turns it happens to use is a poor proxy for how serially constrained the task is. Depth isolates the irreducibly sequential part: the chain of turns in which each command's choice depends on the previous turn's output.

The audit quantifies a known worry about benchmark inflation. Many synthetic tasks look long because they involve many operations, yet they are shallow enough that a capable model dispatches them in a handful of turns. Depth explains residual difficulty that work alone cannot.

DEPTH addresses this by construction. Rather than emitting an entire task script at once, the generator works segment by segment in a live environment, carrying state forward, so that later steps genuinely depend on earlier outcomes. The resulting tasks are harder for current models and provide useful fine-tuning signal, as evidenced by the Qwen3-8B improvement.
