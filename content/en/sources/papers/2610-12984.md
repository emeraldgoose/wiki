# Work2Skill: Capturing Human GUI Experience for Reusable Agent Skill Induction

**Source**: Huang et al., arXiv, 2026-10-09

**Lead**: Computer-use agents handle routine GUI tasks but fail on unfamiliar software whose procedures live only in human operators' heads. Work2Skill captures human demonstrations with synchronized screen, input, and accessibility-tree evidence (WorkRecorder), curates them into the 350-episode WorkDemo-350 dataset, and uses a tool-using agent to turn each episode into a reusable skill file. Across four execution models the induced skills beat both no-skill and prior demonstration-to-text baselines.

## Background

Humans and computer-use agents share the same GUI interaction space, so demonstrations are a natural source of procedural knowledge. Prior work converts demos into instructions, tutorials, or skills, and vendors now ship "record a skill" features. Three gaps remain: action coordinates say where a click happened but not what the control means; different studies use different demos and harnesses so induction methods cannot be compared fairly; and fixed pipelines prescribe an inspection order instead of letting the agent revisit unclear steps on demand.

## Work2Skill Framework

**WorkRecorder** — collection infrastructure. Records screen video, keyframe images, mouse/keyboard events, and available accessibility-tree (AX) snapshots on a common timeline, grouping events into actions (clicks, drags, hotkeys) linked to keyframes and video times. Target-element association uses pointer location, timing, and AT-SPI queries so a click carries explicit control semantics (name, role, bounds), not just coordinates.

**WorkDemo-350** — shared evidence resource. 350 screened human demonstrations: 64 MyPCBench Bounded Action tasks plus a 286-task OSWorld-Verified subset, ~8.48 hours total (mean ~119s per MyPCBench episode, ~80s per OSWorld episode, ~24 evidence images each). Every episode passed completeness and task-success review.

**Agentic skill induction** — a NexAU tool-using agent inspects evidence on demand (file/image/video tools with timestamp-labeled frames) interleaved with drafting, following a skill-creator policy: generalize demo-specific inputs into task-dependent descriptions while keeping workflow rules, step dependencies, and completion checks. Output is a `SKILL.md` per capability (Agent Skills convention), validated by a `finalize_extraction` structural check. Skills are never executed during induction, so downstream results measure genuine reuse.

## Experiments

**Setup**: Official task evaluators on both benchmarks; skills injected as a delimited `<task_skills>` block appended to the executor prompt, identical across methods. Executors: GPT-5.5, Opus-4.8, Qwen3.5-35B-A3B, Qwen3.5-9B. Baselines: No Skill, ShowUI-Aloha (action semantics), Demo2Tutorial (tutorial text), all adapted to the same text-guidance interface and source episodes.

**Benchmarks**: MyPCBench Bounded Action (64 tasks), OSWorld-Verified subset (286 tasks), plus MyPCBench Jitter (64 requirement-changed variants) for generalization and a GPT-5.5/Qwen3.5-9B cross-pairing for model transfer.

**Results** (mean score 0–100; success rate = full-credit %):

| Setting | Gain over No Skill | vs. stronger demo baseline |
|---------|-------------------|---------------------------|
| MyPCBench (RQ1) | +4.67–10.54 score pts, +6.25–25.00 SR pts | +3.95–7.79 score pts |
| OSWorld-Verified (RQ1) | +3.11–7.50 score pts, +1.40–7.69 SR pts | +1.65–6.96 score pts |
| MyPCBench Jitter (RQ2, reuse) | +3.93–8.64 score pts, +6.25–9.38 SR pts | +4.28–6.25 score pts |

Highlights: GPT-5.5 on MyPCBench reaches 48.44% success vs. 37.50% for both baselines; skills transfer across induction/execution models (all pairings beat No Skill, GPT-5.5-induced skills best); evidence ablations show full multimodal evidence matters. Induction token cost is model-dependent and not consistently cheaper than baselines — the win is quality, not cost.

## Relevance to Software Engineers

- **Reusable procedure artifacts**: `SKILL.md` files are plain Markdown under version control — reviewable, diffable procedure knowledge that outlives any single agent run.
- **Harness-agnostic injection**: appending skill text to the system prompt (no pipeline changes) makes the same skills work across executors — a practical pattern for multi-model agent stacks.
- **Evidence tooling pattern**: timestamp-labeled, on-demand inspection (coarse video scan, then zoom into ambiguous actions) avoids loading whole recordings into context — directly applicable to any trace-analysis agent.
- **Evaluation discipline**: shared episodes + shared executors + official evaluators is the template for fairly comparing agent-improvement methods; the Jitter-variant idea (same app, changed entities/constraints) is a cheap reuse test worth copying.
