# AutoPILOT: A Visual Agent Harness for Real-Time Gameplay

**Source**: [arXiv:2611.28202](https://arxiv.org/abs/2611.28202) · **Published**: 2026-11-20 (v1)
**Authors**: Mark Zhao, Pengcheng Wang, Rui Yang, Jiarui Yao, Xirui Jiang, Yuxi Chen, Bingxuan Li, Hanyang Chen, Ke Yang, Manling Li, Tong Zhang, Huan Zhang

## Overview

Multimodal foundation models can play video games well when the game waits for them, but often fail when it keeps running. The authors locate much of this gap in the harness — the layer that decides what the model sees, what it remembers, and how its outputs become actions over time. Existing harnesses such as VISTA improve perception and memory, yet turn each model call into at most one action, so the agent acts only as often as its model thinks.

AutoPILOT changes that third part: in each model call the model can (1) send a primitive action directly to the game, (2) start an open-loop macro — a sequence of actions it writes out, or (3) write a closed-loop controller, a short Python program it authors at run time that reads the screen and acts about every 0.4 s without any further model calls until control returns on a wake event (the macro/controller finishes, requests a handoff, or meets a screen it was not written for). Both the model and its controllers see screenshots, never the game state.

## Key points

- Benchmark: AFK-Bench ("Away From Keyboard"), 120 diverse browser games grouped by how they respond to inaction, playable in real time or with the clock paused, to measure what real time costs an agent.
- Results with GPT-6.1 Sol under identical budgets: 68.6% real-time success on AFK-Bench vs 38.3% for VISTA; on GameWorld it keeps 80.0% in real time while VISTA drops from 84.1% (paused) to 42.9% (real time).
- Cost: AutoPILOT reaches VISTA's final success rate at roughly one fifth of its API cost; gains hold across different underlying models, and on AFK-Bench AutoPILOT wins even with the clock paused.
- Analysis: the paper dissects how the components (execution modes), budgets, reasoning effort, and generation speed each contribute, arguing that how a harness turns model outputs into actions over time is a central yet underexplored part of agent design.

## Details

The harness treats acting-over-time as a design choice: controllers are model-written Python that run locally against screenshots, so low-level control loops no longer consume model calls; the model regains control on wake events and can delegate routine control back. The paper includes detailed ablations over execution-mode usage, action budgets, and model backbones, plus qualitative traces (e.g. after three losses a controller takes over and wins at 1:26). AutoPILOT and AFK-Bench are positioned as a foundation for agents "in a world that does not wait".
