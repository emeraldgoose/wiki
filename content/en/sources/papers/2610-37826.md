# DeFT-RAG: Decomposing Multi-Hop Questions into Self-Contained Sub-Questions with Reusable Answers

**Source**: [arXiv:2610.37826](https://arxiv.org/abs/2610.37826) · **Published**: 2026-10-30
**Authors**: Dingyi Kang, Bingzhe Li

## Overview

Retrieval-augmented generation helps large language models answer by retrieving relevant passages, but multi-hop questions require chaining facts across multiple documents through intermediate entities the question never mentions. Graph-based RAG retrieves once from named entities and rarely recovers the full evidence chain. Iterative RAG can recover it step by step, but suffers under the many tasks it asks the model to perform, including planning sub-questions, deciding dependencies, rewriting them as answers arrive, and tracking known facts.

DeFT-RAG is a RAG framework with three components. It generates one self-contained sub-question at a time from the original question and prior question-answer pairs, naming every entity it asks about. This removes the need to plan, track dependencies, or rewrite, letting the model focus on one fine-grained task. It also moves bookkeeping outside the model through rule-based updates to a question-answer table and yes/no decisions by a lightweight decision model. Finally, it caches answers and reuses an answer when a later question has the same meaning. On MuSiQue, 2WikiMultiHopQA, and HotpotQA, DeFT-RAG achieves the best accuracy among thirteen baselines while giving the model fewer input tokens than other iterative methods. A shared cache across 1,000 MuSiQue questions answers 23.1% of sub-questions from cache, reducing model calls by 12.9% without lowering accuracy.

## Key points

- Multi-hop RAG fails when intermediate entities are not named in the question.
- Graph-based methods retrieve too little of the evidence chain.
- Iterative methods suffer from heavy planning and tracking overhead.
- Self-contained sub-questions remove planning, dependency, and rewrite burdens.
- Rule-based tables and a lightweight decision model reduce model work.
- Answer caching and reuse substantially reduce calls without hurting accuracy.

## Details

The paper's central insight is to make each sub-question independently meaningful, so sub-questions do not depend on hidden state or future rewriting. This simplifies both generation and evaluation, because each request is self-contained. Moving bookkeeping and binary decisions outside the main model also lowers the number of tasks the language model must handle, while caching exploits repeated sub-questions across a dataset. The result is a more token-efficient iterative RAG method with strong accuracy.
