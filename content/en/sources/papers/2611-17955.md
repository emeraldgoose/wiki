# WebArena-Pro: A Heterogeneous, Multimodal, Reproducible Benchmark for Web Agents

**Source**: [arXiv:2611.17955](https://arxiv.org/abs/2611.17955) · **Published**: 2026-11-13
**Authors**: Imene Kerboua, Fatemeh Pesaran Zadeh, Xing Han Lù, Weijian Qi, Alexander Miller, Junyi Song, Yunjia Tian, Dongjin Kang, Seyeon Choi, Marzia Nouri, Ewen Gueguen, Matteo Boglioni, Fengyuan Liu, Zeyi Liao, Mengqi Yuan, Yue Li, Alexandre Lacoste, Alexandre Drouin, Spandana Gella, Huan Sun, Gunhee Kim, Siva Reddy

## Overview

Web agents driven by large language and vision-language models are being handed increasingly realistic browser work — drafting and triaging messages, updating records in business applications, extracting insight from dashboards, editing media — yet the benchmarks that measure this progress have lagged behind. Reproducible, self-hosted benchmarks cover only a small number of web applications drawn from a few software categories and restrict modality to text and vision, while live benchmarks that operate on real production websites broaden coverage at the cost of reproducibility, since pages, data, and layouts drift between runs. None of these evaluations meaningfully probes whether agents can understand and use audio and video content embedded in the tasks themselves.

WebArena-Pro, built by a team led from McGill University and Mila – Quebec AI Institute with collaborators at ServiceNow AI Research, The Ohio State University, INSA Lyon, Esker, and Seoul National University, closes these gaps at once. It spans 20 self-hosted web applications across six domain categories — productivity, communication, analytics, business operations, design and media, and travel — with 300 tasks whose applications are modeled on widely used services such as Notion, Slack, Spotify, Figma, and Airbnb, though data and feature scope stay under benchmark control. Every task is authored as its own dedicated template rather than instantiated in bulk from a shared template, and the pool divides into 204 single-site and 96 cross-site tasks, and into 221 text/vision and 79 audio/video tasks.

The results show how much headroom remains. Under a 50-action budget, the best configurations — Codex with GPT 6.1 Sol and Claude Code with Claude Opus 5.5 — tie at 62.3% success, while the strongest GenericAgent setups, Gemini 3.1 Pro omni and Gemma4 31B, both stop at 30.3%. Among reproducible, human-curated web-agent benchmarks, the authors position WebArena-Pro as offering the broadest application coverage and the most comprehensive multimodal support to date.

## Key points

- Scope: 300 tasks over 20 self-hosted applications in six domains; every task gets its own dedicated template, whereas the predecessor WebArena instantiates 812 instances from 241 templates, so evaluation diversity comes from application breadth rather than template reuse.
- Audio and video as core observations: media sources appear as nodes in the accessibility tree; vision-language agents get transcribe() (a local Whisper transcript) and extract_frames() (evenly spaced video frames), omni models get listen() and watch() for direct audio/video input; transcripts are merged into the tree as synthetic nodes and frames return as image content.
- Reproducible isolation: each application runs as a Docker container with seeded data and fixed credentials, and state resets to the seeded baseline before every task, enabling contamination-free parallel evaluation; 9 of the 20 sites adapt open-source applications while 11 are AI-assisted custom builds.
- Leaderboard: Codex with GPT 6.1 Sol and Claude Code with Claude Opus 5.5 tie for the best overall success rate at 62.3%, followed by OpenCode with Kimi 3.1 Pro at 60.7% and OpenCode with Qwen 3.8 Max Prime at 55.7%; the strongest GenericAgent scores are 30.3% for both Gemini 3.1 Pro omni and Gemma4 31B, and even the best configuration leaves 38% of tasks unsolved (on the separate, easier 100-task dev set, Gemma4 31B reaches 74.0%).
- Domain and coverage effects: communication is the easiest domain for coding agents (Codex 81.8%) and travel the hardest (best 57.7%); cross-site tasks are consistently harder than single-site ones — Gemma4 31B falls 24.7 points from 38.2% to 13.5%, while Claude Code posts the best cross-site rate at 55.2% and the smallest gap (10.5 points).
- Media ablation: across the 79 audio/video tasks on AcidWave and YT-Lite, and especially the 43-task subset unsolvable from titles, metadata, or thumbnails alone, removing media tools drops Gemini 3.1 Pro and Qwen 3.6 27B to 0% on audio tasks; Claude Code with Opus 5.5 climbs from 14.0% without tools to 48.8% with them.
- Rubric-based scoring: each task carries human-written action and outcome criteria organized as a directed acyclic graph, graded by deterministic backend checks first, then heuristic URL/action matching, then an LLM judge applied last — Qwen 3.6 27B, chosen because its pooled agreement with human annotations is 89.5% while judging costs under USD 4 per 300-task evaluation.
- Costs: recorded API costs for a full 300-task evaluation run from USD 166 (Codex with GPT 6.1 Sol) and USD 386 (Claude Code with Opus 5.5) to USD 689 (OpenCode with Qwen 3.8 Max Prime) and roughly USD 800 (GenericAgent with Claude Opus 4.7).

## Details

Episodes run in a BrowserGym-compatible environment: the benchmark starts a fresh website container, waits for readiness, performs the required UI login, and navigates to the task start URL; the agent then acts until it calls done() or send_msg_to_user() or exhausts the 50-action budget. GenericAgent is a ReAct-style agent that works from the accessibility tree with Set-of-Mark-augmented screenshots and the BrowserGym bid action set extended with done(), transcribe(), and extract_frames(). OpenCode, Codex, and Claude Code are evaluated through the Harbor harness with a Playwright MCP for browser control plus an augmented media MCP. Twelve backbones are covered — seven open-source models (Qwen 3.5 9B through Qwen 3.8 Max Prime, Gemma4 26B A4B and 31B, Kimi 3.1 Pro) and five closed models (Gemini 3.1 Flash Lite and Gemini 3.1 Pro, Claude Opus 4.7 and 5.5, GPT 6.1 Sol) — all with extended thinking at high reasoning effort and temperature 1.0, and a 40k per-step token cap for GenericAgent.

Task construction is human-gated: through a dedicated annotator interface an author writes the intent, selects sites, and drafts the rubric; automated triage runs an LLM agent on the candidate and discards tasks solved correctly on the first attempt; a second annotator then confirms feasibility on the live application, finalizes the rubric items, and sets the difficulty label before human validation gates release. The failure analysis is telling: of 2,400 GenericAgent test runs, 878 of the 1,683 unsuccessful runs (52.2%) exhausted the 50-step limit, whereas only 14.5% of the 633 unsuccessful coding-agent runs did, and 59.2% of those failures still earned partial rubric reward.

The authors note two limitations: the action-space extension covers only prerecorded audio segments and discrete video frames, and results compare particular model–harness–tool combinations, so differences cannot be attributed to model capability or harness design alone. The same infrastructure doubles as a future training environment — the rubric-based verifier supplies per-task rewards for reinforcement learning or rejection sampling — and as a testbed for robustness studies on UI drift and prompt injection.
