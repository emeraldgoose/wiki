# BitDecoding-FP4: Native FP4 KV Cache Decoding via Algorithm-System Co-Design

## Overview

Long-context LLM serving is dominated by the key-value (KV) cache: unlike static weights, it grows with sequence length and concurrency, and it is re-read on every decoding step. Four-bit microscaling formats such as NVFP4 and MXFP4 shrink that cache and are natively executed by fifth-generation Tensor Cores on NVIDIA Blackwell (and Rubin) GPUs, promising roughly 2-3x the throughput of FP8. Yet a gap remains between algorithmic quantization and system-aware acceleration: existing FP4 KV systems quantize naively and lose substantial accuracy, while accuracy-oriented 4-bit methods rely on vector codebooks whose lookup overhead erodes decoding throughput.

BitDecoding-FP4 (Du et al., University of Edinburgh and Tencent Hunyuan) closes that gap with an algorithm-system co-design for native FP4 KV decoding. On the algorithm side, it targets three distinct error sources in microscaling FP4 quantization; on the system side, it removes the softmax bottleneck so both attention matrix multiplications run natively on FP4 Tensor Cores against paged KV caches. The result is a decoding path that is both accurate and fast, rather than trading one for the other.

Across dense and Mixture-of-Experts models using both grouped-query attention (GQA) and multi-head latent attention (MLA), BitDecoding-FP4 stays within 0.5 points of BF16 KV accuracy with NVFP4 (within 1 point with MXFP4), and tracks BF16 KV even inside RL training rollouts. In end-to-end serving on NVIDIA B300 GPUs with Qwen3-4B and Qwen3-30B-A3B, it delivers 2.4-3.0x higher peak serving throughput than BF16 KV. The implementation is open source at https://github.com/OpenBitSys/BitDecoding-FP4.

## Key points

- Targets the KV-cache bottleneck in long-context serving with native FP4 (NVFP4 / MXFP4) execution — no runtime dequantization step.
- Dual-Residual Query Quantization splits queries into two FP4 tensors, cutting query logit error from 60% to 1%.
- Underflow-Aware Probability Scaling stops E4M3 scales from rounding long-context probabilities down to zero.
- Outlier-Aware Key Quantization combines static smoothing, Hadamard rotation, and scale search to suppress key outliers under token-wise scaling.
- System-level: transposed softmax with fused probability quantization, plus stacked query MMA on paged KV caches, removes the softmax bottleneck.
- Evaluated on dense and MoE models with GQA and MLA; NVFP4 stays within 0.5 accuracy points of BF16 KV (1 point for MXFP4).
- 2.4-3.0x higher peak serving throughput than BF16 KV on NVIDIA B300 (Qwen3-4B, Qwen3-30B-A3B); tracks BF16 KV in RL training rollouts.
- Builds on the Tensor Core-aware KV layout and mixed-precision buffer of the authors' earlier BitDecoding work.

## Details

**Method.** BitDecoding-FP4 quantizes both attention operands (Q/K for the score product, P/V for the output product) into microscaling FP4 and executes both as FP4 matrix multiplications. Three compounding error sources are addressed. (1) *Dual-Residual Query Quantization*: the query is quantized once, then the residual (query minus its dequantized approximation) is quantized into a second FP4 tensor; the two partial products are accumulated, which cuts query logit error from 60% to 1%. (2) *Underflow-Aware Probability Scaling*: in the online softmax, probabilities for long contexts are tiny and can round to zero under E4M3 scaling; the method adaptively rescales probabilities (choosing a scale factor κP of 2 when the block max falls below a threshold, else 6) so they survive E2M1 rounding. (3) *Outlier-Aware Key Quantization*: keys are preprocessed with static smoothing (subtracting a per-channel mean), a Hadamard rotation, and a scale search, which suppresses outlier channels under token-wise scaling. At the kernel level, a transposed softmax with fused probability quantization and stacked query MMA over paged KV cache blocks keep the softmax off the critical path and Tensor Cores fed — prior work noted dequantization consuming 7-21% of decode kernel time at 128K context, which native FP4 removes entirely. The method extends the BitDecoding layout with an accurate FP4 quantization algorithm and Blackwell-native kernels; appendices cover teacher-forced KL as a fast accuracy proxy, calibration ablations, a SageAttention3 comparison, MXFP4 block-scale search, and FP4 multi-head latent attention.

**Results.** Across dense and MoE LLMs with GQA and MLA, BitDecoding-FP4 with NVFP4 KV stays within 0.5 accuracy points of BF16 KV (within 1 point with MXFP4), and its accuracy tracks BF16 KV in RL training rollouts. In end-to-end serving on NVIDIA B300, Qwen3-4B and Qwen3-30B-A3B achieve 2.4-3.0x higher peak serving throughput than BF16 KV. On Blackwell-class GPUs, native FP4 operands offer roughly 2-3x the throughput of FP8. The work is positioned as the algorithm-system counterpart to accuracy-oriented codebook methods, which pay lookup overhead that negates FP4's throughput advantage.
