# AgentBaton: Efficient Model Collaboration in Agentic Tasks

**Source**: [arXiv:2610.35959](https://arxiv.org/abs/2610.35959) · **Published**: 2026-10-25
**Authors**: Junlong Li, Jindong Jiang, Yonggan Fu, Jiarui Yao, Hanrong Ye, Wonmin Byeon, Peter Belcak, Hao Zhang, Pavlo Molchanov

## Overview

Long-horizon agentic tasks are solved by repeated interaction with an environment — calling tools, observing feedback, revising actions — and the reliability needed for these loops usually comes from expensive capable cloud models, while cheaper efficient models (lower-tier cloud models, or small open-weight models that fit on local hardware) trail in accuracy when used alone. The paper asks a question that query-level routing does not answer: can a capable model and an efficient model collaborate inside a single long-horizon task so that cost drops substantially and accuracy holds? Its unit of collaboration is a handoff, in which one model takes over from another.

Because actions change the workspace and generate dynamic feedback, the capabilities a task needs evolve across turns, so a routing decision made from the initial query is not enough. The authors therefore study two design choices: handoff direction (efficient-to-capable versus capable-to-efficient) and context transfer (including the full interaction history in the receiver's context, or writing a structured execution log that the receiver inspects on demand with tools such as cat, grep and sed). In both cases the receiving model continues from the workspace its predecessor produced.

The experiments show a clear asymmetry. Efficient-to-capable handoffs generally underperform capable-only execution with limited or no cost reduction, even when they favour log-file transfer. Capable-to-efficient handoffs at a suitable stage of task progress, by contrast, largely preserve capable-only accuracy while cutting cost markedly. This implies a one-way dependency — progress made by the capable model enables an efficient model to finish work it could not do alone — and makes frequent per-turn switching impractical, because accumulated trajectory errors would force the capable model to keep recovering them.

## Key points

- Case studies characterise the handoff window: the capable model has usually produced a substantive implementation or artifact and received task-relevant feedback, leaving mainly localized repair, validation or finalization.
- AgentBaton is a lightweight detector trained on recurring patterns in execution history rather than a hand-written rule: the capable model starts the task, AgentBaton scores progress after each turn, and once it predicts a suitable handoff point the efficient model continues to termination.
- Across 11 capable–efficient model pairs and two benchmarks, Terminal Bench 2.1 and DeepSWE v1.1, AgentBaton reduces API cost by 65.9% on average while largely preserving task accuracy, with accuracy gains of up to 8.8 percentage points over capable-only execution.
- The authors also compare context-transfer methods per direction, and find the preferred method varies across models — in-context history helps the receiver reuse prior progress but lengthens prefill at handoff and keeps the sequence longer afterwards, and may bias the receiver by exposing it to its predecessor's reasoning.
- Experiments across reasoning-effort settings show AgentBaton extending the empirical accuracy–cost Pareto frontier rather than only operating at one fixed budget.
- A single well-timed handoff is described as sufficient: the results indicate that a one-time, simple, well-timed strategy beats more elaborate collaboration schemes for cost-effective agent execution.

## Details

The evaluation covers both handoff directions on multiple capable–efficient pairs, with two context-transfer variants: direct inclusion of prior interaction history in the receiver's context versus a structured execution history written to a log file that the receiving model reads as needed. The paper reports that efficient-to-capable handoffs benefited from log-file transfer yet still did not beat capable-only runs, while capable-to-efficient handoffs preserved accuracy at much lower cost, although which transfer method worked best depended on the models involved. Motivating the detector, the authors note that prior work on heterogeneous model combinations focused on query-level routing and cascading for individual requests, which cannot capture capability requirements that emerge mid-trajectory.
