# AuXSpec: Learning to Autoformalize Program Specifications via Executable Postconditions

**Source**: [arXiv](https://arxiv.org/abs/2611.21421)
**Published**: 2026-11-16

## Overview

Formal specifications define intended program behavior and underpin verification, but writing them in theorem provers such as Lean is slow and expertise-intensive, making specification a major bottleneck to scaling formally correct code. Autoformalization from natural-language problems is promising, yet training specification models requires scalable feedback on whether a generated specification captures the intended behavior. Prior approaches obtain this feedback through explicit proofs or separately implemented code with correspondence proofs — both expensive.

AuXSpec is a Lean framework that pairs declarative postconditions with executable counterparts, obtained through type class resolution when possible and otherwise defined separately with an equivalence proof. Test cases can then evaluate declarative specifications by execution, letting execution agreement serve as a reinforcement-learning reward. Using AuXSpec, the authors synthesized 3,037 LeetCode problems and expanded training to 19.5K samples through expert iteration on Codeforces. Models, data and the 300-problem AuXSpec-Test benchmark with expert review are released at huggingface.co/collections/eth-algopt/auxspec and auxspec.org.

## Key points

- In-domain (AuXSpec-Test): training lifts SpecGen pass@4 from 0.7% → 82.7% (Qwen3.5-9B) and 14.3% → 84.3% (Qwen3.8-27B). AuXSpec-27B-RL surpasses every frontier model in both pass@1 and pass@4 on SpecGen and CodeGen — 65.7% SpecGen pass@1 vs 57.7% for Claude-Opus-5 (strongest frontier); the 9B RL model also beats every frontier model in SpecGen pass@1 (58.6%).
- Repair tasks: 27B RL model attains the best CodeGen-Repair pass@1 (88.1%) and stays within 2 points of the best elsewhere; the 9B RL model surpasses most frontier models in SpecGen-Repair pass@1.
- Out-of-domain (Verina, original prompts): both models improve 7.0% → 90.5% and 21.9% → 90.5%, surpassing VeriSpecGen-30B-A3B (prior open-source SOTA) on pass@1 (73.7% and 84.5% vs theirs 47.6%) and pass@4 (90.5% vs theirs 63.9% at pass@10).
- False-positive control: the postcondition equivalence theorem is proved for 99.2% of accepted RL outputs (Appendix H.4); expert review confirms 90 of 100 sampled outputs, with all errors in the validity predicate (Appendix I.2).
- Reward design: executable postconditions obtained via type class resolution (or defined separately with an equivalence proof) make test-case evaluation of declarative specifications cheap, unlike symbolic specification testing which needs per-test-case proofs in Lean.

## Details

- Pipeline: synthesize executable+declarative postcondition pairs for LeetCode problems (3,037), expert iteration on Codeforces expands training to 19.5K samples; SFT then RL with the execution-based agreement reward. Decontamination, source selection and data breakdown in Appendix C.
- Evaluation: AuXSpec-Test (300 problems, expert-reviewed, correctness proofs) and Verina OOD; metrics include SpecGen/CodeGen pass@1/pass@4 and repair variants; self-repair on ICPC-Eval and general capabilities in Appendix D; RL reward-stage analysis in Appendix E.
