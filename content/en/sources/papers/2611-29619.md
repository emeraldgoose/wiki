# Wactorz: Self-Writing LLM Agents That Discover, Repair, and Migrate at the Edge

**Source**: [arXiv:2611.29619](https://arxiv.org/abs/2611.29619) · **Published**: 2026-11-22 (v1)
**Authors**: Panagiotis Kasnesis, Lazaros Toumanidis, Amalia Contiero Syropoulou, Christos Chatzigeorgiou

## Overview

Most LLM agent frameworks (AutoGen, CrewAI, LangGraph) run a crew that executes a task and exits, while edge automation tools (Home Assistant rules, Node-RED) are long-lived but static. Physical environments need agents that stay up for months, survive their own bugs, and run on existing low-power hardware. Wactorz combines three traditions: the Erlang/OTP actor model with supervision trees, code-generating LLM agents that write their own behavior at runtime, and MQTT pub/sub as the sole coordination substrate. The result is a single-process asyncio actor system (plus a Mosquitto broker) in which every agent is an Actor with an inbox, message loop, 10 s heartbeat, and a persist()/recall() key-value API (SQLite for structured keys; blob files for models, numpy arrays, tensors; pickle for other objects), addressed as name@node so the same agent name can exist on two machines.

A chat request is classified by MainActor (direct actuation, Home Assistant query, pipeline, chat). Pipelines go to an ephemeral PlannerAgent that emits a JSON plan and, per step, Python source with setup()/process()/handle_task(); each block becomes a DynamicAgent spawned without restart. An InstallerAgent pip-installs declared dependencies (allow-list, else operator approval on the dashboard), and a catalogue of trusted recipes covers common needs. Agents never address each other by name: a TopicBus registers a contract per topic (producer, consumers, captured sample payload), so a later planner is handed real contracts and consumers read payload fields that actually exist — removing the classic two-LLM field-name disagreement.

## Key points

- Supervision and self-healing: generated code passes a pre-execution AST blocklist (no shell execution, file deletion, eval); a sanitiser fixes the common mistake of awaiting sync methods; repeated runtime errors in setup()/process()/subscribe callbacks are sent back to the LLM with the traceback for in-place repair, persisted to the spawn registry; process() calls are timeout-guarded. Above that, a Supervisor applies ONE_FOR_ONE restarts — a crashing agent restarts alone and reloads persisted state, with backoff growing to minutes and up to an hour. MonitorActor tracks heartbeats and deliberately does not restart agents whose code fails to compile (reported to the user instead). The spawn registry is persisted, so all dynamic agents come back after reboot.
- Topic-graph observability: the dashboard Wiring view (also GET /api/wiring) draws agents and topics grouped by machine and flags orphan topics, subscribers with no producer, and field mismatches between declared and observed payloads; selecting an agent/topic shows its last payload.
- Operator in the loop: agents can notify_user / ask_operator via dashboard, Telegram, Discord, WhatsApp; the wait survives restarts and the dashboard Inbox lists pending questions and package approvals.
- Edge nodes and live migration: any Python 3.11 machine becomes a node via wactorz --node; /deploy provisions one over SSH (venv, systemd unit + watchdog, reports success only after broker heartbeat). /migrate AGENT NODE stops the agent, ships state as JSON and blobs in SHA-256-checked chunks on their own topics, keeps the source copy until the destination confirms start, and restarts an agent leaving a node from main's own copy of its program (never code handed back by the node). State caps: 8 MiB, blobs 64 MiB.
- Security model: loopback binding unless API key; signed node commands; TLS to the broker; per-node broker accounts with access lists; main accepts replies only from their own node; model-written agents can be confined to a credential-less sandbox container whose network reaches only the broker.
- Model-agnostic and offline-capable: providers (Anthropic, OpenAI, Gemini, NVIDIA NIM, Ollama) configured per call site (cheap local 4B for routing, hosted for codegen); a built-in evaluation harness scores models per call site (exact-match routing, action-set match for actuation including expected refusals, plan validity, compile checks) reporting accuracy/latency/cost; a deterministic fake provider and --minimal profile run with no model at all.
- Wactorz as a library: a decorator turns a hand-written function into the same kind of supervised, persistent, topic-wired, migratable agent; Actor subclasses with SUBSCRIBES/PUBLISHES/schemas integrate too; LangGraph/AG2 graphs can run as agents and call me.llm with spend accounting.
- Models at the edge: wactorz-artifacts stores models by name+version on main (SHA-256 dedup); load_model reads npz/npy/safetensors/state_dict/ONNX without executing file code, refuses pickle/joblib/whole torch modules unless allow_code=True; migration pins exact model versions, the node fetches only what its cache lacks and hash-checks each file; active/shadow pointers with audited promotion policies (metric, margin, minimum days, labelled trials reporting precision/recall/F1/false alarms) close the training loop with trainer and drift agents (PSI, KS, ADWIN).
- Demo: camera-person detection -> lamp actuation from one chat request; a counter auto-wired by topic that hits a deliberate ZeroDivisionError three times in four seconds, gets its code repaired by the LLM and resumes 10, 11, 12... without a reset; /deploy of a bare Raspberry Pi and /migrate of the counter onto it — under four minutes wall-clock, $0.13 total model cost, one unedited video, Claude Sonnet 5 at every call site.
- Limitations (stated by the authors): the validator is a blocklist over the AST, not a sandbox (indirect names pass; all agents in one process share one privilege level — isolation comes from placement); repair restores liveness, not intent; non-serializable state blocks migration unless forced; main and nodes must run the same release series; no systematic repair-success measurements yet (the evaluation harness is the instrument for that future study).

## Details

Sections describe the architecture (MainActor, PlannerAgent, DynamicAgent, InstallerAgent, Supervisor, MonitorActor, TopicBus, Mosquitto), the Wiring view, supervision/self-healing pipeline, operator channels, /deploy and /migrate protocols with their consistency rules, the security model, per-call-site provider configuration and the evaluation harness, the library API (decorator, Actor subclassing, pipelines, framework integration via me.llm), and wactorz-artifacts model storage/transfer/replacement (active/shadow, promotion policy, trainer and drift agents). The Demonstration section walks the five recorded steps. Ships as pip package, Docker image, and Home Assistant add-on under Apache-2.0 with a 500-file test suite. Code: github.com/waldiez/wactorz.
