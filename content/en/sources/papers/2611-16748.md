# PhysLoop: Harnessing LLMs' Physics Awareness for Self-Improving Video Generation Models

**Source**: [arXiv:2611.16748](https://arxiv.org/abs/2611.16748) · **Published**: 2026-11-12
**Authors**: Yuxuan Chen, Xiaojie Li, Hao Chen, Juncheng Ma, Kewei Zhang, Zhongjing Du, Guoqiang Wei, Fangfang Wang, Zhen Dong, Zhiyang Dou, Liming Zhao, Yan Zeng, Jianwei Zhang, Daquan Zhou

## Overview

Video generation models render convincing frames, yet realism does not guarantee physical consistency: objects vanish or multiply, contacts fail to produce plausible responses, and speeds contradict gravity, inertia, or contact forces. Fixing this through real-world data collection scales poorly, because varying a single factor in a physical event, such as the release height of a falling glass, demands repeated setups and careful annotation. The authors target recursive self-improvement, where a video model identifies its physical weaknesses, generates candidate training videos for them, and learns from the ones that survive verification.

The obstacle is that generating more videos is not enough. Current models still make physical errors, and general-purpose multimodal evaluators cannot reliably judge physical validity. The paper's insight is that LLMs already hold substantial physical knowledge but apply it inconsistently, so the right move is to guide and constrain that knowledge inside an executable environment. PhysLoop is a unified harness in which an agent turns a request into a task specification, builds a simulator scene from retrieved assets, runs the physics, verifies the event against recorded requirements, and only then refines the verified simulation into realistic video, followed by a second verification pass.

The harness ships with PhysLoop-100K, a training set of 100K accepted videos from 2.5K distinct physical events, and two evaluation sets: PhysLoop-Gen with 100 generation tasks and PhysLoop-Repair for videos with annotated physical errors. In evaluation, the default configuration (GPT-6 Astra as agent backbone, Seedance 2.5 as refiner) reaches 85% task success on PhysLoop-Gen versus 73% for standalone Seedance 2.5, and 86.00% repair success versus 19.33% for the strongest standalone baseline.

## Key points

- PhysLoop-100K contains 100K accepted videos from 2.5K distinct physical events, averaging 40 videos per event, captured from 3-5 perspectives and covering 2-4 key configurable parameters such as mass and initial velocity.
- Coverage spans kinematics, dynamics, rigid-body dynamics, magnetism, fluid mechanics, flexible and elastic materials, and fragmentation and fracture; depth maps, instance segmentation, and object states accompany the videos.
- PhysLoop-Gen contains 100 generation tasks over rigid-body, cloth, and fluid phenomena, from simple bouncing or sliding to coupled interactions and multistage mechanical chains.
- The default configuration pairs GPT-6 Astra as the agent backbone with Seedance 2.5 as the video refiner; Unreal Engine is the primary simulator, with Taichi and Genesis as additional backends.
- On PhysLoop-Gen, PhysLoop achieves an 85% task-success rate versus 73% for standalone Seedance 2.5, with higher human ratings for physical plausibility (4.06 versus 3.80) and causal consistency (4.12 versus 3.80), though lower visual realism (3.72 versus 4.29).
- On PhysLoop-Repair, PhysLoop reaches 86.00% success versus 19.33% for the strongest standalone baseline; all three standalone generators stay below 20%.
- Ablating the refiner: with GPT-6 Astra fixed, the no-refiner configuration already achieves 80.00% generation success, and adding Seedance 2.5 refinement raises generation success to 85.00% and repair success from 60.67% to 86.00%.
- On Physics-IQ Verified the default configuration scores 52.06 versus 48.07 for standalone Seedance 2.5, and Claude Opus 5 as backbone achieves the comparison's highest 53.75 despite lower success on the other two benchmarks.
- Refiner choice matters sharply: with the same GPT-6 Astra backbone, H3 and Gemini Omni score 39.10 and 12.08 on Physics-IQ Verified.
- Both PhysLoop and standalone baselines allow up to five repeat calls to the video generation model per task and return one final result.

## Details

### A verification-first harness workflow

The harness wires together a task manager, asset management and scene generation, simulator execution, a verifier, and a video refiner. The agent expands a request into a task specification recording the target event, construction assumptions, and verification conditions, so construction and checking refer to the same contract. Assets come from external search or Meshy when suitable objects are missing, with visual meshes kept separate from physical collision proxies; a low-resolution preview render per camera view catches misplaced objects before full simulation. Only after simulation checks pass does appearance refinement begin, and the refined video is re-verified against the same event requirements, since refinement can alter motion that previously passed.

### Verification and revision

Successful execution alone does not establish that the requested event occurred. The verifier compares simulation states and visual observations with the predefined requirements: for a collision task it checks that contact occurred and that subsequent motion matches the specification, and conservation checks account for external forces, dissipation, and numerical error. On failure it returns a description with supporting evidence, and the agent revises the responsible stage while the task objective and criteria stay fixed. Runs end when all checks pass or the attempt and resource budget is exhausted, with unresolved failures kept in a persistent run record, and users can step in mainly during verification.

### Two applications and measured trade-offs

For training-data construction, task-specific parameters such as release height or initial velocity are varied while other conditions stay fixed, and videos that pass final verification become video-text pairs retaining their generating configurations. For repair, the requirements become an explicit reconstruction task checked against both the simulated event and the refined video, which explains the large repair gap over standalone generators. The human evaluation also exposes an honest trade-off: PhysLoop wins on physics and causal consistency while standalone Seedance 2.5 wins on perceived realism, with the gap concentrated in material appearance and backgrounds, and case studies show baselines failing on event outcomes such as an untoppled vase in a domino chain or extra cue balls on a billiard table.
