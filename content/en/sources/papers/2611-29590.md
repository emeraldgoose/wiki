# KernelShift: Benchmarking Kernel Optimization Across Evolving Hardware

**Source**: [arXiv:2611.29590](https://arxiv.org/abs/2611.29590) · **Published**: 2026-11-22 (v1)
**Authors**: Shuaiwei Huang, Weihua Du, Allen Wu, Ivan Fox, Manupa Karunaratne, Yiming Yang, Sean Welleck

## Overview

AI hardware evolves, and so do the optimization strategies performant code needs — for CPU kernels, the set of architectural extensions is the key moving part. KernelShift studies how well coding agents use new, unfamiliar extensions. It is both a pipeline and an environment: an agent-assisted, human-verified construction pipeline turns real, actively developed repositories (ncnn, llama.cpp, Arm SIMD Loops, KleidiAI) into 99 benchmark kernels, including inference workloads derived from real model executions; the environments give agents a unified interface with feedback from the actual target hardware (Graviton4, Apple M4), with measurement protocols and integrity/correctness checks, and support adding new kernels and hardware as libraries and processors evolve.

Experiments evaluate proprietary and open-weight models across an instruction-set ladder — Neon, SVE, SVE2, SME2 — using Speedup@40 (speedup over the expert reference after a 40-tool-call budget) across fixed-machine ladders and cross-generation task pairs.

## Key points

- Established extensions: every evaluated system beats the -O3 auto-vectorized reference (which is also the agents' starting point) on all four repositories, 2.4-19.8x. Best systems on SVE reach 2.74x the ncnn reference, 1.95x llama.cpp, 1.56x SIMD Loops; even -O3+SVE reaches at most 0.47x of expert references. On six KleidiAI SVE kernels no system matches Arm's hand-tuned vendor kernels in geomean; the best (Claude Code / Claude Opus 4.8) gets 0.70x.
- Adaptation to evolving hardware: incremental extensions (SVE -> SVE2 on 8 SIMD Loops kernels) cost almost nothing (After/Before ratios 0.94-1.05 for all five models; fixed-machine Graviton4 ladder Neon 1.105x / SVE2 1.101x). The SME2 shift (streaming mode + ZA matrix tiles, a programming-model change) is much harder: SME2/SVE ratios drop to 0.42/0.46/0.41 for DeepSeek-V4-Pro, GLM-5.3, GPT-5.6-luna while Claude models hold (1.29/1.03). On Apple M4's 20 KleidiAI SME2 kernels, exposing streaming SVE cuts Speedup@40 from 0.141 (Neon only) to 0.059, full SME2 recovers to 0.085; compile failures rise 13% -> 20% -> 24%; no final SME2 kernel used ZA outer products successfully (ZA written twice, never passing). Case study gemm_bf16_n512_k512: Opus 4.8 used streaming MOPA/ZA accumulation and hit 0.94x of expert, while Sonnet 4.6 / DeepSeek-V4-Pro stayed vector-style at 0.06x/0.05x; of 18 final SME2 solutions only Opus (15) used ZA tiles predominantly.
- Expert headroom drives agent gains: across 79 SVE kernels, median Speedup@40 falls as the expert reference gets stronger vs scalar (Spearman rho = -0.69; -0.75 in llama.cpp). llama.cpp RMSNorm: reference only 1.3x scalar, agents beat it 6.0x median; q4_K_M GEMM/MoE: experts already 25-29x scalar, agents reach only 0.57-0.69x of expert.
- Test-time scaling: most progress within 40 tool calls; Claude Sonnet 4.6 gains 23-25% more at 100 calls than at 40 (mostly a few kernels structurally rewritten between 40-60 calls); curves converge past ~60.
- Ablations (nanobot + GPT-5.6-luna): forbidding SIMD intrinsics collapses 1.074 -> 0.300 (agents' gains come from using intrinsics correctly); Arm docs don't help SVE, on SME2 raise 0.083 -> 0.130 only via fewer compile errors (102 -> 54) with more Neon fallbacks; SME2 pitfall prompts with failure examples double SME2 Speedup@40 (0.083 -> 0.167) but worsen 5/20 kernels; cross-kernel notepad and disassembly tool contribute little (agents rarely disassemble; humans do).
- End-to-end: agent-optimized shape-specialized quantized GEMM kernels (11 for Qwen3.5-4B, 7 for Llama-3.1-8B-Instruct Q4_K_M, Claude Code + Fable 5.1) served via llama.cpp on Graviton4 give 1.30-1.57x prefill and 1.04-1.10x decode over llama.cpp's repacked i8mm fast path across 1-16 threads, perplexity unchanged; all 18 kernels use i8mm with shape-specific tiling/layout/prefetching — deployment-time specialization beats general expert libraries.

## Details

Section 2 describes task construction (kernel + reference + workload construction, validation scripts, human verification, correctness criteria, human-effort accounting in Appendix B), benchmark composition (Appendix A: by source, task sets — 32-kernel subset, SIMD Loops cross-generation, test-time scaling subset, end-to-end kernels; kernel inventory inclusion criteria), and the evaluation environment (hardware-in-the-loop targets in Appendix C: machines, instruction-set ladders, unified agent interface/harnesses/prompts, measurement protocol and integrity, contamination statement in Appendix H). Section 3 covers models/harnesses, task sets, hardware/budgets, and metrics (Speedup@t, fraction of hardware peak in Appendix D). Section 4 reports the results above; Appendix E gives case studies (end-to-end LLM serving regimes; SME2 learning trajectory), Appendix F use of target-specific intrinsics, Appendix G the SIMD class of SME2 kernels on M4.
