# Feedback Shortcut: Speculative Decoding for Latent Feedback Transformers

**Source**: [arXiv:2611.28227](https://arxiv.org/abs/2611.28227) · **Published**: 2026-11-20 (v1)
**Authors**: Benhao Huang, Xuezhe Ma, Hector Liu

## Overview

In a latent feedback Transformer, the input of position t is the token embedding plus a projection of the previous position's top-layer state, u_t = e_t + W·RMSNorm(h_{t-1}). This recurrence makes the model better than a standard Transformer of the same memory cost, but it breaks speculative decoding: verifying a drafted token requires the true top-layer state of its preceding position, so a parallel verification pass can only use an approximate stand-in. Training the model to tolerate stand-ins can lower the exact-decoding quality ceiling, and using stand-ins only at inference adds approximation error on top.

Feedback Shortcut addresses both bottlenecks without touching base model training. First, State alignment trains a lightweight projection P that maps multi-token-prediction (MTP) head states to the stand-ins a_{t+k} fed to drafted positions, using in-place substitution during training (each position's window is extended past it with probability 0.75). Second, Pipelined correction re-evaluates each pending draft with its predecessor's newly computed state — a much closer proxy to true feedback — inside the verification pass of subsequent drafts, so the correction costs zero extra model calls. A draft is committed only when it matches the committed token and its state has been corrected at least D times; the scheme maintains a sliding window of at most (K+1)(D+1) pending positions, so memory and batch size barely change.

## Key points

- Setup: latent feedback Transformers of 135M and 780M parameters with K=3 MTP heads, trained one epoch on Dolma 3 (13.4B tokens at 135M, 77.8B at 780M), three seeds, quality in bits per byte (BPB, lower is better) averaged over seven Paloma subsets; speed is steady-state throughput of a batched serving engine.
- Served quality at batch size 1 (Table 1, D=1): at 135M, the standard Transformer serves Paloma BPB 1.0065 with 2.49x speedup, exact latent feedback reaches 0.9950 (1.10x training FLOPs), and Feedback Shortcut serves 0.9951 at 1.13x FLOPs with 2.36x speedup. At 780M: Transformer 0.8379 / 2.93x, exact feedback 0.8288 (1.17x), Feedback Shortcut 0.8287 at 1.19x FLOPs with 2.75x speedup — within 1e-4 BPB of the exact-decoding ceiling.
- Net effect: 2.4x-2.8x decoding acceleration for only ~2% extra training compute over exact latent feedback, and at large batch sizes skipping correction entirely still preserves Transformer-level speed while retaining over 80% of latent feedback's quality gains.
- The projection P is small: 3.7M parameters at 135M and 14.9M at 780M (hidden widths 2048/4096, RMSNorm without learned scale).
- Single-request timing on 480 Spec-Bench questions (greedy and sampled): every task lies within 0.15x of the greedy speedup over all questions at D=1; measured speedups around 2.40-2.45x at both scales (e.g. 2.45 ± 0.02x at 135M). The Transformer verifies exactly and needs no correction.
- Mechanism detail: corrections iterate the same fixed-point update used in training (u_j = e(x_j) + W·RMSNorm(h_{j-1})); D=0 is verification without correction, D=∞ is exact decoding, and each call still commits at least one token.

## Details

The two failure modes are separated deliberately: State alignment removes the training-time ceiling drop (the base model is never trained on stand-ins; only P is), and Pipelined correction removes the inference-time approximation error by upgrading stand-ins to freshly computed states as soon as they are available, piggybacking on calls that would happen anyway. Appendices cover training/evaluation details, single-request timing and 1,024-token generations, drafting quality vs readability, and the quality actually served by speculative decoding. Code is released at https://github.com/ifm-ai/LoRM.
