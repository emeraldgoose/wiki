# Interpreting Coding Agents Through Their Behavioral Trajectories

**Source**: [arXiv:2611.17440](https://arxiv.org/abs/2611.17440) · **Published**: 2026-11-12
**Authors**: Ibragim Badertdinov, Alexander Golubev

## Overview

Standard coding-agent benchmarks reduce a complex, multi-step interaction to a binary outcome — did the agent resolve the issue and pass the tests — producing a solve rate that ranks systems but says little about how they operate. Two Nebius authors argue that the behavior behind the outcome matters for diagnosing failures and understanding how models and scaffolds differ, and that behavior depends on the entire system, not just the underlying model. Analyzing behavior at scale is hard because execution traces are heterogeneous: different harnesses expose different tools, command formats, and schemas, so direct comparison conflates semantic actions with implementation details.

Their answer is a shared representation: a deterministic, rule-based parser that maps heterogeneous trace events onto a common taxonomy of high-level actions such as repository search, file editing, and test execution. The parser is audited against a six-model consensus reference on 500 sampled events, and applied to 143,209 execution trajectories from SWE-rebench, covering 125 agent configurations and 117 unique models.

The resulting analyses show that solve rate does not uniquely characterize agent behavior, that aggregate behavioral profiles alone identify the deployed stack across disjoint repositories and even programming languages, and that scaffold choice and configured reasoning effort systematically shift how agents explore, modify, and verify code.

## Key points

- Outcome-matched comparisons: across all 60 pairs of configurations sharing the same harness with near-identical solve rates (median |Δsolve| = 0.40 pp, max ≤ 1.0 pp, ≥50 shared tasks), every pair separates on at least two of six workflow metrics under task-paired 95% bootstrap, and 58/60 (96.7%) separate on at least three.
- Null control calibration: simultaneous separation on ≥3 of six workflow metrics occurs in only 0.78% of identical-stack split-half null runs, versus 96.7% for real outcome-matched pairs — the divergence is not run-to-run noise.
- Model generations differ mechanistically: in the Claude Opus lineage, targeted line-range slicing via `sed -n` rises from 6.9% (Opus 4.6) to 57.7% (Opus 5) and quiet test flags (`pytest -q`) from 22.7% to 99.8%; newer GPT models compress action sequences from 24.4 tool operations (GPT-5.4) to 12.8 (GPT-5.6 Sol) while routing 72.1% of recognized edits through inline Python scripts.
- Reasoning effort raises exploration: GPT-5.5 at xHigh versus Medium effort performs 43.4 versus 24.2 tool actions, and Claude Opus 4.8 under Claude Code scales from 31.3 actions (Low) to 54.4 (xHigh).
- Scaffolds shape editing and reading: in the Claude Code stack 92.4% of recognized edits and 90.5% of reads use native APIs, versus heavy shell redirection and inline Python under generic bash harnesses; Codex routes 30.9% of edits through native editing.
- Cross-repository retrieval (413 Python repos split 207/206, 111 stacks, 222 queries) reaches 85.1% Top-1 and 96.8% Top-3 recall against a 0.9% random baseline using an 8-dimensional profile that excludes solve outcomes, token counts, and native tool names; cross-language retrieval across Go, Java, Python, Rust, and TypeScript (16 configurations, 8,880 trajectories) reaches 90.3% Top-1 and 98.8% Top-3 versus 6.25% chance.

## Details

The 8-dimensional profile combines four normalized action coordinates (exploration, file reading, non-test repository writes, formal-test invocations) with four sequential verification features (normalized entropy, tool-switch rate, post-write workspace inspection, unverified termination). The authors are explicit about limits: repository-disjoint splits do not control task composition, so retrieval does not establish task-independent behavioral signatures, and since action composition alone reaches 87.5% Top-1 in the multilingual panel, profiles are interpreted as low-level operational signatures rather than evidence about higher-level reasoning. Appendices document the observable-event codebook, the multi-model consensus audit with fieldwise agreement rates, null-control false positive rates, three paired-task case studies (including workflows that diverge even when both agents succeed in all five rollouts), effort decomposition in Claude Code, and compute resources. The deterministic parser, analysis pipeline, and an annotated trajectory subset are released. This is the v1 (12 November 2026) HF-listed submission.
