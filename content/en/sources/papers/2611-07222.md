# SPILLWAY: Separating Target Admission from Sanitization to Defend Tool-Using Agents against Prompt Injection

**Source**: [huggingface](https://arxiv.org/abs/2611.07222)
**Date**: 2026-11-19

## Overview

Tool-using agents now read and act across email, calendars, file stores, chat, and payment services, usually through standardized interfaces such as the Model Context Protocol. Any tool result the agent reads may carry text written by someone else, so an attacker who plants an instruction in a web page, a shared document, or an email can induce the agent to forward data, pay an account, or invite a stranger — all with the user's authority. This is indirect prompt injection. Many runtime defenses put a language model on the decision that lets an action through, which makes the decision depend on a model that may read the attacker's text and adds model calls to every step; provenance defenses keep the model off the final check but still need a model to plan or route each task first.

SPILLWAY instead reads where an action goes from the tools' typed returns. An email's sender or a payment's account arrives in a typed field, while injected instructions arrive as free text. The paper turns this observation into a deterministic floor with no per-task plan: a call is admitted when every target value that appears in tool output but not in the user's task was returned by a read-only tool in a typed identity field (or is covered by a fixed delegation rule). A deterministic sanitizer strips instruction-like regions its fixed rules match before the model reads them and retains the removed spans as evidence, and a local judge may restore a refused call — never one whose target lies inside the removed text.

Across three backbones and, on one of them, seven task suites, no standard templated injection redirects an action to an attacker's target under SPILLWAY. It does so at the highest observed mean utility and composite scores (NRP, ERS) among the defenses evaluated under that attack, a forged chat template also produces a raw zero, and mean in-scope attack success under a released reinforcement-learning attacker (PISmith) is .005. The floor is reached with no defense-triggered backbone re-run and almost no added model call, giving personal AI agents an auditable refusal floor on where their actions go.

## Key points

- Target admission from typed tool returns, with no per-task routing: the target decision is a set lookup over identities read from typed tool returns before they are serialized for the model.
- Only read-only returns are indexed, and only when a declared field type is an identity format (email, URI, UUID, hostname, IP) or a routing-role field (recipient, sender, participant, channel); bodies, subjects, and descriptions never enter the index, so an attacker-written address in free text stays taint-novel.
- Sanitization coupled to target admission: the two-view judge is the only model allowed to overturn a refusal, and it is never asked about a target the sanitizer removed; without the sanitizer the judge admits an attacker's account, with both, in-scope attack success is zero on every suite.
- Zero in-scope attack success on every backbone-by-suite cell (twelve cells) — the only defense in the grid to do so — at the highest utility under attack of any defense, with no defense-triggered backbone re-run.
- Holds against stronger attacks: a forged chat template (ChatInject) produces a raw zero, and mean in-scope attack success under the released PISmith RL attacker is .005.
- Released as an SDK on PyPI (spillway-guard 1.0.0); an earlier version was accepted at the Third Workshop on Agents in the Wild: Safety, Security, and Beyond (NeurIPS 2026).

## Details

**Method.** SPILLWAY splits the defense into two boundaries joined through evidence. At ingress, a deterministic sanitizer removes forged chat turns and instruction-like regions its three rule groups match before the model reads them, keeping the removed spans (S) as evidence. At egress, the floor admits a side-effecting call when every taint-novel target value (one whose tokens appear in tool output but not in the user's task text, Eq. 1) is in the typed identity index I built from read-only tool returns, is not repeated in untrusted free text, and any principal (grantee) is named in the user's task. Grants and destructive actions are stricter: a member or workspace named only in tool output is refused with no judge override, and a deletion is refused unless the task asks for it. Fixed delegation rules admit targets carrying a name the user wrote, a contact attribute of a named entity, or a resource owned by the user's own account, plus (after the judge) downloads from a domain the user named and repository grant targets outside the removed spans only when the task asks. A refused target outside the removed spans goes to a fail-closed two-view judge (route and payload views, both must pass); a target inside the removed spans never reaches it.

**Results.** On AgentDojo (suite v1.2.2, full user/injection grid) across three backbones (gpt-4o-mini, qwen3-coder:30b, qwen3:8b) and four suites, SPILLWAY drives in-scope attack success to exactly zero in all twelve cells (Table 1), at mean utility under attack of .489 — the highest of any defense — while keeping 99.8% of the undefended agent's benign utility (ROPE with the agent as router keeps 73%). ROPE, the closest defense, leaks on all three Slack cells; MELON, Progent, and DRIFT each leave raw hits in ten, eleven, and seven cells respectively. In the delegated-routing comparison against ROPE with its authors' Claude Opus 4.8 router on seven suites (AgentDyn GitHub/DailyLife/Shopping plus four AgentDojo suites, gpt-4o-mini), SPILLWAY holds zero in-scope attack success on all seven while ROPE leaks on three (DailyLife .010, Shopping .044, Slack .048); SPILLWAY's utility under attack is higher on four suites (e.g. Workspace .848 vs .670) and ROPE with the agent as its own router falls to mean utility .361 and still leaks on Shopping (.072) and Slack (.019). On one backbone without the judge, the floor alone already holds all four suites at zero. Ablations (Table 3) show the judge without the sanitizer opens the only executed leaks, while adding the sanitizer lifts Slack (+.105) and Travel (+.100) utility; with both, mean utility is .370. Cost on qwen3:8b benign traffic: SPILLWAY calls its judge 0.43 and 0.05 times per Workspace/Slack episode (added backbone calls under 0.15), versus MELON +5.29/+3.25, Progent +8.67/+5.94, DRIFT +9.91/+9.59 backbone calls; SPILLWAY episodes run within 0.5 s of undefended, against +4.9/+7.9 s (MELON), +1.6/+2.3 s (Progent), +9.9/+10.5 s (DRIFT). With a 4-bit gemma4:12b judge the qwen3:8b cells also keep zero attack success at mean utility .348 instead of .370. Traces: no standard templated injection redirects an action to an attacker's target; in a 126-pair attacker-as-sender Workspace variant, SPILLWAY, floor-only, Progent, and the PI detector let no attack through. An earlier version was accepted at the Third Workshop on Agents in the Wild (NeurIPS 2026); v2 updates the AgentDojo grid and stress-test results with the released SDK.
