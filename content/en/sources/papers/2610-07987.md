# VisionWeave: Weaving Elastic Visual Representations as a Native Capability of MLLMs

**Source**: Yuan Feng et al., arXiv, 2026-10-06

**Lead**: MLLMs encode visual inputs as dense, fixed-size patch tokens—wasting compute on uniform regions while underserving detail-rich areas. VisionWeave makes elastic visual representation a native, learned capability: a gated spatial pooler builds coarse-grained tokens alongside fine-grained ones in a shared MRoPE coordinate, while a granularity router learns content-adaptive allocation end-to-end via self-distillation.

## Background

Multimodal LLMs (Qwen, LLaVA, etc.) use vision encoders that produce fixed patch grids. Downsampling loses detail; token pruning methods use fixed ratios or heuristics lacking content-adaptive granularity and task generalization. Existing adaptive approaches don't integrate cleanly with modern MLLM architectures or serving engines (SGLang, vLLM).

## VisionWeave Method

Two learned components trained end-to-end on frontier MLLMs (Qwen3.5-4B → Qwen3.8-27B, 30K+ A100 GPU-hours):

1. **Gated Spatial Pooler (GSP)**: Constructs coarse-grained representations *alongside* native fine-grained patches within a shared MRoPE coordinate system. Gating controls pooling granularity per region.
2. **Granularity Router (GR)**: Predicts per-region granularity allocation conditioned on visual content and task. Learns via self-distillation from the unmodified teacher model—no external supervision.

The combined "elastic visual weaving" lets the model decide *where* and *at what granularity* to represent visual information, as a native capability.

## Results

On Qwen3.8-27B across eight benchmarks:
- **Average 43.0% token savings** with **98.9% native performance retention**.
- Token pruning baselines at fixed 50% savings retain only 88% performance.
- Robust across resolutions, video frame budgets, and diverse tasks (VQA, document analysis, video understanding).

Serving on SGLang:
- **2.3× throughput gain**.
- **54.4% lower mean TTFT** (time-to-first-token).
- **60.6% lower mean TPOT** (time-per-output-token).

## Relevance to SW Engineers

- **Serving efficiency**: 2.3× throughput and 50-60% latency reduction directly cut GPU costs for MLLM deployment.
- **Native integration**: Works with MRoPE coordinates and standard serving engines (SGLang)—no custom kernels or pipeline surgery.
- **Adaptive compute**: Token savings adapt to content (detail-rich vs. uniform regions), unlike fixed-ratio pruning.
- **Scalable training**: Self-distillation from teacher enables scaling to 27B+ without human-annotated granularity labels.
