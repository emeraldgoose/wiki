# WeVisCut: The Whole Editing Room in One Agent From Narration to Long-Form Video

**Source**: [arXiv:2610.38352](https://arxiv.org/abs/2610.38352) · **Published**: 2026-10-28
**Authors**: Chenyu Mu, Wenming Weng, Qinrui Wang, Xingsong Ye, Hao Yu, Jun He, Chong Sun, Chen Li, Jing Lyu, Erkun Yang, Cheng Deng

## Overview

Producing long-form videos from narration requires interdependent decisions that remain coherent across shots. Existing agentic editors often use multi-stage workflows driven by general models, leaving unclear the quality-cost trade-off of compact, task-adapted policies. WeVisCut is a long-form script-to-video system that connects tool execution with policy learning. Its agent harness maintains shared production state so tool feedback informs subsequent decisions and repairs. Because finished videos do not expose the decisions behind them, a four-stage data pipeline combines editing inversion with verified replay to turn recovered editing intent into executable supervision. Applied to 3,750 finished videos, the pipeline yields over 130,000 training examples. These examples train a single 9B policy that coordinates production and recovers from failures within the same harness. WeVisCut also introduces a 100-task benchmark and five metrics assessing editing quality and delivery reliability. Under a shared tool environment, WeVisCut substantially outperformed its base model and achieved comparable performance to Claude Opus 5 while using nearly 33x fewer generated tokens per successful output minute. It also outperformed task-matched native editors on the proposed metrics.

## Key points

- The system connects tool execution and policy learning through shared production state.
- Shared state lets feedback inform later decisions and repairs.
- Editing inversion plus verified replay turns finished videos into executable supervision.
- 3,750 videos yielded over 130,000 training examples.
- A single 9B policy coordinates production and recovers from failures.
- A 100-task benchmark with 5 metrics was introduced.
- WeVisCut matched stronger-model performance with nearly 33x fewer tokens.

## Details

The task-adapted 9B policy replaces multi-stage general-model workflows with one model operating inside the same tool harness. Token efficiency comes from recovering editing intent as supervision rather than prompting larger general models at inference time.
