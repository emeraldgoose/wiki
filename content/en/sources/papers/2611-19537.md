# Continuation-Guided LLM Evolution of Program Policies and Goal Compilers in Craftax

**Source**: [huggingface](https://arxiv.org/abs/2611.19537)
**Date**: 2026-11-14

## Overview

Coding agents can synthesize and optimize code-based policies from simulator feedback, producing a program that acts at deployment with zero inference-time model calls. This neuro-symbolic split — expensive search offline, cheap and auditable execution online — runs into two problems on long-horizon tasks: local improvements to a policy can hurt final success, and switching to a new objective normally demands another expensive synthesis run.

This paper proposes a two-stage framework. First, competence is developed by refining the policy through a feedback cascade, moving from coarse episode-level returns to hierarchical goals and belief updates that can be scored densely from simulator state. Second, the competent controller is factored into an environment interpreter (models, memory, skills) and a rule program, and coding agents optimize a reusable goal compiler that maps structured task descriptions into new rule programs.

In Craftax, a partially observed, procedurally generated survival environment, episode-level feedback stalls at under 1% final-level arrival, while the cascade-refined policy reaches the final stage 50% of the time (28% final boss defeats). Across five independent compiler searches trained only on short tasks, the compilers transfer zero-shot to longer tasks with no task-specific tuning and no inference-time LLM calls.

## Key points

- Continuation-scored feedback: edits are judged by how they change the eventual final milestone (the continuation they leave behind), not by whether a subgoal's local completion condition fires.
- Feedback cascade with five regimes (A–E): episode outcomes, per-milestone pass rates, save-state branching from captured snapshots, persistent internal goals, and model audits that score belief accuracy against true simulator state.
- Paired comparisons on the same world/seed cancel world-to-world variance; candidate and incumbent start from identical states or restored snapshots.
- Factorization: the controller is split into an environment interpreter (models, memory, skills) and an editable rule program, enabling a separately optimized goal compiler.
- Reusable goal compiler: maps structured tasks into rule programs; five independent compiler searches trained on short tasks transfer zero-shot to longer tasks.
- Zero inference-time LLM calls at deployment; the artifact is plain executable code.
- Code available at https://github.com/vicgalle/craftax-program-policies.

## Details

**Method.** During development a coding agent edits a program with explicit state, rules, and memory; the deployed artifact is used directly as the policy. Because decision edits (actions) and model edits (internal beliefs) have different effects, they are evaluated separately. Continuation value Q(h,u,b) measures the probability that, after replacing one goal invocation with a candidate sub-program running for τ steps, the incumbent policy from the resulting history still completes the parent goal — terminal success plus an alive-return continuation value. The five feedback regimes instantiate a paired-comparison estimator Δ_F(P′,P) = E_{s~ρ_F}[Y_F(P′⊕_F P, s) − Y_F(P, s)], differing in where comparisons start (fresh resets vs. captured snapshots), how long the candidate acts, and which outcome is measured. Edits are integrated only after verification from fresh resets, and snapshots are recaptured after upstream updates.

**Results.** On Craftax (100,000 actions, eight procedurally generated floors), refinements scored only on episode-level reward stall below 1% arrival at the final level. With the full feedback cascade, the optimized policy reaches the final stage 50% of the time and defeats the final boss in 28% of episodes. Edit effects on reaching the next level are negatively correlated with effects on reaching the final level, motivating continuation scoring. Factoring the controller into interpreter + rule program yields a goal compiler C_θ; across five independent compiler searches trained only on short tasks, the compilers transfer zero-shot to longer tasks without task-specific tuning or inference-time LLM calls.
