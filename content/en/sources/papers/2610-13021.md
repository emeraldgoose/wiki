# EmbodiedCLBench: Evaluating Continual Learning for Self-Evolving Embodied Agents

**Source**: Huang et al., arXiv, 2026-10-09

**Lead**: Continual learning — accumulating past experience and transferring it to new tasks — has almost no embodied benchmark. EmbodiedCLBench fills the gap by framing continual learning as compositional generalization: agents learn basic household tasks, then must recombine those skills on unseen advanced tasks. Across four agent harnesses, basic-task experience consistently triples advanced-task success, but piling on more learning samples yields no further gain.

## Background

Self-evolving agents promise to improve without human supervision, yet continual-learning benchmarks live in knowledge, web, or symbolic domains, while embodied benchmarks test perception, navigation, or manipulation without a learning-over-time dimension. EmbodiedCLBench combines both: the TongSim household simulator (rich object/action space, low data-contamination risk) with a protocol where basic tasks serve as test-time learning data for advanced tasks.

## Benchmark Construction

Four stages — environment setup (TongSim), task generation, graph construction, evaluation protocol:

- **Three compositional levels**: atomic actions (single object interactions, 3 steps each) → basic tasks (2 atomic actions, 6-step shortest path, 6 household categories, 168 tasks) → advanced tasks (4 atomic actions drawn from 2–4 basic categories, 12-step shortest path, 100 tasks).
- **Offline state-transition graphs**: each node is an environment state with a first-person image and action candidates (optimal / suboptimal-but-executable / invalid); edges are deterministic transitions, with distractor paths branching off the BFS shortest path. Fully reproducible, no live simulator needed.
- **Evaluation protocol**: learning phase (complete basic tasks, +6 extra-step tolerance) then testing phase (attempt unseen advanced tasks with that experience, +3 extra steps). Per-step action-type labels enable fine-grained error analysis.

## Experiments

**Setup**: Three settings — Zero-shot, In-Context Learning (full basic-task trajectories retained), Skill Learning (concise Markdown skill summary instead of trajectories). Four harnesses (OpenClaw, Claude Code, Codex, Hermes) × two backbones (Qwen3.8-Flash, GPT5.6-Terra). Metric: success rate within step budget.

**Benchmarks**: 168 basic + 100 advanced tasks, plus extended 3–6 atomic-action advanced tasks for complexity analysis.

**Results**:

| Harness / Model | Basic (zero-shot) | Advanced zero-shot | + ICL | + Skill Learning |
|---|---|---|---|---|
| Hermes / Qwen3.8-Flash | 58.9% | 8.0% | 44.0% | 33.0% |
| Codex / GPT5.6-Terra | 54.8% | 11.0% | 52.0% | 26.0% |
| OpenClaw / Qwen3.8-Flash | 50.6% | 5.0% | 35.0% | 38.0% |
| Claude Code / Qwen3.8-Flash | 42.9% | 3.0% | 27.0% | 31.0% |

Key findings: (1) experience transfers — advanced success jumps from ~10% to 30%+ everywhere; (2) the gain over zero-shot stays ~30 pts as complexity grows from 3 to 6 atomic actions; (3) **no sample scaling** — one basic task gives nearly all the gain (8–10% → 28–40%), and k=2…6 fluctuates flatly; (4) experience shifts decisions from invalid (−13–20%) toward optimal actions; (5) the ICL-vs-Skill ranking holds across step budgets.

## Relevance to Software Engineers

- **Memory-design signal**: one good prior episode beats many mediocre ones — invest in retrieval/selection of the single most relevant experience, not in stuffing context with more trajectories.
- **Compact skill summaries match raw trajectories** on success rate with smaller decision shifts — prefer summarized memory for serving cost unless you need the behavioral nudge of full traces.
- **Offline graph evaluation**: compiling simulator tasks into deterministic state graphs gives parallel, reproducible agent evals without flaky live environments — a pattern worth copying for any stateful-agent benchmark.
- **Action-type instrumentation** (optimal/suboptimal/invalid) turns a pass/fail metric into a diagnostic of what memory actually changes — cheap to add, high debugging value.
