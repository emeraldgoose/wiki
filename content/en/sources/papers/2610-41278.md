# AuditFL: A Contract-Backed Clearing Layer for Open Federated Learning

**Source**: [arXiv:2610.41278](https://arxiv.org/abs/2610.41278) · **Published**: 2026-10-27
**Authors**: Alexandros Balla, Spyros Lalis

## Overview

Federated learning keeps raw data local, but many deployments still rely on a trusted coordinator for admission, checkpoint distribution, update collection, aggregation, and rewards. AuditFL is a contract-backed clearing layer designed for auditable federated learning in open settings.

It uses a ledger to order and validate small state transitions, while keeping model bytes in distributed off-chain storage referenced by content identifiers. A task coordinator holds the trusted authority for defining rounds and aggregating weights, while the chain records accountable admission, deposit, termination, and reward operations.

## Key points

- Targets open federated learning with weak trust assumptions.
- Uses a contract-backed ledger for small state transitions.
- Keeps model bytes off-chain in content-addressed storage.
- Delegates authority to a trusted task coordinator for rounds and aggregation.
- Records auditable admission, deposits, termination, and rewards on chain.
- Positions itself above naive blockchain designs that are insufficient for FL.
- Aims to clarify consensus assumptions and round-level state-machine details.

## Details

Federated learning is useful when data movement is expensive, sensitive, or restricted. AuditFL adapts open FL for settings where clients may join without strong bootstrap guarantees.

The design distinguishes ledger state transitions from large model artifacts, so the chain records order and validation while storage handles bulky data. This makes auditability practical without forcing all model bytes through a blockchain.
