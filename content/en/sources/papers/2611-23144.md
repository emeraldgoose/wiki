# π^4: A Foundation Model for 4D Scene Geometry and Motion

**Source**: [arXiv](https://arxiv.org/abs/2611.23144)
**Published**: 2026-11-17

## Overview

π^4 is a unified foundation model for 4D scene perception. From diverse, uncalibrated RGB observations in the wild — a single image, an unordered collection, or a video sequence — it recovers dense geometry, camera poses and metric scale, together with 2D/3D point tracks and moving-object masks for multi-image inputs. It couples a geometry branch with a geometry-conditioned motion branch that predicts image-space correspondences, lifted into 3D using the reconstructed target-view geometry.

Across diverse benchmarks, π^4 achieves the best overall average rank in geometry evaluation, with competitive performance in single- and multiview 2D/3D point tracking and moving-object segmentation. With a shared backbone, the full geometry-and-motion system contains approximately 0.5B parameters — less than half the size of most baselines. It produces joint reconstructions and tracks in one forward pass, even for large-scale scenes with thousands of input images, despite training with contexts of at most 64 views.

## Key points

- Best overall average rank across the geometry benchmarks in Table 2; competitive single-/multiview 2D/3D tracking and moving-object segmentation (Figure 2); joint geometry + motion in a single forward pass, including scenes with 1,000+ input images at training context ≤ 64 views.
- ~0.5B parameters total, under half the size of most baselines; π³-style permutation-equivariant geometry (no reference view); looped Transformer decoding for both branches (cross-benchmark performance, parameter efficiency, memory savings for longer contexts).
- Geometry-conditioned motion: the geometry network is frozen and a separate motion decoder predicts image-space correspondences, lifted analytically to 3D using the reconstructed target-view surface — a scale-independent objective that places every visible 3D track point on the reconstructed surface.
- Data engineering: scene-level renders from Funes/Sketchfab with coverage-aware view selection and connected chains; complementary natural/counterbias cameras (roll, focal length); FOV/lens augmentation; foreground-suppressed pseudo-labeling for Internet videos; GameRealm engine-native supervision for dynamic scenes.
- Training: stochastic view-count sampling from single images, 2–24-view sets and 32/48/64-view sets with short contexts dominating; sparse 3D refiner improves local surface detail.

## Details

- Architecture: shared image encoder; looped Transformer geometry branch (permutation-equivariant, no reference view); separate motion decoder trained on frozen geometry features; sparse 3D convolution refiner; geometry-conditioned motion decoding (image-space correspondences composed with reconstructed geometry).
- Training protocol: view-count curriculum, loss weighting for relative-point supervision, camera-readout gradient routing (Appendix/Sec. 6); training data mixture includes GAME-style GameRealm supervision; full data curation pipeline documented in Sec. 4.
