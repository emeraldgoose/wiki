# WeightCode: Installing New Capabilities into Neural Networks via Weight-Space Programming

**Source**: [arXiv:2611.25476](https://arxiv.org/abs/2611.25476) · **Published**: 2026-11-19 (v1)
**Authors**: Bo Li, Taoyong Cui, Bob Zhang, Mengran Li, Chengyang Zhang, Yang Zhang, Pheng Ann Heng, Wanli Ouyang, Zhenfei Yin, Yingcheng Wu, Ling Yang

## Overview

Neural networks store capabilities in their weights, but extending them with explicit task knowledge remains hard. Weight-Space Programming (WSP) is the paradigm where executable programs read, construct, or modify a network's weights directly. WeightCode, a WSP framework, uses a frozen language model to write executable weight programs that install new computations into a trained network from task knowledge plus the network's existing weights — no gradient-based training, and once installed the capability runs without the LLM.

On robot-style command following, weight programs given a grammar or eight demonstrations enable previously unseen command compositions (0% → 99.8% exact match) and a new pickup action (0% → 98.4% success), while preserving original command and navigation capabilities. On ImageNet, four weight programs — two for Gaussian noise, two for contrast reduction, each with only 64 labeled corrupted + 64 labeled clean examples, matched checks, and retention constraints — reach net gains of +8.84 to +17.62 points while keeping clean accuracy within 0.89 points on ImageNetV2, beating the best of eight fine-tuning methods (+8.67/+3.38) and fixed references; on CIFAR-10 ViT-Lite the first programs reach +32.79/+16.51 vs +22.78/+7.89 for the best fine-tuning.

Causal interventions in a Vision Transformer show the installed noise-correction gates drive the robustness gains (the gate opens on noisy, not clean, inputs) while selective activation preserves clean accuracy. Re-running the same programs on five independently trained ViTs without further LLM calls constructs network-specific edits: ten programs retain 83–110% of their source-network gains on average (Gaussian-noise program +27.55 to +30.54, mean +28.57, clean change −0.19 to +0.07), whereas copying fixed weight edits yields negligible gains. Six programs written for an already-edited network add +5.23 to +14.50 points of contrast robustness on top of the previously installed noise gain — showing capabilities can be accumulated through reusable weight programs.

## Key points

- WSP paradigm: executable programs directly read/modify network weights; WeightCode's frozen LLM writes these weight programs from task knowledge + existing weights, no gradients; installed capabilities run standalone.
- Command following: grammar or 8 demos → unseen command compositions 0%→99.8% exact match, new pickup action 0%→98.4% success, original capabilities preserved.
- ImageNet robustness: 4 weight programs (64 labeled corrupted + 64 clean per corruption) net +8.84 to +17.62 points (Gaussian +10.47/+17.62, contrast +8.84/+14.26) vs best fine-tuning +8.67/+3.38, clean accuracy within 0.89 points on ImageNetV2; CIFAR-10 ViT-Lite +32.79/+16.51 vs +22.78/+7.89.
- Mechanistic: causal interventions identify an installed gate in existing MLP units that opens on noisy inputs and removes the noise shift; selective activation keeps clean accuracy.
- Transfer: same program re-executed on five independently trained ViTs (each with its own 64 examples, no new LLM calls) keeps 83–110% of gains; fixed weight edits copied across networks give negligible gains — the program, not the patch, is what transfers.
- Composition: six new programs on an already-edited network add +5.23 to +14.50 points of contrast robustness while retaining the noise gain — capabilities accumulate via reusable weight programs.

## Details

Experimental protocol controls for examples, checks, and retention: every method gets the same 64 labeled corrupted and 64 labeled clean images, 8 checks, and a retention rule. The correction construction does not need condition labels — network predictions, image statistics, and labeled check feedback suffice. Ablations (Tab. 10) show the gated computation, more than the choice of units, is the source of the gain. Baselines include eight fine-tuning methods and fixed references under matched constraints. Code is released.
