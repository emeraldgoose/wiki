# GameAnything: From Any Inspirations to Playable Game Worlds

**Source**: [arXiv:2611.29238](https://arxiv.org/abs/2611.29238) · **Published**: 2026-11-22 (v1)
**Authors**: Wenyi Wu, Siqi Liu, Yuru Feng, Zixuan Song, Aayush Salvi, Sibo Zhu, Kun Zhou, Biwei Huang

## Overview

AI-driven game development usually starts from explicit specifications or design documents, but real game ideas come from novels, photographs, films, gameplay videos, and personal experiences. Existing systems and benchmarks largely ignore adapting such multimodal references into playable content, and evaluate with scripted action replay and runtime probes rather than actual gameplay experience. GameAnything is an open-source agentic platform that closes this gap: given multimodal references R, a user instruction I, and a game project P_t, a coding agent iteratively updates the project (Δ_t ~ π_builder(· | R, I, P_t, S_t, M); P_{t+1} = Apply(P_t, Δ_t)). Two complementary processes make the loop work: (1) within each task, autonomous playtesting and verification — the builder launches the updated project, collects a gameplay trace τ_t, and an independent playtester verifies it against the instruction and references (v_t), updating a persistent development state S_t = (Q, σ_t, E_t, K_t) that tracks each requirement as todo/partial/done/broken/regressed, stores evidence, and keeps a recheck list of regressed items; (2) across tasks, a cross-task experience memory M that extracts lessons (observed issue, cause, corrective action, evidence) from completed cycles, consolidates similar ones, promotes reproduced candidates to confirmed lessons, and retrieves the relevant ones under a fixed context budget B before each round. A local web interface lets users supply references and goals, answer interactive design cards, and give frame/region-level feedback that is converted into verifiable requirements.

To evaluate this setting, the authors introduce GameAnything-Bench: 205 tasks across 14 target games — 125 Construction tasks (create new playable content in an existing game from references) and 80 Editing tasks (modify existing content while preserving unrelated systems) — spanning four input modalities (text, image, video, hybrid) and three adaptation categories (Scene & World, Mechanics & Behavior, Narrative & Event). The open-source core has 77 Construction tasks over nine games and 64 Editing tasks over six; a separate commercial track has 48 Construction tasks over five games and 16 Editing over two. References are curated from fiction, photos, manga, film clips, sports footage, gameplay recordings, travel videos; videos are deduplicated into timestamped clips/keyframes/transcripts and annotated in two independent passes grounded in evidence. Tasks are built rubric-first: rubrics for content, functionality, visual presentation, and host fidelity are cross-reviewed by models and revised by humans, then grouped into instructions. Evaluation is independent of the agents: Claude Sonnet 5.5 judges replay verification, playtest verification, visual assessment, and adjudication; each submission passes executability probes (3 per game), then action replay plus independent agentic playtesting (40 actions / 30 min).

## Key points

- Main results (Table 2, nine native coding-agent configurations, one autonomous 120-minute attempt each): Claude Fable 5.2 (Claude Code) leads with Construction Overall 84.1 and Editing Overall 86.5 at $5.96/$1.63 per task; second-best Construction is Claude Sonnet 5.5 at 59.2, and five of nine agents score below 40 Construction Overall. Content scores exceed Functions & Playability scores for every agent — creating requested content is easier than making it actually playable.
- Editing: Preservation exceeds 94 across all nine agents (62.6–87.4 Edit Success), so the hard part is realizing the requested change precisely, not avoiding damage. Behavior & Flow edits are hardest: lowest Edit Success (66.3 vs 73.3 Appearance, 73.0 Content & Structure) and highest collateral damage (14.3% vs 2.1%); Content & Structure edits keep Edit Success but drop Preservation to 94.5 (from 98.7 for Appearance).
- Iterative refinement works but varies by agent: one extra round (critic feedback on gameplay replay + 60 min revision with retrieved lessons) raises both Construction and Editing for all eight evaluated configurations, 11 of 16 gains statistically significant (95% bootstrap CI excludes 0); three rounds add 7.6–14.8 Construction points for selected agents — e.g., Qwen3.8-Flash gains only 0.8 after round 1 but 14.8 after three. Cost-efficiency caveat: DeepSeek V4.1 Flash reaches 59.1 after three rounds at $1.72/task, approaching native Claude Sonnet 5.5 (59.2, $1.84), but Qwen3.8-Flash reaches only 50.0 at $1.90 — refinement gains do not always beat starting with a stronger agent.
- Multimodal references matter: removing references (instructions kept) drops Claude Sonnet 5.5's Overall by 7.1 points, concentrated in Visual & Presentation (-14.9); Functions & Playability is unchanged. Image references give the highest mean Construction score and are best for 7 of 9 agents, but Kimi K3 peaks on hybrid and Qwen3.8-Max on video; Qwen models do relatively better on Mechanics & Behavior while Claude Sonnet 5.5 and DeepSeek V4.1 Flash peak on Narrative & Event.
- Protocol details: agents use native harnesses (Claude Code, Codex CLI, OpenCode) with default prompts/tools, identical instructions and initial state; evaluation uses executability gates (3 probes/game), action replay, and independent playtesting limited to 40 actions/30 min; 95% CIs from 4,000 paired bootstrap resamples; three independent evaluations on 47 submissions assess scoring stability; reported costs exclude evaluation.

## Details

GameAnything's builder loop (Eq. 3–6): each round the builder revises the project per the state, launches it, collects trace τ_t; the independent playtester produces verification v_t identifying verified requirements, remaining issues, and regressions (previously satisfied requirements that fail later are marked regressed and put on the recheck list); the state updates and guides the next round until requirements are verified or the budget is exhausted. Experience memory (Eq. 7–8): lessons L_j = Extract(H_j) are consolidated into M (similar lessons merged; a candidate reproduced by a later task is promoted to confirmed); retrieval selects confirmed lessons first, then candidates by relevance to the target game G, agent role ρ, and current state S_t, capped at budget B, and logs which lessons were retrieved and applied each round. Platform: modular game adapters expose build/install/launch/interact interfaces for heterogeneous engines; supported agents include Claude Code, Codex, Gemini CLI, and OpenCode. Appendices detail benchmark construction (game selection incl. commercial track criteria, reference annotation, rubric-first task construction, QC on unmodified and deliberately corrupted game instances), evaluation protocol (capability probes, executability gate, adjudication, scoring aggregation), agent configurations, per-game results, refinement tables, and evaluation reliability (agreement with human judgments, evidence ablation, stability across playtest budgets, judges from other model families). Code: github.com/AetherLabsAI/GameAnything; benchmark: github.com/AetherLabsAI/GameAnything-Bench; space: huggingface.co/spaces/GameAnything/GameAnything.
