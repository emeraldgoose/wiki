# 3AGameFactory-Motion: Agentic Rigging and Reliable Complex Motion Generation for Diverse 3D Assets

**Source**: [arXiv:2611.30013](https://arxiv.org/abs/2611.30013) · **Published**: 2026-11-23 (v1)
**Authors**: Bohan Zeng, Kaixin Zhu, Yifan Yang, Dongge Yu, Zihao Wu, Yifan Dai, Zhou Liu, Junbo Niu, Xiaochen Ma, Shiran Ge, Zimeng Meng, Junzhu Liang, Huanyao Zhang, Jinhang Liu, Tianqi Xiao, Jinhao Zhang, Tianyi Bai, Zhixiong Zeng, Penghao Zhao, Yuanbo Peng, Key Zhang, Wentao Zhang

## Overview

Animating arbitrary 3D assets from instructions like "raise the left wing to 60 degrees within two seconds, flap three times, then glide and land" requires both structural inference (rigging) and fine-grained motion control, yet existing motion benchmarks mostly cover conventional human/animal skeletons with simple instructions. The authors introduce DivDynBench — 50 assets across six morphology categories (humanoid, multiped, axial, winged, mixed-limb, mechanical) with 428 text and 422 numeric instructions forming 850 motion tasks that demand multi-phase part coordination and explicit timing, angle, repetition, and trajectory constraints. Evaluation separates textual semantic compliance from program-verified numeric accuracy, plus phase completeness, morphology fit, and animation quality (0–100 scale).

On this benchmark they systematically compare three LLM-based paradigms: (1) LLM + specialized motion generator (cheap and natural, but bound to the generator's skeleton and coarse semantics, no fine control); (2) LLM + video generation + motion recovery (strong visual priors, but expensive, human-centric recovery, and timing/amplitude lost); (3) direct LLM motion generation (adapts to arbitrary structures with fine-grained control, but frame-by-frame joint outputs are token-hungry and lack kinematic constraints, causing interpenetration). The comparison favors direct agent-driven generation for adaptability and control, so the authors propose an Agentic Motion Framework: the agent writes a compact parametric program — duration/frame rate, phase windows and key events, root control, and per-part joint chains with operators, motion parameters, and contact windows — and a deterministic executor performs rigging, IK/FK kinematic solving, and mesh-feedback correction of penetration, contact errors, and end-effector deviation.

## Key points

- Agentic rigging: the agent labels joints in the calibrated view where each part is clearest, the executor fuses multi-view labels into a 3D skeleton following the asset's actual morphology (no fixed template), computes distance-based skinning weights smoothed in geodesically gated neighborhoods, and validates with probe deformations. On the nine-tailed fox, specialized methods leave most tails unrigged and direct LLM rigs place chains outside the mesh, while the framework grows one chain per tail; on a door it places the main bone along the hinge edge. Gains in Source Fidelity, J2J, mIoU, and joint validity without worse Edge p99/Rigid RMS.
- Motion program: P = (T, f, H, K, R0, {Pp}, ξ) — phase windows with eased control curves, repetition counts, root operator, and per-part (chain, operator, parameters, contact windows). An end-effector operator bends a whole chain by one scalar distributed over per-joint weights, so arbitrarily long chains (tails, tentacles) are shaped via end-effector trajectories; bone lengths never change and unreachable targets stay within joint limits with the residual passed to refinement.
- Motion results on DivDynBench: specialized generators and video-recovery rarely satisfy ordered phases and numeric targets; on the humanoid subset MoMask and video-recovery score below 26 overall, agent-guided MotionBricks (structured IK targets) reaches 49.09, and the same agent + Agentic Motion Framework reaches 57.27 — supporting arbitrary skeletons plus explicit phase timing. Example: a 2.2 s left-punch/right-punch/spinning-back-kick sequence is completed in order with the framework but dropped phases without it.
- Cost: direct LLM generation is already economical, and the framework lowers its cost further because the agent writes only a small set of semantic parameters instead of frame-by-frame joint values.
- User study: 30 volunteers rate Semantic/Completeness/Morphology/Aesthetics for three methods; ratings follow the same trend and ranking as the GPT-6.1-based rubric scores, validating the automated scoring.
- Evaluation hygiene: rigging is scored programmatically on raw meshes against manual ground truth; motion is evaluated on a provided reference rig so scores reflect instruction following alone; generation sees only the source asset, instruction, and reference rig; invalid cases count as zero in the per-case weighted Overall.

## Details

Rigging metrics include Source Fidelity (mesh preservation — SkinTokens/UniRig/RigAnything process the input mesh and lose it, Puppeteer keeps it but trails on J2J/mIoU/joint validity), joint-to-joint error, mIoU, joint validity, Edge p99, and Rigid RMS. Motion metrics (morphology fit, penetration, foot sliding, deformation) are computed on the skinned mesh; results export as animated GLB rendered from fixed views. Baseline agents: GPT-6.1-sol and Claude-ops5.5 with and without the framework under the same setup and comparable turn counts; humanoid-only methods (MoMask, MotionBricks, DuoMo recovery) compared separately on the humanoid subset. Related: 3AGameFactory open-source framework (github.com/OpenDCAI/GameFactory-3A).
