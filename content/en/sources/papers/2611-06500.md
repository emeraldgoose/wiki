# Tools Need Not Speak in Text: Latent Context Compression for Agents

**Source**: [arXiv:2611.06500](https://arxiv.org/abs/2611.06500) · **Published**: 2026-11-04
**Authors**: Yuetong Liu, Zhehao Zhou, Yitong Zhang, Haorui Chen, Jia Li

## Overview

Agents that follow the ReAct pattern append every raw tool output to their context, so long and noisy observations accumulate across steps. The paper measures the cost of that habit: tool returns grow to 96.7% of the agent's total tokens by the fourth step, and a single observation may only need one fragment to drive the next decision, for example a driver's name that prompts a search for his birth year while the rest of the race report is irrelevant. Redundant observations therefore both inflate computational cost and dilute attention on decision-critical evidence.

Existing remedies stay inside text. Token pruning uses a model to delete low-information tokens, and text summarization uses an auxiliary LLM to condense observations or interaction history. The authors argue this approach is bounded by construction: because the compressed result must remain a coherent sequence of discrete tokens, the achievable compression ratio is inherently limited. They instead question the premise that tool observations must be expressed as text at all, noting that those observations exist to support the agent's next reasoning step and action. Continuous latent tokens, high-dimensional vectors in the embedding space, offer a more flexible carrier: compact under a small token budget and differentiable, so they can be optimized directly against the downstream objective.

The proposed model, Coca-Cola (Context Compression via Continuous Latent Tokens), is conditioned on the task instruction and the agent's current-step reasoning trajectory and compresses a long tool observation into a few latent tokens that are mapped into the agent's input embedding space. Two design problems follow. Making the compressed representation usable by the target agent is handled by a context-aware encoder with a latent adapter that maps it into that agent's embedding space, and preserving decision-critical information under a tight budget is handled by Action-Preserving Training, which aligns the agent's next-action distributions under full and compressed observations so the compressor learns action-sufficient latent tokens. Across two model configurations and four web-search QA benchmarks, Coca-Cola reduces token consumption by 70.01%-89.24% and end-to-end runtime by 24.45%-55.97% relative to an uncompressed agent, while improving task performance and posting the best EM and F1 in six of the eight model-dataset settings.

## Key points

- Coca-Cola represents tool observations as continuous latent tokens and embeds them into the agent's input embedding space instead of appending text.
- Action-Preserving Training minimizes the difference between next-action distributions under full and compressed observations, so the latents stay sufficient for the decision.
- Compression is conditioned on the task instruction and the current reasoning trajectory through a context-aware encoder plus a latent adapter.
- The result is a 70.01%-89.24% drop in token consumption and a 24.45%-55.97% drop in end-to-end runtime versus the uncompressed agent.
- Accuracy moves in the right direction: Coca-Cola beats the uncompressed agent on EM and F1 and takes the best score in six of eight model-dataset settings.
- Without compression, tool observations reach 96.7% of agent context by step four, which motivates compressing observations rather than whole histories.
- The authors claim the first treatment of tool outputs as latent tokens rather than discrete text, reframing tool-agent communication as an information transfer problem.

## Details

The evaluation targets web-search agents, where a search call returns long documents and snippets that are easy to compress away but often contain one decisive clue. The authors compare Coca-Cola against the uncompressed agent and against text-level compression, and they measure both efficiency, in token consumption and end-to-end runtime, and effectiveness, in exact match and F1 on four question-answering benchmarks. The efficiency gains hold across both model families tested, so the approach is not tied to a single base model.

Training happens on the agent's own decision problem rather than on a reconstruction objective. By aligning the next-action distributions computed from full and compressed observations, the compressor is pushed to preserve whatever changes the agent's next tool call or final answer, which is the paper's explanation for why aggressive compression does not cost accuracy. The reported accuracy gains over the uncompressed agent are framed as a side effect of the mechanism: removing redundant observation text keeps the model's attention on the evidence that matters.

The paper positions latent tokens as an emerging substrate for agent information flow, alongside prior work that uses them for reasoning, inter-agent communication and memory. Its contribution is to point those ideas at the tool-agent boundary. Limitations are not central to the paper, and the released code at the project repository allows the reported setup to be reproduced.
