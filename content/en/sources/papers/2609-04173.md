# Last Translation Benchmark

Source: Vilém Zouhar and 259 other authors, arXiv:2609.04173, Sep 3, 2026 (v2 Sep 29, 2026). Typeset in Typst.

**Lead**: Machine translation evaluation is stuck: standard benchmarks approach saturation as models get stronger, automatic metrics are unreliable, opaque, and hackable — and even gold human evaluation lacks reproducibility and scale. The **Last Translation Benchmark (LTB)** answers with a community collection of **human-authored, peer-reviewed examples (texts, images, audio, videos) that break leading MT models**, where every example ships with **handcrafted verification rules** describing its concrete failure cases. It is a **live dataset** accepting ongoing contributions; **LTBv1** contains contributions accepted before September 1, 2026.

## Why breaking examples plus rules

The design pairs two ideas. First, examples are adversarial by construction — contributed specifically because they defeat current state-of-the-art systems, so the benchmark tests the capability frontier rather than the saturated middle. Multimodal inputs (image, audio, video) extend this beyond text-only translation. Second, each example carries hand-written verification rules for its known failure modes, making future evaluation **reliable** (rule-checked, not metric-guessed) and **actionable** (a failure names the concrete case, pointing at the fix).

## A live benchmark, not a frozen snapshot

Unlike static releases that decay as models memorize or surpass them, LTB is versioned and continuously collected, with LTBv1 as the first cut and future releases planned. The 260-author list reflects the community-contribution model: progress tracking becomes a shared, ongoing process rather than a one-time release.

## Caveats

This summary is abstract-based: the paper has no arXiv HTML version (Typst source, PDF only), so per-example statistics, rule schema details, and LTBv1 size/composition figures are not verified here. Adversarial community benchmarks risk coverage skew toward contributors' languages and pet phenomena, and handcrafted rules need maintenance as models change failure modes. Check the project repository for the current LTBv1 contents before citing numbers.

## Relevance to SW engineers

- If you ship MT features, saturating BLEU/COMET scores hide frontier failures — an adversarial, rule-verified suite complements aggregate metrics.
- Per-example verification rules are a portable pattern: encode known failure cases as executable checks alongside any eval set, so regressions name themselves.
- Live versioned benchmarks beat frozen ones for tracking fast-moving models; pin the version (e.g. LTBv1) in your reports.
- Peer review on contributions is a quality gate worth copying for internal eval sets.
