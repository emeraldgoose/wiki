# ProgramGym: Scaling Training Environments for Long-Horizon Program Reproduction Agents

**Source**: Yang et al., arXiv, 2026-10-09

**Lead**: Coding agents mostly patch given repos (SWE-bench) or implement from requirement docs—never discovering *what* to build and *how* to design it, as engineers working from scratch do. Program reproduction (rebuild a program's observable behavior from its binary + docs, no source or network) tests exactly that, but verifiable training environments are scarce and single-session agents lose early evidence over long horizons. ProgramGym answers with Program-Env, a feedback-driven pipeline producing 1,648 verified environments (C/C++/Go/Rust), and Program-Agent, a role-isolated analysis→implementation→review loop with revision management. Fine-tuning Qwen3.8-27B on its trajectories raises ProgramBench Tests Passed from 34.87% to 42.84%; Program-Agent raises base and SFT models to 55.71% and 56.25%, beating flagship models.

## Background

Issue-resolution and NL-to-repo tasks hand the agent a codebase or a spec, reducing the job to localized edits or implementation. ProgramBench-style reproduction removes the scaffold: only an execute-only reference binary, docs, and a network-isolated sandbox are given, and black-box tests compare candidate vs. reference behavior on shared inputs. Prior resources (SWE-Gym, SWE-smith) supervise edits, not from-scratch builds; MindForge is CLI-only and leaves supervision unverifiable; no flagship model fully solved any of the 200 original ProgramBench tasks. Two gaps result: (1) building reference executables + discriminative black-box tests across diverse toolchains at scale, and (2) sustaining coordinated explore-then-build development over horizons exceeding single-session context.

## Program-Env: Feedback-Driven Environment Construction

From 30,459 GitHub candidates (language/star-stratified, commit-locked, build-config-screened), three stages run on Claude Code/Codex harnesses with outer validation loops:

1. **Executable + sandbox**: the agent writes `download.sh` (online deps) and `compile.sh` (offline build); the loop advances only when both succeed and the binary passes a loadability check, else diagnostics return for repair.
2. **Dispatch**: modules are split across parallel branches by codebase size, coverage instrumented, docs extracted.
3. **Black-box tests**: each branch iterates with three feedback documents (summary, program-analysis-guided uncovered targets, validation screens)—pass, double-run consistency, dummy-implementation rejection, and weak-assertion checks; only tests passing all checks survive merging.

Result: 1,648 environments, mean coverage 72.99% (median 81.63%), 665,512 validated test cases (~404/repo), ~83M tokens construction cost each on average.

## Program-Agent: Role-Isolated Long-Horizon Workflow

Three stages run in independent sessions (no shared history, only handoff artifacts) to stop context contamination: **Analysis** explores docs + reference binary and freezes `analysis.md` read-only; **Implement** builds from handoffs without touching the reference (baseline first, then incremental fixes); **Review** diffs candidate vs. reference behavior into actionable requirements. **Revision management** compiles clean snapshots outside the workspace, archives passing ones, retries failed stages in fresh sessions within budget, and rolls back to the last validated revision. With $K = 5$ rounds, Tests Passed rises 43.49% ($K{=}1$) → 54.13% ($K{=}3$) → 56.25% ($K{=}5$), most gains by $K{=}3$.

## Experiments

**Setup**: ProgramBench; baselines Claude Code (single-session, context compression) vs. Program-Agent ($K = 5$); models DeepSeek-V4-Flash-0731, Qwen3.8-27B base, Qwen3.8-27B-SFT (ms-swift fine-tune on rejection-sampled trajectories); isolated containers (8 CPU, 16 GB, 8h limit). Metrics: % Tests Passed (macro avg), % Almost Resolved (≥95%), % Resolved (100%, no cheating).

**Benchmarks**: ProgramBench program-reproduction tasks; frontier models under mini-SWE-agent as reference points.

**Results**:

| Model | Scaffold | Tests Passed | vs. base |
|-------|----------|-------------|----------|
| Qwen3.8-27B | Claude Code | 34.87% | — |
| Qwen3.8-27B-SFT | Claude Code | 42.84% | +7.97 (training effect) |
| Qwen3.8-27B | Program-Agent | 55.71% | +20.84 (scaffold effect) |
| Qwen3.8-27B-SFT | Program-Agent | **56.25%** | +21.38 |
| Claude Opus 4.7 / Gemini 3.5 Flash (mini-SWE-agent) | — | 50.90% / 53.60% | beaten by both Program-Agent runs |
| DS-V4-Flash-0731 | Claude Code → Program-Agent | 57.68% → 58.97% | +1.29 |

Behavior analysis: Program-Agent shifts action mix toward read/git (exploration + revision), especially after SFT; yet % Resolved stays ~0% everywhere—full reproduction remains unsolved, and SFT alone even drops Almost Resolved (3.50% → 1.50%) under Claude Code.

## Relevance to Software Engineers

ProgramGym's lessons transfer to any team building SWE agents: (1) invest in *verifiable* environments—four automated test-quality gates (pass/consistency/dummy/weak-assert) are a reusable recipe for trusting agent supervision; (2) scaffold long-horizon work as isolated roles with frozen handoffs and validated checkpoints rather than one giant session—here worth +20pp, dwarfing the +8pp from fine-tuning; (3) budget iterations explicitly ($K{=}3$ captures most gains). Caveat: task difficulty skews easy (1,492/1,648), and gains are measured on behavior-matching tests, not semantic equivalence—passing tests means agreement on tested inputs only.
