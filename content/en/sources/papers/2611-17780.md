# LuthorSQL: A One-Pass Text-to-SQL Model as System 1 for a Slower LLM Agent

**Source**: [arXiv:2611.17780](https://arxiv.org/abs/2611.17780) · **Published**: 2026-11-13
**Authors**: Ibrahim Memon, Armin Karamzade, M. Hanif Jhaveri, Roy Fox

## Overview

Frontier LLM agents that query databases through tools are among the most accurate text-to-SQL systems, but per-query calls to a hosted model are slow, costly, and expose sensitive organizational queries to external APIs — the authors compute that a Claude Opus 5.5 agent serving 10,000 queries a day costs over $70,000 a year at list price. Their question: how much of this burden can hardware an organization already owns offload without compromising the agent's accuracy?

LuthorSQL is a non-autoregressive 7B text-to-SQL model that serves as a rapid System 1 gate in front of a slower LLM agent (System 2), escalating a query only when the local model is uncertain. In a single forward pass it predicts slot scores over a bounded grammar of query plans, compiles and executes up to 32 candidate plans, and selects an answer with a trained validator. Design follows Kahneman-style System 1/System 2 framing: cheap, fast, local processing handles the routine; the expensive agent handles the hard and uncertain tail.

On its own, LuthorSQL reaches 68.03% execution accuracy on BIRD's hidden test set at 0.84 seconds per question on a single GPU. Combined with Claude Opus 5.5 in a pre-registered confidence cascade over 227 questions on databases published after Opus's training cutoff, it answers nearly half of all questions locally and cuts API cost by 33.3% at the same accuracy.

## Key points

- Standalone accuracy/latency: 68.03% execution accuracy on BIRD's hidden test set at 0.84 s per question on a single GPU; the model maintains accuracy within 9 GB using 8-bit quantized weights.
- Portability: zero-shot transfer to Snowflake, BigQuery, MySQL, PostgreSQL, and DuckDB within 3.1 points of its native SQLite accuracy.
- Cascade economics: with Claude Opus 5.5 behind a pre-registered confidence cascade (227 post-cutoff questions), LuthorSQL answers nearly half of all questions locally and cuts API cost by 33.3% at the same accuracy.
- Architecture: one forward pass predicting slot scores over a bounded query-plan grammar, up to 32 candidate plans compiled and executed per question, and a trained validator choosing the final answer.
- Contamination probing is a headline result: without seeing the schema, Claude Opus 5.5 reproduces 48–92% of public benchmark gold queries verbatim — yet its tool-assisted accuracy holds on renamed schemas and reaches 95.6–97.4% on post-cutoff databases, supporting the paper's decision to evaluate the cascade on post-cutoff data.

## Details

The bounded grammar plus slot scoring replaces free-form SQL decoding with constrained, verifiable plan generation, and the validator turns executed candidates into a calibrated confidence signal for the escalation gate; ancillary files (decision_ids.json, reserved_ids.json) accompany the release. The pre-registered evaluation protocol and the contamination analysis distinguish this work from benchmark-only claims: both the cascade's question set and the renamed-schema robustness checks are designed around what a hosted agent may have memorized.
