# Dory1.0-4B: A Looped Normalized-GPT

**Source**: [arXiv:2611.03998](https://arxiv.org/abs/2611.03998) · **Published**: 2026-11-02
**Authors**: Maxim Fishman, Simeng Sun, Shantanu Acharya, Faisal Ladhak, Brian Chmiel, Santiago Akle Serano, Ron Banner, Boris Ginsburg, Krishna C. Puvvada

## Overview

Dory1.0-4B is a 4-billion-parameter looped language model with elastic depth: one checkpoint can serve different inference compute budgets. It is built on a normalized Transformer backbone with interleaved sliding-window and full-attention layers, organized into input, shared recurrent, and output blocks. At inference, the recurrent block can be applied a variable number of times. Pre-training covers 6 trillion tokens, the first 4.5 trillion in NVFP4, followed by context extension to 256K tokens. Post-training uses supervised fine-tuning and reinforcement learning with verifiable rewards, with a difficulty-aware loop curriculum that routes harder prompts to deeper loops. Increasing the loop count improves accuracy, with the largest gains on coding, agentic, and long-context benchmarks.

## Key points

- A single checkpoint serves variable inference compute budgets.
- The architecture reuses a shared recurrent block.
- Context length is extended to 256K tokens.
- A difficulty-aware curriculum routes harder prompts to deeper loops.
- Deeper looping improves token efficiency in latent space.
- Inference caches keys and values only from the last loop.

## Details

With two or more loops, Dory1.0-4B outperforms larger models such as Qwen3.5-9B and selected Gemma models on average across 12 benchmarks. With four loops, it generates 1.3 to 2.5 times fewer tokens than with one loop, because extra computation is spent in latent space rather than longer outputs. On the other hand, caching only last-loop key values introduces a quality tradeoff and memory savings depend on implementation constraints. The model weights are released in BF16, MXFP8, NVFP4, and GGUF quantized formats.
