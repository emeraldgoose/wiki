# "Shall We Approve?" Consequence-Aware Approval for Autonomous Coding Agents

**Source**: [arXiv:2610.40753](https://arxiv.org/abs/2610.40753) · **Published**: 2026-10-29
**Authors**: Weiheng Wu, Junkai Chen, Zhensu Sun, Jieke Shi, Yunbo Lyu, David Lo

## Overview

Coding agents increasingly rely on automated approvers to decide whether a proposed shell command may run. Existing approvers range from rule-based checkers to guardrail models and deployed permission classifiers, but they typically base decisions only on the text of the request and command. Yet a command's behavior depends on the code it invokes and the surrounding workspace state; systems that observe file changes after execution leave assessment to the agent or a human.

The paper presents Caper, a consequence-aware approval mechanism. It pre-executes each command in a snapshotted sandbox, gives an independent approver a bounded report of observed effects, commits allowed commands, and rolls back blocked ones with an actionable reason for the agent. This shifts approval from request-text inspection to observed runtime consequences.

On SABER, Caper achieves a 6.7% harmful-outcome rate versus at least 14.8% for six compared systems. On YoloFS-Ext, where harmful behavior is hidden inside invoked tools, it achieves 7.8% versus at least 35.3%. It also blocks only 1.0% of safe twins of dangerous tasks.

## Key points

- Request-text-based approvals miss the actual runtime effects of shell commands.
- Caper snapshots and pre-executes commands in a sandbox before committing them.
- An independent approver reviews bounded reports of observed effects.
- Blocked commands are rolled back with reasons the agent can act on.
- Caper lowers harmful-outcome rates on SABER and YoloFS-Ext compared with six existing systems.
- Only 1.0% of safe twins are blocked on YoloFS-Ext.

## Details

The results emphasize consequence-aware approvals for autonomous coding agents, especially when harmful behavior is hidden inside tools. By sandboxing and rolling back blocked commands, Caper aims to prevent irreversible damage while keeping approval overhead low for safe commands. Full method and benchmark details are in the source paper.
