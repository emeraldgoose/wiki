# G-CAST: Governed Continual Self-Training for E-Commerce Agents under Evolving Demands

**Source**: [arXiv:2611.17814](https://arxiv.org/abs/2611.17814) · **Published**: 2026-11-13
**Authors**: Yuechun Yu, Wenzheng Kong, Xiaofeng Mao, Jin Zhang

## Overview

As large language models (LLMs) power more conversational shopping agents in e-commerce, the target keeps moving. Users keep surfacing new product categories, procurement scenarios, and feature requests, while the agent's execution harness — its tools, skills, and operating procedures — evolves to support ever more sophisticated interactions. The authors frame this as two compounding practical challenges: demand drift alters the distribution, intent, and complexity of user requests, so a model trained once falls behind; and harness evolution requires the model to use newly introduced capabilities correctly without losing behavior users already rely on. Periodic manual retraining, meanwhile, is too delayed and labor-intensive for this pace.

G-CAST is the authors' governed continual self-training system for this setting. It converts daily production evidence, read under evolving demand and capability contracts, into two things: reward-routed, entropy-prioritized training data, and governed evolution of the reward signal itself. Each model update passes through a governed checkpoint transition controlled by cumulative evaluation, which is what lets the agent learn newly introduced behaviors without sacrificing previously accepted capabilities.

The experiments run on a real production e-commerce agent rather than a benchmark proxy. Compared with a strong autonomous post-training baseline, G-CAST adapts more strongly to newly introduced demand while better preserving previously accepted behavior, and ablations attribute the gains to both the data orchestration and the reward evolution components. The system is now deployed in Yuancai, a B2B procurement agent on Alibaba's 1688 platform.

## Key points

- Two failure modes in production LLM shopping agents: demand drift (user request distribution, intent, and complexity shift as new product categories, procurement scenarios, and feature requests emerge) and harness evolution (new tools, skills, and operating procedures that the model must adopt correctly while keeping behavior users already depend on).
- The paper argues that periodic manual retraining cannot keep up in this setting — it is too delayed and labor-intensive for continually changing demand and harnesses.
- Data side: G-CAST turns daily production evidence into training data through reward-routed, entropy-prioritized orchestration, so what gets trained on is selected by reward and prioritized by entropy under the current contracts.
- Reward side: contract-driven reward evolution updates the reward signal itself as demand and capability contracts evolve, with defined evaluation metrics and a frozen evaluation reward anchoring scoring.
- Governed checkpoint transition: every model update is gated by cumulative evaluation, letting the agent absorb newly introduced behaviors without sacrificing previously accepted capabilities.
- Production comparison: on a real e-commerce agent, G-CAST achieves stronger adaptation to newly introduced demand and better preservation of previously accepted behavior than a strong autonomous post-training baseline.
- Ablations: both reward-routed, entropy-prioritized data orchestration and governed reward evolution are shown to be important to the gains.
- Deployment: G-CAST is live in Yuancai (cai.1688.com), a B2B procurement agent on Alibaba's 1688 platform.

## Details

Method structure: two coupled mechanisms around a shared contract layer. Reward-routed, entropy-prioritized data orchestration decides which daily production evidence becomes training data; contract-driven reward evolution keeps the reward signal aligned with the evolving demand and capability contracts. The method section pairs this with defined evaluation metrics and a frozen evaluation reward, so scoring stays comparable while contracts move, and checkpoint transitions are governed by cumulative evaluation rather than released automatically.

The experiment sections cover continual self-training under evolving contracts, a routing and prioritization ablation, and a dedicated reward evolution evaluation, all on the production agent. Related work situates G-CAST among automatic training agents, autonomous LLM post-training, autonomous data engineering, and self-evolving agentic AI, with a specific line distinguishing harness and context evolution from joint harness-and-model evolution. The conclusion discusses operational impact and limitations; the paper does not announce a public code release. This is the v1 (13 November 2026) arXiv submission.
