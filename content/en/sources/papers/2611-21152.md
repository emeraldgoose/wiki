# From Repositories to Training Environments: Scaling Long-Horizon Coding Agents with Environment Evolution Loop

**Source**: [arXiv](https://arxiv.org/abs/2611.21152)
**Published**: 2026-11-17

## Overview

Training coding agents for long-horizon tasks requires environments with verifiable feedback. Existing pipelines follow a linear process ending with validation, which establishes usability but gives little guidance on improving training value, while recursive self-improvement (RSI) needs costly model rollouts and downstream evaluation with long feedback delays. RepoFactory is an automated pipeline that converts real repositories into verifiable environments where agents build complete projects from scratch given a language specification. Its Environment Evolution Loop optimizes a multiplicative objective combining validity, structural coupling, and implementation scope through timely, low-cost proxy feedback from verification and code analysis, jointly revising oracle implementations, task specifications, and tests.

RepoFactory produces 10,159 environments across 17 software domains (all construction agents use Qwen3.8-Max). Training Qwen3.5-35B-A3B on these environments yields RepoHorizen-35B-A3B, which gains 22.6 percentage points on NL2Repo-Bench (23.8 → 46.4) and 8.5 points on average across five benchmarks covering long-horizon coding and agentic tasks in real-world production settings, compared with 17.5 and 6.4 points without environment evolution.

## Key points

- NL2Repo: 23.8 → 46.4 (+22.6), the strongest listed result among open-weight models below 200B; surpasses GPT-5.5 (45.1), Gemini-3.1 Pro (33.4), DeepSeek-V4-Pro (38.5) and MiniMax-M3 (42.1). Gains of 1.3–6.8 points extend to issue resolution and cross-domain long-horizon tasks in Terminal-Bench 2.1.
- Environment evolution adds 5.1 points on NL2Repo and 2.1 points on average over the no-evolution variant (17.5 / 6.4 without evolution), supporting the proxy metrics as evolution guidance.
- Scaling: performance rises steadily from 23.8% (no RepoFactory data) to 46.4% with 5,577 environments, with gains becoming more pronounced beyond 3,000 environments (36.5% → 46.4%) and no evidence of saturation at the largest scale tested.
- Model sizes: NL2Repo gains of 12.2–22.6 points across 9B, 27B and 35B-A3B models; the 35B-A3B model gains the most despite the 27B model's higher baseline.
- 10,159 environments across 17 software domains, covering the Python ecosystem and development operations in training trajectories; construction cost is dominated by repository search/filtering, runtime construction and task synthesis with materialized tests.

## Details

- Pipeline: repository search and filtering → runtime construction and repository analysis → task synthesis and environment materialization, closed by the Environment Evolution Loop that revises oracle implementations, task specs and tests against a multiplicative objective (validity × structural coupling × implementation scope).
- Training: Qwen3.5-35B-A3B SFT on filtered/cleaned trajectories (see Appendix A for trajectory filtering and hyperparameters); benchmarks include NL2Repo-Bench and Terminal-Bench 2.1 plus three further long-horizon coding/agentic benchmarks.
