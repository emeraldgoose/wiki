# Weight-Space Programming Doesn't Need Transformers

**Source**: [arXiv](https://arxiv.org/abs/2611.22055)
**Published**: 2026-11-17

## Overview

Standard neural architectures such as the Transformer were chosen because they train well with gradient descent and run fast on GPUs. In weight-space programming (WSP), an LLM writes target-model weights by hand without gradient-based training, so those reasons no longer apply. Should we keep the Transformer? Given minimal guidance, ten labeled examples and a sandbox, three frontier LLMs (Claude Opus 5.5, GPT-6.1 Sol, GPT-6 Astra) were tasked either with writing the weights of a fixed architecture or with designing the architecture themselves, evaluated mainly on ARC multiple-choice science questions.

When free to design, all three compile plain-text facts into a sparse table queried by a fixed procedure, reaching up to 54.4% test accuracy — an LLM-designed model scoring above the most accurate released Transformer the same LLM wrote while using about 1,800× fewer parameters. Without gradients, the writers choose a table because the LLM can state what each weight means and can find and rewrite a wrong one: each wrong answer traces to one row, and removing a row changes about one other answer. Building on this, the authors propose an associative-memory-based model up to 17× faster on GPUs than a same-sized Transformer. Pretrained LLMs remain more accurate overall; the claim concerns which structure to build when writing weights. Code and project page are linked from the paper.

## Key points

- Convergence without coordination: all three LLMs independently converge on sparse-table associative memory — no attention, no MLPs, no dense embeddings — when free to design the target architecture (ARC multiple-choice science questions).
- Size efficiency: the associative-memory design is about 680× smaller than the most accurate released architecture the same LLM wrote, and the LLM-designed model beats the best released Transformer the same LLM wrote with ~1,800× fewer parameters.
- Local editability: in Claude Opus 5.5's models, keeping only the single best-matching row per option nearly matches full-model accuracy, and deleting one row alters roughly one prediction; by contrast, the same facts written into a Transformer underperform plain BM25 keyword search, consistent with interference between dense keys.
- Speed: the proposed associative-memory-based model stays within about three percentage points of the LLM-designed models' accuracy while answering up to 17× faster on GPUs than a same-sized Transformer (reads a fixed number of rows per question instead of scoring every stored fact).
- Scope/limits: also tested on pretrained weights, math questions, open-ended generation, several tasks at once, and vision tasks — images are where WSP does not work; pretrained LLMs remain far more accurate overall, so the claim is about architecture choice under WSP, not about beating pretrained models.

## Details

- Setup: minimal guidance — ten labeled questions, execution sandbox, multiple-choice questions (mainly ARC science); regimes (i) WSP on diverse released architectures (Transformers, SSMs, RNNs) from random init and (ii) free architecture design. Writers: Claude Opus 5.5, GPT-6.1 Sol, GPT-6 Astra.
- Analysis: LLM first expresses domain facts as plain-text sentences, then writes a build script converting each sentence into a sparse-table row; a fixed lookup procedure matches question/option tokens against rows and selects the highest-scoring answer. Verification by line-removal test, BM25 control, test-set overlap checks, and row-retention tests.
