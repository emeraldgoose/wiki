# Typhoon OCR 2: From Thai Document Transcription to Multilingual, Multi-Task OCR

**Source**: [arXiv:2611.27494](https://arxiv.org/abs/2611.27494) · **Published**: 2026-11-20 (v1; v2 revised 2026-11-23)
**Authors**: Surapon Nonesung, Natapong Nitarach, Sittipong Sripaisarnmongkol, Kunat Pipatanakul, Warit Sirichotedumrong

## Overview

Typhoon OCR 1.5 could transcribe Thai documents into plain text, but real workflows usually need either one specific piece of information from a page or a fully structured representation of the whole page — and typically run OCR first and then pass the text to another model to find the value. Typhoon OCR 2 removes that two-step pipeline: a single compact model handles both targeted, prompt-driven extraction (chart data, form fields, a document label, a question about the page) and structured full-page parsing, with the input prompt selecting the task. Full-page parsing covers Thai, English, and Chinese.

The authors release two open-weight sizes, 2B and 0.8B, adapted from specialized open document parsers — Infinity-Parser2-Flash for the 2B model and OvisOCR2 for the 0.8B model. Training is supervised fine-tuning (SFT) on a curated 420,327-example mixture of rule-filtered legacy Thai data, newly labeled in-house Thai pages, and public mostly English/Chinese multitask, VQA, and instruction data, followed by Group Relative Policy Optimization (GRPO) with per-task sequence-level rewards plus a hard rule that any completion hitting the token cap without an end-of-sequence token gets zero reward. This directly targets sequence-level failure modes that next-token training does not score, such as repetition loops and premature stopping.

## Key points

- Single model, two tasks: prompt-driven targeted extraction and full-page layout parsing (JSON elements in reading order with bounding boxes, semantic categories, tables as HTML, formulas as LaTeX, running text as Markdown).
- Compact open models: 2B (from Infinity-Parser2-Flash) and 0.8B (from OvisOCR2); weights, GGUF/MLX/Ollama quantizations, a Python package (`pip install typhoon-ocr2`), and the evaluation suite are released.
- Best open model on Thai benchmarks among those evaluated: 80.7 on Thai MDPBench (vs 68.9 for Typhoon OCR 1.5) and 59.91 on ThaiOCRBench (vs 40.45); the compact 0.8B scores 36.43 on ThaiOCRBench.
- No regression on English/Chinese parsing: 84.7 vs the base's 84.4 on olmOCR-bench, and 90.97 vs 91.03 on OmniDocBench v1.6.
- GRPO cuts repetition loops on MDPBench from a mean of 3.2% of pages to 0.7% for the 2B model; the score gain for the 0.8B model is smaller and statistically uncertain.
- Data curation: deterministic rule filtering of legacy Typhoon OCR 1.5 data (99,616 kept), multi-stage labeling of 47,031 new Thai examples (large-model annotation, rule + LLM-judge verification with quality score >= 90, manual bounding-box audits of 4,562 pages with 1,961 corrections), PII filtering, and image-hash contamination checks against MDPBench, SEA-DocBench, and ThaiOCRBench.
- GRPO reward: per-task metric (box overlap + reading-order text similarity for layout, TEDS for tables, edit similarity for formulas/Markdown, value-matching F1 for charts, ANLS for QA) multiplied by a structural penalty max(0.6, 1 - 0.1k) over k triggered rule families; token-cap-without-EOS completions score zero. LoRA adapters are updated with a KL penalty against the SFT policy; the GRPO prompt set (12,993 prompts) is held out from SFT.

## Details

Evaluation covers five public benchmarks — MDPBench (320 EN/TH photographed pages, parsing score), olmOCR-bench (1,403 English PDF pages, test pass rate), ThaiOCRBench (2,808 Thai queries over 13 tasks), SEA-DocBench (3,091 EN/TH multilingual pages, edit distance), and OmniDocBench v1.6 (1,651 EN/ZH complex PDF layouts) — with greedy decoding up to 16,384 new tokens, images up to 16.7 MP for the layout-JSON prompt, and vLLM 0.33.0 serving (v0.27.0 produced incorrect outputs for the compared models). Repetition at evaluation is detected from the output text itself (one line covering more than half of >= 30 non-empty lines, a 6–80 character phrase repeated >= 15 times, or a > 3,000-byte output compressing to under 8% of its size with zlib), because truncation during training is only a proxy for loops. SFT uses full-parameter next-token training with a long context window and dynamic image resolution, with rotation/downscaling/photometric augmentation applied to both images and bounding boxes. The HTML full text describes the v1 submission; the v2 revision (2026-11-23) reports the same headline numbers in the abstract.
