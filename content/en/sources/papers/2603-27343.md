# WMIP: A Working-Memory-Inspired Programmable Probe of Cumulative State Tracking in Large Language Models

**Source**: [arXiv:2603.27343](https://arxiv.org/abs/2603.27343) · **Published**: 2026-03-28

## Overview

Keeping a running score in your head is a working-memory task, and large language models face a close analogue whenever a prompt lists an initial state plus a series of updates and asks for the final result without written steps. Existing state-tracking tests disagree about this demand: Minerva's quantity-state task allows 4,096 output tokens, enough to work through updates in writing, and GSM-Infinite explicitly requests step-by-step reasoning. WMIP is a working-memory-inspired probe of cumulative state tracking in which the generator fixes the number of updates (3 to 100) and the response protocol fixes how much room is left for written steps, so the two levers are controlled separately on identical items.

The core items initialize three named entities with integers, list K ordered gains, losses, or transfers between them, and ask for one entity's final value as a single free-response integer. Reference answers are computed by program, not by model consensus. Sixty core items cover K = 3, 5, 7, and depth items from the same generator extend to 100 updates; the query types cover final states, intermediate states, and multi-target blocks. Four response protocols run on the same items: the core protocol (a 16-token output budget plus a one-integer rule), a large-budget protocol (512 tokens, prompt unchanged), an instruction variant at 16 tokens, and a written-steps protocol that requests steps followed by the final answer on the last line.

Across 18 LLMs, accuracy is 84.9% on single-step arithmetic but 31.7% on the core items, and from 50 updates on no model exceeds 10%. The protocol levers dominate the picture: a 512-token budget alone removes truncation but leaves one-integer scoring unchanged, while the written-steps protocol lifts pooled core accuracy to 88.0% (950 of 1,080 responses), with the instruction change contributing roughly twice as much as the budget. Core accuracy also correlates positively with Berkeley Function Calling Leaderboard scores (Kendall tau-b 0.417–0.449 across Overall, Multi-Turn, and Agentic criteria).

The paper's conclusion is about measurement as much as about models: strong single-step arithmetic does not ensure reliable cumulative tracking, and output protocols substantially change measured accuracy. Claude Sonnet 4.5 scores 0/60 under the core protocol (every response truncates) and 60/60 under both the large-budget and written-steps protocols, so low core accuracy alone does not imply the model cannot solve the underlying problems. The generator, items, scoring code, and all responses are released for reproducible comparisons across depths, query types, and protocols.

## Key points

- Two controlled levers: the generator sets update count and query type; the protocol sets output budget and scoring. The core protocol keeps the full update sequence visible but restricts written steps with a 16-token budget and a one-integer rule.
- Pooled over 18 models: 84.9% on single-step arithmetic versus 31.7% on core items (three to seven updates), and below 10% for every model from 50 updates on.
- The instruction change outweighs the budget: a 512-token budget adds 195 correct responses under last-integer scoring, and the written-steps instructions add 400 more, reaching 950/1,080 (88.0%). Written steps improve all 18 models; truncations fall from 217 to 4.
- Model spread is large under the core protocol: GPT-5.2 answers 56/60 and GPT-4.1 49/60, while Llama-3.2-1B scores 0–2/60 — the pooled 31.7% hides a frontier-versus-small-model split.
- Intermediate-state queries rule out end-state shortcuts: accuracy after the queried entity's third update is 23.3 points below accuracy after its first (30.0% versus 53.3%), so later states are not simply easier to report.
- As more entities are queried, tracking accuracy falls (28.6%, 25.3%, 23.3% at M = 1, 2, 4), while readout items — where the queried entity receives no updates and the correct answer equals its initial value — score higher (37.8% to 51.7%), a pattern consistent with anchoring on initial values.
- Extension blocks separate domains: direct assignment reaches 90.0% while set updates and counting reach 54.1% under the main parser, with meeting counts lowest at 34.1%.
- Results are seed- and wording-sensitive: across four generation seeds ranking correlations average 0.821 (GPT-4.1-mini spans 40 points), and five numeric-only rewordings of the same 30 items average 0.674 (Sonnet 4.5: 0/30 under the original wording, 27/30 under casual wording).
- The BFCL association is positive but not unique to state tracking: core tau-b 0.417–0.449 versus arithmetic 0.687–0.740, with paired core-minus-arithmetic and core-minus-cancellation intervals all including zero.

## Details

- Version note: the paper was renamed from WMF-AM; v1 appeared 2026-03-28 and v3 (2026-10-30) is a substantial revision with new experiments — this summary follows v3.
- Core bank: 60 items with K = 3, 5, 7 updates over three named entities; depth items extend the same generator to K up to 100. Intermediate-state blocks use five-entity trajectories and contribute 60 items; multi-target and readout blocks contribute 120 items over M = 1, 2, 4 queried entities.
- Under the core protocol's one-integer rule, responses containing several integers receive no credit — which is why written-steps responses score only 2/1,080 under that rule but 950/1,080 under last-integer scoring; the pooled 31.7% core figure uses one-integer scoring (342/1,080).
- The instruction variant (user and system instructions changed, 16-token budget kept) improves eleven models, ties two, and declines five, so the gain cannot be assigned to either instruction alone; bare-number answers number 813, 986, and 0 of 1,080 under the core, instruction, and written-steps protocols.
- Scoring validity checks accompany accuracy: integer compliance, truncation flagging, and 10,000-resample model-bootstrap intervals; only 7 of 3,240 assignment/set/count responses change correctness between two independent scoring parsers, and a hosted Llama-3.3-70B endpoint matched its local run (31 correct each) on the core items.
- Code, items, scoring specifications, and all model responses are released at github.com/dengzhe-hou/WMIP.
