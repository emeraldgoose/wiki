# MEM-SQL: Memory-Empowered Text-to-SQL

**Source**: [arXiv:2611.18338](https://arxiv.org/abs/2611.18338) · **Published**: 2026-11-13
**Authors**: Xiaoqi Wang, Wenqi Pei, Shizheng Hou, Yilai Liu, Han Chen, Boyan Li, Yuyu Luo, Hongyang Du

## Overview

Text-to-SQL systems translate natural-language questions into SQL queries, and the field's benchmarks have grown from cross-domain generalization (Spider) to value-dependent questions (BIRD) and enterprise schemas that can exceed 1,000 columns (Spider 2.0). Yet these benchmarks score every question in isolation, while real users repeatedly query the same database. A verified query from an earlier request may already contain the join or the intermediate calculation a new question needs; reconstructing that logic from the schema each time is costly on large databases, and a query can still execute even when part of its logic no longer matches the request.

A team from the University of Hong Kong (NICE Lab), the National University of Singapore, and HKUST (Guangzhou) attacks this gap on two fronts. HARE (History-AwaRe Text-to-SQL BEnchmark) turns 823 verified queries drawn from Spider, BIRD, Spider 2.0, and BEAVER into 1,600 requests, each annotated with the components it preserves from history and the edits it requires — six single reuse categories (rephrase, parametric changes, component parametric changes, structural changes, shared joins, shared concepts) plus six composite pairings — so adapting a whole query can be distinguished from assembling partial evidence.

The proposed system, MEM-SQL, maintains a fixed per-database memory with three layers: whole-query templates with typed slots, reusable SELECT-block components, and schema concepts that map domain terms to columns and join relationships. Retrieval is coverage-gated per requirement — a layer contributes evidence only if every requirement assigned to it has a match above that layer's threshold — and On-demand Schema Linking (OSL) fetches raw schema details only when no layer qualifies or the generator judges the retrieved evidence insufficient.

Across six language models on HARE, mean execution accuracy rises from 37.1% for Direct Generation without history to 50.0% for MEM-SQL, with 76.6% fewer input tokens and 68.8% lower latency; 95.4% of requests are answered from memory alone.

## Key points

- HARE: 1,600 requests built from a fixed pool of 823 verified queries across Spider, BIRD, Spider 2.0, and BEAVER; 1,300 requests belong to a single reuse category and 300 combine two categories, with 50 requests per composite category.
- Three-layer memory: templates replace literals, sort directions, LIMIT/OFFSET clauses, aggregates, window functions, and grouping keys with typed slots; components keep the FROM/JOIN and clause structure of a SELECT block; schema concepts record semantic roles, column mappings, and join keys. A new item merges into an existing one only when description cosine similarity is at least 0.9 and the stored SQL or schema mapping is equivalent.
- Coverage-gated selection: the question is decomposed into layer-specific retrieval atoms, each with its own retrieval budget; a layer is accepted only when its worst-covered atom still clears the layer threshold, so a strong match on one atom cannot hide a missing requirement.
- Savings come mainly from avoiding schema access: MEM-SQL completes 95.4% of requests from memory on average and escalates only 4.3% (1.1% through the coverage gate, 3.2% through the generator).
- Main results: mean execution accuracy 50.0% versus 37.1% for Direct Generation (+12.9 points), input tokens down 76.6% and latency down 68.8% averaged over six backbones (GLM5.3-Flash, Gemini4-Argon, GPT6-Luna, Qwen3.8-27B, Qwen3.5-9B, Granite4.2-8B); MEM-SQL leads the memory baselines DAIL-SQL, A-MEM, and BIRD-History — all using unconditional schema linking — on every backbone, for example 54.2% EX on GLM5.3-Flash and 57.5% on Gemini4-Argon.
- Ablations: removing the template layer costs the most accuracy (5.3 EX points on average) and raises tokens on all backbones; removing components costs 3.7 points on composite requests versus 1.1 on single-category ones; removing schema concepts barely moves accuracy but raises tokens on all six backbones. Retrieval atoms raise micro recall from 56.67% to 94.58% on a 240-question calibration set while returning 37.7% fewer items per question than flat retrieval.
- Multi-source composition is the bottleneck: accuracy falls from 56.7% to 29.7% when a request reuses several verified queries, at least 21.7 EX points lower on every backbone. For structural changes, MEM-SQL retrieves all sources on 90.8% of multi-source requests yet reaches only 9.9% accuracy — generation, not retrieval, fails.
- OSL transfers: applied to three other memory designs, it cuts input tokens by at least 60% and latency by at least 34% for every design, but the accuracy benefit depends on retrieval completeness (+6.0 points for DAIL-SQL and +5.1 for A-MEM on full-recall requests, while BIRD-History loses accuracy on five of six backbones).

## Details

HARE construction starts from a lead query whose SQL contains the evidence a request must retain, then adds companions from the same database — up to two companions for structural changes and shared joins, and up to six queries for a composite request. A catalog of business rules (BR0–BR17) constrains the permitted edits to dates, thresholds, ranking, measures, grouping, and join paths. GLM5.3-Flash generates three candidates per request; each candidate must execute and return at least one non-NULL row, and Claude Opus 5.5 reviews question–SQL agreement, consistency with domain knowledge, and category constraints, repairing failed candidates with up to three attempts.

At inference, MEM-SQL decomposes the question into layer-specific retrieval atoms, retrieves the nearest items for each atom by cosine similarity, and unions the evidence from qualifying layers. If every layer fails the coverage gate, the schema-linking route runs immediately; otherwise the generator first tries memory-only generation and escalates to schema linking only if it declares the evidence insufficient. The generated query is checked with a database dry run and repaired if validation fails.

Error analysis shows aggregation remains the largest error class on the memory route (36.1% of wrong answers, versus 38.2% for the strongest baseline A-MEM), while table errors fall from 31.4% to 21.4% (55.0% to 33.7% on BEAVER); without schema access, execution failures rise to 10.8% versus 3.2% for A-MEM. By source benchmark, gains concentrate on the join-heavy BEAVER (+8.6 EX points) and BIRD (+3.0), with small losses on Spider (−0.6) and Spider 2.0 (−0.7), which are dominated by shared concepts and structural changes. The authors list three limitations: HARE does not model schema drift (for example, a fiscal year's start month changing), MEM-SQL is evaluated with static memory, and execution accuracy rejects answers that differ only in format while missing SQL that returns the right rows for the wrong reason.
