# Evolving Infra: Agent-Adaptive LLM Serving at Scale

**Source**: [arXiv:2611.12304](https://arxiv.org/abs/2611.12304) · **Published**: 2026-11-09
**Authors**: Hao Kang, Weili Xu, Ziyang Li, Zheng Du, Hanchen Li, Tian Xia, Song Bian, Tushar Krishna, Huizi Mao, Ion Stoica, Song Han

## Overview

Agentic workloads are now a major source of LLM inference demand, and they strain prefill-decode (PD) disaggregated serving in two ways. First, compute demand varies across agents and over time: PutnamBench, Claude Code, and OSWorld agents differ so much in prefill-versus-decode work per request that their best static splits range from 2P7D to 6P3D, and as the workload mix shifts, the best split per 10-minute window moves from 3P6D to 7P2D - a single static split loses up to 24% of throughput. Second, agent context management reshapes KV cache value: harnesses fork sub-agents, pause for tools, and compact histories, so access recency does not predict reuse - in Claude Code traces, 98% of the prompt after a 359-second sub-agent call matches earlier KV, but only 14% after a 12-second compaction.

Evolving Infra is presented as the first agent-adaptive serving framework, attacking the two limitations behind existing systems' failures: compute allocation and KV cache management are coupled (a node's cached KV is indexed in local state, so switching its phase strands or discards it), and planners, routers, and memory pools rely on coarse signals (queue depth, input lengths, access recency) that miss the agent workload and its context management. The design decouples the two planes: every node runs a symmetric engine that can serve either phase and is reassigned at runtime without restart, while KV lives in a shared pool formed by the host memory of all nodes, indexed by a cluster-wide directory that counts the active branches referencing each copy. On this data plane, an online planner learns iteration-time models of prefill and decode (separating cached from uncached tokens) and reassigns the PD split only when a predicted throughput gain persists across a 600-second planning window; the router sends each request to the node with the shortest predicted TTFT while KV is fetched asynchronously during queueing; and eviction removes first the KV that no active branch references - replaced histories, finished sub-agents' contexts, duplicate transfer copies.

On coding, math, and computer-use agents serving GLM-5.2 and Kimi K2.6 on 36 GB300 GPUs (scaling studies up to 256 GPUs and simulation at 3,072), Evolving Infra beats NVIDIA's production Dynamo framework across the board: 1.10-2.73x throughput, 81-95% less lost KV reuse, up to 4.12x lower mean end-to-end latency, and up to 13.92x lower P95 TTFT under stationary load; under a shifting math-to-computer-use composition it reaches 2.14x Dynamo's throughput and 1.28x the best static split's. A phase switch completes in 6.2 seconds on average - over 100x shorter than a Dynamo relaunch.

## Key points

- Three failure modes of existing PD systems on agent workloads: costly phase switches (Dynamo takes 681 s per switch in the authors' Claude Code measurements; Arrow loses 55.5% of available KV reuse over 34 in-place switches), misestimated compute demand (offline-profiled static splits go stale; queue-depth and TTFT-based planners get perturbed by sub-agent bursts and planners that estimate prefill work from full input length ignore KV reuse), and misjudged KV reuse (cache-aware routers overload the few nodes holding a prefix, raising P95 TTFT; LRU eviction drops the KV of branches waiting on tools or users while keeping compacted-away history and finished sub-agent contexts).
- Decoupling mechanism: symmetric engines make every node prefill- or decode-capable and the planner reassigns phases at runtime with no restart; KV moves to a shared pool built from all nodes' host memory (each node's host tier caches 4x as many tokens as its GPU tier), and a cluster-wide KV directory tracks active-branch reference counts, updated by agent context management and inter-node transfers. A phase switch therefore leaves KV readable everywhere.
- Agent-adaptive planning: iteration-time models for prefill and decode are fitted online (no offline profiling), with the prefill model explicitly incorporating KV reuse; the planner evaluates them on the average work of a request over a planning window (600 s, 10 slices) and switches only when the predicted gain persists - short bursts do not trigger switches. Evolving Infra switches 2.0 times per run on average versus Dynamo's 3.6, and stays within the best static split's behavior while Dynamo deviates from it for 41-100% of the measurement period.
- Agent-aware KV management: asynchronous KV fetching during queueing lets the router target shortest predicted TTFT instead of prefix locality; the most loaded prefill node queues requests 1.75-1.85x the average node versus 2.29-2.61x under cache-aware routing. Directory-guided eviction retains nearly all KV that active agents still need; Dynamo's LRU discards waiting-branch KV that accounts for 34-46% of its lost reuse on CC, and it prefills up to 2.99x more prompt tokens without cached KV.
- Stationary-load results (three workloads, three concurrency levels each): throughput 1.10-2.73x Dynamo, lost KV reuse down 81-95%, mean E2E latency down 1.15x (Putnam), 2.34-2.69x (OSWorld), 3.80-4.12x (CC), P95 TTFT down up to 13.92x; at the lowest concurrency of each workload, 0.98-1.38x the throughput of the best static split under SGLang.
- The planner picks 3P6D-4P5D for Claude Code and 8P1D for OSWorld - differing from SGLang's best static splits (4P5D, 6P3D) because symmetric engines shift the optimum. On decode-heavy Putnam it keeps only one or two prefill nodes, explicitly trading P95 TTFT (above Dynamo at two of three concurrencies) for throughput and lower mean latency.
- Shifting composition (288 Putnam agents, then 144 Putnam + 72 OSWorld, then 144 OSWorld over three consecutive hours): the split tracks the best per-10-minute window and settles at 8P1D in the OSWorld period; throughput 2.14x Dynamo and 1.28x the best static split, mean E2E latency down 2.15x and 1.33x, P95 TTFT down 3.58x and 1.88x, with the highest throughput in every period.
- Switch cost: 6.2 s average including the wait for the switching node's running requests (which it keeps serving) versus 754 s for a Dynamo relaunch that takes the node out of service; insensitive to the initial split (mean E2E varies at most 1.8% across four initial splits from 3P6D to 6P3D, all converging to 4P5D on CC).
- Ablations: the infrastructure plus KV-reuse-aware routing/eviction alone (fixed 4P5D split) reaches 1.37x the best static split's throughput; asynchronous fetching alone under SGLang routing gives 1.12x upstream (prefill-node idle time cut from 23.6% to 14.4%); versus cache-aware routing at the same split, Evolving Infra loses 0.7% instead of 2.4% of KV reuse and prefills 31% fewer uncached prompt tokens; ThunderAgent-style agent pausing yields 0.95x because KV capacity is not the binding constraint on GB300 nodes.
- Cost of adaptivity: enabling online phase-split adaptation at the already-best static split costs only 0.3% throughput; offline profiling for comparison baselines would take 10,752 GPU-hours for the three-hour Claude Code trace on 256 GPUs even with binary search; iteration-time models converge to low mean error within a minute of learning.
- Evaluation infrastructure: mini-SWE-agent on PutnamBench (decode-heavy, one branch per problem, no context management), Anthropic's computer-use agent on OSWorld 2.0 (prefill-heavy multimodal multi-agent, a screenshot appended every step), and real-user Claude Code traces replayed with the Trie replayer that preserves pauses and prefix sharing; GLM-5.2 serves Putnam and CC, Kimi K2.6 serves OSWorld and the shifting run; both models quantized to NVFP4 with FP8 KV cache and multi-token-prediction speculative decoding, TP4 across nine 4-GPU GB300 nodes.

## Details

- Positioning of baselines: Dynamo v1.5.1 is described as the state-of-the-art open-source dynamic PD-disaggregation system and is configured with the SGLang Model Gateway using cache-aware prefill routing and round-robin decode routing (the lowest-P95-TTFT setup in the paper's own measurements); nodes run HiCache with LRU eviction. SGLang's runtime role switch was excluded because it rejects speculative decoding, and Llumnix cannot run on the GB300's Arm CPUs (it is compared on H200 GPUs in the appendix).
- Workload realism: a production study of 11.7 million requests (cited) shows user-triggered task starts follow workday rhythms while automatically triggered starts are spread evenly - motivating online adaptation to shifting composition rather than any fixed split.
- Why recency-based signals fail: branches pause for tools, sub-agents, or users and later reuse their prefix; compaction drops recently accessed history from subsequent requests. The 98%-versus-14% prefix-match contrast between a long sub-agent pause and a fast compaction is the paper's sharpest evidence that reuse is context-driven, not recency-driven.
- Scalability studies (appendices): evaluation up to 256 GB300 GPUs, simulation at 3,072 GPUs, open-loop arrivals (the planner allocates more prefill nodes as arrival rates rise, sustaining twice the arrival rate of the best static split), and different parallelism for prefill and decode phases.
- Team and institutions: Georgia Institute of Technology, University of Illinois Urbana-Champaign, UC Berkeley, NVIDIA, OpenAI, and MIT - including systems veterans Tushar Krishna, Ion Stoica, and Song Han.
- Naming: xPyD denotes x prefill and y decode nodes; L1/L2 denote a node's GPU-memory and host-memory KV tiers; the planning window is 600 seconds with 10 slices, preceded by a 30-minute warmup excluded from measurements; stationary runs serve each workload for one hour at fixed concurrency, replacing finished agents with new ones.
