# SWE-Duel: Towards a Self-Scaling Arena for Coding Agents

**Source**: Minn et al., arXiv, 2026-10-08

**Lead**: Static coding benchmarks begin leaking into training data and falling behind agents the moment they are released, while continuously refreshed variants still fix difficulty at the human-issue level. SWE-Duel proposes a *self-scaling* arena: two coding agents evaluate each other over mirrored Red–Blue turns, where the Red agent authors a new feature with an embedded bug at evaluation time and the Blue agent must review and repair it blind. A 1,500-turn tournament shows the format ranks agents coherently, separates task-authoring from task-solving skill, and produces tasks whose difficulty grows with author capability.

## Background

Repository-level benchmarks (SWE-bench and successors) use public, fixed task sets that eventually enter training corpora; refresh-based variants (SWE-bench-Live, SWE-rebench) collect newer but not harder tasks. Model-generated-task approaches (BugPilot, SwingArena) still rely on fixed task pools or pre-generated sets. The desiderata are twofold: tasks and oracles created *at evaluation time* (nothing exists in advance to leak), and difficulty set *by the participants* rather than fixed at release.

## The Red–Blue Duel Protocol

A task is a tuple of repository, feature specification, pull-request diff (feature + hidden bug), feature tests, and sealed bug-triggering tests. Blue receives only the public bundle—never told a bug exists—and wins the turn only if existing tests, feature tests, and sealed bug tests all pass on its revision (hard conjunction, no partial credit). Because the bug lives inside the new feature, Blue cannot win by reverting the PR.

Red creates each task across three context-isolated sessions with executable validation gates: (A) feature implementation—existing and feature tests must pass on the feature-only diff; (B) bug embedding—the bug must keep all visible tests green while the sealed tests pass on the clean feature and fail on the bugged diff; (C) blind self-repair—a fresh session of the same agent must fix the bug from the public bundle alone, ruling out unsolvable tasks. Admitted tasks are banked and reused against every opponent. A match plays both roles on the same repositories; missing tasks (exhausted slots) score as Blue wins to avoid survivor bias. Tournaments use round-robin with Bradley–Terry ratings, and newcomers join via $\lceil \log_2 M \rceil + 1$ actively sampled matches.

## Experiments

**Setup**: 11 model–harness participants (GPT-5.5, Claude Opus 4.8, Kimi K2.7 Code, DeepSeek-V4-Pro, GLM-5.2, Qwen3.7-Max, Nemotron-3-Ultra, MiniMax-M3, Gemini 3.1 Pro late entrant; harnesses mini-swe-agent, Codex CLI, Claude Code) on 15 repositories in 5 languages (Python, Java, Go, JavaScript, C/C++). 50 matches × 30 turns = 1,500 turns. Total API spend $2,109 (~$26/match); newcomer onboarding $243.

**Results**:

| Participant | BT rating | Red win % | Blue win % |
|-------------|-----------|-----------|------------|
| GPT-5.5 + Codex CLI | +2.82 | 11.3 | 98.7 |
| Claude Opus 4.8 + mini-swe-agent | +2.46 | 27.3 | 88.7 |
| GPT-5.5 + mini-swe-agent | +2.13 | 10.4 | 97.0 |
| Kimi-K2.7-Code + mini-swe-agent | +1.82 | 15.6 | 90.4 |
| DeepSeek-V4-Pro + mini-swe-agent | +1.50 | 18.5 | 91.9 |

The leaders win differently: GPT-5.5 is the strongest solver (98.7% Blue wins), Claude Opus 4.8 the strongest task author (27.3% Red wins, 2× the GPT-5.5 rate). Across contested turns Blue succeeds 85.1% (1,037 clean repairs; 158 shipped bugs; 24 collapses). By language, Java is easiest to repair (89.2%) and Node hardest (82.9%); logic errors are the hardest bug category (81.9% repaired). Difficulty scales with author capability: tasks from GLM-5.3 defeat a fixed DeepSeek-V4-Pro solver 42.9% of the time vs. 8.3% and 0.0% for GLM-5.1/5.2 (trend test $p = .015$). Quality controls check out: 91.7% pooled self-repair rate on re-runs, 6.0% sealed-test false-negative rate on manual audit. Adding Gemini as a late entrant with 5 matches leaves incumbent ordering untouched (Kendall's $\tau = 1.0$).

## Relevance to Software Engineers

SWE-Duel is directly actionable for teams building or buying coding agents: it is an open toolkit for running contamination-resistant evaluations where the test content is generated at eval time rather than curated. The Red–Blue pattern (author hides a defect, reviewer fixes blind, sealed tests adjudicate) generalizes beyond benchmarking—use it for adversarial testing of review bots, fault-localization agents, and repair pipelines, or as a training-data generator for repair models. The role decomposition is also a hiring-style lens: solver skill and task-authoring (test-writing, bug-finding) skill are distinct, and the paper shows they must be measured separately. Caveat for practitioners: every admitted task is solvable by its own author by construction, so difficulty is capped by author capability.
