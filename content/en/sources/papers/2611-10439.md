# Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction

**Source**: [arXiv:2611.10439](https://arxiv.org/abs/2611.10439) · **Published**: 2026-11-07
**Authors**: Yunzhe Wang, Mesut Erhan Unal, Sheng Zhang, Shabnam Ghadar, Peng Tang

## Overview

Self-evolving agents improve their own skills, memory, and harness code from experience without retraining the base LLM, and group-evolving systems pool those lessons across a team of agents. The authors observe that both lines stop short of the setting that actually matters for a platform or an office: a mixed population of independent users and heterogeneous agents learning from one another. Sharing there is not just pooling everything into one store, because a lesson that helps one user or agent may not help another, and some of what an agent learns about a user must never reach anyone else. They call this setting cross-learning, and identify three properties learned knowledge must satisfy: transferability (a discovery made once should benefit the whole population), audience selectivity (each item has an intrinsic generalization scope), and confidentiality (each item has an intrinsic disclosure boundary before it exposes something private to its origin user).

Their system, MixUA, turns independent user-agent trajectories into one shared memory with four scopes. Each entry written by a pair is placed as Pair (only that user with that agent), User (that user with any agent), Agent (that agent with any user), or Global (everyone). The authorized audience of an entry must sit inside the intersection of its generalization scope and its disclosure boundary, so useful knowledge reaches every pair it can while private knowledge stays with its owner. Writing is dual-stream: each trajectory is split into a reusable and a protected stream sent to two isolated writers, and an entry's scope label comes from the stream that produced it, so a writer that saw protected content can never publish a shared entry. Entries consist of a situation, the lesson, a scope, and provenance, and an optional periodic store review re-scopes and merges entries with the whole store in view.

For evaluation the paper introduces CrossLearnBench, which pairs tasks from seven established agent benchmarks, run unchanged in Docker sandboxes on the Harbor framework, with a user layer of planted preferences and privacy probes. Five synthetic users work with seven LLM-harness agents. Each user carries nine always-private PII items plus one fact per category of a privacy survey, where the same category can be private for one user and not another, forcing per-user privacy judgment; facts are planted ambiently in files with neutral names such as a half-filled loan application saved as form.txt. Each user also states four document preferences in round 1 only — a filename, a sign-off date format, an ordered section list, and one banned markup — and later rounds test whether memory carries them.

## Key points

- Four audience scopes from two independent axes: a lesson generalizes across users, across agents, both, or neither, giving Pair, User, Agent, and Global; only opening the user axis exposes an entry to other users, so only that step is gated on privacy.
- Dual-stream writing keeps private evidence with its owner: reusable and protected streams go to isolated writers, and the stream label, not the writer's own judgment, decides whether an entry may leave the owner's User and Pair memory.
- Main scheduled-task results: no memory 72.0 pass rate, best single scope Global-only 85.5 (+11.5), MixUA (LLM) 88.1 (+15.3), MixUA (LLM) + store review 89.8 (+16.3), with preference retention 80-90 percent across MixUA variants.
- Sharing beats repetition: on tasks previously tried only by a different user with a different agent, MixUA gains 11-14 points versus 8.9 for Global-only and 1.6 for Pair-only; with the same user or agent involved, up to 20 points.
- On random task assignment, 526 of 821 attempts in rounds 2-8 hit a task no pair had ever attempted; there MixUA gains 10.1 points, nearly twice Global-only's 5.5, with the gap widening over rounds.
- Privacy holds: at most 0.02 percent of probes find a planted private fact in a forbidden scope; three of four MixUA variants place none in about 18k probes each, and store review removes the agentic writer's 4 violations. Preference leaks run 0.9-4.8 percent versus 5.5-26.3 percent for Global- and Agent-only with a protected stream.
- Scope ablations: removing Global cuts the utility gain from 15.3 to 9.0 points and the cross gain from 13.0 to 4.6; removing User drops preference retention from 90 to 81 percent; Agent and Pair matter on targeted probes, where without Agent crowd pass falls 89 to 40 percent and spillover rises 44 to 67 percent, and without Pair leak rises 22 to 95 percent.
- Held-out scope masking: showing only Global or Agent retains preferences no better than an empty store (8-12 percent), so user conventions genuinely live in User and Pair; all scopes together retain 84-90 percent after review.
- Retrieval budget: at 10k characters per scope MixUA delivers about 23k characters per task, under 60 percent of Global-only's context, yet gains more (13.1 versus 11.5); 20k per scope matches the 40k pass rate at about 20 percent lower cost. A file-based variant gains nearly as much but takes more turns (17.0 versus 13.9) and retains fewer preferences (75 versus 90 percent).

## Details

### Where the four scopes come from

An agent is a fixed LLM-harness configuration and a pair is one user working with one agent. Each entry carries a generalization scope, the pairs for which it is valid, and a disclosure boundary, the pairs it may reach without exposing its origin user. Each scope suits a different kind of knowledge: Global holds what helps everyone such as a library defect, User holds a user's preferences such as a document format, Agent holds advice for one agent such as a tool-calling quirk, and Pair holds preferences that conflict across agents, such as asking a verbose agent for terse replies but a terse one for detail. The single-scope baselines stand in for prior memory designs: Pair-only for an assistant memory such as MemGPT, User-only for a personal memory such as MIRIX, Agent-only for a team memory such as G-Memory, and Global-only for a broadcast skill library such as SkillClaw.

### How the benchmark plants users into task environments

Tasks come from AutoCodeBench, FeatureBench, SpreadsheetBench (verified), SWT-Bench (verified), USACO, Terminal-Bench 2.0, and VMax Tasks, with each environment, instruction, and verifier unchanged. Privacy is measured as exposure, how often the agent opens a planted file, and leakage, whether a planted fact reaches the trajectory passed to the memory writer, the user's own store, or another user's store. Preferences are checked by an automatic parser on the summary document each agent must write on task completion, and a user may hold conflicting preferences across agents. The seven agents are Claude Code with Opus 5 or Sonnet 5, Hermes and OpenClaw with Sonnet 5, and Codex with GPT-5.6 Sol, Luna, or Terra; the memory writer uses Claude Opus 5 and retrieval uses Titan Text Embeddings v2.

### What the numbers say about scope division

Single-scope stores trade utility for personalization: Global-only gains the most utility but retains no more preferences than no memory (11 percent), while Pair-only retains 80 percent but gains only 4.3 points. MixUA attains both at once. Store review improves both writers, raising the LLM writer from 15.3 to 16.3 points and the agentic writer from 12.8 to 14.0, lifting the agentic writer's preference retention from 80 to 86 percent and lowering leaks to 0.9-3.6 percent. In round 8 of random assignment MixUA still retains 76 percent of round-1 preferences while Pair-only declines from 87 to 44 percent, plausibly because its preferences compete with 1.7k task entries for one retrieval budget. The authors name the open problems: users and agents in reality form teams and hierarchies that no pair-to-global boundary expresses, audiences between one and all such as a single team need group scopes with auditable disclosure, and scaling to an open population stresses store growth, review cost, and writing cost.
