# How Complete Must an Environment Be to Train a Capable GUI Agent?

**Source**: [arXiv:2611.23946](https://arxiv.org/abs/2611.23946) · **Published**: 2026-11-18 (v1)
**Authors**: Jingxing Wang, Teng Wang, Xingyu Lou, Zihan Guo, Jun Wang, Weiwen Liu, Weinan Zhang, Jianghao Lin

## Overview

GUI agents are widely trained by reinforcement learning inside executable GUI environments, but building those environments is costly, so each project quietly trades away part of the environment through its construction choices. This paper asks how complete an environment must be to train a capable agent, and frames the trade-offs along three dimensions: reward coverage (which goal-reaching trajectories the verifier rewards), data coverage (the application records the agent is exposed to beyond what tasks read or write), and feature coverage (the application functions beyond what tasks use).

The authors build controlled variants in MobileGym, train Qwen3-VL-4B-Instruct on each, and evaluate every resulting policy in the original full environment over 465 instances. Lowering reward coverage to a single reference path cuts success from 51.61% to 41.08% (−10.53 points, 240→191 successes), because under group-relative advantage a rejected-but-valid solution path gets pushed down while only the reference path is reinforced. Filtering unrelated records (data coverage) also hurts at every level (R0/R1/R2: 47.96%, 47.31%, 49.68% vs Full 51.61%). Surprisingly, pruning unused application features (feature coverage) raises success to 56.13%, entirely on tasks whose own environments were left unchanged.

The feature-pruning gain is explained by episode length weighting: each episode's group-relative advantage is copied to all of its responses, so long detour episodes dominate updates and erode skills on other tasks. Reweighting episodes (w_i = C/T_i, "episode balancing") reverses the gain, and balancing only the pruned-task episodes makes it vanish — confirming length weighting as the mechanism. Following these findings, the authors build MobileGym-Lite, which keeps reward and data coverage complete but prunes dispensable functions, and it outperforms the full environment (55.48% vs 51.61%) at lower construction cost.

## Key points

- Environment construction choices decompose into reward, data, and feature coverage; prior work sets each on engineering grounds without measuring its effect on training.
- Single-path (reference-matching) rewards cost 10.53 success points (41.08% vs 51.61% on 465 instances) because group-relative advantage penalizes valid alternative solutions (e.g., edit-sheet deletion vs the long-press reference path in alarm deletion).
- Removing unrelated app records lowers success at every filtering level (R0 47.96%, R1 47.31%, R2 49.68% vs Full 51.61%) — data coverage should stay complete.
- Pruning unused app features raises success to 56.13% (+4.52 over Full), with gains entirely on tasks whose environments were unmodified — the effect comes through shared policy updates, not the pruned tasks themselves.
- The mechanism is episode-length × advantage coupling: long detour successes are over-reinforced and erode other skills; episode balancing (w_i = C/T_i) reverses the pruning gain.
- MobileGym-Lite keeps reward and data coverage complete and prunes dispensable functions: 87 template–module pairs omitted across 72 of 192 training templates, −14.05% average app source lines, ~33% fewer LLM tokens to rebuild ten apps, visible control nodes on nine fixed screens drop 126→117 (−7.14%), and full-environment success reaches 55.48% vs Full's 51.61%.
- Reduced environments show late-training instability (loop terminations and format errors surge after step 8); narrowing the GSPO clip offsets late in training (0.2/0.28 → 0.002/0.0028, W→N₈) stabilizes Lite and adds 8 endpoint successes.

## Details

All policies are evaluated in the original full environment, so gains cannot come from an easier test. The reward-coverage ablation shows the sign reversal concretely: at step 11 of alarm deletion, six rollouts succeed via the edit sheet and one via the long-press reference; with one failure in the group, each edit-sheet success gets advantage −0.354 while the reference-path success gets +2.475, whereas a native goal check gives all seven +0.354. Record filtering (R0/R1/R2) retains only the records tasks need and varies the rest. Feature pruning starts from F0 and selectively restores nearby navigation and shared operations (e.g., world-clock access for alarm tasks, Calendar settings for date tools, profile editing for WeChat), affecting 36 templates, six of which keep all functions.

The length-weighting analysis crosses environment (Full vs F0) with weighting (response averaging vs episode balancing) from a shared step-12 checkpoint; the interaction between environment and weighting isolates length weighting as the cause. Late-training instability appears in every reduced environment (R0 loop terminations 111→135 and R1 format errors 12→175 from step 8 to 16, vs Full 117→109), motivating the narrow late clip W→Nₖ after step k=8, which leaves already-stable Full runs unchanged.
