# Switch-SWE: Do Coding Agents Hold Focus When Switching Between Unfinished Tasks?

**Source**: [arXiv:2611.02017](https://arxiv.org/abs/2611.02017) · **Published**: 2026-11-01
**Authors**: Shuochen Chang, Qianli Ma, Yibo Miao, Qingyang Liu, Bingjie Gao, Haonan Zhao, Siyu Sun, Yulin Sun, Han Zhao, Jiangtong Li

## Overview

Real software development sessions rarely consist of one issue carried to completion. They more often interleave several unfinished tasks, which means a coding agent must recover an earlier task's requirements and partial progress after working on other things. Existing repository-level benchmarks typically score a single issue-to-patch episode, so they do not directly measure whether an agent can resume a task after advancing other unfinished work in the same repository.

Switch-SWE targets that gap. It is a benchmark for focus-task resumption in sessions that interleave unfinished tasks drawn from the same source repository, with a persistent checkout for each task. Each focus task is evaluated in matched uninterrupted and switched sessions with identical focus requirements and executable verifiers.

## Key points

- The benchmark contains 200 focus tasks from 19 Python repositories, reconstructed from issue, pull-request, and review histories and rendered as 400 matched session specifications.
- Across 7 coding agents, interleaved unfinished work produces an average focus-task resolution gap of 11.5 percentage points, ranging from 6.0 to 15.0 percentage points.
- Trajectory analysis identifies cross-task requirement confusion and loss of task state as recurrent resumption behaviors.
- A plug-in context-management module that selects task-relevant history and maintains concise task-state summaries improves focus-task completion on OpenCode by 5.5 to 15.5 percentage points across evaluated models.
- All code is publicly available.

## Details

The benchmark design isolates the cost of interruption. A focus task is scored in two matched conditions: one uninterrupted session and one switched session with the same focus requirements and verifier. The switched session interleaves ordered stages from other unfinished tasks in the same repository, while only the final focus patch is scored, so the score difference reflects resumption ability rather than task difficulty.

Because each task keeps a persistent checkout, state must actually be carried across the intervening work rather than reconstructed from a clean tree. The reported gap therefore captures a realistic failure mode for repository-level agents: requirements from one task bleed into another and partial progress is lost.

The proposed context-management module addresses this directly by selecting history relevant to the active focus task and maintaining a compact summary of its state. Its consistent improvement suggests that explicit state tracking, not just larger context, is the limiting factor under task switching.
