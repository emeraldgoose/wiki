# MIRIX-2.0: Multi-Agent Memory System

**Source**: [arXiv:2611.12068](https://arxiv.org/abs/2611.12068) · **Published**: 2026-11-09
**Authors**: Wei-Chieh Huang, Weizhi Zhang, Jiayan Nan, Peng Xia, Yu Wang

## Overview

Long-term memory is what lets an LLM agent personalize to its user, stay consistent, and reuse what worked before — but each existing family gives something up. Parametric memories store experience in weights and require training, ruling out closed models. Systems that consolidate records into extracted facts can lose details for good. Systems that keep every record leave a growing store to search. And both of the dominant index designs prune top-down: hypergraph memories descend from topic summaries written at storage time, so a detail is reachable only after its topic has been retrieved, while file-system memories (such as Claude Code's auto memory) route retrieval through one-line summaries behind a size-capped index, leaving anything a summary does not mention to string search.

MIRIX-2.0, a redesign of MIRIX, answers with a layered architecture in which a specific layer meets each requirement. A Meta Memory Manager routes each input to the memory types it updates; six typed writers — Core, Episodic, Semantic, Procedural, Resource, Knowledge Vault — keep complete records in a typed evidence plane inside a vector database. This plane is the system of record: details survive any consolidation, and it commits before graph construction begins, so a failed graph write never rolls back a stored memory. Only episodic and semantic records are indexed by a provenance-preserving n-ary hypergraph whose frames cite the rows they came from, with occurrence identities that keep distinct events apart even when worded alike.

The three technical requirements are explicit: source fidelity (evidence stays recoverable after writing and after consolidation), bounded access (a query inspects a small graph neighborhood and a bounded set of cited rows instead of scanning history), and temporal identity (similar wordings must not collapse distinct occurrences). Consolidation runs outside the write path: AutoDream merges duplicate entity anchors under explicit caps without touching stored memories, and distills task sessions into skills for procedural memory. One store thereby serves both user-centric memory (personalization, where recall of any detail matters) and agent-centric memory (precision and refinement, where retrieving too much distracts the agent) — the first memory system the authors know of to handle both.

## Key points

- Accuracy: best of the compared systems on four of five QA benchmarks — 91.4% on LoCoMo (hypergraph lifts flat memory 85.7% → 88.4% with the largest gain on multi-hop questions; AutoDream raises every question type to 91.4%) and 72.6% on LongMemEval-S, 14.3 points above the strongest baseline, with the hypergraph alone adding 11.2.
- Document QA: on MemoryAgentBench with AutoDream disabled, 83.0% single-hop and 71.0% multi-hop — 31.0 and 22.0 points above HyperMem — and the best of all four metrics for cross-domain review summarization on MemoryCD.
- Procedural memory: highest mean success among compared memory methods on ALFWorld (76.4% with GPT-6 Luna vs 73.6% for Agent Workflow Memory and 69.4% with no memory) and WebShop (37.4%, while using the fewest training and test tokens); on MetaClaw-Bench it reaches 49.2% with GPT-5.2 against 44.0% for MetaClaw's own skill library.
- Efficiency: with AutoDream disabled, MIRIX-2.0 answers faster than HyperMem on all five timed benchmarks, ingests the two conversational benchmarks in less time, and uses fewer answer tokens on four of the five.
- The cost is ingestion of long documents: building the graph makes it about four times slower than flat memory and slower than that baseline; the full system with AutoDream enabled is not timed, and the retrieval bounds cover the evidence a question inspects, not wall-clock latency as history grows.
- Fail-soft indexing: the database write commits first; a failed graph write never rolls back stored memory; a failed graph read falls back to direct evidence retrieval; the graph stores only identifiers and compact structural metadata.
- Safe consolidation: AutoDream verifies pairs on the semantic frontier rather than total memory size, so verification does not pay for the same pair twice; merging adds 3.0 points on LoCoMo without rewriting any record.
- Practicality: no model is fine-tuned, the same system runs with closed and open models, and the code is public.

## Details

### The typed evidence plane and the hypergraph index

Each of the six memory types has its own schema and update operations owned by its writer; a record indexed by the graph is a tuple of immutable row identifier, memory type, stored text, event time, mention/write time, source-and-chunk provenance, and search embeddings. Full summaries and details remain in the vector database; the graph holds only identifiers and compact structural metadata. On the write path, the routed writers commit records, then an extraction-plus-repair step produces candidate n-ary frames (entities, events, relations, roles, times), canonicalized and admitted as anchors; frames involving two or more anchors are upserted into the per-user hypergraph. The n-ary framing is the departure from prior hypergraph memories: hyperedges record the participants of a fact rather than merely which unit belongs where, and retrieval can jump directly to a fact with the rows that justify it.

### Graph-owned retrieval under budgets

Retrieval inspects a small graph neighborhood and the cited rows behind the returned facts, under explicit budgets, so the evidence a question inspects does not grow with the history. Because answers arrive with their justifying rows, an answer is traceable end to end — the property the source-fidelity requirement is for. The lanes, scores, and fusion of the retrieval paths are detailed in the appendix, and the temporal-identity requirement is enforced by occurrence identities assigned at admission, so a repeated description of the same event can share evidence while a genuinely distinct occurrence stays separate.

### What AutoDream does and does not do

AutoDream is the third path, running outside the other two. On semantic memory it consolidates identities: it pairs each anchor introduced by new semantic rows with its existing duplicates and merges them under explicit caps, never rewriting evidence — which is why it raises every LoCoMo question type while keeping the record store intact. On procedural memory it refines skills: a curator creates or edits skills whose edits can cite the experiences behind them, distilling task sessions into reusable strategies. Both operations are outside the write path, so neither can block or corrupt a commit.

### Evaluation scope and provenance

The evaluation spans conversational recall (LoCoMo, LongMemEval-S), long-document QA (MemoryAgentBench), personalized cross-domain review summarization (MemoryCD), and interactive-agent procedural memory (ALFWorld, WebShop, MetaClaw-Bench), with cost measured in answer speed, ingestion time, and tokens.
