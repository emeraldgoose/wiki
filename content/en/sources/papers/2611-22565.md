# MillBill: A Machining Agent with Geometric Feedback

**Source**: [arXiv](https://arxiv.org/abs/2611.22565)
**Published**: 2026-11-18

## Overview

Turning a CAD model into a machining program requires both process knowledge and geometric precision. Language models can generate such workflows by writing geometry and toolpath code for each part, but that makes numerical execution the model's task — and a single wrong number yields a program that runs but machines the wrong part. MillBill separates machining decisions from their geometric execution and verification: given a boundary-representation (B-rep) part, stock and material, a locally hosted mid-sized open model proposes operations and cutting parameters for indexed three-axis machining, while a geometric harness generates toolpaths, simulates material removal, and returns feedback for plan refinement. Setup planning accounts for what the available cutters can physically reach, not visibility alone.

MillBill is evaluated by the fraction of target surface area within tolerance after simulated machining. With Qwen3.8-27B — a locally hosted open model — it outperforms frontier-model approaches that construct their own geometry and toolpath workflows on the evaluated machining tasks. Code: https://github.com/kulibinai/millbill.

## Key points

- Main result (100-part GrabCAD benchmark, τ = 0.1 mm): MillBill leaves 97.4% of target surface within tolerance vs 94.3% (GPT-6 Astra code-writing agent), 83.0% (Opus 5.5), 42.3% (CNC-Net); smallest gouged area (0.54% vs 1.50% best baseline) and smallest excess-material area (2.1%). As a bare code-writing agent, Qwen3.8-27B reaches only 7.9% (below uncut stock at 10.6%) — the harness is what makes the mid-sized open model viable.
- Harness contribution: without the LLM, the reference plan + harness already reaches 97.0%; reach-aware setup planning matters hugely — replacing it with a fixed +z setup drops accuracy to 66.4% with excess material rising to 33.1%.
- Setup selection: a GNN recognises machining features on the B-rep; setups are chosen among the six axis-aligned orientations by what available cutters can reach (holder overhang and reach screened via height-map dilation over the whole tool library, greedy selection, planned on stock left by simulated earlier setups) — a deep, narrow region can be visible yet unreachable once the holder is accounted for.
- Model's role kept minimal: the LLM revises a standard-practice reference of operations, tools and cutting parameters derived from features, the tool library and a cutting-data model; its tools must exist in the library and cutting data are clamped to machine limits — it never computes coordinates, offsets or swept volumes.
- Refinement loop: harness corrects what it can (e.g. adds rest finishing), returns remaining deviations to the model, keeps the best of at most three builds; deviations are attributed to features and operations.
- Open benchmark: 4,294 GrabCAD parts paired with milling stocks, with a simulation-based scoring protocol usable by any planner.

## Details

- Pipeline: feature recognition (GNN on B-rep) → reach-aware setup planning (six orientations, indexed three-axis) → LLM revision of reference plan (operations/tools/cuts from features + library + cutting-data model) → CAM toolpath generation → material-removal simulation → surface-deviation measurement → attribution and refinement (≤3 builds, keep best).
- Failure modes of code-writing agents: errors mainly in ±x/±y setup transformations and tool offsets; some add deburring passes that cut into the part.
- Limitations: reach-aware selection is limited to the six axis-aligned orientations; ablations run on simulation; 100 scored parts from GrabCAD (see Sec. 5 and Appendix S for failure cases, tolerance sensitivity and refinement-round analysis).
