# Compile by Training: Turning Natural-Language Specifications into Local Neural Functions

Source: Yuntian Deng, Pengyu Nie, Stuart Shieber, arXiv:2609.04199, Sep 3, 2026. EMNLP 2026 System Demonstrations. Demo at programasweights.com.

**Lead**: Many recurring text functions (email triage, site helpers) are easy to describe but tedious to encode as rules — yet calling a large remote model per input means repeated cost, latency, and provider dependence. **Compile by training** turns a natural-language specification into a reusable **neural function**: at compile time, teacher models synthesize task examples that train a small adapter for a compact interpreter, producing a storable, versionable, composable artifact that runs without the teachers. On **FuzzyBench-Hard** — specs where the Program-as-Weights fast compiler got zero exact matches — it reaches **83.6% semantic accuracy** (LEM 0.224 → 0.836), at ~1 minute of compile time versus seconds.

## The compile path

All programs share a frozen **quantized Qwen3-0.6B interpreter**; each function is a **rank-64 LoRA adapter** plus a compiler-generated prompt scaffold, initialized from the amortized PAW compiler's prediction and refined with a 100-step cosine schedule. The public recipe mixes a cheaper teacher (bulk examples) with a larger one (complementary supervision); a 2:1 GPT-5.4-mini/GPT-5.5 mix lifts dev LEM 0.746 → 0.851. The deployed service overlaps synthesis with training (GPU never idles waiting for teachers), streams progress as a background build job, and reuses cached teacher outputs — cold compiles take 50.9s (B300), 68.2s (H200), 99.2s (RTX).

## Evidence it composes

| Deployment | Result |
|---|---|
| Multi-site website helper (classifiers + BM25 + validators as a program tree) | Live course answers combining page + forum evidence |
| Language-controlled 3D avatar (spec → action DSL → browser render) | 43/44 validation instructions correct |
| Bidirectional English↔Claudish translator | 100,747 successful requests, Aug 22–Sep 2, 2026 |

The division of labor is the point: compiled functions make fuzzy decisions while ordinary code handles retrieval, caching, and branching.

## Caveats

Correctness is judged by LLM Exact Match (GPT-5.5 grader, κ=0.946 vs authors) — a model-graded metric with its own failure modes. Synthetic supervision inherits teacher errors, so guaranteed-correctness settings still need validation paths. Minute-scale compiles suit stable functions, not rapidly changing specs.

## Relevance to SW engineers

- Treat adaptation as a **build step**: spec in, versioned `.paw`-style artifact out, cached and composed like ordinary software — a saner ops story than prompt-per-call.
- Warm-start from an amortized prediction, then spend optimization budget only where it pays: 3.5s → 50.9s compile buys +0.612 LEM.
- Overlap slow teacher synthesis with training and make compiles background jobs — the serving pattern generalizes to any distillation pipeline.
- Keep deterministic code on the control path (parsing, validation, branching) and let neural functions own only fuzzy decisions.
