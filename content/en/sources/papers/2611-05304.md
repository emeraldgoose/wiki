# LoopVQ: Sub 1-bit KV Cache Quantization for Looped Transformers

**Source**: [arXiv:2611.05304](https://arxiv.org/abs/2611.05304) · **Published**: 2026-11-03
**Authors**: Minsoo Cheong, Sungjoo Yoo

## Overview

Looped transformers are a parameter-efficient alternative to standard transformers for language modeling. By reapplying the same layers across multiple loop steps, recent looped language models match the performance of non-looped models several times their size. While this architecture effectively reduces parameter memory, each loop step still stores its own keys and values, so the KV cache grows linearly with the number of loop steps and becomes the main memory bottleneck. The paper observes that looped-model KV cache is highly redundant along the loop axis and that loop steps differ substantially in their sensitivity to quantization. Based on these observations, it proposes LoopVQ, a KV-cache vector quantization method for looped transformers that codes channels of multiple loop steps jointly and fine-tunes codebooks to match the output of the full-precision model. At 0.5 bits per element, LoopVQ outperforms existing KV-cache vector quantization methods for standard LLMs on general, long chain-of-thought reasoning, and long-context retrieval tasks with Ouro and Huginn models. The design is orthogonal to these methods, and combined with TaSQ it retains much of BF16 accuracy even at 0.25 bits per element. The paper also implements LoopVQ in SGLang, where it nearly halves decode latency at a 32K-token context and raises peak serving throughput by up to 4.3x and 6.1x on the 1.4B and 2.6B Ouro models compared with the BF16 baseline.

## Key points

- Looped transformers save parameters but linearly grow KV-cache memory across loop steps.
- Loop-axis redundancy and uneven quantization sensitivity are exploited.
- LoopVQ jointly vector-quantizes channels across loop steps and fine-tunes codebooks against full-precision output.
- At 0.5 bits per element it beats standard LLM KV-cache VQ baselines on general, long-CoT, and retrieval tasks (Ouro/Huginn).
- With TaSQ it retains BF16-like accuracy at 0.25 bits; in SGLang it nearly halves 32K latency with 4.3x/6.1x throughput gains.

## Details

SGLang implementation demonstrates serving gains. Extensive benchmarks cover general reasoning and long-context retrieval. Full accuracy tables and experiments are in the linked source.
