# Beyond RAG for Agent Memory: Retrieval by Decoupling and Aggregation

**Source**: [arXiv:2602.02007](https://arxiv.org/abs/2602.02007) · **Published**: 2026-02-02
**Authors**: Zhanghao Hu, Qinglin Zhu, Runcong Zhao, Di Liang, Hanqi Yan, Yulan He, Lin Gui

## Overview

Standard Retrieval Augmented Generation (RAG) is poorly matched to the retrieval problem that agent memory actually poses. Unlike large, heterogeneous document collections, agent memory is a bounded and coherent interaction stream in which many spans are highly correlated or near duplicates. Flat top-k similarity retrieval therefore tends to return several memories that are generally relevant but largely repetitive, which is especially damaging when the answer hinges on a small update, constraint, or factual difference hidden among otherwise similar interactions. Summary- or schema-centric hierarchies improve on flat retrieval for scalability, but repeated compression keeps the shared background and blurs the subtle details that distinguish one candidate from another.

The paper argues that agent memory should instead follow the principle of decoupling before aggregation: the system should first isolate reusable facts, state updates, and distinguishing details from similar histories, and only then organise them for efficient retrieval. Crucially, the organising structure should be revisable rather than fixed, because later interactions can reveal better relations among previously stored components and should be allowed to trigger updates to the high-level organisation.

Based on this principle the authors propose xMemory, a framework that couples memory structuring with adaptive retrieval. Starting from raw messages, xMemory builds a hierarchy that runs from original messages to segments, memory components, and groups. Messages are partitioned into contiguous segments that each capture a coherent local event; each segment is decoupled into memory components representing reusable facts, constraints, attributes, relations, or state updates, while links back to the source segment preserve intact local context; related components are then aggregated into high-level groups using a guidance objective that balances sparsity and semantic faithfulness. As memory evolves, new components are attached to compatible groups and the structure is revised by splitting overly large or internally heterogeneous groups and merging overly small or isolated ones. Retrieval proceeds top-down: Stage I selects a compact backbone of complementary groups and components, and Stage II expands down to segments and raw messages only when the additional evidence reduces the reader's uncertainty.

## Key points

- xMemory obtains the best average LoCoMo performance across all three reader backbones tested (Qwen3-8B, Llama-3.1-8B-Instruct, GPT-5 nano), beating the flat baselines (Full Memory, Naive RAG, LightMem) and the structured baselines (Nemori, A-Mem, MemoryOS), with especially clear gains on multi-hop and temporal questions.
- On LoCoMo, average BLEU/F1 improves from 31.44/40.88 for Nemori to 34.48/43.98 with Qwen3-8B, and from 36.65/48.17 to 38.71/50.00 with GPT-5 nano while per-query token usage falls from 9155 to 6581.
- Measuring cost per query, the LoCoMo Qwen3-8B setting improves from 31.44/40.88 BLEU/F1 and 7755 tokens for Nemori to 34.48/43.98 and 4711 tokens for xMemory.
- On PerLTQA, whose contexts average around 25K tokens and whose answers are sentence-style rather than short spans, xMemory reaches 36.24/47.08/42.50 BLEU/F1/ROUGE-L with Qwen3-8B while using the fewest tokens among compared methods, and 42.68/52.37/47.84 with Llama-3.1-8B-Instruct.
- Coverage efficiency is the clearest efficiency result: on LoCoMo with Qwen3-8B, covering all answer evidence units takes 5.66 retrieved blocks and 974.56 tokens with xMemory, against 10.81 blocks and 1979.26 tokens for Naive RAG and 13.31 blocks and 1587.99 tokens for RAG with LLMLingua-2 pruning.
- Retroactive restructuring is not cosmetic. Freezing split and merge yields 0% reassignment and lowers average F1 to 38.59, whereas the full system reassigns 44.91% of existing components and reaches 43.98 average F1.
- The group-size ceiling is set at 12 components per group. A Fano-style bound (2 bits of discriminative information, 85% routing-accuracy target) gives roughly 11.5 admissible candidates, and an empirical sweep from 8 to 14 confirms 12 as best, with about 4.5 components per group on average; larger groups weaken discrimination, smaller ones fragment the hierarchy.
- Ablating the pipeline shows where the gain comes from: memory structuring alone lifts Naive RAG from 27.95/36.48 to 31.81/40.77 average BLEU/F1 on LoCoMo with Qwen3-8B, and adding both retrieval stages gives the best BLEU/F1 with the lowest token usage.
- Retrieved evidence is denser: on LoCoMo multi-hop questions, xMemory raises the proportion of blocks containing two or at least three distinct answer evidence units to 13.14% and 12.19%, compared with 7.82% and 6.53% for Naive RAG.

## Details

Evaluation setup. The framework is evaluated on two long-term memory benchmarks: LoCoMo, with 50 multi-session dialogues averaging about 18K tokens and roughly 300 turns, and PerLTQA, which tests personalised long-term memory over longer contexts (around 25K tokens on average) with sentence-style answers. Following prior work, the four answerable LoCoMo categories are reported and the adversarial subset is omitted because it provides no gold answers for the metrics used. The metrics are BLEU-1 and token-level F1 on both datasets plus ROUGE-L on PerLTQA. Three reader LLMs are used — the open-source Qwen3-8B and Llama-3.1-8B-Instruct and the closed-source GPT-5 nano — with greedy decoding, text-embedding-3-small embeddings, and the same backbone for memory construction and answer generation. Because GPT-5 nano does not expose token-level logits, its uncertainty is estimated with GPT-4.1-mini, and all xMemory hyperparameters are fixed across datasets and backbones.

Why the baselines fall short. Full Memory and Naive RAG preserve large amounts of raw context but often return redundant or weakly discriminative evidence; LightMem reduces cost mainly through post-retrieval compression and performs worse on multi-hop and temporal questions; the structured baselines introduce higher-level organisation, but their structures are not centred on decoupled evidence units and revisable grouping.

Method mechanics. The hierarchy is built in three stages — segments, components, and groups — with components keeping links back to their source segment so that intact context can still be recovered. Grouping is scored by a sparsity-plus-semantic-faithfulness objective that also guides structure updates; split and merge play complementary roles, with split repartitioning broad groups and merge preventing the high-level index from becoming unnecessarily fragmented. Retrieval then runs from coarse to fine units.

Evidence-focused analyses. Decoupling is credited with concentrating answer-relevant evidence before retrieval instead of leaving it dispersed across redundant chunks; the LLMLingua-2 pruning variant shifts retrieved blocks toward single-hit blocks, suggesting that post-retrieval compression can fragment entangled evidence even when the remaining context is broadly relevant. The paper concludes that token efficiency in agent memory should be measured by evidence utility rather than context reduction alone, and that after amortising memory-construction cost the full system still attains the highest average BLEU at a lower total token cost than Nemori, MemoryOS, and A-Mem. Limitations are stated plainly: the empirical evaluation covers LoCoMo and PerLTQA only, so extending the design to broader agentic settings remains future work.
